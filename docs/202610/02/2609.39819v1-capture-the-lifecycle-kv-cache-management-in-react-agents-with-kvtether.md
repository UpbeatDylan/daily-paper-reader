## 摘要
高效服务长上下文推理与行动（ReAct）智能体依赖于 KV 缓存复用，以降低大语言模型（LLM）的预填充延迟和经济成本。然而，智能体执行框架与底层服务栈之间存在语义鸿沟。通过上下文变更、工具执行和子智能体协调，上下文消息可能处于活跃使用、被永久丢弃或暂时未使用状态，而服务栈仅能观察到对相应 KV 缓存的访问。这种生命周期盲区使 LRU 等仅基于最近使用情况的策略无法及时回收已失效 KV，也无法保留那些会比更新条目更早被复用的较旧 KV。我们提出 KVTether，一个面向 ReAct 智能体的生命周期感知 KV 缓存管理框架。通过追踪嵌入智能体执行框架中的语义原语，KVTether 能在高度动态的执行过程中捕获运行时生命周期语义。随后，KVTether 将消息级语义转换为 KV 级生命周期状态，并利用这些状态驱动按状态划分优先级的缓存管理，同时不向智能体执行框架暴露物理复杂性。在回收已失效 KV 后，KVTether 优先保留正在等待复用的存活但空闲 KV，从而减少复用前的过早驱逐。在智能体基准测试和生产负载中，相较于 LMCache 和 MORI，KVTether 分别将端到端请求延迟最多降低 26.3% 和 17.4%，并将估计任务成本平均降低 40.0% 和 33.2%。

## Abstract
Efficient serving of long-context reasoning-and-acting (ReAct) agents relies on KV cache reuse to reduce large language model (LLM) prefill latency and monetary cost. However, a semantic gap exists between agent harnesses and the underlying serving stack. Through context mutation, tool execution, and subagent coordination, context messages may become actively engaged, permanently discarded, and temporarily unused, while the serving stack only observes accesses to the corresponding KV cache. This lifecycle blindness prevents recency-only policies such as LRU from reclaiming dead KV promptly and from preserving older KV that will be reused sooner than newer entries.   We present KVTether, a lifecycle-aware KV cache management framework for ReAct agents. By tracing semantic primitives embedded in agent harnesses, KVTether captures runtime lifecycle semantics during highly dynamic execution. KVTether then translates message-level semantics into KV-level lifecycle states and uses these states to drive state-prioritized cache management without exposing physical complexities to agent harnesses. After reclaiming dead KV, KVTether preferentially preserves live-but-idle KV that is waiting for reuse, reducing premature eviction before reuse. Across agent benchmarks and production workloads, KVTether reduces end-to-end request latency by up to 26.3% and 17.4% relative to LMCache and MORI, respectively, and lowers estimated task cost by 40.0% and 33.2% on average.

# KVTether 论文结构化总结

## 1. 核心问题与整体含义

- **研究背景**：LLM 应用正从交互式聊天机器人演进为自主智能体（如 Claude Code、Codex、OpenClaw、Hermes），通过 ReAct 循环交替执行 LLM 推理与工具调用。一个请求可累积数十万 token（如 Codex 可达 258K token 上下文），对应 GLM-4.7 需 93GB KV 缓存，因此 KV 缓存复用对降低预填充延迟与成本至关重要。
- **核心问题**：智能体执行框架（agent harness）与底层服务栈（serving stack）之间存在**语义鸿沟**。应用层以消息级操作（append、replace、remove、fork、one-shot 构造等）管理上下文，定义了消息的逻辑生命周期；而 KV 存储层只能观察到缓存页、共享前缀和访问事件，无法判断缓存 KV 是逻辑存活、被显式保留、暂时等待还是已经死亡。
- **两种典型失效**：
  - **存活失效（zombie KV）**：逻辑生命周期已结束的 KV 仍驻留物理缓存，例如压缩子智能体用摘要替换长历史后，被丢弃的历史与一次性压缩上下文已逻辑死亡，但其 KV 可能持续存在。回放显示僵尸 KV 最高占 LMCache 容量的 36.3%。
  - **排序失效（wrong-direction eviction）**：LRU 等仅基于最近性的策略会错误驱逐。ReAct 智能体中新产生的 KV 常因等待工具执行、调度或子智能体协调而并非最接近复用，71.0%–95.0% 的 LRU 驱逐是错误方向的。
- **整体含义**：需要一种**生命周期感知**的 KV 缓存管理方案，将应用层生命周期语义导出至服务栈，而非在下游被动推断。

## 2. 方法论

### 核心思想
KVTether 通过追踪嵌入 agent harness 的**语义原语**捕获运行时生命周期语义，将其翻译为 KV 级生命周期状态，并驱动**状态优先**的缓存管理，同时不向 harness 暴露物理复杂性。整体为"语义导出 → 生命周期管理 → 缓存控制"的流水线。

### 关键技术模块

- **语义原语模型（Semantic Primitive Model）**
  - 在消息操作层面进行生命周期导出，匹配现有 harness 的上下文管理方式。
  - 提供 8 个原语，分为三类：
    - 消息编辑：`append`、`replace`、`remove`
    - 上下文创建：`fork`（子上下文共享父前缀）、`spawn`（独立子上下文）
    - 生命周期声明：`one_off`（仅一次推理）、`pin`（长期保留）、`unpin`（释放保护）
  - 空间上覆盖消息列表的增/改/删及顺序变化；时间上覆盖一次性使用、跨轮复用、显式保留等需求。

- **事件驱动生命周期管理器（Event-Driven Lifecycle Manager）**
  - **KV 范围解析**：以 context 为管理单元，维护消息到 token/KV 范围的映射。`remove`/`replace` 会因前缀依赖导致缓存后缀失效，被翻译为后缀失效并进入 Expired 状态。物理翻译受 KV 存在性约束，仅在推理边界应用更新。
  - **生命周期状态管理**：为每个 context 中的每个消息版本维护状态，包含 Pinned、Active、Suspended、Expired、Temporary 四类（Pinned 与 Temporary 为特殊类别）。状态转移由原语操作和运行时事件驱动：
    - 追加消息 → Active；预填充完成 → Suspended；下次请求前重新激活参与消息。
    - 上下文终止 → 普通消息 Expired，Pinned 消息保持保护。
    - fork 时父子状态独立演化，但共享物理 KV。
    - `one_off` 声明的上下文标记为 Temporary，其独占 KV 绕过复用存储。

- **状态引导 KV 缓存引擎（State-Guided KV Cache Engine）**
  - **状态优先的 KV 准入（Algorithm 1）**：按优先级顺序释放空间：
    1. Temporary KV 直接绕过（不进入复用存储）；
    2. 回收 Expired KV；
    3. 驱逐 Suspended KV；
    4. 回退到 Active KV；
    5. 若新 KV 为 Pinned，则与 Pinned KV 竞争。
  - **共享 KV 管理**：为每个 token 的 KV 跨上下文追踪所有消息版本状态，取最高优先级状态作为驱逐决策依据；仅当所有映射版本均 Discarded 时才可回收。
  - **Suspended 层内的 MRU 排序**：经过状态过滤后，剩余不确定性集中在"存活但空闲"层。观察到复用在写入后并非集中于最年轻年龄，而是聚集在数秒之后（Agent-G 43.1% 在 1–3s，Codex 46.6% 在 3–6s，Agent-X 87.5% 在 2–4s）。因此 KVTether 采用 **MRU（最近使用）** 作为启发式实现：压力下优先驱逐最近挂起的 KV，保留等待更久、更可能被复用的条目。

- **实现**：三个组件——轻量级 in-harness 框架（同步记录原语、异步导出）、服务端 Python 生命周期管理器（复现 prompt 格式化与 tokenization，拦截 LLM 调用）、多层级缓存引擎（GPU HBM / 主机内存 / 远程内存，含 CUDA 原生引擎与 MoonCake 跨节点传输及兼容 LMCache 的路径）。

## 3. 实验设计

- **数据集 / 场景**：三个 ReAct 智能体工作负载
  - **Agent-X** 与 **Agent-G**：来自大型云服务商的两种生产编码智能体轨迹，各 400 条任务，合并峰值超 27,000 活跃会话。
  - **Codex**：基于 Codex 的自部署软件工程智能体运行 TerminalBench。
- **Benchmark**：TerminalBench（用于 Codex）；生产轨迹用于 Agent-X/Agent-G。
- **对比方法**：
  - **LMCache (LMC)**：强语义盲 KV 缓存，使用 LRU 驱逐。
  - **MORI**：智能体感知基线，基于推断的请求空闲度预测复用并排序。
  - **KVTether 的两个消融变体**：`KVTether w/o LT`（关闭生命周期追踪，保留 MRU）和 `KVTether w/o RO`（保留生命周期追踪与状态优先级，但 Suspended 层用 LRU 替代 MRU）。
- **评价指标**：KV 缓存命中率、累计预填充时间、端到端延迟、平均任务定价（基于 DeepSeek-V4-Pro 峰值费率估算）。

- **集成评估**：在六个 harness（Codex、SWE-agent、OpenCode、Hermes、Agent-G、OpenClaw）上测量集成代码量，并以 Codex 为案例展示 safety guardian 与子智能体调用两种语义函数。

## 6. 主要结论与发现

- **命中率**：KVTether 相较 LMCache 和 MORI 分别实现平均绝对命中率提升 **33.3%** 和 **24.5%**，最高达 **47.8%** 和 **36.4%**；高负载下 LMCache 在 Agent-X 命中率降至 10.2%，而 KVTether 保持 49.5%。
- **预填充时间**：平均降低 **29.2%** 和 **23.3%**，最高 **41.2%** 和 **33.2%**。
- **端到端延迟**：平均降低 **16.5%** 和 **12.4%**，最高 **26.3%** 和 **17.4%**（延迟收益小于预填充收益，因解码仍需执行）。
- **任务成本**：平均降低 **40.0%** 和 **33.2%**，最高 **53.6%** 和 **44.1%**。
- **消融结论**：
  - 关闭生命周期追踪（w/o LT）导致平均命中率下降 25.6%，僵尸页在 Codex/Agent-X/Agent-G 上平均占 22.1%/21.4%/38.5%，而 KVTether 仅为 <2.5%/0/0；仅改变驱逐顺序无法解决容量被无效 KV 占用的问题。
  - 用 LRU 替代 MRU（w/o RO）导致平均命中率下降 29.1%，错误方向驱逐比例在 Agent-X/Agent-G/Codex 上升至 65.6%/75.0%/92.3%，而 KVTether 降至 38.7%/25.7%/38.6%。
- **集成成本**：六个 harness 集成代码量仅 **26–216 行**，上下文管理器 14–162 行，语义函数 12–54 行。
- **开销**：运行时与资源开销相对 LLM 调用执行时间与服务栈资源占用可忽略（约 2.0%）。

## 7. 优点

- **问题洞察深刻**：明确识别并量化了 ReAct 智能体服务中"僵尸 KV"与"错误方向驱逐"两类由语义鸿沟导致的失效，数据支撑充分（僵尸占比最高 36.3%，错误驱逐比例最高 95.0%）。
- **生命周期导出思路新颖**：不同于下游推断或基于预定义工作流的方案，KVTether 从 harness 侧主动导出生命周期语义，适应 ReAct 运行时动态生成的执行拓扑。
- **语义原语设计通用**：8 个消息级原语抽象稳定，跨 4 种不同语言实现的 harness 验证，集成代码量小（最低 26 行），易于采纳。
- **跨层翻译设计巧妙**：事件驱动管理器封装 tokenization、前缀结构与共享细节，既保证精确 KV 控制，又不将物理复杂性上推给应用开发者。
- **MRU 启发式简单有效**：不依赖精确的逐条目复用预测，仅利用 ReAct 执行导致的稳定方向性偏差，鲁棒性较好。
- **状态优先准入顺序**：先排除语义确定的情形（Temporary/Expired），将不确定性限定在 Suspended 层，避免确定情形干扰真正不确定的决策。
- **实验严谨**：相同部署、容量、任务与到达序列；多负载点；消融与开销分析完整。

## 8. 不足与局限

- **工作负载覆盖有限**：仅在编码类智能体（Codex、Agent-X、Agent-G）上评估，未涵盖研究型、多模态或更广泛智能体任务，泛化性有待验证。
- **依赖 harness 集成**：需要修改 agent harness 代码（尽管量小），对于无法修改或闭源的外部 harness，需离线重建事件（如 Agent-X/Agent-G 的做法），可能损失部分在线精度。
- **MRU 为启发式而非最优**：论文承认 MRU 利用的是稳定方向性趋势而非精确预测，在极端不同的部署条件（如更长队列延迟）下其优势是否持续需进一步验证。
- **回放式评估的偏差风险**：工具调用被模拟为等待记录时长，随机 prompt 匹配复用前缀长度，可能无法完全反映真实工具执行、网络波动与调度竞争的影响。
- **共享 KV 回收时机**：虽然设计了跨上下文状态聚合，但论文对"所有映射版本均 Discarded 后且 in-flight 使用完成后"的回收在复杂并发场景下的表现讨论有限。
- **未涉及模型训练层面**：本文为纯服务系统研究，不涉及模型微调或训练，因此无法评估对模型质量的影响（不过 KV 管理本身不影响输出质量）。
- **生产环境验证有限**：虽使用生产轨迹，但实验在受控回放环境中进行，真实生产部署的端到端效果与长期稳定性尚需验证。
- **潜在偏差**：定价估算基于 DeepSeek-V4-Pro 峰值费率，不同部署与定价模型下的成本收益可能不同。
