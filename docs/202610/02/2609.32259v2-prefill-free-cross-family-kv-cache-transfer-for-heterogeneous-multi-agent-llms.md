## 摘要
近期的多智能体LLM系统越来越多地结合异构模型来承担专门的智能体角色。然而，基于文本的通信要求每个接收方预填充发送方已处理过的共享上下文。复用发送方的键值（KV）缓存可以避免这种冗余，但跨模型家族的免预填充传输必须处理分词、模型深度和KV表示方面的差异。为解决这些问题，我们提出 HeteroFold，一种免预填充的跨模型家族KV缓存传输方法，它使发送方和接收方均保持冻结。HeteroFold 对齐模型结构，将发送方缓存映射到接收方空间，并对其进行校准以保持接收方行为。在六个传输方向上，HeteroFold 在所有四个长上下文基准和大多数短上下文设置上取得了最佳的缓存传输性能。它在多智能体基准上也与基于文本的通信相当。在32K上下文长度下，Llama-3.1-8B→Ministral-3-14B 传输比 Native Prefill 快 10.7×，比最先进的免预填充基线 Dense Latent 和 KV Ridge 快 1.18–1.47×。这些结果表明，HeteroFold 能够在无需接收方预填充的情况下实现高效的跨模型家族KV复用。

## Abstract
Recent multi-agent LLM systems increasingly combine heterogeneous models for specialized agent roles. However, text-based communication requires each receiver to prefill shared context already processed by the sender. Reusing the sender's key-value (KV) cache avoids this redundancy, but prefill-free transfer across model families must handle differences in tokenization, model depth, and KV representations. To address these issues, we propose \textit{HeteroFold}, a prefill-free cross-family KV cache transfer method that keeps both the sender and receiver frozen. HeteroFold aligns model structures, maps the sender cache into the receiver space, and calibrates it to preserve receiver behavior. Across six transfer directions, HeteroFold achieves the best cache-transfer performance on all four long-context benchmarks and most short-context settings. It also matches text-based communication on the multi-agent benchmark. At 32K context length, Llama-3.1-8B$\rightarrow$Ministral-3-14B transfer is $10.7\times$ faster than Native Prefill and $1.18$--$1.47\times$ faster than the state-of-the-art prefill-free baselines, Dense Latent and KV Ridge. These results show that HeteroFold enables efficient cross-family KV reuse without receiver prefill.

# 论文总结：Prefill-Free Cross-Family KV Cache Transfer for Heterogeneous Multi-Agent LLMs

## 1. 核心问题与整体含义（研究动机与背景）

- **研究背景**：多智能体系统（MAS）日益采用异构模型家族（如 Llama、Qwen、Ministral）来承担求解、评估、聚合等不同角色。这类系统常需交换共享上下文（shared context）。
- **核心问题**：基于文本的通信要求每个接收方（receiver）对发送方（sender）已处理过的上下文重新预填充（prefill），以重建自己的 KV 缓存。随着上下文增长，这带来大量冗余计算与延迟。
- **技术障碍**：直接复用发送方的 KV 缓存并跨模型家族传输，需同时解决三类不匹配：
  - **分词器不匹配**（tokenization mismatch）；
  - **模型深度不匹配**（layer/depth mismatch）；
  - **KV 表示不匹配**（KV representation mismatch）。
- **关键洞察**：仅靠 KV 缓存重建误差低并不代表接收方行为被保留。文中图 2 显示，KV Ridge 的重建误差低于 HeteroFold，却扭曲了接收方的注意力；因此有效迁移必须保留接收方下游计算行为，而非仅缓存数值。
- **整体含义**：HeteroFold 被定位为"首个带显式跨分词器对齐的、无需接收方预填充的跨模型家族 KV 缓存传输方法"，目标是让 KV 计算可跨模型家族边界复用，推动异构 LLM 智能体间的高效缓存共享。

## 2. 方法论：核心思想与关键技术细节

- **核心思想**：在发送方与接收方均**冻结**的前提下，对齐二者结构，将发送方 KV 缓存映射到接收方空间，并对其校准以保持接收方行为；学到的修正折叠为固定仿射映射，支持直接解码、无需接收方预填充或额外推理模块。
- **总体流程**：Token 与 Layer 对齐（TA + LA）→ Recolor KV 映射 → 输出感知校准（Output-Aware Calibration）→ 折叠为推理用仿射映射。

- **3.1 Token 与 Layer 对齐**
  - **Token Alignment (TA)**：以**共享字符结束边界**建立发送方与接收方 token 的对应。无精确匹配的接收方边界，使用最近的前置共享边界对应的发送方状态；首个匹配之前使用第一个发送方状态；多对一情形**不做平均**。示例：Qwen3 与 Ministral-3 对 "The unbelievable result." 的不同切分，接收方边界 9、12 复用 Qwen 结束于字符 3 的状态。
  - **Layer Alignment (LA)**：采用比例深度对齐，取匹配层周围偏移 (−4, 0, +4) 的**三个发送方层**拼接：
    - π(ℓ) = 1 + round((ℓ−1)(L_S−1)/(L_R−1))
    - N(ℓ) = clip[1,L_S](π(ℓ)−4, π(ℓ), π(ℓ)+4)
  - 将所选发送方特征按 token 对拼接为 x^ℓ,c_n，接收方目标为 y^ℓ,c_n；展平（flatten）以支持头数不同时的跨头映射。
  - 映射位置：K 在 key normalization 与 RoPE **之前**映射，V 在投影**之后**映射；接收方随后施加自己的 key 归一化与 RoPE。

- **3.2 矩匹配 Recolor**
  - 动机：逐 token 重建目标可能重建误差低却改变接收方注意力。图 4(b,c) 显示 Recolor 比 Ridge（ℓ2 正则最小二乘）更贴近原生 K/V 分布。
  - 计算全局 RMS 标量 r 做缩放：Z = X/r，r 推理时固定。
  - 对 Z 与 Y 做白化，再用 **Procrustes 对齐**配对特征：
    - Σ_Z^{−1/2} Σ_ZY Σ_Y^{−1/2} = UΛQᵀ，R⋆ = UQᵀ
  - 恢复接收方协方差与均值，得到 Recolor 初始化：
    - A = Σ_Z^{−1/2} R⋆ Σ_Y^{1/2}，b = μ_Y − μ_Z A，y^(0) = (x/r)A + b
  - 满足 μ_Z A + b = μ_Y 且 AᵀΣ_Z A = Σ_Y（数值稳定化使协方差匹配近似成立）。

- **3.3 输出感知校准**
  - 关键分解：bO − O* = [(bP − P*)V*]W_Oᵀ（key 引起的注意力模式变化）+ [bP(bV − V*)W_Oᵀ]（value 引起的变化），据此为 K 和 V 设计不同校准目标。
  - 在 Recolor 输出上加**秩为 ρ_c 的低秩修正**：by = y^(0) + (y^(0)B)G，B∈R^{d_R×ρ_c}，G∈R^{ρ_c×d_R}，G 初始化为零，仅优化 B 与 G。
  - **Key 目标**：匹配注意力模式及其输出投影后的影响，用路由 KL + key 引起的输出变化平方误差（除以 d_model^R）。
  - **Value 目标**：在固定映射注意力权重下优化 value，用归一化平方误差拟合原生输出。
  - 校准仅使用与问题跨度重叠的 token 上的原生接收方 query、注意力、value、输出，**不使用金标答案或生成续写**。
  - 校正秩 ρ_c = 16，联合优化 4 个 epoch，AdamW（lr 3×10⁻⁴，weight decay 10⁻⁴，梯度裁剪 1），选取 held-out 组合损失最低的检查点。

- **推理折叠**：A_final = A(I + BG)，b_final = b(I + BG)，Φ_ℓ,c(x_j) = (x_j/r)A_final + b_final。推理时每个接收方层与角色只需一个固定仿射映射，无需独立修正模块。

## 6. 主要结论与发现

- HeteroFold 在**全部四个长上下文基准**和**多数短上下文设置**上取得最佳缓存传输性能，且覆盖全部六个跨家族传输方向。
- 在多智能体 HIDDEN BENCH 上，平均准确率 30.6%、多数投票 29.2%，与 TextMas（29.2%/27.7%）相当，明显优于 Dense Latent+TA（18.5%/7.7%）与 KV Ridge+TA（21.8%/16.9%）。
- **效率**：32K 上下文下 Llama-3.1-8B→Ministral-3-14B 传输比 Native Prefill 快 **10.7×**，比 Dense Latent 与 KV Ridge 快 **1.18–1.47×**；加速比从 4K 的约 3.5–3.8× 增长到 32K 的约 10.7×。
- **组件贡献**（表 3，Ministral-3-14B→Llama-3.1-8B）：替换 TA 为同索引配对退化最大（GSM8K 从 63.46 降至 7.13）；单层与头局部映射均降低性能，支持多层聚合与跨头混合；Recolor 优于 Ridge；key 校正在长上下文贡献最大。
- **行为保持**：HeteroFold 比两个基线更贴近原生接收方的 next-token 分布、注意力权重与答案选择（图 6）；GSM8K 文本重建有序重叠达 83.04（对比 KV Ridge+TA 76.68、Dense Latent+TA 39.74）。
- **资源占用**：映射器参数 201–252M，比 Dense Latent 少约 25%、比 KV Ridge 少约 62%。
- **同家族泛化**：在 Qwen3 同家族迁移中同样优于基线，说明增益不限于跨分词器对齐。
- **自回归稳定性**：仅用 prompt token 校准，解码后期预测分歧未持续增大。

## 7. 优点

- **问题定位准确**：明确指出"KV 重建误差低 ≠ 接收方行为被保留"，并以注意力/输出误差实验佐证，方法论由此展开，逻辑自洽。
- **方法设计有针对性**：
  - TA 基于共享字符边界，直接、无需训练、可处理多对一与细粒度切分；
  - 多层聚合 + 跨头展平映射，适配不同深度与头数；
  - Recolor 用 Procrustes 白化对齐均值/协方差，优于 ℓ2 Ridge；
  - 输出感知校准按 K/V 对输出的不同作用分解，目标设计清晰；
  - 低秩修正可**折叠**进仿射映射，推理零额外模块，部署友好。
- **双方模型冻结**：无需微调，迁移成本低（单方向约 2 H100 GPU 小时）。
- **实验客观性较好**：给基线同等的 TA 对齐以隔离变量；提供同家族 sanity check；校准数据与划分统一；延迟测量在双 H100 + NVLink 真实环境下进行并报告中位数。
- **效率与效果兼顾**：在精度提升的同时，映射器更小、延迟更低、额外显存更少。

## 8. 不足与局限

- **基线复现风险**：Dense Latent 与 KV Ridge 无公开实现，作者自行复现，可能存在调参或实现偏差，影响比较公平性。
- **实验规模有限**：长上下文 Qasper/HotpotQA 各仅 200 项；多智能体基准仅 65 个任务；GSM8K 重建仅 100 题，统计效力有限。
- **模型家族覆盖有限**：仅涉及 Llama、Qwen、Ministral 三家、三种规模（4B/8B/14B），未验证更大规模（如 70B+）或 MoE、不同注意力机制（如 MLA）模型。
- **校准数据依赖**：需针对每个传输方向离线拟合映射（约 2 GPU 小时/方向）并存储 0.40–0.50 GB 映射；方向变化需重新校准，扩展性受限。
- **绝对性能仍有差距**：长上下文任务上仍明显低于 TextMas（如 Llama→Ministral 的 Qasper 21.58 vs 45.59），说明缓存传输在困难长上下文场景下信息损失仍较大。
- **显存问题**：图 D 显示含 payload 拷贝时，缓存传输并不总能降低额外峰值接收方显存。
- **校准范围限制**：仅用问题跨度 token 校准，未使用生成续写；虽在 GSM8K 上验证稳定性，但对长生成任务的泛化仍需更多证据。
- **发送方成本未计入主延迟**：若发送方尚未处理上下文，需额外 sender prefill（32K 下 Llama 3,381 ms / Qwen 3,083 ms），端到端收益取决于发送方是否已缓存。
