## 摘要
键值（KV）缓存的内存占用限制了长上下文模型的实际使用，并且当一份预填充上下文之后需要服务许多不同查询时，它会主导成本。在这种可复用场景下，与查询无关的压缩会在成本与质量之间权衡：轻量级估计器成本低但不够准确，而全上下文重构评分更准确，却会重新处理整个提示。我们提出 KV$^2$，一种基于选择性重构的与查询无关的 KV 缓存压缩方法。KV$^2$ 首先使用轻量级代理评分器来识别上下文中信息丰富的 token，然后仅重新处理该子集以计算最终淘汰分数。在 RULER、Needle-in-a-Haystack 和 LongBench 上，随着预算收紧，KV$^2$ 相对基线的优势扩大：在 RULER 16K 上，当 KV 缓存预算为 2% 时，它将平均分数比次优基线提高超过 40 个百分点；在 LongBench 上，它在 2%-10% 预算下取得最高平均值，同时压缩阶段运行时间和峰值内存低于全上下文重构。因此，可复用 KV 缓存压缩不需要重新处理完整上下文。我们的代码可在 https://anonymous.4open.science/r/KVsquared-0B97 获取。

## Abstract
The memory footprint of the key-value (KV) cache constrains the practical use of long-context models, and it dominates cost when one prefilled context must later serve many different queries. In this reusable setting, query-agnostic compression trades cost against quality: lightweight estimators are cheap but less accurate, whereas full-context reconstruction scoring is more accurate yet reprocesses the entire prompt. We introduce KV$^2$, a query-agnostic KV-cache compression method based on selective reconstruction. KV$^2$ first uses a lightweight proxy scorer to identify informative in-context tokens, then reprocesses only this subset to compute final eviction scores. On RULER, Needle-in-a-Haystack, and LongBench, KV$^2$'s margin over baselines widens as the budget tightens: on RULER 16K at a 2% KV-cache budget it improves the average score over the next-best baseline by more than 40 percentage points, and on LongBench it attains the highest average across 2%-10% budgets at lower compression-stage runtime and peak memory than full-context reconstruction. Reusable KV-cache compression thus does not require reprocessing the full context. Our code is available at https://anonymous.4open.science/r/KVsquared-0B97.

## 1. 核心问题与整体含义

- **背景痛点**：长上下文大语言模型（LLM）的实际部署受限于 KV 缓存的内存占用。KV 缓存随上下文长度线性增长（如 100K token 的 Qwen-2.5-32B 需约 26 GB KV 显存，70B 级模型百万 token 需约 320 GB），并在解码阶段因内存带宽成为瓶颈。MQA/GQA 等架构只降低基线，不解决根本瓶颈。
- **可复用场景**：论文聚焦于"一份预填充上下文需服务多个后续查询"的场景（如长文档问答、持久化 Agent 上下文）。此时单个压缩缓存需与其他请求共存于同一设备，预算常被压到原始缓存的 10% 以下，远严于已有工作通常研究的预算。
- **核心权衡**：查询无关（query-agnostic）压缩面临质量与成本的两难——轻量估计器便宜但精度低；全上下文重构评分（如 KVzip）准确但需重新处理整个提示，对"简单 token"与"信息 token"付出相同代价。
- **关键观察**：长上下文模型并不均等地使用所有位置，信息性"锚点" token 是稀疏的；因此在极紧预算下，只需对少量精心挑选的 token 做重建即可恢复大部分有用信号。
- **整体含义**：论文证明可复用 KV 缓存压缩无需重处理完整上下文，可用更低的压缩阶段开销获得更优质量。

## 2. 方法论

### 2.1 核心思想

- KV² 是一个**查询无关的两阶段选择性重建（Selective Reconstruction）压缩流程**：
  - **Stage 1（查询选择）**：用轻量代理评分器识别少量高信息量的上下文 token。
  - **Stage 2（缓存评分）**：仅用这些被选 token 作为重建查询，对完整缓存做一次重建前向，得到最终淘汰分数。
- 核心设计抉择不在于"是否重建"，而在于**"用哪些查询来重建"**——把昂贵的评分集中在最可能影响压缩后行为的依赖上。

### 2.2 关键技术细节

- **分块（Chunking）**：沿用 KVzip，保留前缀开头的少量 sink token 原样不动，将可压缩部分划分为块 $C_1, \dots, C_M$，每块大小 $|C_r| \le m$（默认 $m = 4\text{K}$）。各块独立提出重建查询，再将局部分数合并为全局淘汰决策。
- **代理评分与查询选择**：
  - 默认代理为 **KeyDiff** 分数 $d_{i,\ell,h}$（逐 token、逐层、逐 KV 头）。
  - 在层与 KV 头上**取平均**聚合到 token 级：$p_i = \frac{1}{LH}\sum_{\ell=1}^{L}\sum_{h=1}^{H} d_{i,\ell,h}$（实验表明平均优于最大聚合）。
  - 在每块内选出得分最高的 $n_q = \max(\lfloor \rho |C_r| \rfloor, 1)$ 个位置作为有序重建集 $Q_r$，其中 $\rho$ 为查询选择比例。这些位置无需连续，作为"探针查询"使用。
- **选择性重建（Selective Reconstruction）**：
  - 将选出的重建 token 追加在预填充缓存之后，赋予紧随上下文的 position ID，在因果掩码下对全缓存做一次新的前向，使其**全局条件化**。
  - 但**分数提取限制在当前块内（局部评分）**。对层 $\ell$、KV 头 $h$，缓存位置 $i$ 的块内分数为：
    $$s_{i,\ell,h} = \max_{j=1,\dots,n_q} a^{(\ell,h)}_{ji}$$
    即取任一重建查询对位置 $i$ 的**最大注意力**，确保只要有任一查询强依赖该位置就保留它。
  - 这种"**全局条件化、局部评分**"的分离是 KV² 的主要设计选择。
- **迭代自精炼（Iterative Refinement）**：Stage 2 产生的逐 token 分数与 Stage 1 代理信号粒度相同，可直接替代下一轮的代理，实现自精炼。单遍 KV² 即第一轮精炼，作为默认配置。
- **复杂度**：代理阶段 $O(n_c)$ 线性；重建前向总代价 $O(\rho n_c^2 + \rho^2 n_c m / 2)$；分数提取为块内 $n_q \times (m + n_q)$ 矩阵，总 $O(\rho m n_c)$。相对 KVzip（重建每块全部 token），KV² 的重建代价随 $\rho$ 而非全块缩放。

## 3. 实验设计

### 3.1 数据集 / 场景

- **LongBench**：双语、多任务长上下文基准（单/多文档 QA、摘要、少样本分类、合成计数、代码等 16 个子任务）。
- **Needle-in-a-Haystack (NIAH)**：基于 Paul Graham 散文构建的针尖检索诊断，比合成模板更真实，用逐样本 ROUGE-2 recall 度量。
- **LongBench-E**（附录）：更均匀的长度分布，用于分析输入长度效应。
- **InfiniteBench**（附录）：约 200K token 规模的扩展评估。

### 3.2 模型与配置

- 主要骨干：**Llama-3.1-8B-Instruct** 与 **Qwen3-8B**；附录使用 **Qwen2.5-7B-Instruct-1M**。
- 默认配置：块大小 4K、KeyDiff 作为一阶段代理、查询选择比例 $\rho$ 跟踪最终保留的 KV 比例。
- 使用 PyTorch + Hugging Face Transformers + FlashAttention-2，基于 NVIDIA 的 **kvpress** 框架。

### 3.3 对比方法

## 6. 主要结论与发现

- **预算越紧优势越大**：在 RULER 16K 的 2% 预算下，KV² 平均分比次优基线高逾 **40 个百分点**；5% 与 2% 预算下退化最平缓。
- **LongBench**：在 2%、5%、10% 预算下均取得最高平均分（Llama 上 2% 从 24.16 提升到 33.59；Qwen3-8B 从 16.59 提升到 32.97）。增益集中在多文档 QA、合成检索与计数任务。
- **NIAH**：KV² 在上下文长度与针尖深度增加时最稳定；KeyDiff 表现参差，KVzip 在长 haystack 上退化更快。
- **效率优势**：单遍 KV² 在各块大小下始终比 KVzip 更快、峰值内存更低，原因是只重建代理选出的子集。
- **最优重建比例随预算增长**：Llama 上 2%/5%/10% 预算对应 10%/50%/100% 重建比例；Qwen3-8B 对应 10%/25%/75%。这支持了"$\rho$ 跟踪最终保留比例"的默认调度。
- **代理选择重要但可插拔**：KeyDiff 最强，Knorm 次之；CUR 与 StreamingLLM 在高压缩下甚至低于 Random 代理。
- **迭代精炼**：增益主要出现在前几轮，且只在初始代理较弱或重建比例极小时显著；作为可选扩展而非默认。

## 7. 优点

- **方法设计亮点**：
  - "全局条件化、局部评分"的分离，既保留全上下文重建的表达力，又将评分限制在块内以降低开销。
  - 两阶段框架**模块化**：代理评分器可替换，便于与更强代理结合。
  - 天然支持**迭代自精炼**，可按需分配压缩算力。
  - **免训练**、即插即用，无需微调或额外训练数据。
- **实验设计亮点**：
  - 聚焦极紧预算（1–2%）这一部署相关但此前研究不足的区间。
  - 同时报告质量、压缩阶段运行时与峰值内存，给出质量—效率权衡。
  - 消融维度齐全（代理、比例、块大小、迭代），并含多骨干验证。
  - 明确披露后端限制，不夸大解码收益。
- **结论价值**：指出"信息锚点稀疏"这一可推广的直觉，为可复用缓存压缩提供新范式。

## 8. 不足与局限

- **实现层限制**：当前基于 kvpress 的 headwise masking 实现**未物化物理紧凑的缓存**，因此只测量了压缩阶段成本，尚未转化为真实解码时的显存与延迟收益。作者指出需 headwise 缓存压缩、支持各头独立序列长度的注意力内核与重复查询服务流水线。
- **迭代精炼非自适应**：目前为固定轮数，作者建议未来做"只在重建集或分数仍显著变化时继续"的自适应调度。
- **代理机制可加强**：内容自适应代理优于结构固定代理，但学习型/模型感知代理仍有探索空间。
- **应用边界**：当有用证据在提示中广泛分散时（如 **RepoBench-P** 子任务），全上下文重建反而更有效；KV² 的增益主要体现在证据稀疏、锚点式的情形。
- **实验覆盖缺口**：
  - 未给出总算力预算与训练/推理时长的量化说明。
  - 部分引用（如 InfiniteBench、部分数据集出处）在提取文本中显示为 "?"，元数据完整性受限。
  - 效率对比仅限压缩阶段，缺少端到端解码吞吐/延迟的实测。
- **潜在偏差风险**：默认 $\rho$ 跟踪最终保留比例并非逐预算最优，可能低估 KV² 的上限；极端压缩下不同代理排序可能对结论敏感。
