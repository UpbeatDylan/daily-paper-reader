KV2: A Self-Refining KV Cache
Johannes Wesch
Danni Liu
Jan Niehues
Karlsruhe Institute of Technology, Germany
johannes.wesch@student.kit.edu, danni.liu@kit.edu
Abstract
The memory footprint of the key-value (KV)
cache constrains the practical use of long-
context models, and it dominates cost when
one prefilled context must later serve many dif-
ferent queries. In this reusable setting, query-
agnostic compression trades cost against qual-
ity: lightweight estimators are cheap but less
accurate, whereas full-context reconstruction
scoring is more accurate yet reprocesses the
entire prompt. We introduce KV², a query-
agnostic KV-cache compression method based
on selective reconstruction. KV² first uses a
lightweight proxy scorer to identify informa-
tive in-context tokens, then reprocesses only
this subset to compute final eviction scores.
On RULER, Needle-in-a-Haystack, and Long-
Bench, KV²’s margin over baselines widens
as the budget tightens: on RULER 16K at a
2% KV-cache budget it improves the average
score over the next-best baseline by more than
40 percentage points, and on LongBench it at-
tains the highest average across 2%–10% bud-
gets at lower compression-stage runtime and
peak memory than full-context reconstruction.
Reusable KV-cache compression thus does not
require reprocessing the full context. Our code
is available at https://anonymous.4open.
science/r/KVsquared-0B97/.

Introduction
Long-context large language models have consid-
erably broadened the range of LLM applications,
including analyzing long documents (Bai et al.,
2024; ?), reasoning over larger code bases (Bai
et al., 2024; ?), and maintaining extended conver-
sational histories (?). However, their practical use
remains constrained by inference cost. A central
reason is the key-value (KV) cache: once a context
has been processed, the model must keep the result-
ing cached state available so that later tokens can
attend to it without reprocessing. This cache grows
linearly with context length, and increasingly dom-
inates memory use during deployment.
Autoregressive inference separates into prefill
and decode (Kim et al., 2025; Feng et al., 2025)
stages. During prefill, the model processes the full
prompt and computes keys and values for every
layer, head, and token. For an L-layer Transformer
decoder model with H key-value heads and a con-
text of nc tokens, this results in a cache KVc, con-
sisting of L · H · nc KV pairs. During decode, new
tokens are generated one at a time, and each query
attends to KVc instead of reprocessing all previous
tokens. Because KVc stores the exact keys and
values produced by prefill, decoding from it yields
the same output distribution as re-running prefill
on the full context at every step (Kim et al., 2025).
Maintaining this equivalence is what makes the
cache expensive. Every context token contributes
L · H new KV pairs to KVc, and the resident foot-
print grows accordingly. A 100K-token prompt
on Qwen-2.5-32B already requires about 26 GB
of KV memory (Chari and Van Durme, 2025),
and a one-million-token cache for a 70B-scale
model would require roughly 320 GB of GPU mem-
ory (Devoto et al., 2025a). Decoding is typically
memory-bandwidth-bound, since each generation
step rereads the cache from memory (Chari and
Van Durme, 2025; Shazeer, 2019; Yang et al.,
2024). Architectural choices such as Multi-Query
Attention (MQA) (Shazeer, 2019) and Grouped
Query Attention (GQA) (Ainslie et al., 2023a) re-
duce the baseline cache, but they do not remove
the underlying KV-cache bottleneck. KV-cache
compression is therefore essential for long-context
deployment, where the goal is to replace KVc with
a smaller cache KVc,evicted that approximately pre-
serves the equivalence above.
Beyond these architectural reductions, prior
work falls into two broad categories. The first
improves attention kernels and serving systems,
e.g., FlashAttention or PagedAttention (Dao, 2024;

out reference to any specific downstream query,
and is the focus of this work.
We introduce KV2, a query-agnostic KV-cache
compression method aimed at the reusable set-
ting described above1: a single prefilled cache co-
resides with other requests on the same device and
must serve many later queries. This requirement
easily pushes per-context budgets well below 10%
of the original cache size, lower than the budgets
typically studied in prior work (Gao et al., 2024;
Srivatsa et al., 2024; Abhyankar et al., 2024; De-
voto et al., 2025b). KV2 is motivated by a simple
observation: long-context models do not use all
positions equally, and adding context can dilute the
model’s access to the tokens that genuinely impact
downstream behavior (Liu et al., 2023). At such

tight budgets, most positions are either trivial to
retain (e.g., attention sinks) or trivial to evict (e.g.,
filler words and punctuation). The eviction deci-
sion therefore depends on a sparse set of informa-
tive anchors (Ainslie et al., 2023b; Xiao et al., 2024;
Zhang et al., 2023). Yet, existing reconstruction-
based methods score every cached entry uniformly,
by recomputing attention output over the full con-
text and measuring each position’s contribution,
which in turn pays the same cost for both trivial
and informative tokens. Instead, we show that scor-
ing a small, well-chosen set of in-context tokens
often suffices to identify the cached entries that pre-
serve the model’s behavior on the original context.
KV2 turns this intuition into a two-stage
selective-reconstruction pipeline (Figure 1).
A
lightweight proxy scorer first identifies a small set
of informative context tokens. These tokens are
then used as reconstruction queries against the full
cache to compute the final eviction scores. This
concentrates the expensive scoring pass on the de-
pendencies most likely to matter under severe com-
pression, which both stabilizes the ranking and
lowers compression-time cost. This two-stage de-
sign has two convenient properties: it is modu-
lar in the choice of the proxy scorer (§5.2), and
supports iterative self-refinement when additional
compression-time compute is available (§5.4).
Our main contributions are threefold:
• Selective reconstruction for reusable KV-
cache compression.
We introduce KV2, a
query-agnostic two-stage method that uses a
lightweight proxy to select a small set of in-
context tokens and reprocesses only this subset
to compute final eviction scores (§3).
• Strong performance under extreme compres-
sion. We evaluate down to 1–2% KV-cache bud-


gets, a highly deployment-relevant scenario im-
posed by the reusable setting and rarely studied
in prior work, and find increasing gains of KV2
over baselines as the budget tightens (§4).
• Favorable efficiency profile.
Compression-
stage runtime and peak-memory measurements
show that KV2 offers a better quality–efficiency
trade-off than applying full-context reconstruc-
tion scoring over every token (§5.1).

Related work
Early training-free eviction.
StreamingLLM
keeps recent tokens together with a small set of
initial “attention sink” tokens (Xiao et al., 2024),
and H2O emphasizes heavy hitters that repeatedly
attract useful attention (Zhang et al., 2023). These
early works established several themes that reap-
pear throughout the literature. First, token utility is
highly unequal. Second, recency is important but
insufficient on its own. Third, substantial compres-
sion can often be achieved without retraining by
exploiting signals already present in the inference
process, especially attention patterns.
Anticipating future decoding. Later methods in-
creasingly score tokens by how likely they are to
matter for future decoding. SnapKV uses an obser-
vation window near the end of the prompt (Li et al.,
2024), LAQ generates pseudo queries (Wang et al.,
2025), and Judge Q learns surrogate query tokens
(Liu et al., 2026). These methods can work well
when compression is guided by the continuation the
model is about to decode, but they are less suitable
for reusable caches that must support multiple later
questions. For that setting, Expected Attention esti-
mates token importance under a distribution of pos-
sible future queries (Devoto et al., 2025a), while
KeyDiff uses key geometry as a query-agnostic
proxy (Park et al., 2025). Both are closer to our
reusable setting because they avoid specializing the
cache to one anticipated continuation.
Context reconstruction. Context reconstruction
changes the objective altogether. Instead of ask-
ing which cached tokens one future continuation
is likely to use, it asks whether the model needs
them to reproduce the prompt itself. KVzip intro-
duced this viewpoint (Kim et al., 2025), aligning
the scoring objective closely with reusable caches
but incurring the cost of broad reconstruction. Sub-
sequent work keeps this reconstruction-based per-
spective while trying to reduce memory and com-
pute. Fast KVzip distills reconstruction-derived
importance into lightweight gating modules, and
KVzap aims to approximate stronger reconstruc-
tion signals more cheaply (Kim et al., 2026; Jégou
and Jeblick, 2026). These methods are the most
direct precursors to KV2: they share the reusable,
query-agnostic objective, but either preserve the
expense of broad reconstruction or approximate it
indirectly. KV2 differs here. It retains an actual
reconstruction pass, but makes that pass selective
by shrinking the reconstruction query set itself.
3
Method
We now describe the overview from Figure 1 in
detail. KV2 is a two-stage compression procedure.
Starting from a prefilled cache KVc, it processes
the prompt chunk by chunk. In Stage 1 (query selec-
tion), the goal is to identify a small set of in-context
tokens that, when used as queries, will most infor-
matively rank the cached entries. KV2 produces
this selection with a lightweight proxy scorer. In
Stage 2 (cache scoring), the goal is to assign every
cached entry a final eviction score. KV2 repro-
cesses only the queries selected in Stage 1 against
the full cache to produce the scores. The core de-
sign choice is therefore not whether to reconstruct,
but which queries to use for reconstruction. After
outlining the main method, we describe an optional
iterative refinement and analyze complexity.
Chunking.
Following KVzip (Kim et al., 2025),
KV2 does not score the prompt with a single global
reconstruction set. Instead, it retains a small set of
sink tokens at the start of the prefix verbatim and
partitions the rest of the cache, i.e., the compress-
ible portion into chunks:

Iterative refinement.
The same two-stage con-
struction also defines a self-refinement procedure.
Since Stage 2 produces a per-token score for each
position in Cr, at the same granularity as the
Stage 1 proxy signal pi, the output of one pass can
directly replace the proxy in the next. Single-pass
KV2 therefore corresponds to the first refinement
round, and we adopt it as the default because it of-
fers the strongest quality-efficiency trade-off. The
multi-pass variant is studied in Section 5.4 as an
optional extension.
Complexity analysis.
The proxy pass added be-
fore reconstruction is linear in the prompt length, so
the reconstruction forward pass remains the dom-
inant cost of KV2. Relative to KVzip, which re-
constructs over every token in a chunk, KV2 re-
constructs only a proxy-selected fraction ρ, so its
reconstruction-stage runtime and peak activation
footprint scale with ρ rather than with full-chunk
reconstruction. Score extraction is cheaper because
it remains chunk-local: after the reconstruction
forward pass, KV2 recomputes attention only on


the reduced nq × (m + nq) matrix shown in Fig-
ure 3. The reconstruction forward can still use
standard optimized causal-attention kernels, while
the final score extraction is a smaller chunk-local
postprocessing step. Appendix A gives the fuller
asymptotic derivation.
4
Experiments
After introducing the experimental setup (§4.1), we
present experiments on RULER (§4.2), Needle-in-
a-Haystack (§4.3), and LongBench (§4.4).
4.1
Experimental setup
Data and models.
We use three datasets
from controlled retrieval stress tests and realis-
tic long-context tasks: RULER 4K/16K (Hsieh
et al., 2024), LongBench (Bai et al., 2024),
and a Needle-in-a-Haystack diagnostic built from
Paul Graham essays (Hsieh et al., 2024; De-
voto, 2026).
We mainly use two backbones,
Llama-3.1-8B-Instruct (Llama Team, 2024)
and Qwen3-8B (Yang et al., 2025a; Qwen Team,
2025). Results from Qwen2.5-7B-Instruct-1M
(Yang et al., 2025b) and InfiniteBench (?) are in
the appendices.
Implementation details.
Unless stated other-
wise, KV2 uses a chunk size of 4K tokens, Key-
Diff as the first-stage proxy scorer, and by de-
fault sets the query-selection ratio ρ to the final
retained KV-cache ratio. Tighter compression bud-
gets therefore use smaller reconstruction sets. All
runs use PyTorch and Hugging Face Transform-
ers with FlashAttention-2 (Dao, 2024), are built
on NVIDIA’s kvpress framework (Devoto et al.,
2025b), and run on a single NVIDIA A100 80 GB
or H100 94 GB GPU.
Baselines. In the main comparisons, we compare to
three state-of-the-art query-agnostic methods that
cover the main families of approaches: lightweight
proxy scoring (KeyDiff (Park et al., 2025)), ex-
pected future-query scoring (Expected Attention
(Devoto et al., 2025a)), and reconstruction-based
compression (KVzip (Kim et al., 2025)). For the
choice of first-stage proxy scorer inside KV2, we
compare KeyDiff, Knorm (Devoto et al., 2024),
CUR (Sengupta et al., 2025), and StreamingLLM
(Xiao et al., 2024), while keeping the same second-
stage selective reconstruction fixed.

5.1
Single-pass efficiency
The clearest practical advantage of KV2 over
KVzip is single-pass efficiency. Figure 6 shows
that, within this masking-based backend, it is con-
sistently faster than KVzip and uses less peak mem-
ory across the relevant chunk sizes. The reason is
structural rather than incidental: KV2 reconstructs
only a proxy-selected subset of queries, so the
compression stage performs less work and keeps a
smaller active reconstruction footprint. The chunk-
size curves in Figure 6 also show why 4K is the
default chunk size. Below 4K, the repeated per-
chunk overhead drives compression-stage runtime
up, as shown in the left subfigure. Above 4K, the
reconstruction set grows linearly with chunk size,
raising both runtime and peak memory until the
largest configurations run out of memory (missing
bars in the figure). In contrast, the quality-side pic-
ture is comparatively flat: across length buckets in
LongBench-E (Bai et al., 2024) (LongBench with
a more even length distribution), KV2’s score is
largely insensitive to chunk size, with larger chunks
helping mainly on the longest inputs (Appendix C).
A chunk size of 4K therefore captures nearly all the
available quality while remaining highly efficient.

5.2
Proxy scorer
The first-stage proxy mechanism matters, even
though it is not the final scoring rule. Figure 7 iso-
lates this effect. All curves are KV2 with the same
second stage, and only the proxy scorer changes.
KeyDiff (Park et al., 2025) is the strongest option
throughout, with Knorm (Devoto et al., 2024) as
the closest alternative. CUR (Sengupta et al., 2025)
and especially StreamingLLM (Xiao et al., 2024)
fall off much more quickly as compression tightens,
with both dropping below a random-proxy baseline
at the highest compression ratios studied. A plau-
sible reason is that StreamingLLM is designed to
preserve sink tokens and recent context for stream-
ing generation, and both StreamingLLM and CUR
rely on structurally fixed selection patterns rather
than content-adaptive ones. Therefore, under se-
vere compression, a content-adaptive proxy set can
cover the useful signal better. Appendix E shows
the same effect qualitatively for the default KeyDiff
proxy after layer- and head-averaging: the proxy
mass concentrates on the instruction, assignment
chain, and answer span, while only a sparse set of
tokens is drawn from the repetitive filler context.
This makes the role of the proxy clear: KV2 is mod-
ular regarding the proxy choice, but stronger initial
proxies still matter most under severe compression.

5.3
Reconstruction budget
Figure 8 makes the reconstruction-budget trade-
off explicit. On both backbones, the optimal re-
construction fraction grows with the final KV-
cache budget. For Llama-3.1-8B-Instruct, the
RULER score peaks at 10%, 50%, and 100% recon-
struction for final budgets of 2%, 5%, and 10%, re-
spectively. For Qwen3-8B, the corresponding max-
ima are 10%, 25%, and 75%. These trends demon-
strate that more retained cache rewards more recon-
struction, and no single ρ is optimal across budgets.
This monotonic relationship strengthens the default
schedule in Section 4.1, which sets ρ to track the fi-
nal retained KV-cache ratio, where tighter budgets
get smaller reconstruction sets, looser budgets get
larger ones. While this matched default does not
reach the per-budget optimum, it does capture the
right scaling and keeps reconstruction cost propor-
tional to the budget.
5.4
Iterative refinement
The proxy-scorer and reconstruction-budget results
suggest a next question: once one KV2 pass has
produced a useful but potentially imperfect recon-
struction set, how much can later passes improve
it? Figure 9 shows that iterative refinement can im-
prove quality, but that most of the gain appears in
the first few passes. The benefits are largest when
the initial proxy is weak, either because the first-
stage proxy is less effective (random proxy), or the
reconstruction fraction is very small (2%). Once
the first pass is already strong, the benefit shrinks
to minimal. Iterative refinement is therefore most
attractive as a targeted extension for harder settings
rather than as the default configuration.
Moreover, Appendix B shows that these gains
come mainly at a runtime cost, while peak memory
changes much less.

Summary
The analyses in this section identified
the main operating regime of our method. The
single-pass version is the strongest practical de-
fault because it already delivers the main quality
gains while staying clearly cheaper than broader re-
construction (§5.1). The proxy scorer is swappable,
but its quality matters most at severe compression
(§5.2). Reconstruction percentage provides a use-
ful deployment knob (§5.3), while iterative refine-
ment can recover additional quality mainly when
the initial proxy is weak (§5.4).
6
Conclusion
In this work, we showed that reusable KV-cache
compression does not need to choose between
cheap heuristics and reconstructing everything.
KV2 shows that a small, well-chosen reconstruc-
tion set can already preserve much of the useful
long-context signal under severe compression. The
two-stage structure, paired with the observation
that informative anchors are sparse at extreme bud-
gets, points toward compression methods that are
both cheaper and more accurate.


Limitations
Three directions appear most important to improve
the current work.
First, iterative refinement should be explored
further and should become adaptive rather than
fixed. Section 5.4 shows that additional passes help
mainly when the initial proxy is weak or the recon-
struction budget is very small, while Appendix B
shows that these gains come mainly at a runtime
cost. This suggests refinement schedules that con-
tinue only while the reconstruction set or the re-
sulting scores are still changing meaningfully, and
perhaps allocate more compression-time compute
only to harder retrieval or multi-document work-
loads.
Second, the first-stage proxy mechanism itself
should be strengthened. Because KV2 is a modular
two-stage framework, better proxy scorers should
improve both single-pass quality and the value of
later refinement. The proxy ablation in Section 5.2
suggests that content-adaptive scorers outperform
structurally fixed ones at low budgets, suggesting
that learned or model-aware proxies may be able
to improve further.
Third, the current masking-based realization
should be replaced by a compact serving back-
end. Within the kvpress toolkit, KV2 measures
compression-stage runtime and memory faithfully,
but it does not yet materialize physically compact
reusable caches due to the toolkit’s implementa-
tions. Headwise cache compaction, optimized at-
tention kernels that allow each head’s individually
compressed sequence length, and repeated-query
serving pipelines are therefore needed to translate
the present compression results into full decoding-
time memory and latency gains.

A
Complexity Analysis
Let nc denote the prefilled context length. The com-
plexity is easiest to understand by separating KV2
into the lightweight proxy stage and the two compu-
tations inside selective reconstruction. The proxy
stage is inexpensive. In the default implementation,
the efficient KeyDiff proxy computes one anchor-
style key score per token, so proxy scoring is linear
in context length, O(nc).
The reconstruction forward pass is the expensive
part. For one chunk, the reconstruction block has
length nq ≈ρm. Because these reconstruction


queries are appended after the prefilled document,
each one attends over the full cached context and
also over earlier reconstruction tokens in the same
block. The resulting per-chunk cost is therefore
O(ncnq +n2
q/2). Repeating this across the roughly
nc/m chunks gives a total reconstruction-forward
cost of O(ρn2
c + ρ2ncm/2). However, this recon-
struction forward remains an ordinary causal pass
over the shared cache, so it can still use optimized
attention implementations such as FlashAttention-
style kernels during the forward computation (Dao,
2024).
Score extraction is cheaper because it is chunk-
local. After the reconstruction forward pass, KV2
recomputes attention only on a reduced matrix of
size nq × (m + nq) for the current chunk, as illus-
trated in Figure 3. This gives O(nq(m + nq)) =
O(ρm2) work per chunk and O(ρmnc) over all
chunks. Unlike the reconstruction forward, how-
ever, the final score extraction requires a Softmax
over keys followed by a max over queries, a cross-
dimensional dependency that does not map cleanly
onto the usual blockwise attention algorithms (Kim
et al., 2025).
B
Iterative refinement cost
Section 5.4 showed that iterative refinement can
improve quality, especially when the initial proxy
is weak or the reconstruction fraction is small. The
remaining question is cost. Figure 10 shows that
runtime rises roughly in proportion to the number
of refinement passes, especially when chunk size
is small and many local reconstructions must be
repeated. Peak memory remains driven mainly by
chunk size because each pass reuses essentially the
same working buffer. This is why iterative refine-
ment is best viewed as an optional extension for
harder settings rather than the default configura-
tion.
