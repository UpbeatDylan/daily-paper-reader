## 摘要
在长上下文场景下，大语言模型的服务受限于键值(KV)缓存，每个解码步骤都需要读取完整的缓存。注意力键在全局上呈现高秩，但在局部上却是低秩的：共享的低秩基会丢弃页面特定的方向，而页面自身的紧凑基则保留了这些方向。LOCKS为每个页面提供其自身的谱摘要（常驻内存，约为缓存大小的十分之一），重构页面内的logits，通过log-sum-exp估计每个页面的注意力质量，并仅关注top页面；选择过程本身不读取任何候选键或值。仅基于该摘要进行选择，在长文档问答（LongBench-v1）中与完整缓存的差距在一分以内，在检索密集的RULER任务上，即便在最小预算下也能接近逐键读取的oracle，在长文本推理任务（AIME26， MATH-500）中取得最大优势，而基线选择器在此失效。在已部署的2048 token预算下，LOCKS在100K+上下文长度下匹配FullKV的总体质量，同时仅关注约2%的token，相较于密集注意力，将每token解码延迟减半（1M token时加速2.0倍）。LOCKS作为即插即用插件，适用于未修改的vLLM，并在完整的CUDA图中运行批量解码。

## Abstract
Serving large language models at long context is bottlenecked by the key-value (KV) cache, which is read in full at every decode step. Attention keys are locally low-rank though globally high-rank: shared low-rank bases discard page-specific directions that a page's own compact basis retains. LOCKS gives every page its own spectral summary (resident, about a tenth the cache's size), reconstructs within-page logits, estimates each page's attention mass by log-sum-exp, and attends only the top pages; selection itself reads no candidate keys or values. Selecting on this summary alone stays within about a point of the full cache on long-document QA (LongBench-v1), tracks the read-every-key oracle on retrieval-dense RULER down to the smallest budgets, and shows its largest margins on long-form reasoning (AIME26, MATH-500), where baseline selectors collapse. At its shipped $2048$-token budget LOCKS matches FullKV aggregate quality at $100$K$+$ context while attending about $2\%$ of the tokens, and halves per-token decode latency ($2.0\times$ at $1$M tokens) against dense attention. LOCKS ships as a drop-in plugin for unmodified vLLM, with batched decode running in full CUDA graphs.

#### 1. 核心问题与整体含义（研究动机与背景）

- **问题**：长上下文 LLM 解码时，每次需读取完整 KV 缓存，导致高延迟和带宽瓶颈。缓存占据大量显存（例如，128K 上下文对于 Llama-3.1-8B 需要约 16 GiB KV 缓存），远超过模型权重。
- **现有方法不足**：很多稀疏注意力方法试图通过选择少量页面来减少读取量，但依赖共享的低秩投影（如全局或序列级 PCA）会丢失页面特有的方向信息，尤其在需要检索少数关键页面（carrier pages）的任务中表现不佳。
- **动机**：注意力键在页面内是低秩的（页面内能量集中在少数主成分上），但在全局是高秩的。因此为每个页面维护其自身的紧凑谱摘要可以更忠实反映页面内容，从而更准确地估计注意力质量。
- **整体含义**：提出 LOCKS，一种训练无关、即插即用的查询感知稀疏注意力后端，通过页面局部谱摘要实现高效选择，在不显著降低质量的前提下大幅减少解码步骤的 KV 读取量。

#### 2. 方法论：核心思想、技术细节、公式与算法流程

- **核心思想**：为每个页面（通常 16 tokens）维护一个紧凑的秩 r 谱摘要（约 KV 缓存大小的十分之一），包括页面均值 μ_j、正交基 V_j ∈ ℝ^{d×r}、以及每个 token 的系数 c_i ∈ ℝ^r。解码时，对于每个查询 q，先重构页面内所有 token 的 logits，再取 log-sum-exp 得到页面质量的估计值 ŝ_j(q)，然后对所有页面按估计注意质量排序，只选择前 k 个页面参与实际注意力计算（加上始终保留的 sink 和 recent 页面）。
- **关键技术细节**：
  - **摘要构建**：当页面填充完毕时，对页面内 token 的 key 去均值，计算 Gram 矩阵的特征分解，保留前 r 个特征向量作为基 V_j，系数 c_i 为投影坐标。基用 int4 存储，系数和均值用 int8 存储，总开销约页面的 9.4%（r=8, B=16）。
  - **评分公式**：ŝ_j(q) = log ∑_{i∈P_j} exp( (q^T μ_j + (V_j^T q)^T c_i) / √d )，即基于重构的 logits 计算 log-sum-exp，归一化得到页面质量份额。
  - **GQA 组合规则**：使用 share-average（组内各查询头的份额取平均），理论上最大化组平均覆盖率。
  - **理论保证**：提出命题1证明共享固定投影会丢失页面特定方向；定理1给出在未量化摘要下的保留覆盖率界，依赖重建误差 η。
  - **部署实现**：作为 vLLM 插件，解码过程全部在 CUDA 图中执行，包括评分、选择和稀疏注意力。
