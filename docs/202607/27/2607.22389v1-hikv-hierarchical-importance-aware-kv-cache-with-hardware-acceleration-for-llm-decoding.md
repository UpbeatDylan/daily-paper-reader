## 摘要
随着长上下文大语言模型的快速普及，解码过程中持续增长的KV缓存已成为关键的内存瓶颈。为解决这一挑战，我们提出HiKV，一种通过分层重要性感知来挖掘KV缓存冗余的新型算法-硬件协同设计方案。在算法层面，HiKV以两种粒度压缩KV缓存：阶段I在固定预算内驱逐不重要的令牌，阶段II进一步仅加载每个保留令牌中的重要元素，达到单一粒度无法实现的压缩比。在架构层面，我们开发了一种以可重构重要性排序器为核心的专用加速器，该排序器可在两个阶段所需的不同的排序数据路径间切换，以最小开销将两阶段加速统一于一个电路中。在代表性大模型上的评估显示，与原始KV缓存基线相比，HiKV在注意力计算中实现了高达7.95倍的加速和90%的能耗降低，同时精度损失可忽略不计（1%以内）。在等精度约束下，HiKV通过额外减少1.82~4.87倍的外部内存访问，超越了当前最先进的重要性方法。这些优势得益于专用硬件组件，其仅增加了8%的系统面积。

## Abstract
With the rapid adoption of long-context large language models (LLMs), the continuously growing KV cache during decoding has become the critical memory bottleneck. To tackle this challenge, we propose HiKV, a novel algorithm-hardware co-design that exploits KV cache redundancy through hierarchical importance awareness. Algorithmically, HiKV compresses the KV cache at two granularities: Stage I evicts unimportant tokens within a fixed budget, and Stage II further loads only the significant elements of each retained token, reaching compression ratios unattainable at a single granularity. Architecturally, we develop a dedicated accelerator centered on a reconfigurable importance sorter that switches between the distinct sorting datapaths each stage requires, unifying the two-stage acceleration in one circuit with minimal overhead. Evaluated on representative LLMs, HiKV achieves up to 7.95x speedup and 90% energy reduction in the attention computation over the vanilla KV cache baseline within negligible 1% accuracy loss. Under iso-accuracy constraints, HiKV outperforms state-of-the-art importance-based methods by achieving an additional 1.82~4.87x reduction in external memory accesses. These benefits are enabled by specialized hardware components that add only 8% to the system area.

- **现有方法局限**：已有重要性感知方法（如 H2O、Scissorhands）仅在 token 级别进行压缩——保留重要 token、驱逐不重要 token，但每个保留 token 的完整向量仍须从外部内存加载，忽略了元素级冗余。图 5 的注意力可视化表明，即使保留 50% 的 token，再进一步保留每个 token 的 50% 元素，主要注意力模式仍然保持，说明两层冗余可以正交组合。
- **动机**：提出一种算法-硬件协同设计，同时利用 token 级和元素级冗余来显著减小 KV 缓存内存占用量，突破单粒度压缩的瓶颈。

## 2. 方法论：核心思想、关键技术细节

- **整体框架**：两阶段层次重要性压缩，集成到每个解码步骤的注意力计算中（Algorithm 1）。
  - **Stage I（粗粒度 token 级管理）**：维护一个固定预算的“双银行”结构——最近银行 R（存储最近连续的 BI/2 个 token）和重要银行 I（存储历史高重要性 token）。采用局部累积策略：仅对 R 中的 token 累积注意力得分作为重要性得分（IS），并使用最小堆维护 I 中的 token，驱逐操作复杂度为 O(log BI)。
  - **Stage II（细粒度元素级管理）**：
    - 对 Q 向量：按幅值全局排序，选择 top-BII 个元素（BII = dh / rII），指导加载对应的 K 缓存元素。
    - 对 P 向量（softmax 后）：分块排序（chunk size = dh），每个块内独立选择 top-BII 个元素，指导加载对应的 V 缓存行（每个元素对应一个 token 的行）。分块排序将全局 O(N log N) 降为 O(N log dh)，且召回率超过 95%（图 7）。
  - **两阶段协同**：QK^T 计算前执行 Stage II 的 Q 排序和 Stage I 的 token 集选择；P V 计算前执行 Stage II 的 P 分块排序。具体流程见 Algorithm 1 和图 8。
- **关键算法特性**：局部累积 + 冻结 IS 的堆维护，减小排序开销；两阶段正交压缩（总压缩比 r_total = rI × rII）。
- **硬件加速器**：
  - 核心组件：可重构重要性排序器（RIS），基于统一 2-输入双调排序器构建，支持四种模式：HEAPIFY_UP（堆构建）、HEAPIFY_DOWN（堆维护）、GLOBAL_SORT（全局排序）、CHUNK_SORT（分块排序）。通过配置控制信号在不同模式间切换。
  - 其他模块：Token 重要性评分生成器（TISG）、分数板缓冲器、解码计算引擎（CU+VU）、KV 缓存选择控制器。
  - 外部内存布局：K 缓存采用“元素优先”布局，V 缓存采用“块索引”布局，以匹配两阶段的访问模式。
  - 后综合结果：TSMC 16nm，300MHz，总面积为 2.059 mm²，功耗 135.4 mW。HiKV 特有模块（RIS+TISG+分数板）仅占 8.64% 面积和 7.01% 功耗。

## 7. 优点：方法或实验设计亮点

- **算法创新**：首次在 KV 缓存压缩中同时利用 token 级和元素级冗余，且两阶段可正交组合，突破单粒度压缩的天花板。
- **硬件创新**：可重构重要性排序器（RIS）用单一电路支持两种不同粒度的排序需求，通过配置模式切换，节省面积和功耗。
- **局部累积策略**：仅对最近 token 累积重要性得分，并使用冻结堆，将排序复杂度从 O(BI) 降至 O(log BI)。
- **分块排序策略**：对长 P 向量采用分块独立排序，既降低计算开销又保持高召回率（>95%），并利用硬件并行性。
- **实验设计全面**：覆盖多种模型、任务、压缩设定，并在统一硬件平台上公平比较，结果可信度高。
