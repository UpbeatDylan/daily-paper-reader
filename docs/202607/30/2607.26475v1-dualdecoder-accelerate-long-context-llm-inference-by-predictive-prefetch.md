## 摘要
长上下文推理正成为现代LLM服务的基础能力，特别是在新兴的代理类应用推动下。然而，它面临严重的内存墙问题，即KV缓存随上下文长度和请求并发性的增加而按比例扩展。现有的稀疏KV缓存方法将大部分KV条目卸载到主机内存，仅检索每个解码步骤所需的关键KV条目。但它们通常会在GPU内存中引入大量辅助状态用于KV检索管理。我们的测量显示，这些常被忽视的辅助状态在GPU内存中引入显著开销，并在高并发工作负载下成为新的瓶颈。 本文提出DualDecoder，一个轻量级的长上下文LLM推理服务系统，能够实现从主机内存高效检索稀疏KV缓存。我们的关键洞察是：解码下一个token所需的关键KV条目可以从前一推测token中准确预测。这种可预测性使得KV检索能够被主动预取并与解码计算重叠，从而有效消除辅助状态的GPU内存开销。为高效实现此预取，DualDecoder利用一种新颖的双token解码流水线，以可忽略的计算开销准确识别关键KV条目，并设计了层感知传输调度以重叠KV预取与模型计算，以及层范围内存管理器以减少GPU运行时缓冲区。实验结果表明，与最先进系统相比，DualDecoder在保持解码延迟和模型质量的同时，将解码吞吐量提高了最多2.62倍。

## Abstract
Long-context inference is becoming a fundamental capability for modern LLM serving, especially driven by emerging agentic applications. Yet it faces a severe memory wall that the KV cache scales proportionally with increasing context length and request concurrency. Existing sparse KV cache methods offload most KV entries to host memory and retrieve only the critical KV entries needed by each decoding step. However, they commonly introduce substantial auxiliary states in GPU memory for KV retrieval management. Our measurements show that these often-overlooked auxiliary states introduce significant memory overhead and become a new bottleneck under high-concurrency workloads.   In this paper, we present DualDecoder, a lightweight serving system for long-context LLM inference that enables efficient sparse KV cache retrieval from host memory. Our key insight is that the critical KV entries required for decoding the next token can be accurately predicted from the preceding speculated token. This predictability enables KV retrieval to be proactively prefetched and overlapped with decoding computation, effectively eliminating the GPU memory overhead of auxiliary states. To achieve this prefetching efficiently, DualDecoder leverages a novel dual-token decoding pipeline that accurately identifies critical KV entries with negligible computational overhead, and designs a layer-aware transfer schedule to overlap KV prefetching with model computation and a layer-scoped memory manager to reduce the GPU runtime buffer. Experimental results show that DualDecoder improves decoding throughput by up to 2.62$\times$ over state-of-the-art systems while preserving decoding latency and model quality.

## 1. 核心问题与整体含义（研究动机和背景）

- **背景**：长上下文推理是LLM服务的关键能力，但面临严重的内存墙问题——KV缓存随上下文长度和请求并发线性增长。现有动态稀疏KV缓存方法将大部分KV条目卸载到主机内存，仅检索解码所需的关键条目，但在GPU内存中引入了大量辅助状态（如低秩key缓存、量化KV表示）用于加速检索，这些辅助状态在高并发下成为新瓶颈，占用高达64%的GPU内存，限制了批处理大小和吞吐量。
- **核心问题**：如何在不引入大量GPU内存辅助状态的前提下，实现高效稀疏KV检索，从而提升长上下文推理的吞吐量。

## 2. 方法论：核心思想、关键技术细节

### 2.1 核心思想：预测性预取（Predictive Prefetch）
- **关键洞察**：在动态稀疏KV缓存中，下一解码步骤所需的关键KV条目可以从当前步骤的推测token中准确预测（平均预测准确率88%）。利用这一可预测性，系统可提前预取未来步骤所需的KV条目，并与解码计算重叠，从而消除对GPU辅助状态的依赖。
- **实现目标**：将稀疏KV检索从延迟关键路径移出，通过预取隐藏CPU→GPU传输延迟，同时释放原本被辅助状态占用的GPU内存。

### 2.2 关键技术设计（三个组件）

#### (1) 双token解码流水线（Dual-Token Decoding Pipeline）
- 在每个解码步骤中，同时生成输出token和推测token（speculative token），推测token用于预测下一解码步骤的检索索引。
- 通过将两个token沿序列维度拼接并添加因果掩码，避免额外解码pass，使计算开销可忽略。
- 初始化：第一个推测token使用预解码步骤生成的真实输出token，以稳定预测轨迹。

#### (2) 推测性KV缓存传输调度（Speculative KV Cache Transfer Schedule）
- **层感知传输重叠**：按模型层执行顺序调度预取。对目标层i+2，在层i注意计算完成后开始预取其KV条目，平衡延迟隐藏与GPU缓冲区占用。
- **优先级缺失KV传输**：预测失误的缺失KV条目通过高优先级紧急流传输，背景预取通过低优先级流传输，避免关键路径阻塞。
- **自适应key重建**：对预测准确率低的层（通过离线profiling确定），启用低秩key重建（类似ShadowKV），仅对这些层保留少量辅助状态，减少缺失KV获取延迟。

#### (3) 层范围内存管理（Layer-Scoped KV Memory Manager）
- **两层乒乓缓冲**：仅维护两个GPU缓冲区（计算缓冲和传输缓冲），通过CUDA事件协调角色切换，将GPU驻留KV缓冲区从全模型深度降低为常数两层。
- **GPU侧稀疏KV组装**：主机仅传输连续KV块到GPU暂存区，由GPU内核进行紧凑、重排和合并，延迟布局更新直到真实索引确定，避免CPU不规则收集开销。

## 6. 主要结论与发现
- DualDecoder相比ShadowKV最高提升2.62×解码吞吐量（128K上下文），相比SpeCache提升8.63×，相比vLLM提升3.65×。

- **工程实现精巧**：双token解码流水线、层感知调度、两层乒乓缓冲、GPU侧组装等设计兼顾效率与内存。

## 8. 不足与局限
- **对首次推测token敏感**：初始化依赖一个预解码步骤，若预解码质量不佳可能影响后续预测（实验显示随机初始化准确率仅56%）。

- **未考虑跨请求共享**：当前设计针对单GPU单次推理，未讨论多GPU或跨机KV缓存共享场景。
- **实验规模**：仅使用8张GPU，未在更大集群上验证可扩展性；仅测试Llama和Qwen两个系列，未覆盖更多架构（如Mamba、Gemma）。
- **预测失误代价**：虽然优先级调度缓解了影响，但在预测准确率极低（<50%）的边缘场景下，延迟可能明显退化，论文未充分探讨这类极端情况。
- **辅助状态并未完全消除**：自适应key重建仍需为少数层保留低秩key缓存，尽管量小但仍是额外开销。
