## 摘要
大语言模型越来越多地部署了持久的个性化上下文，例如累积的记忆档案或长对话历史，这些内容在用户的多次请求中共享。生产级记忆系统（如Mem0、MemGPT和Zep）会检索该记忆的相关子集并将其注入提示中，迫使服务引擎重复预填充相同的内容。随着检索预算的增长，即使底层记忆在请求间被重用，首Token延迟（TTFT）也会增加。我们提出了InferScale，一种GPU原生的LLM记忆系统，用可重用的KV状态取代重复的提示预填充。InferScale预先计算每个记忆事实的KV表示，将其与语义嵌入一起存储在GPU上，在服务时检索相关事实，并直接将它们的KV注入vLLM的分页缓存中。为了支持在旋转位置嵌入下动态组合的记忆，我们引入了分块RoPE（Chunked RoPE），它在旋转前存储键，并在注入时应用它们服务时的位置。然而，独立编码记忆事实会忽略联合预填充时可用的跨事实上下文。我们通过上下文窗口编码（Context-Window Encoding）来缓解这一问题，该方法将每个记忆事实与前面对话上下文的一小段窗口一起编码，同时仅缓存目标事实的KV。InferScale通过vLLM的KV连接器接口实现，无需修改引擎或微调模型。在LoCoMo上的三个开放权重模型中，随着检索预算的增加，InferScale使TTFT几乎保持不变：在k=50时，TTFT降低了72-79%（3.6-4.8倍），在无需服务时重新计算的情况下，达到了60.3%的准确率（Mem0为63.3%），并且在并发负载下提供了3.7-4.5倍的吞吐量。因此，可重用的KV状态将基于记忆的服务延迟与检索上下文大小解耦，同时保持了应用质量。

## Abstract
Large language models are increasingly deployed with persistent personalized context, such as accumulated memory profiles or long conversation histories, that is shared across a user's many requests. Production memory systems (e.g., Mem0, MemGPT, and Zep) retrieve a relevant subset of this memory and inject it into the prompt, forcing the serving engine to repeatedly prefill the same content. As the retrieval budget grows, time-to-first-token (TTFT) increases even though the underlying memory is reused across requests.   We present InferScale, a GPU-native LLM memory system that replaces repeated prompt prefilling with reusable KV state. InferScale precomputes each memory fact's KV representation, stores it alongside a semantic embedding on the GPU, retrieves relevant facts at serving time, and injects their KV directly into vLLM's paged cache. To support dynamically assembled memories under rotary position embeddings, we introduce Chunked RoPE, which stores keys before rotation and applies their serving-time positions during injection. However, encoding memory facts independently omits the cross-fact context available during joint prefilling. We mitigate this with Context-Window Encoding, which encodes each memory fact together with a small window of preceding conversation context while caching only the target fact's KV.   InferScale is implemented through vLLM's KV-connector interface, requiring neither engine modifications nor model fine-tuning. Across three open-weight models on LoCoMo, InferScale keeps TTFT nearly constant as the retrieval budget increases: at k=50 it reduces TTFT by 72-79% (3.6-4.8x), achieves 60.3% accuracy versus 63.3% for Mem0 without serving-time recomputation, and delivers 3.7-4.5x the throughput under concurrent load. Reusable KV state thus decouples memory-conditioned serving latency from retrieved-context size while preserving application quality.

### 1. 论文的核心问题与整体含义（研究动机和背景）

- **核心问题**：在个性化 LLM 服务中，用户具有持久的记忆（如累积的个人档案或长对话历史），这些记忆在多次请求之间是共享的。现有生产级记忆系统（如 Mem0、MemGPT、Zep）每次请求都会检索相关记忆并以文本形式注入提示（prompt）中，导致服务引擎每次都要重复预填充（prefill）相同的记忆内容。随着检索预算（retrieval budget k）的增大，时间到首 Token 延迟（TTFT）线性增长，即使底层记忆内容在请求间被重复使用。
- **整体含义**：将记忆从“Token 层注入”转移到“注意力层注入”（即 KV 注入）可以消除重复预填充的计算开销，使服务延迟与检索上下文大小解耦，同时保持应用质量。InferScale 实现了这一思想，是一种 GPU 原生的检索-注入系统。

### 2. 方法论：核心思想与关键技术细节

- **核心思想**：对于因果注意力，记忆事实的 Key-Value（KV）表示只取决于事实本身，与查询无关。因此可以一次性计算每个记忆事实的 KV 并存储，服务时检索到相关事实后直接将其 KV 注入到注意力缓存中，而无需重复预填充这些 Token。
- **关键技术细节**：
  1. **Chunked RoPE**：由于旋转位置编码（RoPE）将位置信息编入键向量，直接在注入时使用预计算的键（已包含原位置编码）会出错。InferScale 在存储时保存前 RoPE 的键（即经过线性投影但未旋转），注入时根据服务时的目标位置动态应用 RoPE 旋转，从而使任何位置下的注意力得分与原始预填充完全相同（Theorem 6）。
  2. **Context-Window Encoding**：独立编码每个事实会丢失相邻事实之间的上下文交互，降低答案质量。该方法在离线预处理时，将每个事实与之前 w 轮对话一起编码，但只缓存目标事实的 KV。这样既保留了必要的局部上下文，又保持了事实的独立可重放性，且不增加服务时的开销。
  3. **GPU 原生检索与 KV 存储**：使用 Jasper（GPU 上的图索引）进行语义近似最近邻搜索，并将预计算的 KV 存储在 GPU 显存中。检索过程全程在 GPU 上完成，无需 PCIe 传输。
  4. **系统实现**：通过 vLLM 的 KV-Connector 接口实现，无需修改服务引擎或微调模型。离线阶段一次性编码并构建索引；在线阶段嵌入查询、检索、Chunked RoPE 注入、仅预填充查询 Token。
- **理论保证**：Theorem 3 证明，对于因果 Transformer，若记忆在相同位置注入，KV 注入与提示注入在所有查询位置产生完全相同的隐藏状态和输出分布。Chunked RoPE 和 Context-Window Encoding 分别处理了位置偏移和上下文缺失问题，前者是精确的，后者是近似但有效的补偿。

- **基准方法**：对比 **Mem0**（生产级记忆系统，使用 Qdrant CPU 向量库 + 提示注入）为 baseline。在向量后端消融中对比了 Jasper（GPU 索引）与 Qdrant（CPU 索引）的效果。

  - 准确率（由独立的 Gemma-2-9B-Instruct 评判）
  - 吞吐量（QPS）
- **变量**：检索预算 k ∈ {5,10,20,50}；编码窗口 w ∈ {0,5,20,50}；GPU 存储 vs. CPU 卸载存储；并发用户数 N ∈ {10,25,50,75,100}。
- **覆盖模型**：Llama-3.1-8B-Instruct、Mistral-7B-Instruct-v0.3、Qwen2.5-7B-Instruct，以及额外测试 Qwen3-14B。
- **实验充分性**：共报告了 3 个模型 + 1 个附加模型的完整数据，包含 TTFT、延迟、准确率、吞吐量、消融实验（窗口大小、CPU 卸载）、鲁棒性测试（更大模型）、经验等价性验证（18 个 case）。涵盖了主要维度，实验设计全面且公平（开启 vLLM 前缀缓存，Mem0 处于最佳状态）。

### 4. 资源与算力

### 6. 论文的主要结论与发现

- **延迟解耦**：InferScale 使引擎 TTFT 几乎不随检索预算 k 增长。以 Llama-3.1-8B 为例，k=5 到 k=50 时 TTFT 仅增加 4%（16.6 → 17.3 ms），而 Mem0 增加 106%（33.2 → 68.3 ms）。端到端查询到首 Token 延迟 k=50 时 InferScale 约 60 ms vs Mem0 约 236 ms，降低 72-79%。
- **吞吐量**：在 100 并发用户下，InferScale 吞吐量达 100-135 QPS，是 Mem0 的 3.7-4.5 倍，且呈近线性缩放（Mem0 饱和）。
- **准确性**：独立编码（w=0）准确率随 k 增大而下降。Context-Window Encoding（w≥20）恢复准确率，k=50 时 InferScale 达 60.3%（Llama），Mem0 为 63.3%，接近但有差距。差距主要来自多跳推理问题（跨事实注意力不足）。
- **CPU 卸载可行性**：将 KV store 卸载至 CPU 虽增加 PCIe 传输延迟（约 33-38 ms 端到端），但引擎 TTFT 仅增加 1.5-3 ms，整体仍比 Mem0 快 2.3 倍，且吞吐量几乎无损。这缓解了 GPU 显存容量限制。
- **模型无关性**：在 7-8B 及 14B 模型上效果一致，且更大模型收益更显著（TTFT 降低 5×）。

- **创新性**：首次将 KV 注入从理论等价推向实际系统，解决 RoPE 位置偏移和上下文缺失两大挑战。
- **高效性**：无需修改引擎或微调模型，直接通过插件接口集成，部署成本低。
- **理论完备**：提供严格证明（Theorem 3、6、8），解释系统行为与近似边界。
- **实验全面**：覆盖多模型、多参数、多种负载模式，并给出消融分析（窗口、GPU/CPU、索引后端）。
- **实用性**：支持 CPU 卸载，解决 GPU 容量瓶颈，保持低延迟。

### 8. 不足与局限

- **跨事实注意力缺失**：独立编码无法实现事实之间的注意力交互，导致多跳推理准确率低于 Mem0（约 58% vs 73% in Qwen3-14B multi-hop，k=50）。Context-Window Encoding 只能部分补偿，窗口增大到所有检索事实理论上可达到全预填充，但存储和离线成本也线性增长。
- **GPU 容量瓶颈**：每个用户的 KV store 占用 1.8-4.8 GB，在 96 GB 显存下约可容纳 10-50 个用户，但对于大规模生产部署（数千用户）仍不够。论文提出 CPU 卸载方案但牺牲了端到端延迟约 33-38 ms。
- **单数据集、单卡测试**：仅在 LoCoMo 上验证，未在更广泛的长对话/RAG 数据集上测试；仅使用单 GPU 场景，未考虑多节点或多 GPU 分布式部署。
- **无在线更新**：假设记忆是静态的（离线一次性构建），但实际对话中用户记忆会持续更新，论文未讨论增量更新到 KV 和索引的策略。
- **与其它 KV 复用方法的对比不足**：论文 Related Work 提到了 CacheBlend、LazyAttention、LMCache 等，但实验仅与 Mem0（纯提示注入）对比，未在相同条件下与这些系统比较 latency/accuracy trade-off。
- **评估指标局限**：准确率仅用单一评判模型（Gemma-2-9B），可能引入偏差；未报告生成质量其他指标（如 ROUGE-L、BLEU、事实一致性）。
- **实施细节可重复性**：论文声称代码开源于 GitHub，但未详细说明如何设置 Mem0 的检索阈值、Qdrant 配置等，可能影响复现。
