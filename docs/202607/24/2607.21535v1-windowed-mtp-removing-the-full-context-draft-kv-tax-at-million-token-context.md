## 摘要
推测解码通过让一个廉价草稿模型提出token，目标模型并行验证，从而加速自回归生成。前沿模型越来越多地内置多头预测（MTP/NEXTN）草稿头，假设草稿开销可忽略不计。但在百万token上下文中，这一假设被打破：MTP草稿头通常在每个草稿步骤中对整个KV缓存进行全注意力计算，因此其读取量随上下文线性增长，并主导了草稿成本——而这正是推测最有价值的场景。该效应随着草稿长度增加而加剧（深度原生草稿可能变为净负效应，比无推测更慢），并在混合注意力/线性注意力目标下更加突出，因为更便宜的验证暴露了草稿的全注意力读取。我们将StreamingLLM风格的滑动窗口加注意力汇聚仅应用于草稿注意力（窗口化MTP），保持全注意力验证不变。该方法无需训练，即插即用，且通过构造保证无损：全注意力目标仍然决定每个被接受的token，因此窗口化只改变被提议的token，而绝不改变被接受的token。它将草稿的KV工作集限制为常数，在1M时丢弃约99%的KV条目。在SGLang中单GPU上针对三种架构家族（Qwen GDN-MoE 35B/122B和Mamba2混合NoPE 120B）的1M上下文实验表明，窗口化将每个解码步骤的成本相比现用原生MTP草稿降低了28%到44%，这是一个输入不变的增益，随上下文扩大。由于每个token的延迟等于该成本除以接受长度，在匹配的接受率下端到端解码延迟提升相同幅度，而在窗口化也提高接受率时提升更大，同时保持目标验证的输出分布。最后，未读取的草稿KV（在1M时占总KV的7.7-11%）通过紧凑的环形缓冲区回收，而不影响接受率或质量。

## Abstract
Speculative decoding accelerates autoregressive generation by having a cheap draft propose tokens that a target verifies in parallel. Frontier models increasingly ship a built-in Multi-Token-Prediction (MTP/NEXTN) draft head under the assumption that the draft is negligibly cheap. At million-token context this breaks: an MTP draft head typically runs full attention over the entire KV cache at every draft step, so its read grows linearly with context and comes to dominate the draft cost -- precisely where speculation is most valuable. The effect compounds with draft length (a deep native draft can turn net-negative, slower than no speculation) and sharpens under hybrid/linear-attention targets, where cheaper verification leaves the draft's full-attention read exposed. We apply a StreamingLLM-style sliding window plus attention sink to the draft's attention only (Windowed-MTP), leaving full-attention verification intact. It is training-free, drop-in, and lossless by construction: the full-attention target still decides every accepted token, so windowing changes only which tokens are proposed, never which are accepted. It bounds the draft's KV working set to a constant, dropping ~99% of KV entries at 1M. Across three architecture families (Qwen GDN-MoE 35B/122B and a Mamba2-hybrid NoPE 120B) at 1M context on a single GPU in SGLang, windowing cuts the per-decode-step cost over the shipping native MTP draft by +28% to +44%, an input-invariant margin that widens with context. Since per-token latency is this cost divided by acceptance length, at matched acceptance end-to-end decode latency improves by the same amount, and more where windowing also lifts acceptance, while preserving the target's verified output distribution. Finally, the unread draft KV -- 7.7-11% of total KV at 1M -- is reclaimed via a compact ring buffer at no acceptance or quality cost.

# Windowed-MTP 论文详细中文总结

## 1. 核心问题与整体含义（研究动机与背景）

- **核心问题**：在长上下文（百万token级）的推测解码中，内置的多头预测（MTP/NEXTN）草稿头在每个草稿步骤都要对整个 KV 缓存进行全注意力计算。这导致草稿阶段的成本随上下文长度线性增长，**打破了“草稿成本可忽略”的常见假设**，甚至可能使深度草稿变得比无推测（dense）更慢（即净负效应）。
- **研究动机**：随着模型向混合注意力/线性注意力架构（如 GDN、Mamba2）发展，目标验证步骤变得更便宜，反而**暴露了草稿的全注意力读取瓶颈**，使得草稿成本在总解码步骤中占比陡增。
- **整体含义**：当前长上下文场景下，原生 MTP 草案存在显著的“全上下文草稿 KV 税”，严重侵蚀推测解码带来的加速收益。本文旨在通过训练无关、即插即用的窗口化方法消除这一税负，既保持目标分布不变（无损），又显著提升长上下文生成效率。

## 2. 方法论：核心思想、关键技术细节

### 2.1 核心思想
- **不是让草稿看到更少从而更准，而是让草稿只看到一个固定大小的局部上下文（滑动窗口+注意力汇聚），因为高质量的局部猜测不需要全量历史**。目标验证仍使用全注意力，因此窗口化**只改变提案的质量（可能降低或提高接受率），绝不改变被接受的 token**——从而保证输出分布与标准解码一致（无损）。

### 2.2 关键技术细节
- **窗口化草案注意力**：在草稿的每次自回归步骤中，将注意力计算限制到两个部分：
    - 开头的 `n_sink` 个 token（注意力汇聚，StreamingLLM 风格，固定 64 个）。
    - 最近的 `W` 个 token（滑动窗口，默认 4032）。
- 在分页 KV 缓存系统中实现：只需截断草案请求的块表为 `[sink blocks] ∥ [recent W blocks]`，无需新内核或掩码。
- **无损性论证**：定义目标分布 `p`、草案分布 `q`（全上下文）、窗口化草案分布 `q_win`。推测解码的接受规则基于目标 `p`，因此任何被接受的 token 都来自 `p`，仅提案来源变化。在精确算术下，贪婪解码完全等价。实际 bf16 验证的微小差异源于批处理浮点归并顺序，窗口化草案与原生草案的扰动程度相同，不影响无损性。
- **内存回收**：草案 KV 池在 1M 上下文中占总 KV 的 7.7–11%，窗口化后仅需 `(W + n_sink + d)` 的环形缓冲区（其中 d 为草案深度），其余 99% 的草案 KV 变为“死内存”可被回收，用于容纳更多并发请求或加深草案。

### 2.3 关键公式
- 每步解码步骤时间：`T_step = t_verify + t_draft`
- 草案阶段：`t_draft = t_ctx_draft + γ * t_fwd_draft`，其中 `γ` 为草案步数，`t_ctx_draft` 为一次性的 O(S) 上下文索引构建，`t_fwd_draft` 为每步前向（仍含 O(S) 注意力读取）。
- 窗口化后：`t_draft_win` 固定为 O(W)，常数级别。
- 速度比：`Speedup = (T_step_native / T_step_win) * (AL_win / AL_native)`，其中 AL 为接受长度。

## 6. 主要结论与发现

1. **草案全上下文 KV 税确实存在**：在 1M 上下文中，原生草案阶段（γ=6）比裸验证**额外增加 92%~138% 的解码步骤时间**，几乎翻倍。
2. **Windowed-MTP 显著降低解码成本**：在 1M 上下文、单 GPU 上，每步解码成本降低 **28%~44%**（输入不变），且随上下文增长而扩大。
3. **保持甚至提升接受率**：窗口化后接受长度 AL 通常在原生草案的 ±10% 以内，某些任务（如 Qwen-35B 多 needle 检索）甚至**略有提升**（4.49→4.74），这是因为窗口化移除了远上下文的稀释作用。
4. **无损性质实证验证**：窗口化草案与原生草案的输出差异完全落在验证器 bf16 噪声范围内；直接探针显示 86-94% 的 top-1 提案保持不变，修改的 flip 主要集中在低置信度近分裂位置。
5. **深度草稿的极端硬任务中窗口化拯救了推测加速**：在代码 QA、频繁词枚举等低接受率任务上，原生模板在 d=7 时**已经低于密集基线**（0.80×、0.97×），而窗口化使其回到净正向加速（1.05×~1.67×）。
6. **内存回收实际有效**：草案 KV 池（7.7%-11% 总 KV）的超过 99% 被回收为紧凑环形缓冲，允许在相同内存下容纳更多并发请求（如图 4 中 Qwen-35B 在 B=5 时原生 OOM，窗口化仍提供服务）。
7. **跨架构、跨硬件、跨后端通用**：在 Qwen 系列和 Nemotron 上都有效；在 H100 上也复现类似提升；窗口化收益主要源于减少 KV 读取代价，而非特定后端。

## 7. 优点：方法与实验亮点

- **彻底的无损设计**：不改变验证器，仅修改草案注意力范围，从理论上保证了输出分布不变（贪婪精确算术下）。实验验证了该性质。
- **训练免费、即插即用**：无需重训练、无需新增参数、无需蒸馏，可在现有 SGLang 等框架中通过数行代码实现。
- **硬件无关的通用性**：核心思想（固定 KV 工作集）适用于任何注意力草案，且已在 B200、H100 上验证。
- **实验设计严谨**：
    - 区分了成本侧和接受侧的影响，给出明确的公式和分离分解。
    - 通过窗口剂量-响应、位置条件接受率、决策不变性探针等多角度机制解释。
    - 最佳深度基线的引入避免了单一深度的偏差。
    - 后端消融实验排除了实现层面的混淆。
    - 批量并发和 TP2 实验验证了系统级好处。
- **内存回收实际收益**：不仅是抽象概念，物理实现了环形缓冲并在批量扫描中观察到 OOM 边界改善。

## 8. 不足与局限

- **成本增益率依赖窗口化比例**：不同草案的 O(S) 注意力读取代价占总草案成本的比例不同，因此增益百分比有差异（如 Nemotron 为 28%，Qwen MoE 为 30-44%）。
- **框架与实现依赖性**：精确百分比是针对 SGLang 框架测量的，不同运行时可能略有不同（但方向定性不变）。可回收的内存比例也依赖于 KV 池分配策略。
- **无损性依赖于精确算术假象**：在 bf16 下，批处理验证与密集解码不完全位精确，但该扰动对窗口化和原生草案对称。严格无损仅适用于精确算术或采样下的分布匹配。
- **自适应深度策略尚未实现**：虽然窗口化使最佳深度主要由接受率而非成本驱动，论文未实现在线自适应深度控制器，仅提议为未来工作。
- **静态窗口可能不完美**：对于需要极远上下文信息（如多个 needles 跨越百万 token）的任务，窗口化可能导致较小的接受率损失（Qwen-122B 多 needle 检索 AL 从 5.57 降到 4.74），虽然总体仍正向，但在极端情况下可能缩小甚至反转增益（实验中没有出现，但理论可能）。
- **需要 Triton 后端支持环形缓冲索引重映射**：当前实现依赖 Triton 后端，FlashInfer 后端暂不支持紧凑环形缓冲（但原生 FlashInfer 仍然可以通过窗口化减少 KV 读取，只是无法回收内存）。预期未来 FlashInfer 原生支持可进一步扩大增益。
- **KV 量化场景下相对增益可能缩小**：fp8 下字节读取减少，窗口化节省的 KV 字节也减少，但该论文通过实验显示即便在 fp8 下增益仍为正（14-46%）。
- **树形推测兼容性未实证验证**：虽然论文提到与树形推测正交，但未做实证实验。
