## 摘要
查询无关的KV缓存驱逐会对上下文压缩一次，并将所得的缓存重用于任意未来的查询，但在预算紧张时性能可能会崩溃。现有方法主要改进保留哪些原始KV对。我们引入了RestoreKV，它在相同的总KV预算下，通过学习的恢复机制来补充这种基于选择的方案。我们的关键见解是，尽管驱逐所丢失的信息是上下文特定的，但生成其紧凑补全的机制可以在不同上下文之间共享。在上下文预填充之后，几个恢复令牌在单次LoRA适配的传递中关注完整的KV缓存，生成一个紧凑的、上下文条件下的恢复缓存。基础重要性评分器和驱逐规则保持不变，适配器在所有后续查询和解码中都被禁用。RestoreKV通过从冻结的全缓存模型进行参数高效的自蒸馏来训练，仅优化$0.4\%$的参数，且无需任务特定的调优。在四个骨干网络和四个长上下文基准上，RestoreKV显著减少了压缩引起的性能下降。在Qwen3-4B上，它在五种基础驱逐方法的60个配对、预算匹配设置中改善了59个；在$5\%$预算下，它将RULER-4K上的KVzip从$38.2$提高到$73.2$。应用于KVzip+时，RestoreKV在KVPress基准上以$16\times$压缩达到$86.4$的RULER准确率，同时在32K上下文评估中仅增加了不到$0.5\%$的一次性缓存构建开销。我们的项目页面可在https://paper.pnu-cvsp.com/RestoreKV/ 获取。

## Abstract
Query-agnostic KV cache eviction compresses a context once and reuses the resulting cache for arbitrary future queries, but performance can collapse under tight budgets. Existing methods primarily improve which original KV pairs are retained. We introduce RestoreKV, which complements this selection-based formulation with learned restoration under the same total KV budget. Our key insight is that, although the information lost through eviction is context-specific, the mechanism for generating its compact complement can be shared across contexts. After context prefill, a few restore tokens attend to the full KV cache in a single LoRA-adapted pass, generating a compact, context-conditioned restore cache. The base importance scorer and eviction rule remain unchanged, and the adapters are disabled for all subsequent queries and decoding. RestoreKV is trained through parameter-efficient self-distillation from the frozen full-cache model, optimizing only $0.4\%$ of the parameters and requiring no task-specific tuning. Across four backbones and four long-context benchmarks, RestoreKV substantially reduces compression-induced degradation. On Qwen3-4B, it improves 59 of 60 paired, budget-matched settings across five base eviction methods; at a $5\%$ budget, it raises KVzip from $38.2$ to $73.2$ on RULER-4K. Applied to KVzip+, RestoreKV reaches $86.4$ RULER accuracy at $16\times$ compression on the KVPress Benchmark, while adding less than $0.5\%$ one-time cache-construction overhead in a 32K-context evaluation. Our project page is available at https://paper.pnu-cvsp.com/RestoreKV/

# RestoreKV 论文详细总结

## 1. 论文的核心问题与整体含义（研究动机和背景）

- **背景**：大语言模型依赖长上下文，但KV缓存随序列长度线性增长，内存开销巨大。KV缓存驱逐（KV cache eviction）通过仅保留部分KV对来降低这一成本。
- **研究对象**：**查询无关（Query-Agnostic）的KV缓存驱逐**——对上下文仅压缩一次，并将压缩后的缓存重用于任意未来的查询。这类方法在压缩时看不到未来请求，因此必须在查询到达前完成缓存构建。
- **核心问题**：在**预算紧张（激进压缩）** 下，查询无关驱逐的性能会严重崩溃。现有方法（如KVzip、KVzip+、ContrastKV等）本质上都遵循同一范式：**仅从原始KV对中选出一个更好的子集**。然而，仅靠“选得更好”不足以防止信息丢失——被驱逐的KV对可能携带对某些查询至关重要的信息。
- **论文的洞察**：虽然驱逐造成的信息丢失是**上下文特定**的（不同上下文丢失的关键信息不同），但**生成这些信息紧凑补全（complement）的机制**可以在不同上下文之间共享。换句话说，不需要为每个上下文单独优化恢复方案，而是训练一个跨上下文通用的恢复机制。
- **整体意义**：该论文提出从“选择”走向“选择+恢复”的新视角，在不增加总KV预算的前提下，通过一个轻量级、可学习的恢复机制，显著缩小压缩缓存与全缓存之间的性能差距。

## 2. 论文提出的方法论

### 2.1 核心思想
RestoreKV不改变基础驱逐器（base evictor）的重要性评分和驱逐规则，而是**在驱逐之前**，从完整KV缓存中生成一组紧凑的、上下文条件化的“恢复缓存”（restore cache），与保留的上下文KV对共同构成最终缓存，且**总KV预算不变**。

### 2.2 关键技术细节

**（1）恢复令牌（Restore Tokens）与LoRA适配**

- 引入 n 个可学习的恢复令牌嵌入 E = [e₁, ..., eₙ] ∈ R^(n×d)，默认 n=8。
- 在上下文预填充完成后，恢复令牌在位置 T+1 ~ T+n 处处理，通过**因果注意力**访问完整KV缓存 C。
- 在恢复过程中启用**LoRA适配器**（rank=8，α=16），对注意力投影和MLP投影进行低秩适配。LoRA仅在此过程中激活，之后全部禁用。

**（2）恢复缓存生成**

- 每个恢复令牌为每层每个KV头生成一个KV对，共产生 |C_res| = nLH 个KV对。
- 恢复缓存 C_res 是上下文条件化的（context-conditioned），即针对当前特定上下文生成。

**（3）预算匹配（Budget Matching）**

- 总预算 B = ⌊rTLH⌋（r为KV预算比率）。
- RestoreKV保留 nLH 个槽位给恢复缓存，基础驱逐器填充剩余的 B - nLH 个槽位：
  - C̃ = Concat(Evict(C, s, B - nLH), C_res)
- 最终缓存大小仍为 B，与基础方法完全相同，保证查询时的KV内存一致。
- 保留的上下文KV对保持原始RoPE相位，恢复令牌占据 T+1~T+n 位置，未来查询从 T+n+1 开始。

**（4）自蒸馏训练目标**

- 训练数据：上下文 x₁:T 和查询 q，冻结的全缓存模型（教师）先生成答案 y。
- 教师分布：p_full(·) = p_θ(· | q, y<i, C)（使用完整缓存）
- 学生分布：p_res(·) = p_θ(· | q, y<i, C̃)（使用预算匹配后的恢复缓存）
- 损失函数：对称KL散度
  - L_distill = (1/2M) Σ [KL(p_full ‖ p_res) + KL(p_res ‖ p_full)]
- 只更新恢复令牌嵌入和LoRA参数（约0.4%的4B模型参数），骨干网络和基础评分器保持冻结。
- 训练时从 U(0.025, 0.25) 中均匀采样预算比率 r，使一个共享机制支持多种预算。

**（5）推理流程**

- 每个新上下文只执行一次恢复令牌的8位前向传播，生成恢复缓存，之后LoRA关闭，所有后续查询和解码使用原始冻结模型。

## 6. 论文的主要结论与发现

1. **RestoreKV显著且一致地缩小与全缓存性能的差距**，且在更激进的预算下收益更大。例如：
   - Qwen3-4B，r=0.05时，RULER-4K上KVzip从38.2提升至73.2（+35.0）
   - KVzip+从51.6提升至70.7（+19.1）
   - 应用于KVzip+时，在KVPress基准16×压缩下达到86.4 RULER准确率

2. **注意力侧适配是恢复效果的主要来源**。固定恢复嵌入（用\n的嵌入代替）配合LoRA可达71.9，而仅学习嵌入只能到42.1——说明LoRA生成的上下文条件化恢复缓存远比恢复令牌本身的记忆重要。

3. **全上下文条件化提供额外收益**。从完整缓存生成（73.2）比从已驱逐缓存生成（64.4）多出8.8个点。

4. **恢复效果来自对上下文注意力的恢复**。RestoreKV将最终查询令牌对非sink上下文KV的平均注意力质量从0.56%恢复到1.30%，并使逐层注意力分布更接近全缓存模式（KL从0.198降至0.167）。

5. **位置偏移不能解释提升**。仅将查询位置偏移+8而不添加恢复状态，性能（36.9）接近原始KVzip（38.2），远低于RestoreKV（73.2）。

6. **训练-推理驱逐器需要匹配**。用SnapKV训练的RestoreKV在KVzip推理时，r=0.05下只能达到42.0（匹配时73.2），虽然仍略优于无恢复的38.2。

7. **开销可忽略**。一次性恢复缓存构建耗时不足0.5%，推理时注意力延迟和KV内存与基础方法完全一致。

## 7. 优点

- **视角创新**：首次明确提出“选择+恢复”互补框架，将问题从“哪些KV对该留下”扩展为“如何生成丢失信息的紧凑补全”。
- **即插即用兼容性**：不改变基础评分器和驱逐规则，理论上有潜力直接集成到任何现有查询无关驱逐管线中。
- **预算严格匹配**：每组对比都保持相同KV内存，公平且实用。
- **极低的额外成本**：仅优化0.4%参数，推理时LoRA完全关闭，无额外查询时间或解码开销。
- **无需任务特定调优**：每个模型+驱逐方法只训练一次，即可用到所有下游任务。
- **彻底充分的消融**：隔离了恢复嵌入、LoRA适配、全上下文条件化、位置偏移等各个因素，论证逻辑严密。
- **效率与性能平衡**：相比Attention Matching等合成缓存方法，RestoreKV+在相似或更好精度下快约13倍。

## 8. 不足与局限

- **训练-推理驱逐器错配敏感**：在不同驱逐方法之间迁移RestoreKV训练权重时性能明显下降（r=0.05时从73.2降至42.0），限制了实际部署中更换驱逐方法的灵活性。
- **训练上下文长度有限**：最长训练上下文约15K token，虽然SCBench实验（~104K）验证了泛化能力，但训练-推理长度差距较大，超长上下文下的稳定性仍需更多验证。
- **与AM-fast对比覆盖有限**：仅在Qwen3-4B和部分预算点上对比，且在较宽松的LongHealth预算下AM-fast更强，未充分展示对多种合成缓存方法的全面优势。
- **通用指令查询的依赖性**：训练数据中部分使用固定的通用指令（如总结、解释），可能与实际部署中多样化的查询类型存在分布差异。
- **恢复令牌存在性能波动**：n=2（70.4）优于n=4（68.5），n=16（69.1）反而不如n=8（73.2），说明令牌数量与效果并非单调关系，最优配置可能随模型或任务变化。
- **内存开销虽小但恒定存在**：LoRA权重常驻（84MB），虽然与上下文长度无关，但在极小模型（如0.6B）上的相对占比可能更大。
- **单GPU实验环境**：所有实验在单卡上完成，未验证多卡或分布式推理场景下的行为。
- **训练数据构建依赖教师生成**：教师响应离线生成的成本和潜在的生成失败/过滤偏差未被详细讨论。
