## 摘要
LLM推理已成为一种全球规模的异构工作负载，涵盖代理、检索、工具使用、代码执行和多模态推理。这些工作负载天然支持重叠输入中的上下文重用，为存储和重用上下文的KV缓存而非重新计算创造了重要机会。然而，模型侧缩小KV缓存的进展和系统侧降低计算、存储和传输成本的进展，在传统云边界内独立演进。我们提出，未来的推理基础设施应允许在云和数据中心之间解耦计算与KV缓存存储。网络成为主动分发渠道；带宽、延迟和定价直接决定KV缓存应如何管理。我们提出了一个KV缓存互联网的愿景，将KV缓存管理作为内容分发系统运作。在这一视角下，KV缓存存储和重计算决策由模型、基础设施和应用指标驱动，以实现自适应、内容驱动的决策，从而最小化延迟和成本。

## Abstract
LLM inference has become a global-scale, heterogeneous workload spanning agents, retrieval, tool-use, code execution and multi-modal reasoning. These workloads naturally enable context reuse from overlapping inputs, creating a major opportunity to store and reuse the contexts' KV Caches instead of recomputing them. However, model-side advances that shrink the KV Cache and system-side advances that reduce compute, storage, and transfer costs are evolve independently within legacy cloud boundaries. We argue that future inference infrastructure should allow decoupling of compute and KV Cache storage across cloud and datacenters. The network becomes an active distribution channel; bandwidth, latency and pricing directly determines how the KV Cache should be managed. We propose a vision for an Internet for the KV Cache, with KV Cache management working as a content-distribution system. In this view, KV Cache storage and recompute decisions are driven by model, infrastructure, and application metrics, to enable adaptive, content-driven decisions for minimizing latency and cost.

## 2. 方法论：核心思想、关键技术与公式

- **核心思想**：将 KV Cache 视为可移动、可复制、可重新生成的“内容”，像 CDN 分发内容一样分发 KV Cache。
- **决策框架**：KV Cache 放置与传输决策由三类指标联合驱动：
  - **模型侧指标**：prefill FLOPs、KV Cache 大小等；
  - **基础设施侧指标**：GPU 成本、存储成本、网络带宽与传输定价；
  - **应用侧指标**：KV Cache 重用频率、工具调用时长、请求轮次等。
- **成本模型公式**：
  - `CacheCost = DeviceCost_hr · K · KV_MB + TransferCost · KV_MB`
  - `PrefillCost = GPUCost_hr · (Prefill_TFLOPs / PeakFlopRate)`
  - 比较 `CacheCost / PrefillCost` 是否小于 1 来决定存储复用还是重新计算。
- 由公式导出两个可独立计算的比率：
  - **模型侧比率**：`Prefill_TFLOPs / KV_MB`
  - **基础设施/应用侧比率**：`(DeviceCost_hr · K + TransferCost) / (GPUCost_hr / PeakFlopRate)`
- **减少 miss-rate 是核心目标**：传统前缀缓存只重视命中率，但一次缓存未命中可能触发昂贵的长上下文重算；应通过 KV Cache 混合（cache blending）、语义化近似匹配等实现非精确前缀复用，降低 miss-rate。
- **系统架构构想**：
  - 全局 KV Cache 控制平面，包含目录查找、放置规划、预取调度；
  - 带宽感知的跨云/跨区域 KV Cache 移动；
  - 基于复用时间尺度区分冷/温/热 KV Cache，采用不同存储策略；
  - 支持部分获取、部分重算、复制、驱逐等多种动作。

## 6. 主要结论与发现

- KV Cache 不应再被视为普通数据结构，而是 LLM 推理中一种可共享、可复用、可持久化的“上下文知识表示”。
- “存储还是重算”没有统一答案，决策取决于模型、基础设施和应用三方面指标的交互。
- 降低 KV Cache 的 miss-rate 比简单地提高 hit-rate 更重要，因为缓存未命中导致的重新计算代价可能极高。
- 现有云架构的存储-计算绑定和数据传输定价模型，严重限制了 KV Cache 的跨域复用；需要设计一种“Store Anywhere, Use Everywhere”的分布式架构。
- 网络带宽、时延和价格应成为推理基础设施的一等公民；KV Cache 的放置和移动应由内容分发原则指导。
- 呼吁学术界和工业界研究新的控制平面、传输协议、抽象和度量，以支持互联网规模的 KV Cache 管理。
