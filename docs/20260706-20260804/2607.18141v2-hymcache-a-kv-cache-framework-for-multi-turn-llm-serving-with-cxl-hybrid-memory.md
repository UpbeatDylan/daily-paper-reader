## 摘要
长上下文、多轮和智能体LLM工作负载越来越多地重用先前处理过的上下文，使得KV缓存重用对于减少冗余计算至关重要。然而，这种重用将瓶颈转移到在集群规模上存储和提供可重用KV状态的内存层级。GPU HBM和主机DRAM成本过高，难以扩展到TB级共享上下文容量，这促使采用更低成本、更高容量介质构建远程层级。本文提出了HyMCache，一个集成CXL混合内存(CXL-HM)的KV缓存框架，用于多轮LLM服务。CXL-HM将少量设备内DRAM与大型SSD支持的容量结合在CXL接口之后。通过利用多轮KV缓存访问的读主导、可预测和仅追加特性，HyMCache重新思考了CXL-HM内的DRAM管理，以高效支持TB级SSD支持的KV重用。它使用请求级前缀预取和机会性写缓冲，将延迟关键的读取暂存到设备DRAM中，从而以SSD级别的成本实现DRAM规模的KV缓存效率。我们在真实的CXL-HM原型上，在单聚合器和PD分离服务配置下评估了HyMCache。在相同DRAM预算下，HyMCache在单节点服务中比本地LMCache快3.0倍，在PD分离服务中快1.45倍。与1 TB分布式DRAM Mooncake相比，HyMCache性能降低约30%，但DRAM使用量减少16倍。

## Abstract
Long-context, multi-turn, and agentic LLM workloads increasingly reuse previously processed context, making KV-cache reuse essential for reducing redundant computation. However, this reuse shifts the bottleneck to the memory tier that stores and serves reusable KV states at cluster scale. GPU HBM and host DRAM are too costly to scale to TB-scale shared context capacity, motivating remote tiers built from lower-cost, higher-capacity media. This paper presents HyMCache, a KV-cache framework that integrates CXL-hybrid memory (CXL-HM) for multi-turn LLM serving. CXL-HM combines a small amount of in-device DRAM with large SSD-backed capacity behind a CXL interface. By exploiting the read-dominant, predictable, and append-only nature of multi-turn KV-cache access, HyMCache rethinks DRAM management within CXL-HM to efficiently support TB-scale SSD-backed KV reuse. It uses request-level prefix prefetching and opportunistic write buffering to stage latency-critical reads in device DRAM, enabling DRAM-scale KV-cache efficiency at SSD-level cost. We evaluate HyMCache on a real CXL-HM prototype under both single-aggregator and PD-disaggregated serving configurations. Under the same DRAM budget, HyMCache outperforms local LMCache by 3.0x in single-node serving and 1.45x in PD-disaggregated serving. Compared with 1 TB distributed-DRAM Mooncake, HyMCache incurs about 30% lower performance but uses 16x less DRAM.

## 1. 核心问题与研究动机

**背景与问题：**
- 现代LLM工作负载正从单轮提示向长上下文、多轮对话和智能体（agentic）应用演进，推理成本不仅由计算决定，更由内存容量主导。
- 多轮对话中大量前缀（prefix）被反复复用（agent轨迹可跨数十至数百轮，>95% token被跨轮复用），KV缓存重用成为减少冗余计算的关键。
- 然而，KV缓存重用将瓶颈转移到了内存层级——GPU HBM和主机DRAM成本过高，难以经济地扩展到TB级共享上下文容量（15.36 TB DRAM约需$78-$81万美元，而相同容量NAND TLC仅约$1.36万美元）。
- 业界趋势（NVIDIA CMX、DeepSeek磁盘上下文缓存）表明KV缓存重用正日益成为内存分层（memory tiering）问题。

**核心主张：**
- CXL混合内存（CXL-HM）——结合少量设备内DRAM与大型SSD支持容量，通过CXL.mem接口以内存语义暴露SSD支持容量——提供了介于DRAM-only内存池与纯存储分层之间的中间方案：以SSD级成本实现DRAM级KV缓存效率。

## 2. 方法论与技术细节

### 2.1 工作负载特征分析（4个关键观测）

通过远程DRAM tier实验（A100 GPU、100Gbps RDMA、LMSYS多轮数据集），识别出多轮KV访问的核心特征：

- **观测➊**：读流量跨轮增长——累积上下文增长导致每轮需重载更多前缀KV块。
- **观测➋**：KV重用为读主导且只读——被复用的KV块不被修改，保持干净状态。
- **观测➌**：顺序KV读取且弱局部性——KV块按上下文顺序读取，短期复用率低（类似一次命中即弃的扫描型工作负载），LRU策略失效。
- **观测➍**：写入为仅追加新生成的KV块——每轮只写新增输出token对应的KV，写流量相对稳定。

### 2.3 关键技术组件

**① 请求级前缀预取（KV-object prefetching）**
- 多轮前缀缓存查找揭示请求将消费的有序KV对象列表。
- 服务运行时将对象级访问顺序传递给CXL-HM，使即将到来的KV对象在远程读取到达之前完成预取。
- 提供显式预取API：`chm_prefetch_object(ptr, size)`、`chm_prefetch_wait(req)`、`chm_prefetch_release(req)`，构成有界的发起-等待-释放协议。

**② 延迟隐藏的暂存窗口（Latency-hiding staging window）**
- 不是将内部DRAM作为累积前缀的容量缓存，而是通过固定深度的暂存窗口流式传输KV对象。
- 预取流水线保持窗口填充时，有界DRAM可支持大型且增长的前缀KV缓存。
- SSD带宽成为可持续预取的实用旋钮，而非将DRAM尺寸与KV总占用空间匹配。

**③ 读优先写隔离的KV刷新（Read-Prioritized Write-Isolated KV Flushing）**
- KV写入只影响未来复用，不影响当前请求正确性。
- 保留小写侧缓冲区，当缓冲区满时允许跳过或重试写入。
- 异步大批次刷新到SSD，优先在读取压力低时执行，避免与前台前缀读取在SSD后端路径上交错。

**④ 软件集成模块（四个模块）**
- **HyMCache Master**：全局元数据管理，维护KV标识符到远程访问信息的映射（节点ID、地址、长度）；约10TB KV容量仅需约40MB元数据。
- **HyMCache Lookup**：提前远程命中匹配、批量元数据查找、在vLLM worker重载KV块之前协调预取。
- **KV Connector**：通过vLLM的KV传输回调集成，远程命中后只执行批量RDMA读取的数据移动；10秒超时回退到重计算。
- **KV Manager**（CXL-HM内部）：协调跨并发请求的预取，按请求动态分配预取窗口（每请求约128MB，8个16MB块或4个32MB块）。

## 6. 主要结论与发现

1. **CXL-HM是可行的低成本远程KV tier**：以SSD级成本（$40K vs DRAM $782K，表1）提供TB级共享KV容量。
2. **性能对比核心结果**：
   - 同DRAM预算下，HyMCache较本地LMCache在单节点服务提升**3.0×**，PD分离服务提升**1.45×**。
   - 相比1TB分布式DRAM Mooncake，性能降低约**30%**，但DRAM使用量减少**16×**。
   - 比较NVMe-oF存储tier：XFS on NVMe-oF将原始23GB/s降为6.5GB/s顺序读带宽，导致请求超时回退到重计算——CXL-HM的内存语义绕过文件系统栈，有效避免了此退化。
3. **命中率优势**：Turn 7时HyMCache命中率74%（vs GPU prefix caching 12%、LMCache 20%、Mooncake 65%）；单节点设置中保持约90%命中率，而本地缓存基线在Turn 3-4后因LRU驱逐破坏连续前缀链而崩溃。
4. **传输缓冲敏感性**：Mooncake在10GB传输缓冲下性能急剧退化（接近重计算基线），HyMCache因机会性写入策略对此不敏感。
5. **预取有效性**：平均带宽提升35%以上，峰值接近200Gbps线速，E2E延迟降低14%。

1. **深入的工作负载特征分析**：四个观测清晰揭示了多轮KV访问与通用CMM-H设备LRU策略的根本性错配，技术叙事有力。
2. **软硬件协同设计**：将服务层KV复用知识（可预测的前缀顺序）与设备侧DRAM管理耦合，而非将CXL-HM作为通用内存扩展黑盒。
3. **原型系统验证**：在真实FPGA CXL-HM原型上评估，而非仅做仿真或建模。
4. **成本量化**：表1提供详尽的成本分析，并讨论FPGA原型成本中91-95%来自开发板本身。
5. **对NVMe-oF路径的公平对比**：识别XFS文件系统叠加的带宽退化（23GB/s → 6.5GB/s），说明单纯存储路径不足以满足KV缓存读取延迟需求。
6. **针对实际部署问题的鲁棒性设计**：传输缓冲敏感性分析挖掘出Mooncake等分布式DRAM缓存在规模部署时被忽视的本地DRAM依赖。

## 8. 不足与局限

1. **FPGA原型代表性有限**：FPGA-based CXL-HM与控制器的真实ASIC产品在延迟和带宽特性上存在差距；原型中FPGA板占91-95%成本，商业化后的成本主张是否仍然成立需进一步验证。
2. **性能差距未完全消除**：相比1TB分布式DRAM，30%的性能差距在服务场景中可能是显著的SLA差异；且`>15%的KV插入被跳过`（写缓冲满）表明机会性写入策略的一个明显代价。
3. **实验场景覆盖有限**：
   - 未测试通过CXL交换机/结构连接的部署方式（仅RDMA路径）。
   - 未使用真实agentic推理轨迹（如工具调用链）评估（仅chat多轮和合成AIPerf）。
   - 未进行更大规模（如跨8+节点、多CXL-HM设备）的扩展性测试。
4. **对比公平性偏倚**：Mooncake的1TB DRAM vs CXL-HM的64GB DRAM + 2TB SSD，虽然DRAM预算角度合理，但32倍媒体容量差使结果部分由容量而非技术优势驱动；且Mooncake的元数据/传输开销被单独归因于"DRAM缓存vs CXL-HM"的差异。
5. **KV Connector的10秒超时回退**：遇到CXL-HM瞬时延迟抖动时直接回退重计算，实际生产环境中可能过于激进，增加服务延迟方差。
6. **缺少对故障恢复与持久化的深入讨论**：CXL-HM基于NAND，其持久化语义、断电保护和数据完整性如何在KV缓存tier中保证，论文未充分展开。
