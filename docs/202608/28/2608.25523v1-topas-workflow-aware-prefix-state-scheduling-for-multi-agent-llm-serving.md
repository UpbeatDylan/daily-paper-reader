## 摘要
前缀缓存在多智能体大语言模型（LLM）服务中引入了一个基本权衡：为某个智能体保留较长的系统提示键值（KV）缓存可以加速未来的调用，但会减少可用于批处理并发请求的GPU内存。在多阶段工作流中，现有调度器往往倾向于优先考虑即时前缀局部性，或者整体工作流进展。然而，在共享KV缓存预算下，单独优化任一目标都可能通过下游延迟或频繁的前缀替换延长任务级作业完成时间（JCT）。为了取得平衡，我们在此提出TOPAS，一种任务导向的前缀感知调度器，它联合决定在缓存中保留哪些智能体前缀，以及调度哪些请求执行。TOPAS通过权衡每个任务最长剩余服务路径的预期减少与下游前缀复用的近期收益，并考虑前缀移动和抢占的成本，对候选决策后状态进行评分。还引入了任务级老化机制以防止饥饿。我们在SGLang框架中实现了TOPAS，并在三个合成DAG和两个MetaGPT软件开发工作流上评估其性能。与每个工作负载和指标下表现最佳的基线相比，TOPAS在合成工作负载上将平均/第99百分位JCT最多降低了39.8%/49.4%，在MetaGPT-SOP上将平均JCT降低了9.8%，在MetaGPT-TL上将平均/第99百分位JCT降低了22.0%/26.6%。

## Abstract
Prefix caching introduces a fundamental tradeoff in multi-agent large language model (LLM) serving: retaining a long system-prompt key-value (KV) cache for an agent accelerates future calls, yet it reduces the GPU memory available for batching concurrent requests. In multi-stage workflows, existing schedulers tend to prioritize either immediate prefix locality or overall workflow progress. However, under a shared KV cache budget, optimizing either objective in isolation can prolong tasklevel job completion time (JCT) through downstream delays or frequent prefix replacement. To strike a balance, we here propose TOPAS, a Task-Oriented Prefix-Aware Scheduler that jointly decides which agent prefixes to keep in the cache and which requests to schedule for execution. TOPAS scores candidate post-decision states by trading off the expected reduction in each task's longest remaining service path against the near-term benefit of downstream prefix reuse, accounting for the costs of prefix movement and preemption. A task-level aging mechanism is also incorporated to prevent starvation. We implement TOPAS within the SGLang framework and assess its performance on three synthetic DAGs and two MetaGPT software-development workflows. Compared with the best performing baseline for each workload and metric, TOPAS reduces the mean/p99 JCT by up to 39.8%/49.4% on the synthetic workloads, while lowering mean JCT by 9.8% on MetaGPT-SOP and mean/p99 JCT by 22.0%/26.6% on MetaGPT-TL.

## 1. 论文的核心问题与整体含义（研究动机和背景）

- **背景**：多智能体 LLM 应用通过多个角色专业化智能体之间的相互依赖请求来完成复杂任务。每个请求包含一个智能体特定的静态前缀，其 KV 缓存可跨任务复用；服务系统（如 SGLang）利用 radix 树管理缓存，保留前缀可消除冗余 prefill 计算，但与并发请求竞争有限的 GPU KV 内存。

- **核心冲突**：前缀缓存引入一个基本权衡——为某个智能体保留长系统提示 KV 缓存能加速未来调用，但会减少可用于批处理并发请求的 GPU 内存。在多阶段工作流中，现有调度器要么优先前缀局部性，要么优先整体工作流进度，但孤立优化任一目标都会延长任务级作业完成时间（JCT）：前者导致下游阶段延迟，后者导致频繁前缀替换和重计算开销。

- **诊断性发现**：作者通过两个微型实验揭示问题本质：
  - 异构前缀共驻留会缩小可用批大小（交替调度比分组调度的平均批大小约减半，耗时增加 1.8–1.9 倍）；
  - 局部性优先策略（LPM）和服务于进度优先策略（SRPT）在 A→B→C 链式工作流中均不如一个简单的下游门控干预策略，说明协调前缀复用与任务进度至关重要。

- **研究问题**：在受限 GPU 内存预算下，服务系统如何协调前缀驻留和请求准入以最小化任务级 JCT？作者将这一问题形式化为**在线前缀状态调度**问题。

## 2. 论文提出的方法论

### 2.1 核心思想

TOPAS 是一个**任务导向的前缀感知调度器**，核心创新在于将前缀驻留视为显式的工作流级调度决策，与请求准入联合优化，而非请求排序和缓存淘汰的间接副产品。在每个调度时刻，TOPAS 同时决定保留哪些智能体前缀和接纳哪些请求，目标是直接选择最优的"决策后状态"。

### 2.2 问题形式化

- **状态定义**：调度时间点 t 的 GPU 状态为 S_t = (R_t, Q_t)，其中 R_t 为驻留智能体前缀集合，Q_t 为运行中请求集合。调度动作选择决策后状态 S' = (R', Q')。
- **容量约束**：选定的联合状态需满足：∑(静态前缀 KV) + ∑(动态后缀 KV) ≤ B_t（可用 KV 容量）。
- **未知信息**：未来任务到达、就绪时间、ReAct 迭代次数和工具输出均未知，属于在线决策问题。

### 2.3 基础转移效用函数

TOPAS 对候选状态 S' 评估：

**U_base(S'|S_t) = J_admit − J_move − J_redo − J_revoke**

- **J_admit（准入收益）**：估计被选请求对任务剩余路径的期望缩减。对 DAG 中每个节点，请求的完成可使任务关键路径上的剩余服务量减少。使用经验条件残差分布计算最大剩余路径（Longest Path），并允许关键路径随进度变化而切换。
- **J_move（前缀移动成本）**：前缀 KV 缓存在 GPU/CPU 内存间转移的时间开销，按交换带宽序列化计算。
- **J_redo（重计算成本）**：被抢占请求已生成 token 需要重新解码的代价。
- **J_revoke（信用撤销）**：被抢占请求原本获得的准入价值（on-admission credit）被撤销。

### 2.4 短视野前缀复用

**V_reuse = β ∑(即将就绪的代理数 × 前缀加载时间)**——评估保留某前缀对下游刚释放请求的近期复用价值，仅向前看一跳，因为更远的需求依赖未解析的分支和工具结果。

### 2.5 任务级老化机制

**g_i(t) = 1 + ρ·log(1 + (t − τ_i)/H_age)**——防止新到达任务反复超越旧任务，按任务年龄缩放准入收益。该机制只影响服务路径的进度估计，不改变容量约束和候选生成。

### 2.6 分层状态搜索

- 当活动代理池 ≤ M 时，枚举所有前缀集合；否则使用受限的贪婪搜索（单代理添加 → 双代理添加 → 丢弃/交换修复），限制为 O(|A_t|²)。
- 对每个前缀集合 R，使用 **GREEDY PACK** 算法：保留 R 覆盖的运行中请求、分配准入门槽、按"每额外 KV 的年龄加权条件进度"贪心接纳请求。
- 最终从所有可行的中间分配中选择得分最高的状态 S'_t = argmax Score(S'|S_t)，形成事件级贪婪策略。

## 3. 实验设计

### 3.1 数据集与场景

- **合成 DAG 工作负载**（3 个）：

任务到达服从泊松过程，到达率在多个操作点变化；同一到达迹线跨所有策略共享。

### 3.2 对比基线

- **FCFS**（按到达时间排序）
- **LPM**（Longest Prefix Match：优先最长可复用前缀）

- **Autellix-LAS**（Least-Attained Service：优先累计服务量最少的任务）
- **SPF/SRPT**（Shortest-Path-First：优先更深工作流阶段，等价于最短剩余处理时间）

### 3.3 主要指标

以平均 JCT 和 p99 JCT 为主要指标，辅以首任务完成时间和请求吞吐量。

## 6. 论文的主要结论与发现

- **合成 DAG 工作负载**：相比各工作负载/metric 下最优基线，TOPAS 将平均 JCT 降低 27.5%–39.8%，p99 JCT 降低 30.8%–49.4%。
- **MetaGPT-SOP**：对比最强平均 JCT 基线 SPF，平均/p99 JCT 分别降低 9.8%/4.5%，请求吞吐量提升 6.7%。

## 7. 优点

- **问题建模清晰**：将前缀驻留与请求准入正式化为联合优化问题，明确了状态、容量约束和在线决策设定，与已有工作形成清晰对照。
- **联合决策框架**：首次将前缀驻留作为显式的工作流级调度维度，整合到统一的评分函数中，突破了传统"请求排序→缓存淘汰→承接效应"的间接路径。
- **DAG 感知的进度度量**：使用基于经验条件残差分布的最长剩余路径缩减作为进度信号，允许关键路径动态切换，比单一"请求完成数"或"阶段数"更贴近真实任务完成。
- **实际系统实现**：TOPAS 不是纯仿真，而是实现于 SGLang v0.5.3 之上，实验在真实 LLM（Qwen2.5-32B）上进行，结果可信度较高。
- **搜索效率考量**：分层搜索（枚举 + 贪婪 + 修复操作）兼顾了小代理池的全局性和大代理池的可扩展性，调度开销极低（约 0.31%）。
- **消融实验有说服力**：分别移除复用和老化组件验证了各模块的必要性，确认完整模型收益远超任一单组件。

## 8. 不足与局限

- **单 GPU 环境**：所有实验仅在单张 A100 上运行，未覆盖多 GPU 或多节点分布式部署中缓存一致性、跨机前缀迁移、负载均衡等真实服务难题。
- **工作负载多样性有限**：合成 DAG 使用固定长度生成和固定查询，MetaGPT 仅两个工作流；未覆盖工具调用密集型、超长上下文、多轮人为交互等更复杂的 Agent 场景。
- **到达过程单一**：仅使用泊松到达且共享固定迹线，未涵盖突发性强、非平稳或高动态变化的多租户流量模式。
- **关键参数敏感性未分析**：β（复用压力强度）、ρ（老化强度）等超参数如何影响性能未见系统性扫描，实际部署中调参依赖不明。
- **消融实验覆盖窄**：仅报告 MetaGPT-TL 单一操作点的消融，合成工作负载上的组件贡献缺乏分析。
- **与其他先进调度器的对比仍有限**：基线中未包含已发表的 KVFlow（工作流感知缓存管理）和 Astraea（状态感知调度）等同类最先进系统，使对比的充分性有所下降。
- **未讨论系统鲁棒性**：对于估计误差（如服务时间分布不准确）、前缀交换带宽波动、请求等级优先级（SLO/QoS）等实际约束未作讨论。
