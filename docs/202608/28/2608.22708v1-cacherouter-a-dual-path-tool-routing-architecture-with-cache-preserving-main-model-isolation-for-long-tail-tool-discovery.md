## 摘要
LLM系统中的工具使用面临结构性权衡。渐进式披露通过仅显示与当前任务相关的工具来保持提示词简短，而提示缓存则奖励在调用间保持固定的请求前缀；可见工具列表的任何变化都会使缓存前缀失效。本文将这一权衡视为请求架构问题，并提出一种双路径路由设计，将工具选择与工具交付分配到独立通道。主模型始终看到一组小而固定的核心工具，因此其请求头部在调用间保持不变；所有其他工具通过独立路由通道访问，其中路由器子模型搜索完整工具列表，选择一个工具，执行它，并返回结果。工具注册从源代码自动完成并支持运行时更新，因此工具集合可以增长而无需修改主模型的请求前缀。该设计推广了渐进式披露：能力通过路由通道披露，而主模型的前缀保持稳定。原型实现已在55个功能查询和30轮对话上进行了测试；在DeepSeek定价下（缓存命中输入token约为缓存未命中token的1/30），token级缓存命中率达到90.99%和95.2%，将输入成本降低至无缓存基线的约12.0%和8.0%。

## Abstract
Tool use in LLM systems faces a structural trade-off. Progressive disclosure keeps the prompt small by showing only the tools relevant to the current task, while prompt caching rewards a request prefix that stays fixed across calls; every change to the visible tool list invalidates the cached prefix. This paper treats the trade-off as a problem of request architecture and proposes a dual-path routing design that assigns tool selection and tool delivery to separate channels. The main model always sees a small, fixed set of core tools, so the head of its request is unchanged across calls; all other tools are reached through an independent routing channel, in which a router sub-model searches the full tool list, selects one tool, executes it, and returns the result. Tool registration is automated from source code and supports runtime updates, so the tool set can grow without modifying the main model's request prefix. The design generalizes progressive disclosure: capabilities are disclosed through the routing channel, and the main model's prefix stays stable. A prototype implementation was exercised on 55 functional queries and a 30-turn dialogue; token-level cache hit rates reached 90.99% and 95.2%, cutting input cost to about 12.0% and 8.0% of a no-cache baseline under DeepSeek's pricing, where cache-hit input tokens cost roughly 1/30 of cache-miss tokens.

# CacheRouter 论文总结

## 1. 核心问题与研究动机

- **核心冲突**：LLM 工具使用面临“渐进式披露（Progressive Disclosure）”与“提示缓存（Prompt Caching）”之间的结构性矛盾：
  - 渐进式披露要求只向主模型展示当前任务相关的少量工具，以控制上下文长度；
  - 提示缓存则希望请求前缀在多次调用之间保持不变，以便复用服务端缓存；
  - 工具列表的任何动态变化都会使缓存前缀失效，导致高额 cache-miss 费用。
- **问题本质**：作者认为根源在于“工具选择”（选哪些工具）与“工具交付”（工具定义如何进入请求）被耦合在同一个请求通道中。工具集的变化会直接传播到缓存层。
- **解决思路**：通过请求架构层面的“双路径路由”设计，将工具选择与工具交付解耦，使主模型的请求前缀保持稳定，同时不牺牲对长尾工具的完整覆盖能力。

## 2. 方法论

### 2.1 核心思想：双路径路由架构

- 将工具空间划分为：
  - **核心工具集 C**：固定在主模型可见范围内，数量可控，请求前缀稳定。
  - **长尾工具集 T\C**：低频、专用或动态生成的工具，通过独立路由通道按需访问。
- 主模型请求前缀可表示为：
  - \( P_C = (\text{system prompt}_C \parallel \text{history}_i \parallel \text{tools}(C)) \)
  - 工具定义段由固定集合 C 决定，长尾工具变化不会进入主模型请求前缀。

### 2.2 关键技术组件

- **占位工具（Placeholder Tool Triage）**：在主模型第一轮意图分流阶段，只暴露一个不可调用的占位工具 `TOOL_WHICH_WOULD_BE_USED`，其定义永不改变，起到“缓存锚点”和“意图引导”双重作用。模型只需输出 `[STATUS: DIRECT_ANSWER]` 或 `[STATUS: NEED_TOOLS]`，不执行真实工具。
- **INTERNAL ROUTER 伪工具**：注册在主模型固定视图中的元工具。当核心工具不足时，主模型调用它，触发一个独立的子模型通道，由路由子模型完成工具检索、过滤、执行，并将结果以 JSON 形式返回主模型。长尾工具的定义永远不会进入主模型请求。
- **四阶段过滤流水线**：
  1. **黑名单过滤**（安全硬限制）
  2. **白名单过滤**（部署场景限制）
  3. **Top-K 预选**（基于查询词与工具元数据的命中率排序，最多保留 5 个候选）
  4. **黄名单过滤**（软性缓存优先策略，优先保留核心集之外的工具，但不绝对禁止）
- **AST 自动注册与热重载**：通过 Python AST 静态解析脚本中的 argparse 参数定义，自动生成 MCP JSON Schema；通过文件快照轮询实现运行时热更新，无需重启服务。
- **技能自举（Skill Bootstrapping）**：当现有工具无法完成任务时，系统利用已有代码执行能力生成新技能脚本，默认放入独立工具包，不改变主模型可见工具集；后续任务通过路由通道按需发现和复用。

### 2.3 主要算法流程

- **查询处理管道（Algorithm 1）**：第一轮分流 → 工具执行循环（核心工具直接调用、INTERNAL ROUTER 走子通道）→ 深度思考与回退（状态异常/超时>60s/连续4轮工具调用触发）。
- **路由子通道（Algorithm 2）**：上下文压缩（≤800字符）→ 获取全量工具列表 → 四阶段过滤 → 路由子模型单次约束调用 → 返回 JSON 结果。
- **成本公式**：在 DeepSeek 缓存计价比（hit:miss ≈ 1:30）下，输入成本约为无缓存基线的 \((1-h) + h/30\)。

## 6. 主要结论与发现

- **缓存命中率**：实验 1–8 聚合 token 级缓存命中率 90.99%；30 轮长链对话达到 95.2%。
- **成本降幅**：按 1:30 的 hit/miss 定价，输入成本分别降至无缓存基线的约 12.0% 和 8.0%。
- **前缀稳定性**：运行时新增工具、技能生成、网关重启都不会改变主模型请求前缀（实验 3 冷启动对比验证）。
- **路由补充性**：核心工具集覆盖高频常见任务（实验 7 中总计仅 4 次 Router 调用），长尾工具通过路由按需访问，未影响任务完成。
- **诚实回退**：5/5 的不可回答查询均诚实反馈，没有捏造内容。
- **技能自举**：5/5 的技能构建任务成功整合到独立工具包。
- **缓存行为规律**：直接回答路径获益最大；工具执行路径首轮 miss、后续轮次持续命中；多轮调试链（实验 8）前缀变化多，收益最小。

## 7. 优点

1. **问题切入角度新颖**：将“提示缓存”与“工具编排”作为系统性耦合问题处理，而非单纯优化检索算法或缓存策略。
2. **架构解耦清晰**：主模型、路由子模型、网关、仓库分层隔离，工具增长与主模型上下文解耦，工程上可落地。
3. **占位工具设计巧妙**：用不可调用的固定占位工具完成意图分流，既稳定前缀又提供能力边界感知。
4. **全生命周期覆盖**：从自动注册、热重载、路由过滤到技能自举，形成完整闭环，且每一步都不破坏缓存路径。

6. **诚实承认局限性**：明确说明实验规模小、非基准测试，并对未来方向做了合理规划。
