## 摘要
长期运行的助手和智能体消费交互流，最终会超出上下文长度。现有的上下文保留、摘要和检索方法仅保留了对选定历史的访问，但未能在工作上下文变化时提供覆盖完整生命周期的持久状态。我们将这种缺失的推理能力表述为“上下文更替下的状态连续性”：通过固定容量的记忆状态向前推进计算，该记忆状态的寿命独立于活动上下文。我们引入了一种内在记忆方法，即LiveMem，它用一个记忆状态增强预训练的全注意力LLM，该记忆状态在整个生命周期中保留历史信息，而主注意力路径保持有界的KV窗口。上下文更替与记忆状态维护、面向记忆的后训练以及状态感知服务共同使得该记忆状态在其源token被释放后仍能承担负载。我们的实验表明，LiveMem在评估的系统及其他内在记忆方法中取得了领先的整体性能。在LongMemEval上的实验表明，即使支持性证据已从当前上下文中移除，LiveMem仍能基于记忆状态回答问题，并且证据距离分析表明，有用信息在活动窗口之外仍然持续存在。因此，LiveMem将状态连续性确立为持续LLM推理中一个独特且互补的抽象。

## Abstract
Long-running assistants and agents consume interaction streams that eventually outgrow the context. Existing context retention, summarization, and retrieval preserve access to selected history, but do not provide a persistent state over the full lifecycle when working context changes. We formulate this missing inference capability as \emph{state continuity under context turnover}: carrying computation forward through a fixed-capacity memory state whose lifetime is independent of the active context. We introduce an intrinsic memory method, \textbf{LiveMem}, which augments a pretrained full-attention LLM with a memory state that preserves the historical information over the whole lifecycle while the main attention path retains a bounded KV window. Context turnover and memory state maintaining, memory-oriented post-training, and state-aware serving jointly make this memory state load bearing after its originating tokens are released. Our experiments show that LiveMem achieves leading overall performance among evaluated systems and other intrinsic memory methods. Experiments on LongMemEval show that LiveMem is able to answer the question based on the memory state, even when the supporting evidence has been removed from the current context, and evidence-distance analysis shows that useful information persists beyond the active window. LiveMem thus establishes state continuity as a distinct and complementary abstraction for continual LLM inference.

## 1. 核心问题与整体含义

- **研究动机**：长期运行的 LLM 助手与智能体需要在无终止信号的场景下持续交互，历史总长度由交互生命周期决定，没有理论上限。随着历史增长，模型的工作上下文（working context）必然被替换或淘汰。
- **现有方法的不足**：RAG 类系统、摘要、上下文保留等方法本质上属于“重构式推理”（reconstructive inference），通过读取显式的历史表示来重建工作状态，类似于“记事本”式的持久存储，但它们无法在上下文更换时维持一个持续存在的、贯穿整个生命周期的内在状态。
- **关键问题**：如何让语言模型在上下文更替（context turnover）时保持状态连续性？即：当历史信息离开注意力窗口后，模型是否仍能通过一个固定的、独立于活动上下文的记忆状态来承载并利用这些信息？
- **核心贡献**：论文提出了“状态连续性”（state continuity）这一缺失的推理能力抽象，并将其与外部检索系统定性为互补而非竞争关系——检索决定“读什么”，持续记忆状态决定“如何维持信息连贯性”。

## 2. 方法论

### 2.1 核心思想
LiveMem 在预训练全注意力 Transformer 的每一层并行附加一个基于 **Gated DeltaNet-2（GDN2）** 的递归记忆分支：
- **主注意力路径**：维持一个有界的 KV 窗口（工作上下文），提供精确的短期访问能力；
- **记忆分支**：用固定容量的递归状态矩阵持续读取和更新历史信息，其寿命独立于活动上下文；
- 两条路径的输入为同一归一化隐藏表示，输出逐层相加后返回主模型。

### 2.2 关键技术细节
- **递归状态更新**：记忆状态按 token 在线更新，更新过程包含三个可学习操作：衰减（decay）、擦除（erase）与写入（write），分别由 log-decay 门，erase gate $b_t$ 和 write gate $w_t$ 控制。核心公式为：
  $$S_t = \mathrm{Diag}(\exp(g_t)) S_{t-1} + k_t (w_t \odot v_t - S_{t-1}^\top (b_t \odot k_t))^\top$$
  实质上实现了带遗忘与擦除机制的 delta-rule 线性注意力更新。
- **上下文更替机制**：输入按块（chunk）顺序处理，系统提示词作为 attention sink 始终保留；其他块通过 FIFO 队列管理，当块数或总 token 数超过阈值时淘汰最旧块。被淘汰块的 KV 从注意力中释放，但信息已写入记忆状态。
- **训练-推理一致性**：训练时用动态注意力掩码模拟淘汰，推理时直接释放 KV 页，保证两种阶段行为一致。
- **记忆导向后训练**：包含两阶段：
  1. **SFT**：先用长文档 QA 数据冷启动以激活记忆分支，再用包含 QA、分类、多问任务的重平衡数据继续训练。损失只在答案 token 上计算。
  2. **RL**：使用 GRPO 算法并引入 DAPO 实践（clip-higher、token 级损失、动态采样、去 KL），奖励函数基于多问题准确率、全对奖励和格式惩罚。
- **参数初始化**：记忆分支的 q/k/v 投影从主干注意力投影初始化，输出投影零初始化，从而开始时等价于原模型。

## 6. 主要结论与发现

- LiveMem 在 **Wiki QA 和 Long QA 套件上取得最优**，在 Conversation 与 TTL 上位居第二，综合表现显著超过所有基线。
- 在多问（MQ）任务上，现有方法性能急剧下降，只有 LiveMem 保持领先，说明其记忆状态能同时承载多条逻辑链。
- LongMemEval 证据完全移出窗口时，LiveMem 比无记忆基线（Qwen3-4B、δ-Mem）高出 **10 个百分点以上**，证明记忆状态确实承载了被淘汰的历史信息。
- 证据渐远实验显示：准确率随距离增加仅有轻微下降，说明 GDN2 的遗忘机制虽有影响，但关键证据仍能在记忆状态中长期保留。
- 消融实验表明：全参数训练侧路径优于 LoRA；长文本数据冷启动 + 重平衡数据正式训练的课程安排效果最佳。
- NIAH 测试承认：LiveMem 无法精确恢复任意细粒度 token 级信息，记忆是有损压缩，而不是无损归档。

## 7. 优点

- **问题抽象新颖**：将“状态连续性”从检索、摘要等外部记忆手段中独立出来，定位为生命周期尺度的推理能力，概念界定清晰。
- **端到端设计完整**：从架构（GDN2 旁路）、训练（上下文更替约束 + 两阶段后训练）、到服务（分页状态管理与 KV 释放）形成一致闭环，强调训练-推理一致性。
- **实验设计细致**：不仅报告平均指标，还专门设计了“证据完全移出/部分移出”“证据-窗口距离”等针对性分析，直接验证记忆状态是否真的在承载信息，而非仅依赖注意力。
- **客观坦诚**：明确报告了哪些任务上不占优、NIAH 上的失败，以及有损状态的定位，没有过度宣称“无限上下文”。
- **工程实现严谨**：FlexAttention 掩码、分页 KV、固定步长策略等细节完备，可复现性好。

## 8. 不足与局限

- **有损记忆非精确归档**：NIAH 类任务中，当证据完全移出 32K 窗口后，LiveMem 与无记忆基线得分相同（约 0.19-0.23），无法恢复任意细粒度 token。论文承认需要与检索系统或外部存储结合才能实现精确召回。
- **位置编码天花板**：基座 Qwen3 使用 RoPE，最大位置配置 262,144 tokens，实验最多只处理 256K 输入，并非字面意义的“无限上下文”；跨越该范围需要位置外推，质量无保证。
- **部分对比公平性存疑**：Context2LoRA 在 TTL 上直接微调文本-标签对，与其原论文的记忆假设不完全一致，可能高估了其在该套件上的表现；Recurrent 基线的记忆更新依赖模型自提取，其效果受基础模型能力影响较大。
- **训练排除了主干参数**：主路径 LoRA 训练被观察到可能“吸收”本应导向侧路径的记忆，说明主干与记忆分支间的分工仍需更深入的机制性研究。
- **未报告长对话多会话场景**：实验集中在单条长流内的连续性，跨会话、跨任务长期演化场景未充分覆盖。
- **算力需求不低**：SFT 需 16 张 A800 处理 64K 长包，RL 另需独立 rollout 与法官服务，资源门槛较高，未报告总训练时间。
