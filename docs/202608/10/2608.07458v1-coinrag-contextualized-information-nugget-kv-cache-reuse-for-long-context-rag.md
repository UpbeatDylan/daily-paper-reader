## 摘要
近期针对检索增强生成（RAG）的优化研究利用块级KV缓存复用来避免处理冗长的检索上下文以提高效率，但粗粒度块中仍存在显著的信息冗余和噪声。本文提出CoinRAG（面向长上下文RAG的上下文信息碎片KV缓存复用），在低预填充延迟约束下优化帕累托前沿，同时最大化准确性。该名称隐喻地反映了我们的核心机制：就像将小代币（或“硬币”）组合起来以积累更大价值一样，CoinRAG以组合方式复用离线计算的细粒度碎片缓存，以更语义相关且紧凑的方式高效地形成学习到的上下文表示。具体而言，CoinRAG不进行全块编码，而是通过两阶段检索识别检索块中与查询相关的语义单元，并将其切片KV表示与块级上下文无缝组装。在LongBench多跳问答任务上的广泛评估表明，CoinRAG显著降低了运营成本，并在标准快速预填充延迟预算下实现了新的帕累托前沿，答案质量（F1）平均相对提升5.3%，优于其他基线。

## Abstract
Recent optimization studies on Retrieval-Augmented Generation (RAG) have exploited chunk-level KV cache reuse to avoid processing long retrieved contexts for higher efficiency, while significant information redundancy and noise still remain in the coarse-grained chunks. This paper optimizes the Pareto frontier under low prefill latency constraints while maximizing accuracy by proposing CoinRAG (Contextualized Information Nugget KV Cache Reuse for Long-Context RAG). The name metaphorically reflects our core mechanism: much like assembling small tokens (or "coins") to accumulate a larger value, CoinRAG compositionally reuses offline-computed, fine-grained nugget caches to form a learned contextual representation efficiently in a more semantically relevant but compact manner. Specifically, instead of full-chunk encoding, CoinRAG identifies query-relevant semantic units within retrieved chunks through two-stage retrieval and seamlessly assembles their sliced KV representations with a chunk-level context. Extensive evaluations on LongBench multi-hop question answering tasks demonstrate that CoinRAG significantly reduces operational costs and outperforms the other baselines with a new Pareto frontier and an average 5.3% relative improvement in answer quality (F1) under a standard fast prefill latency budget.

# CoinRAG：面向长上下文RAG的上下文信息碎片KV缓存复用

## 1. 核心问题与研究动机

- **问题背景**：检索增强生成（RAG）在问答、知识密集型任务中广泛应用，但传统 RAG 需要在推理时对检索到的长文本块进行完整在线编码，导致 **prefill 延迟高、计算冗余大**，难以满足交互式服务（如 P99 延迟低于 100ms）的 SLA 要求。
- **已有方案的不足**：
  - 现有 KV 缓存复用方法（如 TurboRAG、CacheBlend、KVLink）大多基于**块级（chunk-level）**缓存，虽然避免了对全文重新编码，但粗粒度块中包含大量与查询无关的冗余信息和噪声，容易导致注意力稀释，且上下文长度依然较长。
  - 已有的基于信息碎片（nugget）的 RAG 方法（如 GINGER、Crucible）通常在线用 LLM 生成孤立 nugget，既增加延迟，又失去原始文档上下文，且不支持 KV 缓存复用。
- **核心目标**：在低延迟（P99 ≤ 100ms）约束下，通过**更细粒度的语义单元**（信息碎片）进行 KV 缓存复用，在压缩上下文长度的同时最大化答案准确性，从而建立新的精度-效率帕累托前沿。

## 2. 方法论：CoinRAG

### 2.1 核心思想
将每个文档块离线编码为完整 KV 缓存后，在线仅选择与查询相关的**信息碎片（nugget）**，通过切片对应 KV 缓存并拼接，形成紧凑的上下文前缀，避免对全块或全文重新编码。

### 2.2 关键技术组件

- **离线碎片提取（Offline Nugget Extraction）**：
  - 使用 LLM（如 GPT-4o-mini）从每个 512 token 的块中提取候选碎片（文本跨度）。
  - 通过三段式匹配将候选碎片映射回原块中的 token 区间：**精确匹配（Stage A）**→ **模糊匹配（Stage B，基于词级窗口相似度，阈值 τ=0.7）**→ **丢弃（Stage C）**。
  - 每个碎片最终表示为 `(chunk_id, start_index, end_index)`，便于后续切片 KV 缓存。

- **两阶段在线检索（Two-Stage Retrieval）**：
  - **第一阶段**：用稠密检索器（BGE-M3）从语料库中检索 top-kc 个候选文档块。
  - **第二阶段**：仅在这些候选块内部，基于嵌入相似度对预先提取的碎片排序，选出 top-k 个查询相关碎片。
  - 该策略缩小候选池、减少噪声，提高了检索精度。

- **上下文化的 KV 缓存切片与组合（Contextualized KV Cache Composition）**：
  - 利用碎片在源块中的 token 区间 `[start, end]` 直接切片预计算的块级 KV 缓存 `C_b[start:end]`，从而保留完整的文档上下文语义（优于对孤立碎片重新编码）。
  - 对不同源块的碎片进行 RoPE 位置旋转 `Rot(C; Δ)`，采用**保序连续位置对齐**，消除位置不匹配，并将系统提示 KV 与多个碎片缓存拼接成统一前缀缓存。

- **碎片感知微调（Nugget-Aware Fine-tuning）**：
  - 为了使模型适应“非连续拼接”的上下文结构，在训练时使用与推理相同的碎片拼接流程构造输入，优化标准交叉熵损失，缩小训练-推理分布差距。

### 2.3 形式化流程
- 标准 RAG：`KV = M(prompt ⊕ chunks ⊕ q)`（在线全量编码）
- CoinRAG：`KV = C_ctx ⊕ M(q; C_ctx)`，其中 `C_ctx` 为离线缓存切片拼接后的前缀，仅对查询 q 进行轻量在线处理。

- **在 P99 ≤ 100ms 延迟预算下**：
  - CoinRAG 在所有 3 个数据集上取得最高 F1，平均 F1 达 **41.7**，相对最强基线 TurboRAG（39.6）提升 **5.3%**。
  - 上下文长度比 TurboRAG 缩短 1.84 倍，即用更少 token 获得更高精度。
- **在无延迟限制时**：

- **在上下文长度预算固定时**：
  - CoinRAG 始终取得更高 F1，最长上下文比 Standard RAG 缩短 10.1 倍。
- **消融结论**：
  - 上下文碎片 KV 切片比孤立编码 F1 高 3.9–6.3 分，验证保留文档上下文的重要性。
  - 两阶段检索比单阶段检索相对 F1 提升 9.6%–17.5%，且选出的碎片更少。
  - 位置对齐在紧预算（P99 < 75ms）下提升明显（F1 相对 +3.0%–8.5%），预算宽松时影响不大。
  - 碎片感知微调显著提高峰值 F1（+6.3 到 +11.3 分），是弥合训练-推理差距的关键。

## 7. 优点与亮点

- **粒度创新**：首次将 KV 缓存复用粒度从“块”推进到“信息碎片”，兼顾语义精细度和缓存复用效率。
- **上下文保持**：通过切片原块 KV 而非孤立编码碎片，保留了文档级上下文，显著优于先前 nugget 方法。
- **延迟-精度双重优化**：在不牺牲甚至提升精度的前提下大幅压缩上下文，形成新的帕累托前沿。
- **工程实现细腻**：包括两阶段检索、位置旋转对齐、离线存储格式优化、异步 I/O 等，实用性强。
- **实验分析深入**：提供成功/失败案例分类（如表面词频误导、检索失败等），有助于理解方法边界。

## 8. 不足与局限

- **离线成本与静态假设**：预编码大量文档需要较大磁盘存储和一次性计算成本；假设文档很少更新，不适应频繁变化的语料。
- **模型耦合性**：缓存的 KV 与具体模型权重绑定，更换骨干模型必须重新编码全部文档。
- **检索召回瓶颈**：如果初始检索（块级/碎片级）未召回关键证据，则无法补救，答案质量受限于检索上限。
- **跨块注意力缺失**：碎片来自不同块时互不交互（与 TurboRAG 类似），可能损失跨文档推理能力；与 KVLink 或 CacheBlend 结合可作未来方向。
- **评估范围局限**：仅覆盖 3 个 LongBench 多跳 QA 数据集，未验证对话/重复查询场景；未评估模型规模变化的影响。
- **公平性细节**：虽然与基线相同训练数据，但各方法训练机制不同，可能影响对比绝对公平；未研究在线缓存容量充足时的跨查询复用（与基线一致的假设，但应用场景受限）。
