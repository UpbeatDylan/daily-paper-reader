## 摘要
键值（KV）缓存是长上下文大语言模型推理中的主要内存瓶颈。现有方法从两个相反方向入手：逐出方法永久丢弃令牌，一旦被丢弃的令牌后来被证明至关重要，就会降低性能；而量化方法虽然以低精度保留所有令牌，但提供的压缩有限。我们提出AnchorKV，一种压缩方案，可将缓存缩小20倍而不丢弃任何单个令牌。AnchorKV使用一小部分精确存储的锚点来表示缓存，通过每个其他令牌与最相似锚点的关系来表达它，并且仅细化那些近似值对模型输出影响最大的令牌。AnchorKV在模型和数据集上持续保持准确性，在70B规模下保留了完整缓存得分的99%，同时以极低的成本保留整个上下文。

## Abstract
The key-value (KV) cache is the primary memory bottleneck in long-context LLM inference. Existing approaches attack it from opposite ends: eviction methods permanently discard tokens, degrading performance whenever a discarded token later proves essential, while quantization methods retain all tokens at low precision but offer limited compression. We propose AnchorKV, a compression scheme that shrinks the cache by $20\times$ without discarding a single token. AnchorKV represents the cache using a small set of anchors stored exactly, expresses every other token through its most similar anchor, and refines only those whose approximation most affects the model's output. AnchorKV consistently preserves accuracy across models and datasets, retaining 99% of the full-cache score at the 70B scale, while keeping the entire context at a fraction of its cost.

## 论文总结：AnchorKV——锚点残差KV缓存压缩

### 1. 核心问题与研究动机

长上下文推理已成为大语言模型的主流使用场景，但KV缓存（存储每个token在每个层的key和value）成为主要的内存瓶颈——它随上下文和批次大小线性增长，且在每步解码时都会被完整读取。在128K上下文下，单次Llama-3.1-8B请求的bf16 KV缓存高达16 GiB，与模型权重相当。内存容量决定了设备能处理多少请求以及推理速度。

现有方法存在两个方向的根本矛盾：
- **逐出方法**（如SnapKV、PyramidKV、AdaKV）：打分后保留子集，丢弃其余token。压缩比原则上无上限，但代价是不可逆——一个被丢弃的token在后续查询需要时已无法找回。
- **量化方法**（如TurboQuant）：保留所有token但降低位宽，精度随压缩下降，压缩比被限制在约5倍以内。

AnchorKV的目标是同时实现**高压缩比**与**完整上下文可及性**。

### 2. 方法论：AnchorKV方法详解

#### 2.1 锚点-残差表示

AnchorKV在预填充结束时对每个KV头执行一次性压缩（冻结模型，不改动注意力计算）。核心结构：

- **锚点（Anchors）**：每个KV头选择k个锚点token，其key和value以bf16**精确存储**（始终包含最近W个token的窗口）。
- **投影表示**：每个非锚点token分配到与其方向最相似的锚点，仅存储锚点索引和标量系数γi（投影系数），以几个字节代替完整向量。
- **稀疏残差（Residuals）**：对近似误差影响注意力输出最大的token，额外存储**2比特量化的残差向量**，重建时叠加到锚点投影上。

数学表示：非锚点token xi 用锚点 xa(i) 表示，即 xi ≈ γi·xa(i) + ri，其中ri为残差。存储在残差子集R中的token可恢复为 x̂i = γi·xa(i) + r̃i（r̃i为量化后的残差）。

#### 2.2 关键技术细节

- **锚点选择**：分数 = 观察窗口查询的平均注意力（基于SnapKV机制），取最高分的ρ比例 + 均匀采样的锚点（保证方向覆盖）。key投影在RoPE旋转前进行（实验证明pre-RoPE使锚点余弦中位数提高0.27）。
- **残差效用估计**：基于一阶注意力输出误差近似（公式6），同时考虑key通道（通过注意力权重间接影响输出）和value通道（直接影响输出）， pooling跨所有KV头分配残差预算。
- **残差量化**：随机Hadamard旋转 + 逐token归一化 + Lloyd-Max 4级码本，每个残差约D/4字节。
- **字节预算**：用户只需设置保留比例θ（唯一超参数），精确字节核算决定每层的残差数量，K/V各得一半预算。
- **解码实现**：FlashAttention风格的分块核函数，按需重建key/value，不物化稠密缓存。

### 6. 主要结论与发现

1. **20×压缩下精度接近全缓存**：在Llama-3.1-70B上，20×压缩保留RULER的99.3%精度（94.4 vs 95.0），最强基线仅86.8%。
2. **准确性与压缩比"跷跷板"效应**：AnchorKV在20×下的得分超过所有逐出基线在10×下的得分——**同一精度只需一半内存**。
3. **模型规模越大，压缩越有效**：RULER-32K 20×下，8B保留93.5%，24B保留95.3%，70B保留99.3%，正对缓存最昂贵的场景。
4. **逐出方法的失败模式被揭示**：逐出基线在需要"去干扰物检索"（cwe）和"全上下文聚合"（fwe、multikey_3）的任务上崩溃，准确率低于16%；AnchorKV在这些任务上超越最强基线45-88个百分点。
5. **Needle-in-a-Haystack验证完备性**：5×压缩下AnchorKV平均0.94（全缓存0.99），而AdaKV仅0.18——几乎在绝大多数位置都能找回passkey。
6. **系统效率实际可行**：解码峰值内存降低19×，64K以上延迟与全缓存持平或更快，并发能力约翻倍。

### 7. 方法优点

- **范式创新**：将"是否保留"的二元决策变成"如何分配字节"的连续决策，token永不真正离开softmax，压缩后的缓存是精确缓存的**扰动**而非**截断**。
- **理论保障完备**：给出输出误差界（Theorem 1），明确key/value通道的不同误差结构（最坏情况 vs 注意力加权平均），并证明锚点残差形式天然控制每个token的误差。
- **超参数极简**：仅θ（保留比例）为用户暴露参数，其余固定——工程部署成本低。
- **通用性与尺度友好**：三个模型尺度一致表现良好，且效果随模型增大而提升。
- **效率工程扎实**：三核Triton实现，避免物化稠密缓存，线性代数（Hadamard逆变换的线性性）被充分利用，使残差贡献变换从每次token一次变为每步一次。
- **消融有深度**：不仅验证标准方法学，还分析残差预算的实际分配模式（非均匀、逐层变化），并直接测量注意力输出保真度——定位方法真正优化的目标。
- **对手方法评估透明**：对TurboQuant社区复现的偏差予以披露，说明其与论文原始方案的差异。

### 8. 不足与局限

- **实验维度仍有空白**：未包含多语言基准、更长上下文（>128K）或更完整的批量（batch>4）推理场景验证。
- **70B模型实验较少**：仅有RULER-32K/64K和LongBench各一组（表13-15），缺少96K以上的验证；且数量远少于8B模型。

- **对"观察窗口"假设的依赖**：残差分配假设最近查询需要的token就是解码将需要的，虽然错误后果比逐出温和（仅更粗略存储），但极端情况下仍有精度损失。

- **融合核函数与框架绑定的部署限制**：需要特定的Triton实现，现有推理框架（vLLM等）直接集成有迁移成本。
