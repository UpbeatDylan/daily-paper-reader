## 摘要
本文提出了一种异构解码阶段服务系统，将KV缓存从GPU内存中迁移出去，其动机是近期前沿大语言模型为处理百万级token上下文而采用的检索型稀疏注意力机制。该系统按操作类型划分解码步骤：GPU节点持有模型权重并执行投影和MoE层，而近内存处理（PNM）节点持有KV缓存和索引键，并执行所有读取它们的操作。我们首先表明，先前PIM和PNM设计背后的假设对这些操作不再成立，并为此类节点推导出四项设计要求。基于这些要求，我们提出了KARAT（面向检索型注意力的KV缓存驻留加速器），这是一种通用的PNM设计，是满足全部四项要求的设计点。KARAT设备将大容量LPDDR与适用于检索索引器的通用计算相结合，服务于超越为低强度GEMV构建的PIM/PNM设计所针对的操作强度，同时容纳固定功能单元在演进过程中无法支持的多样化稀疏注意力算法。为了减少两种设备类型在微批次之间交替时产生的流水线气泡，我们进一步提出了机会式细粒度微批次调度（OFMS）和上下文长度感知的微批次再平衡（CMR），前者将专家全对全通信隐藏在另一微批次的GEMM之后，后者在上下文长度变化的情况下均衡它们的令牌数量。在三种最先进的模型和真实代理轨迹上，我们提出的系统在服务水平目标下的每TDP吞吐量比纯GPU基线提高了2.09-6.13倍，并以1.36-3.21倍的提升运行免训练的稀疏注意力方法。

## Abstract
This paper presents a heterogeneous decode-phase serving system that relocates the KV cache out of GPU memory, motivated by the retrieval-based sparse attention that recent frontier LLMs adopt to serve million-token contexts. It partitions a decode step by operation type: GPU nodes hold the model weights and execute the projections and MoE layers, while processing-near-memory (PNM) nodes hold the KV cache and index keys and execute every operation that reads them. We first show that the assumptions behind prior PIM and PNM designs no longer hold for these operations, and derive four design requirements for such a node. From these requirements, we propose KARAT (KV-cache-resident Accelerator for Retrieval-based ATtention), a general-purpose PNM design that is the design point meeting all four. A KARAT device combines large LPDDR capacity with general-purpose compute sized for the retrieval indexer, serving an operational intensity beyond what PIM/PNM designs built for low-intensity GEMV target while accommodating diverse sparse attention algorithms that fixed-function units cannot support as they evolve. To reduce pipeline bubbles as the two device types alternate between micro-batches, we further propose opportunistic, fine-grained micro-batch scheduling (OFMS), which hides expert all-to-all behind the other micro-batch's GEMMs, and context-length-aware micro-batch rebalancing (CMR), which equalizes their token counts despite the variance in context length. Across three state-of-the-art models and real agentic traces, our proposed system improves throughput per TDP under a service-level objective by 2.09-6.13x over a GPU-only baseline and runs training-free sparse attention methods with 1.36-3.21x improvements.

## 1. 论文的核心问题与整体含义（研究动机和背景）

- **研究动机**：随着大语言模型（LLM）在 Agentic 工作负载（如多轮工具调用、编码代理）中的广泛部署，上下文长度急剧增长，真实轨迹的 P99 上下文长度可达 198K–791K token（最大约 1M），且每轮解码都要对整个上下文做注意力计算。KV 缓存规模和读取带宽成为解码阶段的瓶颈。
- **容量瓶颈**：单个百万 token 请求的 KV 缓存和索引键合计占 78–137 GB；配有 1.1–1.4 TB HBM 的 8-GPU 节点同时还要容纳数百亿参数的 MoE 模型，导致能并发服务的请求数极少，MoE 层因批大小过小而无法摊销权重读取（权重读取占总解码时间 58–74%）。
- **检索型稀疏注意力的特殊性**：前沿模型（GLM-5.2、DeepSeek-V3.2、MiniMax-M3）采用检索型稀疏注意力，将每步读取的数据量从 O(L) 降至 O(k)，但**并未减小存储足迹**——全部 KV 对和逐 token 索引键仍需驻留。
- **既有方案失效**：
  - 将 KV 缓存卸载到主机/CXL 内存只扩展容量，O(L) 的索引扫描仍需跨越带宽受限的链路；
  - 既有 PIM/PNM 设计（如 AttAcc、Duplex）是为低操作强度（OI）的稠密 MHA/GQA 和固定功能形式而构建的，无法匹配检索型稀疏注意力 4–128 FLOPs/byte 的 OI 范围，也不能适应算法形态的快速演化。
- **核心含义**：需要一个在固定功率预算下同时满足容量、带宽、计算和通用性四项要求的异构服务系统——GPU 持有权重执行投影与 MoE，PNM 节点持有 KV 缓存并执行所有读取它们的操作。

## 2. 论文提出的方法论：核心思想、关键技术细节

### 2.1 总体架构

- 提出**异构解码阶段服务系统**，在预填充–解码分离架构下，按操作类型划分工作：
  - **GPU 节点**：持有模型权重，执行 QKV 投影、输出投影和 MoE 层；
  - **KARAT 节点**：持有 KV 缓存和索引键，执行索引器扫描（Score & Select）、Gather 和 Attend。
- 每层解码中，GPU 与 KARAT 通过流水线并行（微批次交替）协同工作。

### 2.2 KARAT 设备设计

- **四项设计需求**（源自观察 O1–O5）：
  - **R1 容量**：容量/瓦比 HBM 高一个数量级，使批次 KV 缓存和索引键驻留；
  - **R2 带宽**：带宽/瓦与 HBM 相当，且与索引键同址；
  - **R3 计算**：脊点（ridge point）高于索引器扫描的 OI（4–128），避免计算瓶颈；
  - **R4 通用性**：核心可编程，覆盖表 I 中所有操作形式，支持算法演化。
- **关键硬件参数**：
  - 采用 **LPDDR5X-9600**，512 GB 容量、1.2 TB/s 带宽（容量/瓦为 HBM3 的 19 倍，带宽/瓦为 0.8 倍）；
  - 集成 **18 个 GPNM 核心**（GPU SM 类似物），FP8 250 TFLOPS / BF16 125 TFLOPS，脊点 208 FLOPs/byte；
  - 15 MB L2 缓存；PCIe ×4 接口；TDP 175 W（H200 的 1/4）；
  - 芯片面积约 286 mm²，其中 LPDDR5X PHY 和内存控制器占 58%。
- **KARAT 节点**：32 个 KARAT 设备 + PCIe/CXL 交换机 + 主机 CPU；与 8-GPU 节点等功率（5.6 kW）、等聚合带宽（38.4 TB/s），但容量为 16 TB（14 倍）。

### 2.3 调度与优化技术

- **OFMS（机会式细粒度微批次调度）**：
  - 解决静态粗粒度调度（SCMS）中专家全对全通信阶段 GPU 空闲的问题；
  - 当 ATTEND 完成且 GPU 因等待另一微批次的 MoE combine 而空闲时，立即启动该微批次的输出投影，进而重叠 MoE dispatch 与另一微批次的 QKV 投影；
  - 完全分布式实现，无全局调度器，按运行时延迟动态决策，不差于 SCMS。
- **CMR（上下文长度感知的微批次再平衡）**：
  - 当请求完成或新请求被接纳时，按 KARAT 设备分组、以上下文长度降序排序，将请求贪心分配给累计上下文长度较小的微批次；
  - 只在逻辑上改变请求所属微批次，不移动 KV 数据，开销极低。

### 2.4 系统配置搜索

- 在等功率约束下，对 GPU 与 KARAT 设备数比例、MoE 专家并行度、注意力张量并行度进行穷举网格搜索，选择满足 P99 TBT SLO 的最大吞吐配置。

## 6. 论文的主要结论与发现

- **模型原生稀疏注意力**：KARAT 在全部 9 组（3 模型 × 3 轨迹）中达到最高每 TDP 吞吐量，为 GPU-only 的 **2.09–6.13 倍**（几何平均 2.23 倍），优势随上下文长度增长而扩大（KVCT 上最大）。
- **免训练稀疏注意力**：KARAT 以 **1.36–3.21 倍** 的速度提升运行三种免训练方法而无需硬件改动，其中 MagicPIG（SPNM 完全无法加速）收益最大。
- **稠密注意力**：KARAT 取得 1.24–1.32 倍提升，低于专门为低 OI GEMV 设计的 AttAcc（1.79–2.05 倍），符合设计定位。
- **调度技术**：关闭 OFMS 使吞吐量平均下降 16%；关闭 CMR 平均下降 5%（DeepSeek-V3.2+KVCT 上高达 21%），两项技术均显著提升 GPU 和 KARAT 利用率。
- **容量 ≠ 性能**：SPNM 与 KARAT 容量相同但计算不足，在 GLM-5.2 和 DeepSeek-V3.2 上低于 GPU-only，说明必须同时满足容量与计算需求。
- **EP 度选择变化**：引入 KARAT 后最优 EP 度从 64 降至 16–32，专家全对全通信量减少，每 TDP 吞吐量提升 1.7–7.8 倍。

## 7. 优点

- **问题定位精准**：从真实 Agentic 轨迹出发，以数据驱动方式揭示容量瓶颈，并指出既有 PIM/PNM 假设（低 OI、固定注意力形式）的失效，推导出四项有说服力的设计需求。
- **通用性设计**：GPNM 核心 + 可编程架构使同一硬件支撑 DSA、块级选择、页级扫描、聚类、LSH 等多种算法以及未来变体，避免了专用化带来的"过时"风险。
- **硬件–调度协同**：不局限于硬件设计，同时提出 OFMS（机会式重叠）和 CMR（上下文感知均衡）两项轻量级调度技术，直接解决流水线气泡问题，且实现完全分布式、无全局依赖。
- **设计空间探索**：在等功率框架下对设备配比和并行度做系统搜索，展示了系统级配置对端到端性能的重要影响。
- **评估严谨**：对基线参数做了明确说明和有利假设，敏感性分析覆盖链路带宽/延迟/核心数，偏斜负载与 EPLB 的讨论增强了结论的鲁棒性。

## 8. 不足与局限

- **模拟而非全系统实现**：论文依赖自研制模拟器（事件驱动 + LUT + ASTRA-sim），KARAT 延迟通过 MIG 缩放估计，未在真实硅片上验证，面积/功耗估算（GH100 面积拆解 + LPDDR PHY 估算）也可能与流片结果存在偏差。
- **模型覆盖有限**：仅评估了 3 种模型原生稀疏注意力模型 + 1 个基础模型（LLaMA3-70B）用于免训练方法；对更大规模（如 1T+ 参数）或不同架构族（如纯稠密注意力 + 检索）的泛化性未验证。
- **免训练方法的代表性时序**：Quest、STARC、MagicPIG 是评估时点的方法，且 MagicPIG 在 GPU 上运行已优于 CPU，其结论可能随算法演进而改变。
- **网络模型简化为关键假设**：GPU–KARAT 链路带宽/延迟敏感性表明影响较小，但实际数据中心网络中多租户竞争、拥塞控制等因素未建模。
- **功率/成本分析有限**：只报告了每 TDP 吞吐量，未讨论每美元吞吐量、部署成本、LPDDR 与 HBM 的价格差异、制冷等运维成本。
- **负载均衡假设**：主实验假设 MoE 路由均匀（论文后段讨论偏斜但未做全矩阵分析），且未考虑 KV 迁移、请求优先级、多租户隔离等生产环境问题。
- **时间假设**：文中模型（GLM-5.2、DeepSeek-V3.2、MiniMax-M3）为较新模型的规格，与论文发表时间的实际可用性可能不完全一致。
