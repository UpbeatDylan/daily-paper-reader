## 摘要
长上下文推理受到键值缓存随序列长度线性增长的制约，从而影响大型语言模型的应用。虽然剪枝技术可以提供缓解，但现有方法通常确定特定查询的令牌重要性，这种重要性无法在未见过的查询中复用。为此，我们提出了TaskPress，一个用于任务引导、查询无关的KV缓存驱逐的框架。TaskPress不是针对单个查询优化缓存，而是根据高层任务指南构建一个可复用的记忆表示。该指南在预填充阶段充当元查询，以在下游查询发出之前过滤不相关的令牌。此外，TaskPress利用量化缩放因子作为检测有影响力表示离群值的零成本信号，为令牌重要性提供高效代理。在具有长上下文输入的各种任务上进行的实验表明，TaskPress能够高效地创建紧凑且可复用的缓存，适用于各种查询。

## Abstract
Long-context inference with large language models is constrained by the linear growth of the key-value cache to sequence length. While pruning offers mitigation, prevailing methods determine query-specific token importance that cannot be reused across unseen queries. In contrast, we introduce TaskPress, a framework for task-guided, query-agnostic KV cache eviction. Instead of optimizing the cache for a single query, TaskPress constructs a reusable memory representation conditioned on a high-level task guide. The guide functions as a meta-query during prefill to filter irrelevant tokens before downstream queries are issued. In addition, TaskPress leverages quantization scale factors as a zero-cost signal for detecting influential representation outliers, providing an efficient proxy for token importance. Experiments on conducted on various tasks with long context input demonstrate that TaskPress efficiently creates a compact, reusable cache across diverse queries.

# TaskPress 论文详细总结

## 1. 论文的核心问题与整体含义

- **研究背景**：大型语言模型（LLM）的长上下文推理能力（如支持 2M tokens）依赖 Transformer 中的键值（KV）缓存，但 KV 缓存随序列长度线性增长，常超过模型权重，造成严重的内存/吞吐瓶颈。
- **现有方法不足**：
  - 剪枝方法（如 SnapKV、PyramidKV）按具体查询计算 token 重要性，得到的是“查询相关”的压缩缓存，无法跨查询复用，多轮/多查询场景下需重复预填充。
  - 上下文重建方法（如 KVZip）虽支持多查询，但会将提示长度翻倍，产生 O(Lc²) 的二次计算开销。
- **核心问题**：如何实现**查询无关**的 KV 缓存压缩，使压缩后的缓存可被同一任务下的未来多个查询重复利用，同时保持低开销。
- **论文的整体含义**：提出 TaskPress，将 KV 剪枝从“查询时”解耦到“任务时”，以任务指南作为元查询，构建可复用的压缩缓存，兼顾效率与可复用性。

## 2. 论文提出的方法论

- **核心思想**：用一个高层任务指南（Task Guide）作为“元查询”，在预填充阶段计算该指南与上下文的注意力，过滤掉无关 token，从而生成与具体查询无关的紧凑缓存。
- **任务引导的关键重要性（Key Importance）**：
  - 将任务描述（长度 Lt）附加到上下文（长度 Lc）后，取任务 token 与上下文 token 之间的注意力矩阵 A ∈ R^(Lt×Lc)。
  - 对 Lc 方向做 1D 平均池化（核大小 K），得到第 i 个 context token 的任务引导分数：
    - skey_i = (1/K) Σ_{k=-⌊K/2⌋}^{⌊K/2⌋} Σ_{j=1}^{Lt} A_{j, i+k}
  - 该分数仅反映 Key 的可检索性。
- **量化尺度作为 Value 重要性**：
  - 自注意力输出是 value 的加权和，因此 value 的幅值也重要。
  - 利用 per-token 量化中的尺度因子 γi = max(|vi|) / (2^(b-1) - 1)，因位宽 b 固定，γi 正比于 token 最大绝对值，作为零成本的离群值分数 svalue_i = γi。
  - 优点：量化是服务端标配，尺度因子已存在，无需额外计算。
- **KV 重要性评分**：
  - 最终保留分数为两者乘积：si = skey_i · svalue_i
  - 要求 token 既要被任务引导的注意力“发现”，又要有丰富的语义信息。
- **任务指南构建**：
  - **零样本初始化**：用现成的 LLM（如 Gemini）对任务生成 2–3 句话的指南，作为强基线。
  - **进化式引导发现（Algorithm 1）**：对未知/动态任务，从少量校准查询中推断意图，通过变异/交叉不断迭代优化任务指南（保留 Top-K、生成新候选、评估校准集上的准确率）。
- **整体流程**：预填充时附加任务指南 → 用指南评分对 KV 缓存做驱逐 → 丢弃指南，仅保留压缩缓存 → 后续查询直接复用它生成。

- TaskPress 在 LongBench 上总体平均准确率优于所有基线（如 LLaMA-3.1-8B 上 50% 驱逐时为 46.42，超越 KVZip 的 44.76；75% 时为 43.08，显著高于其他方法）。

- 任务指南的措辞变化、生成模型、粒度对准确率影响较小（标准差低），说明方法鲁棒。

## 7. 优点

- **查询无关**：真正支持跨查询复用 KV 缓存，避免多轮/多查询下的重复预填充，是概念上的重要创新。
- **零成本信号**：复用现成量化尺度因子检测离群值，无需额外推理开销。
- **任务指南可进化**：结合遗传式提示优化，适用于未知/动态任务的部署。
- **模块化设计**：可与其他剪枝策略（如 ThinK）叠加，取得更好效果。
- **效率突出**：驱逐开销 O(Lt·Lc) 远低于 KVZip 的 O(Lc²)，文中给出 80× 延迟提升；预填充阶段 75% 驱逐时 TTFT 仅增加 1.2%。
- **实验较全面**：覆盖多类任务、多个模型、多种消融，并分析了多查询端到端收益。

## 8. 不足与局限

- **任务依赖**：压缩缓存针对任务指南的语义范围优化，若用户查询发生显著任务漂移（如摘要中问代码问题），性能可能严重下降（表 13 显示跨任务指南会导致准确率下滑）。
- **极度密集信息场景**：在 RULER MK-2/MK-3 的“针堆中找针”任务中，因大量相似目标导致注意力稀释，单目标分数低于背景噪声，缓存驱逐失效；论文承认这种人工极端密度在现实任务中较少见，但仍是明显弱点。
- **依赖量化统计**：方法默认 KV 已做 int4 量化并留有尺度因子；全精度（FP16/BF16）下需要临时计算绝对最大值，虽开销可忽略（约 0.26 秒），但并非完全零成本。
- **实验局限**：未验证更大模型（如 70B+）和不同架构；RULER 50% 驱逐时不及 KVZip，说明在中等压缩率下仍有差距；进化式任务指南依赖校准集和外部 LLM API，可能引入额外运行成本。
- **公平性风险**：部分基线的设置采用了近似的查询替代（如最后上下文片段），可能与 TaskPress 的“任务指南”不完全对等，论文虽补充了真实查询对比，但对读而言仍需谨慎看待总体平均的领先幅度。
