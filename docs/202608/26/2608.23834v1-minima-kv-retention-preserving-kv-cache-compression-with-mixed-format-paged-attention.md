## 摘要
键值（KV）缓存是长上下文大语言模型服务中的主要容量和带宽瓶颈。我们提出了Minima-KV，一种用于混合格式分页注意力的保留性层级结构。近期且受保护的Anchor页保留在FP8中，而较旧的非Anchor页转换为紧凑的TQ3格式；每个活跃请求页仍然保持可寻址。特定格式的内核计算部分注意力状态，并通过全局归一化的在线softmax合并将其组合，从而实现直接的异构解码，而无需缓存大小的稠密影子。在单个96GB NVIDIA RTX PRO 6000 Blackwell GPU上，针对独立的、配置绑定的Qwen3.6-27B配置文件，部署核算报告每个活跃token的注意力KV为18.3 KiB，相对于BF16对应3.50倍压缩，相对于FP8为1.75倍。一个物化质量配置在16K RULER大海捞针任务上与其密集控制相匹配。在相同的503道题的LongBench v2测试集上，在16K、32K和64K下测得的差异分别为-0.80、-0.60和-0.40个百分点。一个独立的单对直接解码金丝雀测试，包含两个59,008-token请求，相对于其对照组，测得3.625倍活跃KV压缩和0.9821倍吞吐量，所有16个全注意力层均无回退路由，且不保留稠密影子。这些结果建立了一条实用的混合格式路径，用于压缩长上下文状态而不驱逐活跃请求的KV页。

## Abstract
The key-value (KV) cache is a primary capacity and bandwidth bottleneck in long-context LLM serving. We present Minima-KV, a retention-preserving hierarchy for mixed-format paged attention. Recent and protected Anchor pages remain in FP8, while older non-anchor pages move to packed TQ3; every live-request page remains addressable. Format-specific kernels compute partial attention states and combine them through a globally normalized online-softmax merge, enabling direct heterogeneous decode without a cache-sized dense shadow. Across separate, configuration-bound Qwen3.6-27B profiles on a single 96-GB NVIDIA RTX PRO 6000 Blackwell GPU, deployment accounting reports 18.3 KiB of attention KV per live token, corresponding to 3.50x compression relative to BF16 and 1.75x relative to FP8. A materializing quality profile matches its dense control on 16K RULER needle-in-a-haystack tasks. On the same 503-question LongBench v2 set, measured deltas are -0.80, -0.60, and -0.40 percentage points at 16K, 32K, and 64K. A separate single-pair direct-decode canary with two 59,008-token requests measures 3.625x active-KV compression and 0.9821x throughput relative to its control, routes all 16 full-attention layers without fallback, and retains no dense shadow. These results establish a practical mixed-format path for compressing long-context state without evicting live-request KV pages.

# Minima-KV：采用混合格式分页注意力的保留性KV缓存压缩 — 中文总结

## 1. 核心问题与整体含义（研究动机和背景）

- **核心瓶颈**：长上下文 LLM 服务中，KV 缓存大小随上下文长度、批大小和全注意力层数线性增长，成为内存容量和带宽的主要限制因素。PagedAttention 仅解决分配碎片化与缓存共享问题，并未减少每个物理页存储的信息量。
- **现有方法的矛盾**：
  - 均匀量化（如低比特 KV）对所有 token 一视同仁，不区分重要性，效率低；
  - 基于重要性的驱逐（如 H2O、SnapKV）能按需保留重要 token，但未来注意力可能转移到原本不重要的位置，导致信息不可恢复；
  - 低秩/结构化压缩信息密度高，但需要运行时协同设计，避免重建成本超过节约的内存。
- **Minima-KV 的核心思路**：将 KV 状态视为一个**保真度层级**，而非单一精度或二进制保留/删除。它保留所有活跃请求页面可寻址，仅对不同的层级采用不同的物理格式，从而兼顾压缩率、质量和部署简单性。

## 2. 提出的方法论

### 2.1 三层级保留生命周期

- 将每个物理页 `p` 在任意解码步 `t` 分配状态 `z_{p,t} ∈ {Recent(R), Anchor(A), Stale(S)}`。
  - **Recent（FP8）**：新产生的 KV 保存在 FP8 滑动窗口内，保护近期局部推理；
  - **Anchor（FP8）**：受保护的关键旧页面，如系统指令、注意力锚点、检索证据、高注意力权重页面；
  - **Stale（TQ3）**：旧的非 Anchor 页面，采用 3-bit 旋转标量量化（TQ3，受 TurboQuant 启发），包含打包的编码、缩放和元数据。
- 状态转换由控制器策略 `z_{p,t+1}=π(z_{p,t}, a_{p,t}, h_{p,t}, u_t)` 决定，其中 `a` 为注意力统计，`h` 为结构和年龄特征，`u` 为全局利用率。
- 所有权协议保证：目标页构造完成后再发布映射，源页只有在所有读者和转换事件清空后才释放，实现**无驱逐的格式降级/提升**。

### 2.2 混合格式分页注意力（Mixed-Format Paged Attention）

- 核心难点：FP8 和 TQ3 两种物理格式的注意力输出如何合并。
- 方法：每个格式特定核函数计算局部最大值 `m_j`、指数和 `ℓ_j` 和归一化局部输出 `Ō_j`，然后通过**稳定的在线 softmax 递推**合并：
  - `m = max_j m_j`
  - `ℓ = Σ_j e^{m_j - m} ℓ_j`
  - `O = (Σ_j e^{m_j - m} ℓ_j Ō_j) / ℓ`
- 该合并与直接对拼接逻辑缓存做注意力在代数上等价（忽略编解码误差和有限精度）。
- 在直接推理路径中，FP8 瓦片走高保真分支，TQ3 瓦片在加载时解包，不生成 cache 大小的稠密影子缓存。

### 2.3 可选注意力分数反馈

- 支持计算页面级注意力分数，用于将反复被检索的旧页面提升为 Anchor。
- 计算公式涉及局部质量归一化和全局 softmax 权重，但**当前实验均关闭该评分机制**，因此不宣称其有效性和额外开销。

### 2.4 编解码与元数据

- TQ3 存储：3-bit 旋转键编码 + FP16 键范数校正、3-bit 值编码 + FP16 scale/zero 元数据。
- 有效比特率模型：`b_eff = 8(p_R+p_A) + b_S p_S + b_meta`，其中 `b_S` 为 TQ3 实际物理比特率，`b_meta` 为元数据开销。
- 部署核算：每个活跃 token 的注意力 KV 为 **18.3 KiB**，约合 4.58 bits/scalar，相对 BF16 压缩 3.50×，相对 FP8 压缩 1.75×。

## 6. 主要结论与发现

- **压缩率**：部署核算显示每活跃 token 的注意力 KV 为 18.3 KiB，等效 3.497× BF16 压缩和 1.749× FP8 压缩。
- **质量保留**：

- **总体观点**：在不驱逐任何活跃请求 KV 页面的前提下，混合格式层级压缩可以做到接近密集效果的质量和可接受的性能开销，是一种实用的长上下文服务路径。

## 7. 优点

- **保留性设计**：所有活跃逻辑页均可寻址，不存在不可逆删除，避免注意力漂移导致的信息丢失。
- **混合格式软合并**：通过在线 softmax 递推统一 FP8 和 TQ3 的局部输出，无需稠密影子，内存开销低。
- **所有权协议严谨**：copy-before-publish、引用计数、不可变前缀映射等机制保证了并发安全与缓存复用。
- **诚实且透明的报告风格**：论文明确区分“观测值”、“所有者聚合值”、“解析模型”和“外部全栈结果”，并主动说明证据边界与未验证成分，大量“不宣称”表述体现了高度的科学谨慎。
- **丰富的额外信息**：提供了 claim ledger、证据分类、artifact 清单和外部部署报告，便于审稿人审计。

## 8. 不足与局限

- **适用性窄**：仅验证了 Qwen3.6-27B 单 GPU，未覆盖其他架构、非混合模型、多 GPU 张量并行或视觉语言模型。
- **聚合指标不可解释**：18.3 KiB/token 的部署聚合没有按层级（Recent/Anchor/Stale）拆分的字节数，缺乏可复现的配置清单，不能作为跨上下文长度的恒定率指标。
- **性能证据薄弱**：直接解码只有单对，无方差和置信区间；控制组的 KV dtype 未绑定；CUDA 图启用与快速算术质量失败，导致速度和质量的**联合**声明缺失。
- **质量回归不可忽略**：4K RULER 下降 0.9pp，LongBench v2 在多个长度上均有下降，且 32K/64K 只报告差值，未给出绝对正确数。
- **未验证关键机制**：注意力评分反馈路径未测试；格式转换的吞吐量、暂存内存和异步重叠效果未测量。
- **外部全栈混淆**：Rafay/Qdrant 部署报告同时改变权重精度（如 NVFP4）、内核、调度器和 KV 压缩，无法归因性能增量。
- **总体评价**：该论文作为系统设计提案有很高的工程价值和坦诚度，但作为性能/质量有效性证明，证据强度不足、覆盖有限，尤其是缺乏重复运行和消融实验。
