## 摘要
长期运行的助手和代理消耗的交互流最终会超出上下文长度。现有的上下文保留、摘要和检索方法虽然能保留对选定历史的访问，但在工作上下文变化时，并未提供跨越完整生命周期的持久状态。我们将这种缺失的推理能力表述为\emph{上下文更替下的状态连续性}：通过固定容量的内存状态向前推进计算，其生命周期独立于活动上下文。我们提出了一种内在记忆方法\textbf{LiveMem}，它为预训练的全注意力LLM增加了一个内存状态，该状态在整个生命周期内保留历史信息，而主注意力路径则维持有界的KV窗口。上下文更替与内存状态维护、面向记忆的后训练以及状态感知服务共同使得这一内存状态在原始令牌被释放后仍能承担负载。我们的实验表明，LiveMem在评估的系统和其他内在记忆方法中取得了领先的整体性能。在LongMemEval上的实验显示，即使支持证据已从当前上下文中移除，LiveMem仍能基于内存状态回答问题，并且证据距离分析表明有用信息在活动窗口之外依然持续存在。因此，LiveMem将状态连续性确立为持续LLM推理中一种独特且互补的抽象。

## Abstract
Long-running assistants and agents consume interaction streams that eventually outgrow the context. Existing context retention, summarization, and retrieval preserve access to selected history, but do not provide a persistent state over the full lifecycle when working context changes. We formulate this missing inference capability as \emph{state continuity under context turnover}: carrying computation forward through a fixed-capacity memory state whose lifetime is independent of the active context. We introduce an intrinsic memory method, \textbf{LiveMem}, which augments a pretrained full-attention LLM with a memory state that preserves the historical information over the whole lifecycle while the main attention path retains a bounded KV window. Context turnover and memory state maintaining, memory-oriented post-training, and state-aware serving jointly make this memory state load bearing after its originating tokens are released. Our experiments show that LiveMem achieves leading overall performance among evaluated systems and other intrinsic memory methods. Experiments on LongMemEval show that LiveMem is able to answer the question based on the memory state, even when the supporting evidence has been removed from the current context, and evidence-distance analysis shows that useful information persists beyond the active window. LiveMem thus establishes state continuity as a distinct and complementary abstraction for continual LLM inference.

## 一、核心问题与整体含义

**研究动机**：语言模型正从单次问答演变为持续运行的助手和智能体，交互历史可无限增长，最终必然超出上下文窗口限制。现有方法（RAG检索、摘要、工程化记忆管理等）本质上都是"历史访问"机制——像"记事本"一样按需提供过去的内容，而非在上下文更替时维持一种连续的计算状态。这引出一个根本问题：**当模型的工作上下文被替换时，如何保持跨上下文的连续性？**

**核心概念**：论文将这一缺失能力形式化为 **"上下文更替下的状态连续性"（state continuity under context turnover）**——即通过一个固定容量的内存状态向前推进计算，该状态的生命周期独立于当前活动上下文。这区别于传统的"重建式推理"（reconstructive inference），后者依赖外部系统重新加载相关历史表征。

**意义**：将状态连续性确立为持续LLM推理中一种独特且互补的抽象，与检索机制正交——检索决定模型"读什么"历史，而循环记忆状态决定模型"如何维持"跨生命周期的信息连贯性。

## 二、方法论

### 2.1 核心架构
- **LiveMem** 在预训练全注意力Transformer的每个解码器层上附加一条**并行循环记忆分支**（基于 Gated DeltaNet-2, GDN2  backbone），在保持原注意力路径精确访问有界工作上下文的同时，持续读写固定大小的记忆状态。
- 注意力输出 `a` 与循环分支读取结果 `r` 逐层相加：`o = a + r`，实现历史信息注入。
- 侧分支的 q/k/v 从注意力主干初始化，输出投影初始化为零——初始时模型等价于原模型，通过训练逐步打开记忆通道。

### 2.2 记忆状态更新（GDN2）
单头状态矩阵 `S` 的更新公式（省略层与头索引）：
- **遗忘**：`S = Diag(exp(g)) · S_old`（学习衰减）
- **擦除与写入准备**：`ρ = w ⊙ v − S^T(b ⊙ k)`（擦除门选择性移除旧信息）
- **写入与读取**：`S = S + k·ρ^T`；`r = S^T q`（逐token实时读写，实现在线更新）

### 2.3 上下文更替机制
- 输入按有序块（chunk）处理，系统提示词作为 attention sink 永久保留；其他块通过有界FIFO窗口，达上限后逐块驱逐最旧KV。
- **训练与推理一致性**：训练时用 FlexAttention 动态掩码实现；推理时直接释放被驱逐的KV页。
- 记忆状态不受上下文驱逐影响，隐藏状态扫描全序列。

### 2.4 记忆导向后训练
- **SFT**（监督微调）：固定主干参数，训练完整记忆分支。两阶段课程：先用长文档QA数据冷启动激活侧分支，再用均衡混合数据（多跳QA、对话、长文档、分类等）正式训练，损失仅施加于答案位置。
- **RL**（强化学习）：使用 GRPO 算法，结合 DAPO 实践（clip-higher、token级损失、动态采样、去除KL），奖励函数结合精确匹配与LM判官，含多问题全对奖励和格式惩罚。

## 六、主要结论与发现

1. **LiveMem 整体性能最优**：在所有方法中取得最高的总体平均分（LiveMem-RL 0.519 vs Qwen3-4B 0.458 vs δ-Mem 0.451），且在 Wiki QA 和 Long QA 两个套件上取得 SOTA，在 Conversation 和 TTL 上仅次于对应最优基线，是最均衡的方法。
2. **多问题（MQ）任务是关键优势场景**：当多个问题共享同一历史背景时，Qwen3-4B、δ-Mem 等性能骤降，LiveMem 显著领先（如 2Wiki-MQ 上 0.587 vs 0.336）。
3. **记忆状态确实承载了被驱逐的证据**：在 LongMemEval 上，当支持证据被完全移出活动上下文时，LiveMem（16.5%）比无历史访问的基线（3.1%-3.6%）高出十多个百分点；证据部分驱逐时也有明显优势。
4. **记忆随距离衰减但保持可用**：证据离窗口越远（16K→64K），准确率仅小幅下降，说明 GDN2 的衰减/擦除机制虽影响可用性，但仍能在较长时间跨度内保留关键信息。
5. **训练策略重要**：全参数训练侧路径优于 LoRA；两阶段课程（长文本冷启动 + 均衡混合）优于直接混合或简单再平衡。
6. **记忆状态的边界**：NIAH 实验表明 LiveMem 无法可靠恢复任意细粒度的"针"信息，说明固定容量有损状态并不适合精确存档任务——检索与状态连续性互补，而非替代。

## 七、优点

- **概念贡献**：明确区分"历史访问"（RAG/外部存储）与"状态连续性"（内禀循环记忆）两种正交的长期记忆机制，为长上下文推理提供了一个新的抽象层次。
- **端到端设计**：从问题形式化（公式 2-3）→架构（GDN2 侧分支）→后训练（SFT+RL）→服务（paged KV + 状态槽）形成完整闭环，训练-推理一致性设计（相同的分块驱逐逻辑）是工程细节上的亮点。
- **记忆真正"承重"**：通过上下文驱逐迫使模型学习经由记忆状态而非注意力偷看历史来作答，这是方法有效性的关键设计。
- **实验设计有针对性**：专门验证"证据驱逐后仍可作答"这一核心命题，并细致控制证据距离进行能力边界刻画。
- **消融完整**：涵盖参数量、数据配比、训练顺序等多个维度，有助于理解方法的有效成分。

## 八、不足与局限

- **有损压缩非精确归档**：论文附录E明确承认，NIAH 任务中即使 8K 记忆上下文内也无法恢复任意细粒度内容（准确率仅 0.19-0.21），记忆状态无法替代精确的逐token存储；对需要精确事实回忆的应用需外接检索系统。
- **有限位置编码天花板**：当前基于 Qwen3 的 RoPE 位置编码最大配置 262K tokens，虽然记忆状态本身可持续更新，但实验上限仅 256K 输入，尚未实现真正"无限上下文"；作者建议改用 NoPE 架构做未来工作。
- **不是所有任务最优**：Conversation 套件上 RAG 更强（尤其是 LongMemEval 0.548 vs LiveMem 0.302），TTL 上 Context2LoRA 更优（0.739 vs 0.677）；LiveMem 的强项集中在特定任务类型，泛化至所有场景的结论仍需谨慎。
- **训练成本较高**：两阶段 SFT + RL 各需多节点 A800-80GB 集群，未报告总训练时间，复现门槛可能偏高。
- **可扩展性未知**：仅在 Qwen3-4B 单模型上验证，未测试不同规模/系列基座模型的迁移性；记忆状态 32×128×128 的张量随层数线性增长，更大模型的显存开销需评估。
- **部分实验结果存在偏差风险**：如 Context2LoRA 的构造方式可能非最优、RAG 的 top-k 未精细调优、LongMemEval 分析的样本筛选标准未完全透明等。
- **位置编码与上下文预算的细节**：256K 参考实验中 LiveMem 扫描整个输入而其他方法截断，属于不同的实际条件，需要留意对比的公平性边界。
