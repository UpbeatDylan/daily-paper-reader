## 摘要
大语言模型（LLM）推理服务日益受限于内存而非计算。随着长上下文和长形式推理工作负载日益普遍，键值（KV）缓存主导了LLM令牌生成（即解码）期间的内存占用和内存流量。特别是，HBM容量已成为稀缺且昂贵的资源，严重限制了推理批次大小和系统吞吐量。本文提出OasisKV，一种以内存为中心的LLM推理系统设计，通过在LLM解码期间将完整KV缓存存储与HBM解耦来缓解HBM容量压力。由于解码时的注意力天然稀疏，OasisKV在HBM中仅保留最相关令牌的KV条目用于注意力计算。我们观察到，使用投机解码（SD）草拟的前瞻令牌可以提前准确预测未来的重要令牌。OasisKV采用高效的注意力后台流水线来识别重要的KV块。然后从更高容量的内存层（例如主机或远程内存）预取这些块，并在下一步解码使用之前暂存于HBM中。我们基于vLLM实现了OasisKV。在2,048令牌KV预算下，前瞻预测足够准确，可将精度保持在完全注意力的0.7个点以内。这使得OasisKV能够将稀疏性转化为吞吐量收益：在推理工作负载下，相比密集vLLM提升1.69倍，精度损失0.1个点；在多GPU长上下文服务中最高提升2.1倍。在预填充-解码分离下，OasisKV的吞吐量约为密集处理的2倍，同时每个请求的KV需求减少6.5至9.7倍，解码节点主机内存比完整KV传输减少2.2至2.6倍。

## Abstract
Large language model (LLM) inference serving is increasingly constrained by memory rather than compute. As long-context and long-form reasoning workloads become more prevalent, the key-value (KV) cache dominates both memory footprint and memory traffic during LLM token generation, i.e., decode. In particular, HBM capacity has become a scarce and costly resource that heavily limits inference batch size and system throughput. This paper presents OasisKV, a memory-centric LLM inference system design that alleviates HBM capacity pressure by decoupling full KV-cache storage from HBM during LLM decoding. Because decode-time attention is naturally sparse, OasisKV keeps only the KV entries of the most relevant tokens in HBMs for attention computation. We observe that future important tokens can be predicted accurately in advance using lookahead tokens drafted by speculative decoding (SD). OasisKV employs an efficient attention background pipeline to identify important KV blocks. They are then prefetched from higher-capacity memory tiers (e.g., host or remote memory) and staged in HBMs before being used in the next decode step.   We implement OasisKV based on vLLM. The lookahead prediction is accurate enough to keep accuracy within 0.7 points of full attention under a 2,048-token KV budget. This lets OasisKV turn sparsity into throughput gain: $1.69\times$ over dense vLLM on the reasoning workload at 0.1 points of accuracy loss, and up to $2.1\times$ on multi-GPU long-context serving. Under prefill--decode disaggregation, OasisKV reaches about $2\times$ dense throughput while admitting each request with $6.5$--$9.7\times$ less KV and holding $2.2$-$2.6$ less decode-node host memory than full KV transfer.

## 1. 核心问题与整体含义（研究动机与背景）

- **研究问题**：大语言模型（LLM）推理服务正日益受到**内存瓶颈**而非计算瓶颈的制约。随着长上下文和长形式推理（如 agentic 工作负载、编码代理、科研推理）的普及，KV 缓存主导了推理解码阶段的内存占用与内存流量。
- **核心矛盾**：HBM（高带宽内存）容量有限且成本高昂，直接限制了推理批次大小（batch size）和系统吞吐量。例如文中测算：一个 32B 类 GQA 模型在平均 32.7K 上下文下，单请求约需 8.6 GB KV 缓存，即使 80 GB HBM 全部留给 KV，最大批次也仅约 9 个请求。
- **现有方案不足**：
  - 稀疏注意力（Sparse attention）减少 KV 读取，但不减少 HBM 容量占用；
  - KV 检索（KV retrieval）将 KV 放在主机内存，但按需取回位于解码关键路径，延迟代价高；
  - KV 预取（KV prefetch）虽能重叠传输与计算，但缺乏准确的预测信号和跨层内存管理系统，受限于 CPU–GPU IO 带宽屋顶。
- **本文回答**：能否通过**前瞻（lookahead）预测 + 稀疏预取**，将"完整 KV 存储"与 HBM 解耦，让解码期间 GPU 仅保留一小部分"工作集"，从而突破 HBM 容量墙？

## 2. 方法论：核心思想、关键技术细节

### 2.1 核心思想
OasisKV 的核心洞察是：**解码期注意力天然稀疏**，且**投机解码（SD）产生的 draft token 可作为未来 KV 访问模式的高质量预测信号**。系统只将最相关令牌的 KV 块保留在 HBM 中，其余完整 KV 缓存存放于 CPU DRAM 或远程内存，并通过异步后台流水线提前预取。

### 2.2 关键技术细节

**（1）Look-ahead Attention（前瞻注意力）**
- 将正常令牌与 draft token 的 query 拼接，在一次前向传播中共同处理；
- draft query 基于当前稀疏 KV 工作集传播（前一层输出）后，用于预测下一解码步的 top-K KV 块；
- 通过实验验证：draft query 预测的 top-K 集合与真实下一 token query 的精确 top-K 集合逐层一致性均值达 98.74%（最低 98.2%），远优于用上一 token query 作代理的 83.9%。

**（2）压缩键摘要（Compressed Key Summaries）**
- 采用 Quest 风格的逐块 min/max pooling 摘要，每个逻辑块存两个摘要向量，仅占完整 KV 约 1/16；
- draft query 扫描压缩摘要即可对**全部**历史块排序，无需取回任何完整 key，从而在低开销下实现全局 top-K 预测。

**（3）全异步后台预取流水线**
- 每个层维护独立的 Top-K 预测 → KV 选择 → KV 传输三级流水线，分别在独立的 CUDA stream 上运行；
- 层间任务相互独立，可并行执行（第 l+1 层的预测与第 l 层的选择、第 l-1 层的传输并发）；
- 使用 CUDA events 维护层内依赖；每层在下一步注意力之前仅等待该层自身的传输完成（层局部同步），避免整步等待。

**（4）Delta Selection 与 Capped Eviction（有上限驱逐策略）**
- 将预测集与当前驻留集合求交集，已驻留块不产生 PCIe 流量；
- 对驻留但不在预测集中的块按最后被选择时间排序，选择最久未用者作为驱逐候选；
- 每头每步最多准入 C 块（由 fetch ratio 控制），从而**严格限制每步的跨层传输量**，防止 PCIe 带宽成为解码的瓶颈。

**（5）面向生产级引擎的 KV 管理**
- 在 vLLM 原有 GPU/CPU 页表之上增加**逐头逻辑到逻辑映射层（Head-wise Mapping）**，使不同 KV 头可维护不同的稀疏块集合，同时保持原页表不变；
- 支持请求从"密集解码"中途转为"稀疏解码"：当上下文超过稀疏化阈值时，将完整 KV 复制到 CPU 内存，GPU 仅保留选定块和局部窗口。

**（6）远程部分获取（Remote Partial Fetching, RPF）**
- **部分传输**：预填充节点先多执行一步解码生成首个 query，据此选取各层 top-K 并取并集，仅传输该 KV 子集 + 压缩键缓存 + draft KV 状态到解码节点，随后即释放预填充 GPU；
- **网络预取**：解码期间若选择的块不在解码节点主机内存，通过远程读取从预填充节点的 staging pool 取回，与前台注意力重叠执行；每个块最多跨网络传输一次。

## 6. 主要结论与发现

1. **吞吐提升显著**：真实 AIME24 推理负载下，Qwen3-8B 上比密集 vLLM 快 **1.69×**（精度仅降 0.1 点）；多 GPU 长上下文服务最高 **2.1×**；PD 分离下约 **2.1–2.3×**。
2. **精度损失极小**：2,048 token KV 预算下，整体精度距 full attention 不超过 0.7 点；LongBench v2 上 Qwen3-8B 总分为 33.20 vs 33.60（−0.40）；推理类 Long output 中 pass@8 仅降 0.66 点。
3. **KV 传输大幅减少**：PD 分离下，请求准入时 KV 传输减少 **6.5×（24K）/ 9.7×（32K）**；考虑解码期漂移后整体仍减少 1.9–2.2×；解码节点主机内存占用减少 2.2–2.6×。
4. **PCIe 带宽是绑定约束**：消融显示，吞吐下降与传输字节数成正比 — fetch cap 从 0.01 放宽到全部取回，吞吐从 2,178 崩至 824 tok/s（2.6× 差距），而精度仅从 74.9 微升至 77.4；最优工作点为 fetch ratio = 0.05。
5. **draft token 预测足够好**：利用 EAGLE-3 draft token 的 top-K 预测与真实下一 token 的 top-K 一致率达 98.74%，无需额外训练预测器。

## 7. 优点与亮点

- **训练无关的精准预测**：复用投机解码的 draft token 作为前瞻信号，既是"免费"信号又高度准确，避免了专门训练预测器或使用低精度近似 KV 的折中；
- **系统级联合优化**：将预测、选择、传输、驱逐策略统一视为互相耦合的系统问题而非独立模块，设计了一致的内存层级（HBM ↔ CPU DRAM ↔ 远程内存）管理方案；
- **生产级集成**：基于 vLLM 实现，兼容多 GPU 张量并行和 PD 分离，支持请求中途由密集转稀疏，工程完整性高；
- **严谨的因果分析**：图 2 的 roofline 分析和表 2 的消融直接量化了带宽与吞吐的因果关系，结论可信度高；
- **精度对比方法论严谨**：避免跨框架直接比较绝对分数，而是以各自栈内的 full-attention 为锚点做差，提高了对比公平性；
- **远程部分获取的细致刻画**：区分准入传输与解码期漂移，并分析网络带宽的时间分布，方法论成熟。

## 8. 不足与局限

- **实验覆盖的局限**：
  - 未在真实负载上与其他 KV 预取系统（ShadowKV/InfiniGen/FreeKV）做端到端对比，只在合成负载中测试；这些框架的"不可达点"未被充分讨论；
  - 未验证 AMD/其他非 NVIDIA 硬件平台；UVA 和 CUDA streams 的依赖使系统目前绑定 NVIDIA 生态；
  - 未实验更长上下文（如 128K/1M）、更大批量以及 SSD 存储层；
  - 前缀缓存（prefix caching）仅做了分析建模，未在原型中实现。
- **潜在偏差风险**：
  - 精度结果高度依赖 draft 模型质量；若 draft 模型对特定领域（如非英语、代码之外的领域）预测不准，精度损失可能放大；
  - 精度消融中 K=64 时 Qwen3-235B 精度下降达 6.9 点，说明 sparsity-accuracy 权衡对模型和任务敏感；
  - 论文中"精度提升超过 full attention"的个别结果（如 K=192）被归因为 run-to-run 方差，暗示单次采样实验存在噪声风险。
- **应用限制**：
  - 当前原型保留完整 KV 在预填充节点主机 DRAM 直至请求完成，在极端长上下文下的主机内存总容量仍会受限（论文指出可扩展到远程内存/SSD 但未实现）；
