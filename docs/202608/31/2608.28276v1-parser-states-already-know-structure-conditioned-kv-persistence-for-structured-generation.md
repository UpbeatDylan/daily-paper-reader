## 摘要
结构化生成支撑着生成JSON、SQL和函数调用的大语言模型（LLM）智能体，其中单个字段错误就可能导致下游操作失败。约束解码已通过跟踪解析器状态转换来强制形式有效性，这些转换揭示了生成的令牌如何在当前语法下参与模式关键决策，例如必填字段、参数和结构边界。现有的KV压缩在很大程度上未利用这一与任务相关的结构信号。我们提出了PASK（解析器感知的结构化KV持久化），它将解析器推导出的结构转化为层组特定的KV持久化决策。PASK通过使用任务错误敏感度设置最低保护下限，并使用注意力输出失真来分配剩余KV容量，从而解决了模型侧KV敏感度与任务级结构化风险之间的不匹配。离线校准阶段将这些信号编译为持久化策略，在线仅保留轻量级的结构条件查找。在目标总KV预算为0.33的情况下，PASK在Qwen3-4B上的八个BFCL非实时和实时子类别中，平均比最强压缩基线高出17.39个百分点。在端到端服务中，PASK实现了高达2.2倍的吞吐量提升和3.3倍的TPOT降低，同时使用的峰值GPU内存仅为Full KV的0.53倍。

## Abstract
Structured generation underpins large language model (LLM) agents that produce JSON, SQL, and function calls, where a single wrong field can cause the downstream action to fail. Constrained decoding already tracks parser transitions to enforce formal validity, and these transitions expose how generated tokens participate in schema-critical decisions such as required fields, arguments, and structural boundaries under the active grammar. Existing KV compression largely leaves this task-relevant structural signal unused. We introduce PASK (Parser-Aware Structural KV Persistence), which turns parser-derived structure into layer-group-specific KV persistence decisions. PASK addresses the mismatch between model-side KV sensitivity and task-level structured risk by using task-error sensitivity to set minimum protection floors and attention-output distortion to allocate residual KV capacity. An offline calibration stage compiles these signals into a persistence policy, leaving only lightweight structure-conditioned lookup online. At a targe total KV budget of 0.33, PASK outperforms the strongest compressed baseline by 17.39 percentage points on average across eight BFCL non-live and Live subcategories on Qwen3-4B. In end-to-end serving, PASK achieves up to 2.2x higher throughput and 3.3x lower TPOT, while using 0.53x the peak GPU memory of Full KV.

## 1. 核心问题与研究动机

**背景：**

- 结构化生成（Structured Generation）支撑着 LLM 智能体的关键任务（JSON、SQL、函数调用），这类任务中**单个字段错误**即可能导致下游操作失败。
- 约束解码（Constrained Decoding）通过维护解析器状态（parser state）并屏蔽非法 token 来保证输出形式合法，但解析器状态中蕴含的**结构角色信息**（如"必填键""枚举值""函数参数""结构边界"）在确定合法 token 集合之后即被丢弃。
- 现有 KV 压缩策略（基于注意力显著性、量化误差、最近性、通用 token 重要性等）只捕捉**模型侧数值重要性**，而无法直接编码生成 token 的**任务级结构责任**。

**核心矛盾（核心问题）：**

> 模型侧 KV 敏感度 ≠ 任务级结构化风险。某些数值影响不大的历史 token，若被丢弃，可能导致后续函数名、参数或字段值发生改变，从而改变任务结果。

**解决思路：**

> **任务级失败风险决定"必须保护什么"；模型侧失真决定"剩余内存如何分配"。**

## 2. 方法论：PASK（Parser-Aware Structural KV Persistence，解析器感知的结构化 KV 持久化）

### 2.1 核心思想

PASK 将约束解码已产生的解析器状态转换（parser transition）作为**控制信号**，为生成的每个 token 在**不同 Transformer 层组**上分配持久化动作：`RELEASE(R)`（释放）、`RETAIN-LOW(L)`（低精度保留）、`RETAIN-HIGH(H)`（高精度保留），其中满足 `R ≺ L ≺ H` 的精度/保留等级序关系。

### 2.2 关键公式与形式化目标

**风险与成本定义：**

```
Rtask(π) = E[I[Fail(yπ)]]                  # 结构化任务失败风险
CKV(π)   = 归一化平均 KV 存储成本           # 解码 KV 成本
```

**优化目标（公式 2）：**

```
π*α = argmin CKV(π)  s.t.  Rtask(π) − Rtask(πref) ≤ α
```

即在可靠性损失不超过容忍度 α 的前提下，最小化 KV 存储成本。其策略空间仅使用解析器结构、层组和常量大小的预算状态。

### 2.3 解析器派生的持久化桶（Parser-Derived Persistence Buckets）

每个被接受的解析器转换在活动语法下被解释为结构标签，并与层组组合：

```
zt = (class_t, role_t, state_t, next_t)
qt,c = (zt, c), c ∈ C（层组）
```

- **class**：令牌宽泛类型
- **role**：模式责任（必填字段、枚举值、SQL 谓词、函数参数）
- **state**：当前语法定义的转换状态
- **next**：解析器前沿是否接近关键区域
- 关键性判断**仅依赖语法和解析器转换**，不依赖注意力统计、任务风险测量或未来 token。

### 2.4 双指标离线校准

**（1）注意力输出失真（Attention-Output Distortion）——用于残差分配**

对参考轨迹中的每个桶进行干预（其他桶保持 H），测量后续解码位置在注意力输出上的扰动：

```
D(q,a) = Σ E[ max_h ||o_full − o_a(q)||² ]
```

衡量模型侧数值敏感度，**仅用于残差分配**。

**（2）任务错误敏感度（Task-Error Sensitivity）——用于保护下限**

在同样干预下完整生成，估计失败率变化：

```
V(q,a) = P_fail(q,a) − P_fail(q,H)
V̄(q,L) = max{0, V(q,L)}
V̄(q,R) = max{V̄(q,L), V(q,R)}
```

（单调包络消除有限校准数据造成的经验倒置，保持 H ≻ L ≻ R 的保护排序。）

**（3）保护下限与分配**

给定阈值 τ_low、τ_high，校准保护下限：

```
a_min(q) = H 若 V̄(q,L) > τ_high
         = L 若 V̄(q,R) > τ_low
         = R 否则
```

残差预算通过相邻升级、按**单位成本的失真降低** `ρD` 排序来分配，开发集上按可靠性门限选出最终策略，冻结为查找表 Λ（离线编译成不可变查找表；在线仅轻量结构查询）。

### 2.5 在线结构条件查找（算法 2）

- 在线解码时**无任何重要性估计**：仅按 token 的结构标签和层组查表，取出基准动作、保护下限与升级分数。
- 预算保护：`B_t = max{0, R_t − Γ(s_t)}`，Γ 为解析器状态的未来保护开销储备（使用校准轨迹的经验分位数）。
- 预算不足时按"每节省成本的失真损失"升序降级（不低于保护下限）；在关键/临界状态时用剩余预算升级。

### 2.6 轻量级前缀（Prefill）配套

对输入 token 按语义标签（受保护内容、函数名、参数键、约束、schema 脚手架等）+ 层组分组，用同样的原则线下校准分配前缀 KV 保留策略。

## 6. 主要结论与发现

1. **准确率优势**：在目标总 KV 预算约 0.33 时，PASK 在 Qwen3-4B 的八个 BFCL 子类别上比最强压缩基线平均高 **17.39 个百分点**；在 Qwen3-4B non-live 上达到 88.00%，仅比 Full KV（91.83%）低 3.83 个百分点。
2. **跨规模一致性**：Qwen3-14B 上同样保持最优压缩方法准确率，显示收益随模型规模扩大保持稳定。
3. **内存节省**：峰值 GPU 内存较 Full KV 降低约 **47.5%**（从约 40.0 GiB 降至 21.0 GiB），优于 SnapKV 的 38.8%。
4. **速度提升**：端到端服务中吞吐量最高提升约 **2.2 倍**（A100 8K/1K 场景 +98.9%），TPOT 最高降低约 **3.3 倍**（32K/1K A100 场景 -69.8%、32K/2K A100 -70.1%）；32K/256 短输出场景在 A100 上出现吞吐量 -28.0% 的例外（以时延换吞吐）。
5. **消融验证**：去掉 V-floor 后，满足开发集可靠性门限所需解码预算从 50.08% 涨至 **98.49%**；去掉 D-ranking 后从 50.08% 涨至 60.67%——证明**保护下限是主干，失真排序是高效分配补充**。

## 8. 不足与局限

### 8.1 实验覆盖范围有限

- **仅评测 BFCL 函数调用**，未覆盖 JSON Schema、SQL、代码生成等其他结构化生成基准，外部可推广性尚待验证；
- Live 子集在 Parallel-Multiple 上 PASK 仅 50-57%，虽优于基线但仍有明显差距；
- 未测更大模型（70B+）或更长上下文（>32K）。

### 8.2 校准成本与稳定性

- 离线校准需要一次性成本（分割数据、逐桶干预、完整生成评估），论文**未量化**该成本的时间/算力；
- 校准依赖有限样本，单调包络虽修正倒置，但未分析校准数据的规模敏感性或不同分布漂移下的鲁棒性。

### 8.3 设计粒度较粗

- 论文明确承认：仅用 **3 个层组**与 **3 个离散动作**（R/L/H），更细的层划分或更多精度档位可能带来进一步收益；
- 风险地板阈值（τ）需要人工扫描，依赖开发集选择，存在过拟合开发集的风险。

### 8.4 边界情形存在性能回退

- 32K 输入/256 输出在 A100 上吞吐量相比 Full KV 下降 28.0%（以更低 TPOT 换取），说明极端短输出场景下 PASK 的预算配置并非总最优；
- Prefill 压缩策略的增益与具体语义标签的设定质量有较强耦合。

### 8.5 其他

- 未报告系统级多请求调度下的实际吞吐（仅报告静态并发实验）；
- 未提供代码或开源实现链接，可复现性有待确认；
- 未讨论与现有投机解码（speculative decoding）、前缀缓存复用等技术的协同关系。
