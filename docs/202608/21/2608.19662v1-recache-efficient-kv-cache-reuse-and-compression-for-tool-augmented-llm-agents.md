## 摘要
智能体语言模型在跨请求的不同组合和顺序中重复编码工具和技能模式，这阻碍了标准前缀缓存对其键值（KV）状态的复用。我们提出了\textbf{ReCache}，一个独立缓存资源表示并降低其推理时计算与内存开销的框架。资源级注意力消除了跨资源交互并分配资源局部位置，从而产生组合不变的KV块。随后，ReCache将资源可见性限制在贡献选择的层-KV头组路径上，并通过结构和语义剪枝仅保留调用关键字段。我们在一个由七个公开工具和技能使用数据集（包括资源不相交测试）组成的基准上评估了ReCache。资源级注意力在提供3.655$\times$首令牌延迟加速的同时，与密集调用性能相匹配（82.3\%对比82.4\%的Inv-F1）。完整框架减少了92.43\%的已分配KV张量内存，并将注意力加速了1.423$\times$。这些结果表明，将可复用模式编码与选择性资源访问分离，能够在有限的效果损失下大幅降低智能体推理成本。代码可在https://github.com/EIT-NLP/ReCache获取。

## Abstract
Agentic language models repeatedly encode tool and skill schemas that recur across requests in different combinations and orders, preventing standard prefix caching from reusing their key--value (KV) states. We introduce \textbf{ReCache}, a framework for independently caching resource representations while reducing their inference-time computational and memory overhead. Resource-wise attention removes cross-resource interactions and assigns resource-local positions, producing composition-invariant KV blocks. ReCache then restricts resource visibility to contribution-selected layer--KV-head-group routes and retains only invocation-critical fields through structural and semantic pruning. We evaluate ReCache on a benchmark assembled from seven public tool- and skill-use datasets, including resource-disjoint tests. Resource-wise attention matches dense invocation performance (82.3\% versus 82.4\% Inv-F1) while providing a 3.655$\times$ time-to-first-token speedup. The complete framework reduces allocated KV-tensor memory by 92.43\% and accelerates attention by 1.423$\times$. These results show that separating reusable schema encoding from selective resource access substantially reduces agentic inference costs with limited effectiveness loss. The code is available at https://github.com/EIT-NLP/ReCache.

## 1. 论文的核心问题与整体含义

本文针对工具增强型（tool-augmented）LLM 智能体的推理效率问题展开研究。在智能体系统中，LLM 需要反复调用外部工具和技能资源，这些资源的 schema（称为"resource"）通常会被动态检索并拼接到上下文中。然而，由于不同请求中资源的组合方式和排列顺序不同，同一资源对应的 KV（键值）缓存无法被标准前缀缓存（prefix caching）机制有效复用，导致系统反复对未变化的资源内容执行 prefill 计算，造成大量推理时间和内存浪费。

论文提出 ReCache 框架，核心思路是将"可复用的资源模式编码"与"按需的资源访问"分离开来：先让每个资源以组合不变（composition-invariant）的方式独立编码为 KV 块，再通过结构性和语义性剪枝压缩这些 KV 块的实际存储与访问开销。实验表明，该方法在几乎不损失调用效果的前提下，实现 3.655× 的首令牌延迟加速、92.43% 的 KV 张量内存削减和 1.423× 的注意力计算加速，为大规模智能体推理提供了实用的成本优化方案。

## 2. 方法论

ReCache 采用三阶段渐进式优化流程（如图 2 所示）：

### 2.1 资源级注意力（Resource-wise Attention）

基于一个关键观察（图 1a）：在 Qwen3-4B 上，资源内部的注意力强度显著高于跨资源注意力，说明跨资源交互对资源调用的贡献有限。为此，ReCache 在缓存构建阶段：

- **去除跨资源注意力**：每个资源内的 token 只关注共享前缀和自身资源内的 token，不同资源之间的注意力链接被完全移除，注意力复杂度从 O(D_R²) 降为 O(∑ᵢ Dᵢ²)；
- **重置资源局部位置**：每个资源内部的相对位置索引从 0 开始（pos(tᵢ,ⱼ) = j），使资源表示与全局排列顺序无关，从而得到组合/位置不变的 KV 块，可独立构建与复用；
- 实验表明这种位置重置对任务效果几乎无损害，但为缓存复用奠定了基础。

### 2.2 结构剪枝（Structural Pruning）

Transformer 的层（layer）和 KV 头组（head group）存在显著的冗余。ReCache 采用贡献度引导的路由选择：

- 使用 leave-one-in 分析（而非 leave-one-out）计算每个层或 KV 头组对调用损失的边际贡献；
- 对每条（层，头组）路径定义是否可见资源 KV 状态：选中路径（Ω）使用资源注意力掩码 M_resource，未选路径使用上下文掩码 M_context（完全屏蔽资源 token）；
- 定义调用损失 ℓ_Ω(X, Y)（仅在目标调用响应的 token 跨度上计算），以损失下降量作为层贡献 s_l 和头组贡献 s_g；
- 将正贡献归一化为权重 w_i，按预算 K_L、K_G 选取 TopK 单元，构造最终路由 Ω⋆ = L⋆ × G⋆。

预算分析结果显示：在 Qwen3-4B 上，前 20 层贡献覆盖率达 97.7%，仅需 3 个 KV 头组即可保持接近完整效果；在 Qwen3-1.7B 上则需 7 个 KV 头组（覆盖率 99.3%）。

### 2.3 语义剪枝（Semantic Pruning）

工具/技能 schema 属于结构化文本，不同字段对调用效果的影响差异明显。ReCache 按字段语义进行 token 级剪枝：

- **保留三个核心字段**：资源名（支持资源识别）、参数名（支持参数接口对齐）、参数描述（提供参数值约束）；
- **保留末尾 suffix token**：利用其因果状态天然聚合了前面所有字段的信息，作为紧凑的语义锚点（类似 summary token 的思想，但不引入新的训练 token）；
- 消融实验表明：资源描述（resource description）字段对性能贡献极小，可在保留前述字段后安全剪去；同时验证了多种末尾 token 数量（如 10、20 个）并不能带来明显额外收益。

## 3. 实验设计

### 3.1 数据集与 Benchmark

论文不依赖单一数据集，而是构建了一个统一的工具与技能使用基准，整合了 7 个公开数据集：

- **工具类**：ToolACE、APIGEN、ToolMind、Toucan、ToolRet、WildToolBench
- **技能类**：SkillRouter

在数据构造上，论文采用 **两阶段多样性优先采样**（diversity-first sampling）：先排除轨迹不可解析、调用无依据或资源未声明等无效样本；随后以候选集合签名和调用资源的新颖性为标准，优先纳入从未出现过的资源组合与调用；由于严格唯一性无法满足配额，第二阶段按质量排序补足余量。最终得到 49,424 条训练样本。

测试集分为两个各 1,000 条的切分：

- **T_IND（分布内）**：所用资源在训练中出现过；
- **T_OOD（资源不相交的分布外）**：所有声明资源均从未在训练中出现过，用于检验框架对未见资源的泛化能力。

### 3.2 评估指标

- **有效指标**：turn 级资源调用 F1（Inv-F1，要求资源名和所有参数完全匹配）、资源识别 F1（ID-F1）及精确率/召回率、资源幻觉率（Halluc.）；
- **效率指标**：首令牌延迟（TTFT）、每输出 token 时间（TPOT）、注意力延迟（Attn.）和分配 KV 张量内存（Mem.）。

### 3.3 对比方法

- **Dense**：标准密集注意力（全上下文参与，全层全头可见）的完整 prefill 基线；
- **Block**：去除跨资源注意力但保持全局位置编码；
- **Ω_full**：资源级注意力 + 资源局部位置编码（未做任何剪枝）；
- **结构剪枝对比**：Ω_full+SPEED（层不对称 KV 可见性）、Ω_full+SA₂₀,₃（基于注意力质量选择路径，与 ReCache 的结构剪枝桥接对比）；
- **语义剪枝对比**：Ω_full+Gist（gist token 摘要）、Ω_full+Beacon（chunk 级摘要）、Ω_full+SMP（仅做语义剪枝，不做结构剪枝）；
- **ReCache**：完整框架（结构剪枝 + 语义剪枝组合）。

## 6. 主要结论与发现

1. **跨资源注意力和全局资源顺序对调用性能贡献有限**：资源级注意力（Ω_full）与 Dense 的 Inv-F1 仅差 0.1 个百分点（82.3% vs. 82.4%），却带来 3.655× 的 TTFT 加速；这从智能体调用场景佐证了"位置信息重要性随任务而异"的既有观点。
2. **贡献度引导的结构剪枝优于注意力质量选择**：在相同结构预算下，基于 leave-one-in 损失贡献的剪枝在分布内（+3.2% Inv-F1）和分布外（+10.0%）均显著优于 SPEED 策略；与注意力质量排序的 SA₂₀,₃ 相比，同样拉开数个百分点，尤其在 OOD 场景下幻觉率从 5.1% 降至 0.5%。
3. **字段感知的语义剪枝远优于通用文本摘要**：Gist 和 Beacon 在 KV 压缩上虽然有效，但严重损害了调用有效性（尤其是 Gist，Inv-F1 仅 39.2%，幻觉率飙升至 51.4%）；这验证了结构化 schema 中精确接口字段（资源名、参数名、参数描述）不可替代的观点。
4. **结构预算与模型规模高度相关**：Qwen3-4B 仅需 3 个 KV 头组即可保持效果，而 Qwen3-1.7B 需要 7 个；较大模型在并行头组间表现出更强的功能替代性。
5. **完整 ReCache 框架在效率和效果间取得了良好平衡**：在保持 97.5%（T_IND）和 91.8%（T_OOD）的密集模型 Inv-F1 的前提下，实现 92.43% KV 内存削减和 1.423× 注意力加速，并将资源 KV 内存上限稳定在 0.03 GiB 左右。

## 7. 优点

1. **问题定位准确**：指出标准前缀缓存在"动态组合型工具调用"场景的固有局限，并依据注意力分析（图 1）给出了实证基础，而不是凭直觉设计；
2. **方法设计优雅统一**："资源级注意力保证缓存可复用性 → 结构剪枝限制访问路径 → 语义剪枝削减 token 数量"三层递进，分别对应 KV 的"构建、路由、内容"三个维度，框架整体性强；
3. **贡献度（leave-one-in）选择机制具有方法论价值**：相较 attention-mass 或均匀裁剪，它能捕捉"对最终调用任务的边际贡献"，在分布外泛化上表现更强；
4. **字段感知剪枝在语言上高度对齐领域本质**：基于工具调用失败多源于名称/参数错误这一观察，设计出比通用摘要型压缩更符合任务需求的策略；
5. **数据构造严谨**：对直接聚合 7 个数据集可能导致的高频资源偏置和记忆捷径做了系统排查，多样性优先采样与 OOD 资源隔离设计显著增强了评估的可信度；
6. **效率评估维度全面**：区分 TTFT、TPOT、注意力延迟、内存分配等多层次指标，能清晰揭示优化来自哪个环节；
7. **开源** 代码，便于后续研究与复现。

## 8. 不足与局限

1. **模型覆盖有限**：仅验证了 Qwen3-4B 和 Qwen3-1.7B 两个同架构模型，未覆盖更大规模基座或其他主流开源架构，结论的普适性有待验证；
2. **仅支持可训练设置**：ReCache 修改了注意力掩码与位置编码，需要通过微调适配模型；对无法微调的冻结模型（如纯黑盒 API 场景）不适用；
3. **算力报告不完整**：未提供训练时长、总 GPU 卡时、超参数配置等关键信息，影响可复现性（虽然代码已开源，但算力细节仍对资源评估有参考价值）；
4. **适用环境假设较强**：框架假设系统指令与资源 schema 相对稳定、资源间没有必需的长程依赖或顺序依赖；对资源频繁动态更新、检索顺序本身携带语义信息、或资源间存在强交互的场景，效率与有效性可能明显下滑；
5. **极长上下文的 OOD 压力未充分验证**：XL 资源长度（≥10K token）下的有效性指标未单列报告，只有效率曲线；这些超长上下文中的调用准确性是否同样保持无从得知；
6. **统计严谨性不足**：未提供多次重复实验的方差、置信区间或显著性检验；T_IND/T_OOD 各 1,000 条样本相对较小的测试规模也可能使指标波动；
7. **部分剪枝结果存在效果损失**：完整 ReCache 相对 Dense 在分布内损失约 2.5 个点的 Inv-F1（82.4→80.3），在 OOD 上损失 8.2 个点（66.3→60.8），对高精度要求的真实业务场景，这种差距是否可接受需根据具体场景判断。
