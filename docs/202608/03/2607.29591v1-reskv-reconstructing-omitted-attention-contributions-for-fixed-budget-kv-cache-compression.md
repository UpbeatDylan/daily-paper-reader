## 摘要
KV缓存压缩对于高效的长上下文推理至关重要。现有的驱逐方法会永久丢弃未选中的token，从而移除它们对注意力的总贡献。基于合并的替代方法保留了更多信息，但可能扰动本应保持精确的保留键和值。我们观察到，缓存驱逐所省略的信息可以表示为softmax注意力分子和分母中的残差统计量。基于这一观察，我们提出了ResKV，它将固定的KV预算划分为一个精确的主缓存和一个紧凑的残差缓存，用于重构被省略token的贡献。ResKV让主缓存token和残差条目参与相同的softmax归一化，因此残差条目同时恢复注意力的分子和分母质量，而非作为事后修正。构建时的验证代理决定每层和每个KV头的残差分配，而解码时的动态门控调整单个查询的残差贡献。在LongBench和RULER上的综合评估，涵盖查询感知和查询无关设置、多种骨干网络、缓存预算以及代表性压缩基线，表明在相同保留KV预算下实现了广泛改进，同时保持了压缩解码的实际效率，包括峰值内存使用和长上下文解码吞吐量。

## Abstract
KV cache compression is essential for efficient long-context inference. Existing eviction methods permanently discard unselected tokens and consequently remove their aggregate contribution to attention. Merging-based alternatives preserve more information but can perturb retained keys and values that should remain exact. We observe that the information omitted by cache eviction can be formulated as residual statistics in both the numerator and denominator of softmax attention. Based on this observation, we propose ResKV, which divides a fixed KV budget into an exact main cache and a compact residual cache that reconstructs the contribution of omitted tokens. ResKV lets main-cache tokens and residual entries participate in the same softmax normalization, so residual entries restore both attention numerator and denominator mass rather than acting as a post-hoc correction. A construction-time validation proxy determines residual allocation for each layer and KV head, while a decode-time dynamic gate adjusts residual contributions for individual queries. Comprehensive evaluations on LongBench and RULER, covering query-aware and query-agnostic settings, multiple backbones, cache budgets, and representative compression baselines, demonstrate broad improvements under the same retained KV budget while preserving the practical efficiency of compressed decoding, including peak memory usage and long-context decode throughput.

## 1. 论文的核心问题与整体含义（研究动机和背景）

- **背景问题**：长上下文大语言模型（LLM）依赖 KV 缓存避免重复计算历史 token 的键和值，但 KV 缓存随上下文长度线性增长，迅速成为推理阶段内存占用和访存带宽的主要瓶颈。
- **现有方法的矛盾**：
  - **驱逐（Eviction）类方法**（如 H2O、SnapKV、AdaKV、TOVA）通过评分保留部分 token、永久丢弃其余 token，会造成被丢弃 token 的注意力贡献（包括 softmax 分母的归一化质量）完全丢失——尤其在注意力分散的长上下文中，大量低分 token 的聚合贡献不可忽视。
  - **合并（Merging）类方法**（如 CaM、KVMerger、KeepKV、SemantiCache）将被驱逐 token 折叠进保留槽位，虽保留部分信息，但会扰动原本应保持精确的保留键值，损害尖锐检索场景下的记忆准确性。
- **核心问题**：如何在固定 KV 缓存预算下，既保留主缓存 token 的精确性，又能重构被省略 token 的聚合注意力贡献，同时不增加总缓存槽位数。

## 2. 论文提出的方法论

### 核心思想
ResKV 将固定 KV 预算 b 划分为两部分：**m 个精确主缓存槽位（main cache）** + **r 个紧凑残差槽位（residual cache）**，总预算不变（b = m + r）。残差缓存以“同一 softmax 归一化”的方式参与解码，而非事后修正，从而同时恢复被省略 token 在注意力分子和分母中的质量。

### 关键技术细节
- **残差形式化**：
  将全缓存注意力输出分解为主缓存项和省略项之和：全缓存输出 \( o_S(q) = (N_M(q) + N_E(q)) / (Z_M(q) + Z_E(q)) \)，其中 \( N_E(q) \) 和 \( Z_E(q) \) 即被省略侧的残差统计量。
- **残差缓存构建**：
  - 主缓存按 token 重要性评分 + 近期窗口保护选择：\( M = P \cup \text{Top}_{m-|P|}(s) \)。
  - 对省略集合 E 中的 token 进行**Lloyd 聚类**（以键空间一致性为查询无关代理目标），将 E 划分为 r 个组；每个残差条目存储三个量：**均值键 \( \bar{k}_j \)、均值值 \( \bar{v}_j \)、组内 token 数（popcount）\( c_j \)**。
- **共享 softmax 解码**：
  - 主缓存 logits：\( a_p = \langle q, k_p\rangle / \sqrt{d} \)。
  - 残差条目 logits：\( \tilde{a}_j = \langle q, \bar{k}_j\rangle / \sqrt{d} + \log c_j + \log g(q) \)，其中 \( \log c_j \) 恢复群体 softmax 质量，\( g(q) \) 为动态门控。
  - 主缓存 token 和残差条目在**同一个 softmax 归一化**下计算输出 \( \hat{o}(q) = \hat{N}(q) / \hat{Z}(q) \)，残差条目同时贡献分子和分母。
- **构建期验证代理（Validation Proxy）**：
  - 将观察窗口划分为拟合集（96 个查询）和验证集（32 个查询）；对候选残差预算网格 {0, 0.05, 0.10, 0.15, 0.20}，计算残差增强输出与全缓存输出在验证集上的重构误差 \( L_{val} \)。
  - 仅当残差版本相对纯主缓存改善超过相对边际 δ=0.01 时启用残差，否则回退到 r=0。这使得每层、每 KV 头的残差分配自适应。
- **解码期动态门控（Dynamic Gate）**：
  - 依据主缓存注意力尖度（最大主注意力权重 \( p^{max}_M(q) \)）调节残差贡献：主缓存注意力分散（尖度小）时残差质量放大；主缓存出现尖锐检索峰（尖度大）时残差被压缩，保护精确检索。
  - 门值 \( g(q) = \max(g_{min}, \text{sigmoid}((\tau - p^{max}_M)/T_g)) \)，论文用 τ=0.25、α=12。

### 算法流程（文字描述）
1. **Prefill 阶段**：预填充后生成观察查询，计算 token 评分 → 选择主缓存 → 对省略 token 聚类构建残差条目 → 验证代理选择各层/头的残差预算。
2. **Decode 阶段**：每个解码步，对查询 q 计算主缓存 logits 与残差条目 logits（含 popcount 和动态门），合并到同一 softmax 归一化中输出。

## 6. 论文的主要结论与发现

- **核心结论**：通过“精确主缓存 + 紧致残差缓存 + 共享 softmax”的表示，可以在**不增加 KV 槽位总数**的前提下，有效重构被省略 token 的注意力贡献，显著提升压缩后的模型质量。
- **性能发现**：
  - 查询无关设置下收益更大（更贴合实际部署）。
  - 紧预预算（10%/20% 保留）下收益最大。
  - 任务层面收益集中在**分布式证据任务**（Variable Tracking、FWE、Passage Retrieval、RepoBench-P、LCC），该类任务恰好是驱逐方法最容易丢失聚合信息的地方。
- **效率发现**：ResKV 的峰值内存与压缩基线基本一致；解码吞吐量相比 SnapKV 有中等程度成本，但远优于全缓存，且在长上下文下保持稳定。
- **机理发现**：被逐 key 在 PCA 投影中呈现清晰簇状结构，说明省略侧存在可利用的键空间几何规律，残差条目可有效概括。

## 7. 优点

- **理论动机清晰**：将驱逐信息缺失严格形式化为 softmax 分子/分母中的残差统计量（式 5），从数学上解释了为何“低分 token 聚合贡献不可忽略”，方法设计有理论支撑而非纯启发式。
- **兼顾精确性与压缩性**：主缓存完全保持精确，避免了合并方法的扰动问题；残差缓存用独立条目总结被省略信息，避免了驱逐方法的完全丢弃。
- **共享 softmax 的设计巧妙**：让残差直接参与归一化，同时恢复分子与分母质量，而非事后残差修正（后者无法正确恢复分母的归一化效应）。
- **双重自适应**：构建期验证代理（层/头级残差预算选择）+ 解码期动态门控（查询级残差强度调节），将“哪里放残差”和“何时用残差”都自适应化。
- **效率导向设计**：总槽位数不变、FlashAttention-2 兼容（主支融于 fused path，通过 log-sum-exp 合并残差支）、推理吞吐量和峰值内存接近高效压缩基线。
- **实验报告详尽**：附录包含逐任务完整表格、理论误差界、算法伪代码、超参数细节（τ、Tg、gmin、Lloyd 迭代次数等），复现性较好。

## 8. 不足与局限

- **骨干覆盖有限**：仅评测 LLaMA-3.1-8B 和 Qwen-2.5-7B 两个 7–8B 级指令微调模型，未覆盖 70B+ 规模、编码器-解码器架构、非 GQA 架构或更近期的模型；结论的通用性有待更大规模验证。
- **缺乏跨语言/跨领域验证**：LongBench 本身就是中英双语，但论文未单独分析不同语言或领域上的行为差异。
- **单次运行**：固定随机种子 42、每个配置仅运行一次，未报告多次运行的方差或置信区间，统计稳健性信息不足。
- **一次性压缩限制**：所有方法在 prefill 后仅压缩一次，未处理长生成过程中残差缓存的更新问题（论文也在 Limitations 中承认）。
- **残差表示简单**：仅用均值键/值 + 计数的线性近似，对簇内 logit 异质性较大时误差可能显著（附录给出误差界依赖簇内 logit 一致性 η，但无定量测量）；论文承认更丰富的残差摘要可能进一步改善效果。
- **吞吐量代价**：每个解码步需额外计算残差分支和动态门（虽论文声称“适中”），且 r 个残差逐条目更新 Z/N 在长上下文生成时可能成为新的瓶颈，论文在效率分析中承认相对 SnapKV 有吞吐量成本。
- **验证代理的额外开销**：每个候选残差预算需要构建残差并在验证查询上评估，若层和头数量大（如 70B+ 模型）且预算网格较密，prefill 阶段开销可能显著增加。
- **某些任务表现仍很低**：从附录可见，部分合成任务（如 S3、MK3 等）在紧预算和查询无关设置下所有方法都接近 0–2 分，ResKV 虽总体改进但未根本解决极端困难场景的核心失效，改善幅度有限。
- **与 KVSculpt/RESA 等较新方法的对比缺失**：相关工作提到这些方法，但主实验基线未包含它们，对比范围仍有提升空间。
- **未讨论批量推理（batch serving）场景**：实验均为单查询解码，未验证多查询并发下的内存带宽和调度行为。
