## 摘要
异构大型语言模型（LLM）系统越来越依赖于共享上下文、检索到的证据和多智能体对话历史，然而它们内部的键值（KV）缓存仍然是模型特有的，无法跨架构重用。因此，每个模型必须为相同的上下文重复预填充或存储缓存，这限制了多模型推理和长上下文生成的可扩展性。我们提出了混合翻译器（Mixture-of-Translators，MoT），一个缓存翻译框架，将来自源LLM的上下文KV缓存映射到目标LLM的缓存空间。不同于依赖单一投影路径或全局共享潜在空间的先前方法，MoT使用多个翻译模块来捕获多样的源-目标映射。为了进一步减少残余翻译误差，我们引入了一种上下文校正损失（Context Correction Loss），将重放的目标轨迹与原生目标轨迹对齐。我们揭示了缓存翻译中两个相互竞争的失败模式：早期注入引起的传播平移和晚期注入引起的最后状态平移。MoT通过翻译器混合和目标侧校正来解决这些问题。在Qwen2.5、GPT-2和OPT模型之间的同构和异构翻译中，MoT保持了下游问答性能，包括Qwen2.5-7B规模的翻译，平均闭集问答准确率为51.0%，平均抽取式问答F1为0.43。在实际案例研究中，MoT实现了多智能体推理的保质量内存重用，并在长上下文缓存增强生成中保留了96.3%的直接上下文质量，展示了跨异构LLM的可扩展KV缓存重用。

## Abstract
Heterogeneous Large Language Model (LLM) systems increasingly rely on shared contexts, retrieved evidence, and multi-agent dialogue histories, yet their internal key-value (KV) caches remain model-specific and cannot be reused across architectures. Consequently, each model must repeatedly prefill or store caches for the same context, limiting the scalability of multi-model reasoning and long-context generation. We propose Mixture-of-Translators(MoT), a cache translation framework that maps context KV caches from a source LLM into the cache space of a target LLM. Unlike prior approaches that depend on a single projection path or global shared latent space, MoT uses multiple translator modules to capture diverse source--target mappings. To further reduce residual translation error, we introduce a Context Correction Loss that aligns the replayed target trajectory with the native target trajectory. We reveal two competing failure modes in cache translation: propagated translation shift from early injection and last-state shift from late injection. MoT addresses them through translator mixtures and target-side correction. Across homogeneous and heterogeneous translations among Qwen2.5, GPT-2, and OPT models, MoT preserves downstream QA performance, including Qwen2.5-7B-scale translation with 51.0% average closed-set QA accuracy and 0.43 average extractive QA F1. In practical case studies, MoT enables quality-preserving memory reuse for multi-agent reasoning and retains 96.3% of direct-context quality in long-context cache-augmented generation, demonstrating scalable KV cache reuse across heterogeneous LLMs.

- **核心问题**：异构大型语言模型（LLM）系统的类型中，KV缓存（Key-Value Cache）具有模型特有性，同一上下文在不同模型架构间无法直接复用。这导致每个模型都必须对相同上下文重复进行预填充（prefill）或存储各自的缓存，严重制约了多模型推理、多智能体协作和长上下文生成的可扩展性。
- **矛盾焦点**：现代LLM工作流（如多智能体推理、缓存增强生成CAG）强烈依赖共享上下文与对话历史，但现有缓存复用机制（如Prompt Caching）均假设单一模型或单一缓存格式，无法实现跨架构复用。
- **现有方法的不足**：已有的跨模型通信方法（如C2C、KVComm、Interlat、LSC）要么依赖单一投影路径，要么依赖固定兼容性假设，要么依赖全局共享潜在空间。当源/目标模型在深度、隐藏维度、注意力布局、KV头结构上存在差异时，单一通用映射难以胜任，翻译质量明显下降。
- **本文解决思路**：提出 **MoT（Mixture-of-Translators，混合翻译器）** 框架——通过多个翻译器模块的组合（词元级门控路由）捕获异构源—目标KV缓存之间的多样化映射，并引入**上下文校正损失（Context Correction Loss）** 约束重放轨迹与原生轨迹对齐，从而同时控制两种相互竞争的翻译误差。

## 2. 论文提出的方法论

### 2.1 核心思想

缓存翻译被定义为从源模型上下文缓存到目标模型缓存空间的映射：**KVSrc,Ctx → dKVTgt,Ctx**。MoT的核心思路是：不依赖单一翻译器，而是学习多个翻译器在词元级别的最佳组合，并对翻译后的目标侧前向轨迹进行显式监督校正。

### 2.2 两种相互竞争的翻译误差（理论分析）

论文通过残差Transformer递推进行理论建模，识别出两种误差动力学：

- **传播平移误差（Propagation Error）**：当翻译注入层过早时，翻译引起的隐藏状态偏移经残差网络向上传播，其界为 ∥sL∥ ≤ (1+δ)^(L−T_Start) ∥s_T_Start∥，即随起始翻译层位置T_Start增大呈指数衰减（**Proposition 2.3**）。
- **校正缺失误差（Correction Deficit Error）**：当翻译注入层过晚时，上方剩余层数不足以校正翻译引入的偏移，校正缺失系数 dT:L 随最高翻译层T向最终层靠近而增大，最终 dL:L = 1（**Proposition 2.4**）。
- 两种误差形成**U形损失曲线**：太早→传播误差主导；太晚→校正缺失误差主导。
- **平移分解（Proposition 2.5）**：最终状态偏移 ∥sL∥² = d²T:L·∥sT∥² + β²T:L，即由校正缺失分量与正交偏移分量共同构成。因此翻译必须同时最小化 (∥sT∥, ∥sL∥)，仅优化一个不够。

### 2.3 MoT（Mixture-of-Translators）架构

- **多翻译器与Token级路由**：使用N_Tr个翻译器（backbone translator），通过门控函数产生非负token级分数，经Top-K选择后归一化权重，加权组合各翻译器输出：
  Tr_MoT(zu) = Σ_{m∈Top-K} ĝ_m(zu)·Tr_m(zu)
- **理论保证（Proposition 3.2）**：最优MoT的平移偏移不劣于最优单一翻译器；在词元级路由能实现单一翻译器无法表示的翻译时严格更优。
- **Backbone翻译器**：采用交叉注意力结构，将源侧缓存窗口归一化投影到翻译空间，通过循环交叉注意力融合窗口中各层缓存信息，再投影回目标缓存空间。键/值分别独立翻译（与LSC不同，不引入共享潜在空间）。

### 2.4 上下文校正损失（Context Correction Loss）

- 目标函数：对齐翻译后重放获得的隐藏状态轨迹与目标模型原生预填充的隐藏状态轨迹：
  L_CC = Σ_{ℓ=T_Start+1}^{L} ∥ĥ_ℓ^Tgt − h_ℓ^Tgt∥²
- 实现中使用启发式KV版本：对齐重放期间形成的KV缓存与原生KV缓存（含最终层项 ∥Ŵ_K^L·s_L∥² + ∥Ŵ_V^L·s_L∥²），在最终层key/value投影满列秩条件下，减少KV匹配误差等效于减少最后状态偏移的上界（**Proposition C.1**）。
- 最终训练目标为 **CC + PL** 组合（上下文校正+提示语言建模损失）。

### 2.5 整体推理流程（五阶段）

1. **上下文预填充**：源模型计算上下文缓存，选择翻译通道（Channel Mapping采用Depth-Ratio Mapping，通过滑窗候选加验证损失选出最优通道集）。
2. **KV翻译**：MoT将源缓存映射到目标缓存空间（含Channel Mapping和翻译器混合）。
3. **上下文重放**：目标模型用翻译缓存重新前向传播，重建目标侧上下文缓存；使用**Top-S Source-Guided Sparse Attention**（源引导稀疏注意力）将重放复杂度从O(N²)降至近线性O(N·S)。
4. **提示预填充**：目标模型在重建缓存基础上处理短查询。
5. **完成输出**：生成最终回答。

### 2.6 变体 MoT-h

基于HCache思想，翻译中间激活而非KV缓存，随后通过目标模型自身key/value投影恢复KV缓存，翻译状态大小约减半，降低峰值内存，但翻译直接控制能力有一定损失。

  - 部分基线（C2C、LSC）为论文作者自行实现，存在潜在不公平实现风险；KVComm在同构GPT-2效果显著低于其他设置，作者解释为“KVComm假设同构架构”而省略了异构实验，但同构结果也明显偏弱，可能说明基线调参不够充分。

## 6. 论文的主要结论与发现

- **MoT在闭集QA和抽取式QA上均显著优于其他缓存翻译基线**：Qwen2.5异构翻译（7B→0.5B）平均准确率51.0%、平均F1 0.43，接近Native水平（52.0%/0.45）；GPT-2同构/异构翻译平均准确率42.0%、F1 0.22。
- **MoT同时降低两种误差**：翻译平移∥sT∥和最终状态偏移∥sL∥均大幅下降；U形验证损失曲线转为近单调下降曲线。
- **上下文校正损失单独使用也有效**：即使不使用MoT路由，CC损失也能带来稳定提升；与PL损失组合效果最佳。
- **翻译器选择而非数量决定质量**：默认配置(Top-K, N_Tr)=(1,2)表现最佳，增加翻译器数量并非总带来增益。
- **Depth-Ratio Mapping优于Terminal Mapping**，通道比例为0.3为较优折中。
- **MoT实现多智能体内存近恒定扩展**：10智能体场景下峰值内存仅约0.3GiB（Free策略），远低于Retain策略的1GiB+；且推理质量稳定。
- **MoT保留96.3%的长上下文直接上下文质量**：CAG平均F1为0.2047，Native为0.2125，差距仅0.0078。
- **容量扩展稳定**：固定目标模型、源模型增大时，MoT的F1保持在Native附近，翻译器开销相对恒定。

## 7. 优点

- **理论驱动的方法设计**：论文从残差Transformer递推出发，形式化推导了传播误差的指数衰减、校正缺失误差的单调递增，并以分解公式统一两种误差，方法论严谨。
- **问题识别精准**：发现U形损失曲线背后两个竞争误差，并给出明确的数学刻画（Proposition 2.3—2.5），极具启发意义。
- **架构简洁有效**：MoT通过token级Top-K门控混合多个翻译器，不引入共享潜在空间，避免了LSC的二次方训练复杂度（O(M²)→O(M)级）。
- **训练可扩展性好**：存储冗余从O(M)（随模型数线性增长）降为O(1)，在多项模型池扩展实验中保持稳定。
- **实际场景验证充分**：多智能体推理与长上下文CAG两个案例研究贴近真实部署场景，验证了内存/存储复用的实用性。
- **工程细节扎实**：Top-S稀疏注意力将重放复杂度降至近线性，MoT-h变体降低峰值内存，训练/推理配置统一并公开。

## 8. 不足与局限

- **校正缺失系数改善有限**：论文承认MoT的增益主要来自降低∥sT∥和正交偏移β，而校正缺失系数dT:L变化不大。MoT改善了翻译轨迹，但未直接增强目标模型的内在校正能力。
- **通道映射假设的脆弱性**：Depth-Ratio Mapping在模型间指令微调或训练数据分布差异较大时，相似频谱对角线模式可能消失（论文在gpt2-medium↔DialoGPT-small的初步实验中已观察到该现象）。自适应通道映射留作未来工作。
- **跨分词器翻译未解决**：源/目标模型使用不同分词器时，缓存位置无法直接对应，token级翻译难度大幅增加。论文明确承认该限制。
- **实验规模较小**：训练仅500步、128 token序列；长上下文CAG在HotpotQA-E上最高预算为24K，未覆盖更大上下文窗口。部署到实际生产环境的效果尚未验证。
- **潜在公平性问题**：部分基线（C2C-Project、LSC、MoT-h）为作者自行实现，且未公开代码/超参数细节，复现与公平比较存在风险；KVComm无法处理异构翻译，覆盖面有限。
- **只评估了Decoder-only架构**：未涉及编码器—解码器模型或视觉语言模型，泛化性未验证。
- **峰值内存更高**：MoT本身引入了额外的翻译器模块，峰值内存高于原生和多数基线（Qwen异构设置中为16.62GiB vs 原生15.25GiB），在大规模部署中需权衡。
