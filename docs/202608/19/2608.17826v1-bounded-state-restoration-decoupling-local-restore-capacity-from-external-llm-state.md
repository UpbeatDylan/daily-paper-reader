## 摘要
分层KV缓存系统可以在GPU内存之外保留长上下文LLM执行状态，但保留容量并不决定使该状态可重新执行所需的本地内存。我们将这第二种资源隔离为恢复工作集（RWS）：在恢复过程中生命周期重叠的峰值本地暂存状态。在固定的上游LMCache全计划路径中，针对1.956、7.823和15.646 GiB/秩状态测得的完整重用点首先在2、8和16 GiB L1层级成功，成功时的L1峰值分别为1.956、7.824和15.648 GiB/秩。我们引入了有界状态恢复（BSR），它将完整发现与本地驻留分离。BSR在不将整个命中物化到L1的情况下探测完整的可重用前缀，然后通过至多$W$个块的可重用窗口安装已确认状态。在有界辅助状态下，峰值恢复容量为$O(W)$，而总传输和安装工作量保持$Θ(|S|)$。由于可重用状态跨越异构分配器组和张量并行秩，BSR使用请求级提交规则：部分安装永远不会作为有效的可重用前缀暴露；故障会使通告的前缀失效，并回退到较低的有效层级或确定性重计算。在DeepSeek-V4-Flash上，采用TP=2跨两个DGX Spark节点，一次干净的无恢复扫描将外部状态从1.956 GiB/秩增长到31.277 GiB/秩，而在$W=32$时测得的L1 RWS恰好保持在500.75 MiB/秩，外部状态与活动暂存的最大比率为63.959倍。第二次全新的524K令牌运行重复了最大状态接受结果。评估的层级和秩不对称故障在回退前暴露了完全重用或零外部重用。匹配的SSD优化将512K恢复TTFT从43.1秒降低到17.6秒，而不改变RWS。

## Abstract
Hierarchical KV-cache systems can retain long-context LLM execution state beyond GPU memory, but retention capacity does not determine the local memory required to make that state executable again. We isolate this second resource as the restoration working set (RWS): the peak local staging state whose lifetimes overlap during restoration. In the pinned upstream LMCache whole-plan path, measured full-reuse points for 1.956, 7.823, and 15.646 GiB/rank states first succeed at 2, 8, and 16 GiB L1 rungs, with successful L1 peaks of 1.956, 7.824, and 15.648 GiB/rank.   We introduce Bounded-State Restoration (BSR), which separates complete discovery from local residency. BSR probes the complete reusable prefix without materializing the whole hit in L1, then installs confirmed state through a reusable window of at most $W$ chunks. Under bounded auxiliary state, peak restoration capacity is $O(W)$ while total transfer and installation work remains $Θ(|S|)$. Because reusable state spans heterogeneous allocator groups and tensor-parallel ranks, BSR uses a request-level commit rule: partial installation is never exposed as a valid reusable prefix; failures invalidate the advertised prefix and fall back to a lower valid tier or deterministic recomputation.   On DeepSeek-V4-Flash with TP=2 across two DGX Spark nodes, a clean no-resume sweep grows external state from 1.956 to 31.277 GiB/rank while measured L1 RWS remains exactly 500.75 MiB/rank at $W=32$, a 63.959x largest-state external-to-live-staging ratio. A second fresh 524K-token run repeats the largest-state acceptance result. Evaluated tier and rank-asymmetric failures expose either complete reuse or zero external reuse before fallback. A matched SSD optimization reduces 512K restore TTFT from 43.1 to 17.6 seconds without changing RWS.

## 论文详细总结

### 1. 核心问题与整体含义（研究动机与背景）

- **背景**：长上下文LLM服务将先前计算视为可复用的执行状态，利用分层/解耦KV缓存系统在主机内存、SSD或远程内存中保留这些状态，从而避免未来请求重复执行长前缀预填充（prefill）。
- **核心问题**：现有系统主要关注**保留容量**（可保存在引擎外部的可复用状态量），但保留容量并不决定**恢复容量**——即使外部存储成功保留了状态，要将该状态恢复为可执行状态，本地暂存（staging）所需的峰值内存仍然与完整状态大小成正比。
- **关键洞察**：论文将这一瞬态资源需求命名为**恢复工作集（Restoration Working Set, RWS）**，证明“完整知识（complete knowledge）”并不需要“完整本地驻留（complete local residency）”。外部状态增长不必导致本地恢复容量的同步增长。
- **整体意义**：在DeepSeek-V4-Flash上，外部状态从1.956 GiB/秩增长到31.277 GiB/秩（16倍增长），而本地L1恢复暂存保持恒定的500.75 MiB/秩，实现了63.959倍的外部状态与活动暂存比率；同时512K恢复TTFT从43.1秒降至17.6秒（2.45倍加速）而不改变RWS。

### 2. 方法论：核心技术思想与流程

#### 核心思想

- **分离发现与驻留**：BSR打破了“要了解完整复用前缀就必须将其全部物化到本地”的耦合关系。外部发现可以产生**决策契约**（完整的候选命中集），而本地安装遵循**资源契约**（任意时刻活体暂存单元不超过W个）。

#### 三个关键定义与公式

1. **恢复工作集（RWS）**：
   - RWS(ρ) = maxt Σ ci（对所有在时刻t同时存活的恢复单元求和）
   - 它独立于外部状态足迹和正常模型执行所需的目标内存，衡量的是恢复本身造成的瞬态本地容量税。

2. **全计划物化**：RWS_whole(S) ≥ Σci = Θ(|S|)，本地恢复容量与选定状态大小线性相关。

3. **BSR有界安装**：RWS_BSR(S,W) ≤ W × cmax + Maux(W) = O(W)，与N（状态大小）无关。

#### 三阶段协议流程

1. **Probe（探测）阶段**：向存储层执行**probe-only查找**——确定保留的命中集并返回命中位图，但刻意不将整个L2结果保留在L1中，释放L1/L2读锁。结果为“哪些内容可恢复”的知识，而非字节的驻留。

2. **Install（安装）阶段**：目标块分配完成后，将确认的前缀按至多W个块（chunk）的窗口迭代处理。每个窗口经历**取回→验证完整→映射到目标块片→传输→同步→释放**的流程，只有释放后才能复用暂存空间处理下一窗口。原型使用全局锁串行化有界恢复，防止并发请求倍增暂存预算。

3. **Commit（提交）阶段**：在所有TP秩r和语义组g满足有效性条件后（Q(S)=1）才暴露完整前缀复用。任何窗口失败、超时或传输异常都会使目标块失效，并通过**HMA感知的整前缀失效**将通告前缀坍缩为零外部复用，回退到较低有效层级或确定性重计算。

#### 核心机制（实现层面）

| 机制 | 作用 |
|------|------|
| Probe-only查找 | 返回完整保留命中并释放查找侧暂存与读锁 |
| 恢复窗口配置 | 暴露prefetch window chunks参数；0保留传统行为 |
| 窗口化取回 | 逐窗口取回、验证、安装、同步、释放、复用 |
| 有界恢复锁 | 防止并发有界请求成倍放大暂存预算 |
| 失败块失效 | 防止失败的部分安装成为有效目标状态 |
| HMA感知失效 | 异构组中任一组无效即整前缀失效 |
| Force-local恢复 | 远端恢复失败后跳过重复外部查找，回归本地预填充准入 |
| FS加载并发 | 窗口内并行读取对象，不改变W或RWS |

### 6. 主要结论与发现

1. **全计划路径存在容量耦合**：32K/128K/256K外部状态（1.956/7.823/15.646 GiB/秩）首次完整复用分别需要2/8/16 GiB L1容量，成功时L1峰值跟踪完整选定状态（1.956/7.824/15.648 GiB/秩）。
2. **BSR实现了完全的容量解耦**：外部状态从1.956增长到31.277 GiB/秩（15.99倍），L1 RWS保持精确的500.75 MiB/秩（0字节变化范围），状态/暂存比达到63.959倍。
3. **W是精确的容量控制**：W=8/16/32/64时测得的RWS（125.1875/250.3750/500.7500/1001.5000 MiB/秩）与源核算等式ML1(W) = W × 16,408,576字节/秩完全匹配，零残余误差。
4. **协议对异构和故障fail-closed**：MTP-on的170张量状态满足相同接受标准；三类故障场景均暴露完整前缀复用或零外部复用（不外泄部分复用状态），输出哈希匹配且双秩健康。
5. **吞吐量与容量独立可调**：SSD对象加载并发从1提升到4，512K恢复TTFT从43.1秒降至17.6秒（2.45×加速），RWS保持不变，证明恢复容量和恢复吞吐量是两个可分别控制的资源维度。

### 7. 优点与亮点

- **理论贡献清晰**：将“恢复容量”从外部保留容量和总进程内存中分离为独立的可管理资源，并通过命题证明在固定W下峰值恢复容量为O(W)且与N无关。
- **抽象精准**：区分了“决策契约”（完整候选命中知识）与“资源契约”（活体暂存有界），这是设计的关键跃迁。
- **语义正确性处理严谨**：针对可复用状态跨越异构分配器组和TP秩的现实，设计了请求级提交规则（Q(S)），防止部分安装被解释为有效前缀。
- **实现侵入面小**：只修改了LMCache的控制路径和vLLM的调度器集成，模型内核、外部状态表示和注意力语义完全不变，表明方案可落地性较强。
- **测量方法严谨**：主实验使用无恢复扫描、提交的证据文件、严格的接受标准（缓存token核算+输出哈希+TP健康），避免了常见的“对象计数对齐即成功”的弱验证。
- **容量定律可预测**：W到RWS的映射精确到字节级，为运维人员提供了可计算的容量规划公式。

### 8. 不足与局限

- **实验规模有限**：仅单个模型（DeepSeek-V4-Flash）、单个注册配置、双节点TP=2环境。未验证在更大TP规模、多请求并发、多模型混合场景下的表现。
- **系数不具有普适性**：16,408,576字节/秩的W系数是模型特定值，不同模型/状态表示会有不同的ci值，实际部署需重新测量。
- **并发模型保守**：原型使用全局锁串行化所有有界恢复，限制了多请求并发恢复能力。论文提出全局准入预算B作为扩展方向但未实现。
- **512K上游数据缺失**：全计划阶梯未完成512K/32 GiB测量，对比图中缺少上游大状态的实证数据点（只用BSR侧展示）。
- **正确性是操作性的而非形式化的**：fail-closed属性依赖实现规则的正确执行，论文明确承认缺乏形式化验证。
- **性能未达最优**：恢复延迟随状态大小线性增长（符合理论预期），但未探索预取、I/O重叠、传输与安装的流水线优化；远程路径仍有查找、物化、安装、同步多个开销环节。
- **RWS非总进程内存**：论文只保证LMCache L1恢复池的有界性，模型权重、目标KV状态、通信缓冲区、元数据等其他内存可独立变化。
- **辅助实验重复性不足**：窗口定律、MTP、故障矩阵、吞吐量A/B多为单次测量，缺少统计置信度报告。
