## 摘要
Jaillet等人引入了一个在KV缓存内存约束不断增长的情况下批量处理非抢占式LLM请求的全在线模型。对于总端到端延迟，他们证明了每个确定性算法的竞争比为Ω(√n)，而基本的顺序上界是n。我们填补了这一差距。设R_det(n,M)为在内存M下恰好n个请求的最优确定性竞争比，并设R_det(n)=sup_M R_det(n,M)。对于每个n≥2，我们证明(n-1)/12 ≤ R_det(n) ≤ n，因此R_det(n)=Θ(n)。下界构造释放一个填满内存的长请求，观察其确定性开始时间，然后在长请求运行中途释放n-1个宽的单词元请求。没有短请求能与长请求重叠，而行事后调度在有益时以相反顺序运行两组。困难实例使用显式固定内存M=2(n-1)n。上界由统一因果串行策略实现。精确模型、因果性论证、两个比较器分支和量词顺序均在Lean 4中经过机器验证。精确有限控制和重放命令随证明一起提供。

## Abstract
Jaillet et al. introduced a fully online model for batching nonpreemptive LLM requests under a growing KV-cache memory constraint. For total end-to-end latency they proved that every deterministic algorithm has competitive ratio Omega(sqrt(n)), while the elementary sequential upper bound is n. We close this gap. Let R_det(n,M) be the optimal deterministic ratio for exactly n requests at memory M, and let R_det(n)=sup_M R_det(n,M). For every n >= 2 we prove   (n-1)/12 <= R_det(n) <= n,   so R_det(n)=Theta(n). The lower bound releases one memory-filling long request, observes its deterministic start time, and then releases n-1 wide one-token requests halfway through the long run. No short request can overlap the long one, whereas a hindsight schedule runs the two groups in the opposite order when useful. The hard instance uses the explicit fixed memory M=2(n-1)n. The upper bound is achieved by a uniform causal serial policy. The exact model, causality argument, both comparator branches, and quantifier order are machine-checked in Lean 4. Exact finite controls and replay commands accompany the proof.

## 1. 论文的核心问题与整体含义（研究动机和背景）

- 论文研究的是 **LLM 推理中 KV 缓存（Key-Value Cache）约束下的在线调度问题**。在连续批处理中，每个请求的 KV 缓存随生成 token 数增长，内存是调度器面临的主要瓶颈；调度器需要在请求到达时决定是否准入，并为未来内存增长预留空间。
- 已有的完全在线模型（Jaillet et al.）假设：请求到达时已知 prompt 和 output 长度、请求不可抢占、被准入的请求必须每轮推进，目标是最小化**总端到端延迟（TEL）**。
- 此前已知结果：所有确定性算法的竞争比下界为 **Ω(√n)**，而朴素的串行调度上界为 **n**，两者之间存在巨大多项式间隙。
- 本文的核心贡献是**彻底关闭这一间隙**：证明最优确定性竞争比满足  
  \[
  \frac{n-1}{12} \le R_{\text{det}}(n) \le n
  \]
  即 \( R_{\text{det}}(n) = \Theta(n) \)。
- 这一结果揭示了在完全在线、非抢占、KV 缓存增长的模型下，任何确定性调度器在最坏情况下都必然承受**线性于请求数 n 的竞争比损失**，并且该损失无法被进一步缩小。

## 2. 论文提出的方法论：核心思想、关键技术细节、公式或算法流程

- **上界算法（统一因果串行策略）**：
  - 给每个请求按到达时间和标签字典序排序，定义启动时间  
    \[
    b_q = a_q + \sum_{p \prec q} o_p
    \]
    即按到达顺序依次串行执行，前一个请求完成后才启动下一个。
  - 该策略是**因果的**：启动时间仅依赖已经到达的请求；每个请求单独可行，且任意两个请求不重叠，因此满足内存约束。
  - 竞争比上界证明：任意可行调度中，每个请求的流时间至少为 \( o_q \)，因此 \( \text{OPT} \ge \sum_q o_q \)；而串行策略的总流时间不超过 \( n \sum_q o_q \)，故得到上界 \( n \)。

- **下界构造（宽-短请求硬实例）**：
  - 固定 \( n = k+1 \)，内存 \( M = 2k(k+1) \)。
  - 先释放一个**长请求** \( L = (0, 1, M-1) \)（到达时刻 0，prompt 长度为 1，输出长度 \( M-1 \)），它几乎独占全内存。
  - 由于调度器是确定性的，观察长请求在单例实例中的开始时间 \( b \)；利用**因果性**，在扩展实例中长请求也在 \( b \) 开始。
  - 在时刻 \( r = b + M/2 \) 释放 \( k \) 个“短请求” \( S_j = (r, M/2, 1) \)，每个短请求的 prompt 大小约为 \( M/2 \)，输出 1 个 token。
  - **关键矛盾**：如果某个短请求在 \( b+M-1 \) 之前开始，则它与仍在运行的长请求的内存总和至少为  
    \[
    (M/2+1) + (M/2+2) = M+3 > M
    \]
    违反内存约束。因此所有短请求必须等待长请求结束后才能开始，每个短请求的流时间至少为 \( M/2 \)，总 TEL 至少为 \( kM/2 \)。
  - 为了得到离线最优的上界，论文构造了两个可行的事后调度分支：
    - **晚释放情形（\( r \ge M-1 \)）**：先调度长请求，再依次调度短请求，成本不超过 \( 2M \)。
    - **早释放情形（\( r < M-1 \)）**：先调度所有短请求，再调度长请求，成本不超过 \( 4M \)。
    - 统一取成本上界为 \( 6M \)。
  - 因此任意确定性调度器的竞争比至少为  
    \[
    \frac{kM/2}{6M} = \frac{k}{12} = \frac{n-1}{12}
    \]
    证明下界。

- **形式化验证**：论文使用 **Lean 4 和 Mathlib 4.32.2** 对模型定义、因果性论证、两个比较器分支、量词顺序等进行了机器验证，确保证明严格性。

## 6. 论文的主要结论与发现

- **定理 1**：对任意整数 \( n \ge 2 \)，  
  \[
  \frac{n-1}{12} \le R_{\text{det}}(n) \le n
  \]
  因此 \( R_{\text{det}}(n) = \Theta(n) \)。
- 具体地，最优确定性竞争比在所有内存规模上最坏情况下是**线性增长**的，填补了此前 Ω(√n) 与 n 之间的间隙。
- 下界构造说明：一个长请求造成的“内存堵塞”会导致后续所有短请求被迫等待，而离线最优可以通过选择长优先或短优先的更好顺序绕过这一瓶颈。
- 上界由简单且保守的串行策略实现，说明“串行执行”在竞争比意义上已是渐近最优。
- 论文进一步澄清了量词顺序的重要性：只有先固定内存 \( M = 2(n-1)n \) 再对所有调度器取最小竞争比，才能有效证明 \( \sup_M \inf_A \) 的线性下界，而不需要交换 sup 与 inf。

## 8. 不足与局限

- **固定内存下的精确竞争比未完全刻画**：定理只给出了 \( R_{\text{det}}(n) = \sup_M R_{\text{det}}(n, M) \) 的线性界，但未得到每位固定 \( M \) 下 \( R_{\text{det}}(n, M) \) 的精确函数关系。
- **硬实例的特殊性**：下界构造使用了 prompt 大小为 \( M/2 \) 的请求，因此对“有界 prompt 大小”“小固定内存”“请求大小跨度受限”等更实际的场景，结果未必适用。
- **常数未优化**：常数 \( 1/12 \) 和 \( 1 \) 并非最优，论文承认这一点；线性阶是主要结论，但精确常数仍待改进。
- **模型假设限制**：结果基于“已知输出长度、非抢占、每个活跃请求必须每轮推进”的模型；如果允许 kill/restart 或非 clairvoyant 设置，竞争比行为可能完全改变（论文也指出相关模型不能直接转移）。
- **没有系统级实验**：未用真实 LLM 推理负载或模拟器验证实际延迟表现，因此结论属于理论最坏情况，可能与实际系统平均性能有较大差距。
