## 摘要
一种常见的小模型部署方式是运行一个共享骨干网络和多个 LoRA 专家，它们在同一上下文上作答。朴素地服务它们会为每个专家重新预填充该共享上下文一次。我们研究一个范围狭窄但实际的问题：对于已经训练好的标准 LoRA 适配器——不是为缓存兼容性重新训练的适配器——如果骨干网络的预填充 KV 缓存只计算一次并在各专家间复用，任务质量能保留多少，以及在服务成本上能带来什么收益？在 Qwen3-1.7B 骨干网络上，使用两个适配器（HotpotQA 上的抽取式问答、GSM8K 上的算术推理），我们扫描专家从复用的基础缓存接管的分界点，并测量配对质量差异和服务成本。全前缀复用具有最低的预填充成本，并且在留出 GSM8K 上有较小的质量差异（在 160 token 预算下 Delta = -4.6 EM；320 个 token 下为 -3.0；第二个训练种子下为 -0.8——均偏向原生方案，只有第一个排除了零，且幅度不一致）。部分重计算没有显示出优势。质量等价性和通用边界选择规则均未得到确立。我们还报告了一种闭式岭回归 KV 转换器，其未能优于直接复用；以及专家依赖性对比，其区间均包含零。测得的服务收益是热缓存下的首 token 时间，它随上下文增长（8K 时约 16 倍）；双分支峰值内存仅降低 12%，而且经检查，前缀从未在各分支间物理共享——该实现复用了 KV 值，但复制了其存储，因此未实现共享缓存的内存节省。

## Abstract
A common small-model deployment runs one shared backbone with several LoRA specialists that answer over the same context. Serving them naively re-prefills that shared context once per specialist. We study a narrow, practical question: for already-trained standard LoRA adapters -- not adapters retrained for cache compatibility -- how much task quality is preserved if the backbone's prefill KV cache is computed once and reused across specialists, and what does that buy in serving cost? On a Qwen3-1.7B backbone with two adapters (extractive QA on HotpotQA, arithmetic reasoning on GSM8K), we sweep the boundary at which the specialist takes over from the reused base cache and measure paired quality differences and serving cost. Full-prefix reuse had the lowest prefill cost and a small quality difference on held-out GSM8K (Delta = -4.6 EM at a 160-token budget; -3.0 at 320 tokens; -0.8 under a second training seed -- all favoring native, only the first excluding zero, and the magnitude not consistent). Partial recomputation provided no demonstrated advantage. Neither quality equivalence nor a general boundary-selection rule is established. We also report a closed-form ridge KV translator that did not beat direct reuse, and specialist-dependence contrasts whose intervals all include zero. The measured serving benefit is warm-cache time-to-first-token, which grows with context (~16x at 8K); two-branch peak memory was only 12% lower and, on inspection, the prefix was never physically shared across branches -- this implementation reuses KV values but copies their storage, so shared-cache memory savings are not achieved.

# 论文总结：跨标准 LoRA 适配器的共享前缀 KV 复用

## 1. 核心问题与研究动机

- **背景**：小模型部署日益采用"组合式系统"——一个共享 backbone 挂载多个轻量 LoRA 专家，按请求路由。这些专家常在同一共享上下文（相同检索段落、对话历史、few-shot 示例）上作答，差异仅在于所应用的适配器。
- **痛点**：朴素服务方式会为每个专家对同一共享上下文重复执行一次 prefill，造成算力浪费。
- **现有方案的空隙**：
  - 前缀缓存（PagedAttention、RadixAttention）只解决**同一模型**相同前缀的复用；
  - 跨模型 KV 迁移（NVIDIA 闭式线性映射、CacheBridge）和 Activated LoRA 分别针对**不同规模模型**或**为缓存兼容性改造过的适配器**。
- **本文问题**：对于**已经训练好的标准 LoRA 适配器**（未为缓存兼容性重训），只算一次 backbone 的 prefill KV 缓存并跨专家复用，任务质量能保留多少？服务成本能获得什么收益？

## 2. 方法论

- **核心思想**：backbone 在**禁用适配器**（base 表示）下计算共享前缀的 prefill KV 缓存；随后选定专家在该缓存之上处理非复用的后缀并生成，全程**不施加任何 KV 映射**。
- **关键约束**：第一个答案 token 的 logits **始终来自专家**，专家至少处理一个 prompt token（保证首个答案由专家产出）。
- **算法流程（文字描述）**：
  1. `prefix_kv = forward(B, tokens[0:b], adapters_disabled).kv`——计算 b 个复用 token 的 base KV；
  2. `set_adapter(specialist)`——从 base 切换到专家；
  3. `out = forward(specialist, tokens[b:T], past=prefix_kv)`——专家处理后缀，位置 ID 从 b 继续；
  4. `logits_1 = out.logits[-1]`——首个答案 token 取专家 logits；
  5. 用专家与增长中的缓存做贪心解码。
- **接管边界（Takeover boundary）**：将 prompt 形式化为 `[instructions | demonstrations | question] -> answer`，扫描四种边界：
  - **native**：b = 0（专家计算整个 prompt）；
  - **early**：b = |instr|；
  - **question**：b = |instr| + |demos|；
  - **full-prefix**：b = T − 1（专家仅处理最后一个 prompt token，而非"只做生成"）。
- **辅助尝试（负结果）**：闭式 per-head 岭回归 KV 转换器（RoPE-stripped keys，单层 l→l 与 top-k 多层），意图将 base KV 映射到专家空间，但未优于直接复用。

## 3. 实验设计

- **模型与数据**：
  - Backbone：Qwen3-1.7B（bf16）；专家为 LoRA 适配器，rank 16、α = 32、dropout 0、目标模块 q/k/v/o 投影；
  - 任务一：HotpotQA 抽取式 QA（distractor split）；
  - 任务二：GSM8K 算术推理（main）。
- **Benchmark / 评测指标**：确定性指标——QA 用 token-level F1，GSM8K 用 exact-match（最终数值答案）；配对 bootstrap 95% 置信区间（10,000 次重采样）。
- **对比方法 / 条件**：
  - 四种接管边界（native / early / question / full-prefix）；
  - **base-only 基线**（不用适配器）——用于确立适配器必要性；
  - **own-KV 控制**（复用专家自身重算的前缀 KV，作为 harness 校验）；
  - **aLoRA** 适配器对比（初步运行）；
  - **岭回归 KV translator** 对比。
- **评测规模**：GSM8K 留出 500 例（test[580:1080]）与重叠 500 例（test[80:580]）；QA 2K n=300、8K n=200、700-token n=500；双分支内存 n=20。

- **可复现性**：代码、适配器 checkpoint、精确配置、prompt、逐例分数数组已发布于 GitHub（AltSlate-Labs/routekv）。

## 5. 实验数量与充分性

- **实验组数概览**：
  - 质量实验：GSM8K 留出（500）、GSM8K 重叠边界扫描（500）、QA 700/2K/8K（500/300/200）；
  - 控制实验：own-KV 控制（120）、base-only 基线、第二训练 seed 复制；
  - 诊断实验：320-token 预算诊断、专家依赖性对比（n=120 与 n=500）、双分支内存（n=20）；
  - 负结果：ridge KV translator（N_CAL=40 个上下文）、aLoRA 初步对比。
- **充分性评价（论文自陈）**：
  - **不够充分**：两个 seed 无法刻画 seed 变异性；单 backbone、1.7B 小规模、仅两任务；
  - **评估不独立**：n=500 边界评估（test[80:580]）与开发切片（test[80:200]）完全重叠，且最早开发运行用过 test[0:500]，属"后续放大评估"而非独立留出确认；
  - **混淆因素**：生成预算截断（复用 cap 命中率翻倍 15%→30%）与质量差距纠缠；QA 截断可能丢弃答案文本（未审计）；
  - **公平性亮点**：使用**同例配对**比较与配对 bootstrap CI，避免跨样本噪声；但专家依赖性对比 n 不一致、来自不同运行，区间均含零。

## 6. 主要结论与发现

- **总体定性**：跨标准 LoRA 专家复用 backbone prefill KV 是**质量–延迟权衡**，而非无损等价。
- **服务收益**：
  - 主要收益是 **warm-cache 首 token 时延（TTFT）**，随上下文增长：8K 时 30 ms vs. 486 ms，约 **16× 加速**；
  - 但 TTFT 改善不等于完成时延改善（GSM8K 因输出更长反而变慢：3149 vs. 2787 ms）。
- **内存的"重要更正"**：
  - 双分支峰值内存仅低 12%（8K），且经 tensor storage 检查，**前缀从未物理共享**（0% 试验别名）；
  - 该实现**复用了 KV 值但复制了存储**，因此共享缓存的内存节省**未实现**，需分页缓存才能达成。
- **质量损失**：
  - GSM8K：−4.6 EM（160 token，CI 排除零）、−3.0（320 token）、−0.8（第二 seed），**仅第一个排除零，幅度不一致**；
  - QA：700 token 时 +0.3 F1（匹配原生），2K/8K 时 −6.6/−4.5 F1，**损失随上下文变长**。
- **其他结论**：
  - 部分重算**无展示出的优势**；边界扫描非单调，"question takeover"点估计最差；
  - 岭回归 KV translator **未胜出**；
  - 专家依赖性**未确立**（差异区间均含零）；
  - base-only 差距（约 −45 EM）可复现，**适配器必要性稳健**。

## 7. 优点

- **诚实、克制的不确定性报告**：明确区分探索性与可信测量，主动标注 CI 是否排除零、样本是否重叠、结论是否可推广。
- **配对统计方法**：采用同例配对 bootstrap CI，适合 cached-vs-native 的比较场景。
- **负结果与纠错价值**：报告被拒绝的 ridge translator、未确立的专家依赖性，尤其**纠正了"逻辑复用 = 物理共享"的常见误解**（数据指针身份测试）。
- **控制实验设计**：own-KV 控制用于校验 harness，base-only 用于确立适配器必要性。
- **可复现性强**：公开代码、checkpoint、prompt、逐例分数数组与精确版本。

## 8. 不足与局限

- **覆盖范围窄**：单一 backbone（1.7B 小规模）、仅两任务、仅单 seed/任务，泛化性未验证。
- **评估偏差风险**：
  - n=500 边界评估与开发切片重叠，非独立留出；缺少预设精度/非劣效边界的冻结 harness 与全新评估；
  - 生成预算截断（cap 命中率翻倍）部分解释了质量损失，320-token 诊断后 CI 含零，**无法区分截断与真实损失**。
- **实验未完成项**：持久共享缓存存储未实现；aLoRA 激活正确性未验证，其缓存-非缓存一致性检查 inconclusive，对比不可解释。
- **工作负载歧义**：full-prefix 测的是"完全相同 prompt 跨专家共享"，而"不同问题共享背景段落"对应的是 mid-prompt 边界——恰是 penalty 不确定之处，本文结果**不能推广到该设定**。
- **QA 数据未审计**：700-token 截断可能丢弃答案文本，分数为 oracle-context 设定下的下界。
- **质量与延迟的上下文尺度**：论文自陈未在任意尺度上声称等价；不同实验的上下文长度与测量条件并不完全匹配。
- **应用限制**：不能假定复用无损，需在自有适配器上确认后才可采用。
