## 摘要
长上下文下的自回归 LLM 推理受限于内存带宽，而非算术吞吐量；随着序列长度增长，瓶颈资源从模型权重转向键值（KV）缓存。对于 BF16 精度下的 Llama-3-70B，140 GB 的权重占用超过单块加速器的 80 GB HBM，而一条 128k token 的序列会额外增加 42 GB 的 KV 缓存。压缩、驱逐、分页、共享或卸载 KV 状态的技术大量涌现，但所报告的收益使用不一致的工作负载、硬件和质量指标，导致无法进行跨论文比较。这篇 SoK 论文从分析角度统一该领域，提出一种严格区分推导结论与报告结论的协议。我们推导出闭式算术强度，它是上下文长度的衰减函数，并以 NVIDIA H100、NVIDIA B200 和 AMD MI300X 的硬件拓扑为参数，包括每个 die 的带宽划分以及 KV 流量超过权重流量时的交叉长度。我们将文献分为五个领域：量化、token 驱逐、KV 分页、前缀缓存和异构分层，并在单一协议下于 128k 上下文评估每个领域的一种方法。核心发现是一个三区间结构：在硬件特定的交叉点以下，权重流量占主导，KV 压缩带来的加速可忽略不计；超过该交叉点后，KV 流量占主导，每个领域都以质量换取带宽节省，且带宽节省逼近 roofline 上限。分页和前缀共享是无损的，但解决的是容量问题，而非带宽问题。量化与驱逐直接削减带宽，其质量退化在低于 4-bit 精度时加速，并且在位置敏感任务上，驱逐的退化会变得不连续。分层将带宽墙转化为互连问题，其受 PCIe 或 NVLink 而非 HBM 约束。最后，我们给出在给定硬件、上下文长度和质量预算时选择压缩领域的设计规则。

## Abstract
Autoregressive LLM inference at long context is bounded by memory bandwidth, not arithmetic throughput, and the binding resource shifts from model weights to the Key-Value (KV) cache as sequence length grows. For Llama-3-70B in BF16, the 140 GB weight footprint exceeds the 80 GB HBM of a single accelerator, and one 128k-token sequence adds 42 GB of KV cache. Techniques that compress, evict, page, share, or offload KV state have proliferated, but reported gains use inconsistent workloads, hardware, and quality metrics, preventing cross-paper comparison. This SoK paper unifies the field analytically, with a protocol that strictly separates derived and reported claims. We derive closed-form arithmetic intensity as a decaying function of context length, parameterized by hardware topology for NVIDIA H100, NVIDIA B200, and AMD MI300X, including per-die bandwidth partitioning and the crossover lengths where KV traffic overtakes weight traffic. We classify the literature into five domains, quantization, token eviction, KV paging, prefix caching, and heterogeneous tiering, evaluating one method per domain at 128k context under a single protocol. The central finding is a three-regime structure: below a hardware-specific crossover, weight traffic dominates and KV compression yields negligible speedup; beyond it, KV traffic dominates and each domain trades quality for bandwidth savings approaching the roofline bound. Paging and prefix sharing are lossless but address capacity, not bandwidth. Quantization and eviction cut bandwidth directly, with degradation that accelerates below 4-bit precision and turns discontinuous for eviction on position-sensitive tasks. Tiering converts the bandwidth wall into an interconnect problem bounded by PCIe or NVLink rather than HBM. We close with design rules for selecting a compression domain given hardware, context length, and quality budget.

## 一、核心问题与整体含义（研究动机与背景）

- **背景**：自回归 LLM 逐 token 解码，每一步都要完整前向并注意力读取全部历史 token 的 Key-Value（KV）缓存。测试时推理（长思维链）把单请求上下文从 10³ 推到 10⁵–10⁶ token 量级。
- **核心判断**：解码阶段的成本是"从 HBM 搬运字节"，而非算术。BF16 下解码算术强度仅约 1 FLOP/B，而 H100 的 roofline ridge point 约 295 FLOP/B——相差近 300 倍，任何 kernel 优化都无法把解码变成计算受限。
- **瓶颈迁移**：权重读取按 batch 共享，KV 读取不共享。随上下文增长，KV 流量必然超过权重流量，binding resource 从模型权重转向 KV 缓存。文中例证：Llama-3-70B BF16 权重 140 GB 已超单卡 80 GB HBM，128k 序列再叠加 42 GB KV；10⁶ token 时达 328 GB（超过 4 张 H100 的聚合 HBM）。
- **领域痛点**：缓解技术已分化为五大族（量化、token 驱逐、KV 分页、前缀缓存、异构分层），但各自的评测使用互不一致的上下文长度、batch、硬件目标与质量指标，导致报告收益既无法组合、也几乎无法比较。
- **三类方法论缺陷**（作者归纳）：① 缺乏共享的 KV 流量分析模型，baseline 字节数因 batching/kernel/布局而异；② 忽视硬件拓扑（B200 双 die + NV-HBI、MI300X 八 XCD），同一压缩因子在不同 die/stack 映射下端到端收益差异巨大；③ 质量报告尺度不兼容（perplexity / needle retrieval / 下游任务分数），几乎无研究在同一协议下同时报告质量与吞吐。

## 二、方法论：核心思想与关键技术细节

### 1. 统一足迹模型（taxonomy 的脊柱）

- 提出式 (4)：`B_eff_kv(s) = 2·L·n_kv·d_h · w_q · r · s · σ⁻¹ · (1+φ)`
  - 架构常数 `2L·n_kv·d_h`：由 MHA/GQA/MLA 决定（GQA 按 group factor g 缩小，MLA 存 576 维 latent，约低 5×）；
  - `w_q`：量化后的元素宽度（Domain I 量化）；
  - `r ∈ (0,1]`：驱逐后的保留比例（Domain II）；
  - `φ ≥ 0`：分配粒度造成的碎片浪费（Domain III 分页把它压向 0）；
  - `σ ≥ 1`：跨请求前缀共享因子（Domain IV）；
  - 分层（Domain V）不缩小字节，而是引入驻留向量 `λ = (λ_hbm, λ_dram, λ_nvme)`，决定每次读取走哪条互连。
- **五域在字节记账层面正交、可乘性组合**；但质量代价不可乘，必须联合验证。

### 2. 精确 FLOP / 字节记账（Appendix A 逐 kernel 展开）

- 单步 FLOPs：`F(s,b) = b(2P + 4L·n_q·d_h·s)`（softmax 的 `3L·n_q·s` 为低阶项，占注意力收缩的 3/(4d_h) ≈ 0.59%）。
- 单步字节（假设 FlashAttention 类 kernel 只读一次缓存）：`B(s,b) = P·w_p + 2b·L·n_kv·d_h·s·w_kv`。忽略的项：新 token 写入（相对修正 1/s，128k 时 8×10⁻⁶）、激活与 logit 流量。

### 3. 算术强度与其两个极限

- `AI(s,b) = b(2P + 4Ln_q d_h s) / (P w_p + 2bLn_kv d_h s w_kv)`
- `s→0` 极限 `2b/w_p`（随 batch 增长）；`s→∞` 极限 `2g/w_kv`（**batch 完全抵消**）。
- 强度不动点 `b† = g·w_p/w_kv`，BF16+GQA(g=8) 时 b†=8。生产服务 b ≫ b†，故实际中解码强度随上下文单调衰减。
- 推论：权重侧要到 ridge 需 b ≈ 295（H100），但该 batch 下 Llama-3-70B 的交叉点已降到 1.4k token——"权重可能变计算受限的 batch，恰好是任何超过一页 token 的上下文都已是 KV 受限的 batch"。

### 4. 拓扑感知的有效带宽模型

- 把封装建模为 D 个分区，本地带宽 `β_p = β_agg/D`，die-to-die fabric 带宽 `β_f`：
  `T_read(x,γ) = max(γx/β_p, (1-γ)x/β_f)`，`β_eff = x/T_read`。
- **Pinned（γ=1）** 只能拿到 β_p；**Striped（γ=1/D）** 在 `β_f ≥ (1-1/D)β_agg` 时可恢复全聚合带宽（Proposition 3.6）。
- 结果：B200 pinned 损失 2×（8.0→4.0 TB/s），MI300X pinned 损失 8×（5.3→0.66 TB/s）。

### 5. 两个交叉律

- **流量交叉**：`s*(b) = P·w_p / (2b·L·n_kv·d_h·w_kv)`，KV 流量占比 `η = s/(s+s*)`，随 batch **双曲线式下降**（`s*(b) = s*(1)/b`）——batching 加速而非推迟 KV 受限的到来。
- **容量交叉**：`s_cap = (C_hbm - P·w_p)/(2L·n_kv·d_h·w_kv)`。
