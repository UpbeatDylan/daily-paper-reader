## 摘要
长时间运行的多轮请求会累积可复用的键值（KV）状态。一旦该状态超出固定的 GPU KV 缓存分配，服务系统就会逐出可复用前缀、重复执行预填充工作，并可能抢占请求。这种压力对混合专家（MoE）模型尤为突出：尽管每个 token 仅激活稀疏的专家子集，其专家权重仍占据大部分 GPU 高带宽内存（HBM）。权重与 KV 缓存之间的静态边界，使服务系统无法在对话增长时利用专家内存来保存可复用状态。我们提出 VAMP，一种在运行时改变该 HBM 边界的 MoE 服务框架。当无法满足 KV 分配时，VAMP 会比较三种备选方案的预估未来工作量：从主机内存暂存专家权重、逐出可能需要重新预填充的缓存前缀，或抢占并重新调度请求。当该操作具有最低预估代价时，它会将有界的专家权重区域转换为 KV 缓存容量。CUDA 虚拟内存管理页重映射可在不复制驻留 KV 数据的情况下完成此转换。我们在 vLLM 服务引擎中实现了 VAMP，并在记录的与受控的多轮工作负载上评估 Qwen3-Next-80B。在五次重放一个记录的 2,103 轮 SWE-bench 智能体工作负载中，采用 15% 最大专家卸载比例的 VAMP 将首 token 时延（TTFT）p90 从 26.1 秒降至 1.10 秒（23.6 倍），相对于未修改的 vLLM 将请求吞吐量提高 20.7%，同时将每输出 token 时间（TPOT）增加 31.1%。

## Abstract
Long-running multi-turn requests accumulate reusable key-value (KV) state. Once this state exceeds a fixed GPU KV-cache allocation, serving systems evict reusable prefixes, repeat prefill work, and may preempt requests. This pressure is particularly acute for Mixture-of-Experts (MoE) models: their expert weights occupy most GPU high-bandwidth memory (HBM), even though each token activates only a sparse subset of experts. A static boundary between weights and the KV cache prevents serving systems from using expert memory to preserve reusable state as conversations grow.   We present VAMP, an MoE serving framework that changes this HBM boundary at runtime. When a KV allocation cannot be satisfied, VAMP compares the estimated future work of three alternatives: staging expert weights from host memory, evicting cached prefixes that may require re-prefill, or preempting and rescheduling requests. It then converts a bounded expert-weight region into KV-cache capacity when that action has the lowest estimated penalty. CUDA Virtual Memory Management page remapping performs this conversion without copying resident KV data.   We implement VAMP in the vLLM serving engine and evaluate Qwen3-Next-80B on recorded and controlled multi-turn workloads. Across five replays of a recorded 2,103-turn SWE-bench agent workload, VAMP with a 15% maximum expert-offloading ratio reduces time-to-first-token (TTFT) p90 from 26.1 s to 1.10 s (23.6 times) and increases request throughput by 20.7% relative to unmodified vLLM, while increasing time per output token (TPOT) by 31.1%.

## 1. 核心问题与整体含义（研究动机与背景）

- **背景趋势**：LLM 服务正从单轮短上下文转向长时多轮智能体（agentic）任务。生产环境中的 agent 轨迹平均约 157 轮、32.7k tokens，部分超过 1M tokens。
- **两个被打破的假设**：
  - **假设一**：模型权重只占 HBM 的一小部分，能为 KV cache 留出充足空间。MoE 架构结构性破坏该假设——MoE 通过稀疏激活解耦"模型容量"与"单 token 计算量"，导致总参数量爆炸（Mixtral 47B/激活 13B；DeepSeek-V3 671B/激活 37B；Qwen3-Next-80B 80B/激活 3B）。在 2×H100 TP2 上，仅专家权重就占 72.0 GiB（总 94 GiB），基线 KV-cache 池仅 8.02 GiB。
  - **假设二**：KV-cache 需求始终在预分配池内。多轮场景下 KV 足迹与可复用前缀随轮次持续增长，利用率常驻 80%–100%，反复触发驱逐与重预填充。
- **核心现象——"前缀缓存悬崖"（prefix-cache cliff）**：一旦可复用前缀足迹超出 KV-cache 容量，前缀缓存命中率骤降、TTFT 尾部急剧飙升。这不是渐进退化，而是阈值驱动的突变。
- **根本矛盾**：现有服务系统在权重池与 KV-cache 池之间划出**静态硬边界**，运行时无法跨池借用。压力下调度器只能 LRU 驱逐缓存块或抢占请求，二者恰恰在"前缀复用价值最高时"降低前缀覆盖率，引发"驱逐—重计算"级联。
- **两大挑战**：
  1. 决策时刻各动作的**未来代价未知**（专家卸载的传输代价取决于剩余执行量；KV 驱逐代价取决于未来前缀共享模式）。
  2. 现有框架**缺乏运行时动态调整边界的机制**。既有卸载工作（Fiddler、MoE-Lightning）把专家搬到 CPU，但不把回收的 HBM 转给 KV 池；Oneiros 虽用页重映射做跨池回收，但面向多租户 dense 模型的空闲副本，不适用于单模型 MoE 场景。
- **整体含义**：需要把 HBM 视为**统一共享池**，以"价值感知"的方式在专家权重与 KV cache 之间动态重分区，把前缀缓存悬崖推迟到更高的 KV 需求处。

## 2. 方法论：核心思想、关键技术细节与算法流程

### 2.1 总体思想
VAMP（Value-Aware Memory Partitioning）在**每次 KV 分配无法满足时**，用三路代价模型比较三种动作的预估未来惩罚，选择代价最低者执行；当专家卸载胜出时，用 **CUDA VMM 页重映射**把有界专家权重区的物理页转为 KV-cache 容量（无需拷贝驻留 KV 数据）。

### 2.2 三大组件
1. **价值感知动作选择**（Value-Aware Decision）
2. **动态资源编排器**（Dynamic Resource Orchestrator，基于 CUDA VMM 重分区）
3. **批处理感知的专家卸载**（Batching-Aware Expert Offloading，双缓冲暂存）

### 2.3 三路代价模型（公式说明）

- **缓存块驱逐代价 Cc**：
  - 先估计有效复用概率 `peff = α · rhit / (1 + age/τ)`，其中 `rhit` 为滑窗前缀命中率，`age` 为 LRU 前端候选的年龄，α=0.5、τ=2000 调度步。以 LRU 前端年龄作为整个被回收集合的代理，倾向**低估** Cc（保守保护缓存）。
  - `Cc = peff · (ntok · tprefill + toverhead)`，ntok 为被回收块持有 token 数，tprefill=15 μs/token，toverhead=tsched+tqueue=500+1000 μs。

- **专家卸载代价 Ce**：
  - 卸载后每个模型步都需暂存各层被卸载区域（与路由器选择无关）。设 `ncand = g · ngroups` 为候选扩展的分片等效规模（ngroups 由分配缺口估计，每组含 g 个分片），E 为每层每 TP rank 本地专家分片数。
  - `Ce(ncand) = min(ncand, E) · ceff · w`，其中 ceff=12.3 μs（由 creload=0.63 ms、k=10、E=512 换算），w 为运行请求中最小的剩余解码预算（clamp 到 1–64 解码步）。该 cap 仅用于动作比较，不限制实际暂存数据量。

- **请求抢占代价 Cp**：
  - 单次抢占：`Cp(1) = tsched + tqueue + npartial · tprefill`（npartial 为受害者最后一个未填满块的 token 数）。若正好落在块边界则无收益、不作候选。
  - 覆盖 G 块缺口：`Cp = Cp(1) · G`，与其它动作统一到 G 块基准。

- **组合动作代价 Cb**：
  - 专家扩展按固定增量推进，若缺口非整数倍，向下取整后剩余部分叠加驱逐：`Cb = Ce(floor) + Cc(remainder)`。

- **决策规则**：在 Ce、Cc、Cp、Cb 中选择覆盖分配缺口的最低代价可行方案；若专家卸载已达上限，则只在 Cc、Cp 中选。

### 2.4 动态 HBM 重分区（关键技术）
- **专家组（expert group）**：最小页对齐重映射单元，由若干连续 rank-local 专家分片组成，大小对齐 CUDA VMM 分配粒度。Qwen3-Next 中每组占 3 个 2-MiB 页（6 MiB）：TP2 下为 2 个 3-MiB 分片，TP4 下为 4 个 1.5-MiB 分片。
- **重映射流程**：用 CUDA VMM 取消选中专家组的物理页映射并重新映射到 KV 池；专家张量的虚拟地址范围保持保留，驻留权重地址不变，仅被卸载区域的物理后备被重新指派。KV 分配器把回收页插入空闲块池立即可用。
- **跨 rank 一致性**：各 TP rank 独立计算可新增的 KV 块数，取最小值后统一重映射相同数量。
- **卸载上界**：每 rank 每可卸载层最多卸载 Ebuffer 个分片（受暂存缓冲容量限制），至少保留 E−Ebuffer 个驻留；配置的最大卸载比 VAMP-r 可进一步收紧。层内保留低索引专家组驻留、卸载高索引连续区域，驻留边界在各层按当前缺口与页几何统一移动。
- 当前控制器**不**在压力缓解时反向恢复专家驻留。

### 2.5 批处理感知的专家卸载
- **动机**：虽然每 token 只选 top-k=10 专家，但一个 batch 的 MoE 层执行需要该步内所有 token 选中专家的并集。实测 1,012 个模型步中，每层不同路由专家数均值 262–473（共 512），最高达 494。因此按需逐专家拉取会让 MoE 内核等待传输，跳过缺失专家又会改变输出。
- **策略**：每层在执行前**整块暂存该层整个被卸载区域**，与路由结果无关；用双缓冲（两个 staging buffer 交替）把层 N+1 的权重拷贝与层 N 的 MoE 计算、dense、router 操作重叠（专用 copy stream）。TP2 下可在 gate/up GEMM 权重到位后即启动、继续传 down 投影；TP4 下需等待两部分权重。
- 高索引专家权重初始化时即驻留于 pinned host memory，边界变化时无需 host 侧重打包。

### 2.6 实现
- 在 vLLM 0.15.1 中以约 **7,100 行代码**实现（PyTorch 2.9.1、CUDA 12.8），集成价值感知决策到调度器、VMM 动态编排、MoE 路径批处理感知卸载。

  - 未与 Fiddler、MoE-Lightning、Oneiros、CrossPool 等最相关系统做**实测对比**，仅定性区分。
  - 两平台在 GPU 型号、HBM 容量、TP 度、互连上同时不同，**无法隔离互连效应**（作者已声明）。
  - 缺少对成本模型系数、α/τ/w 等超参的**消融实验**。
  - SLO 分析基于固定并发重放，`Q` 不能估计最大可持续请求率。

## 6. 主要结论与发现

- **TTFT 大幅改善**：2,103 轮记录重放（n=5）中，VAMP-15 把 TTFT p90 从 26.1 s 降到 1.10 s（**23.6×**），p99 从 32.7 s 降到 3.48 s（9.4×）。
- **吞吐与缓存改善**：请求吞吐 +20.7%（0.596→0.720 req/s）；前缀缓存命中率 0.19%→89.8%；平均排队时间 15.1 s→21 ms（−99.9%）；每千轮抢占 562.7→0.18（−99.9%）。
- **代价**：TPOT 从 170.9 ms 升至 224.0 ms（**+31.1%**），即用解码延迟换首 token 延迟。
- **HBM 回收能力**：H100 上 VAMP-15/VAMP-20 把 8.0 GiB 基线 KV 池扩到 18.5/21.8 GiB（**2.30×/2.71×**）。
- **容量边界右移**：
  - H100：基线在 c=16 已越界（TTFT p99 22.1 s）；VAMP-15 在 c=24 越界，VAMP-20 在 c=28，VAMP-25 在评测范围内未越界。
  - H200：c=32 时基线 p99 升至 92.8 s，VAMP-20 保持 9.1 s（**10.2×** 降低）；VAMP-15 仅部分避开（28.3 s）。
- **闭环行为**：6 小时闭环中，基线 KV 利用率常驻 0.967、大量等待与抢占、末段平均 TTFT 142.5 s；VAMP-15 利用率 0.68、无等待无抢占、平均 TTFT 2.63 s。
- **卸载比不是越大越好**：VAMP-20 相比 VAMP-15 TTFT 相近但 TPOT 更高、吞吐更低；VAMP-25 在容量内会因传输开销反而拖累（c=28 时 p99 11.1 vs 8.9 s）。
- **SLO 权衡**：不存在全局最优配置——P=200 ms 紧预算下 vLLM/VAMP-10 领先，P≥250 ms 时 VAMP-15 全程领先，P=150 ms 时所有配置合格吞吐 <0.13 req/s。
- **崩溃可复现**：三次独立基线长跑均呈现"KV 利用率钉在 >95%、抢占近似线性累积（t=7.4 h 时 9,183 vs 9,243，差 0.7%）、前缀命中率衰减至

（接上文）……接近 0"的相同失效模式，说明该崩溃是**系统性、可复现的结构性缺陷**，而非偶发噪声；VAMP 的收益因此在统计上具备可重复性支撑。

- **控制器行为可解释**：决策日志显示，VAMP 在压力初期倾向选择驱逐（代价模型判定被回收块的复用概率低），随着会话轮次加深、`peff` 升高，逐步转为以专家卸载为主；`Cb` 组合动作主要出现在分配缺口非专家扩展增量整数倍时，用于补齐尾部缺口。这印证了三路代价模型确实在按"前缀复用价值"而非"固定优先级"分配 HBM。
- **收益来源分解**：前缀缓存命中率从 0.19% 跃升到 89.8% 是 TTFT 改善的主导因素——避免重预填充直接消除了排队与重计算级联；HBM 池扩容（2.30×–2.71×）则把悬崖阈值整体右移。两者叠加产生**超线性**的尾延迟收益，而非简单的容量线性外推。

## 7. 论文自陈的局限与未来方向

- **无反向恢复（no re-residency）**：当前控制器只在压力下把专家页转为 KV 容量，压力缓解后**不会**把 KV 页归还给专家。作者未做此设计的原因在于：反向迁移需要重新决定哪些专家恢复驻留，且可能引发页重映射抖动（thrashing）；但这意味着长时间运行后驻留专家集合可能偏离最优，是明确的后续工作方向。
- **成本模型为启发式**：α=0.5、τ=2000 步、`tprefill`=15 μs/token 等系数为开发期一次性设定，论文未提供敏感性分析或在线自适应机制，跨模型/跨硬件迁移时需要重新标定。
- **单一模型验证**：所有实验集中在 Qwen3-Next-80B-A3B，未覆盖专家数更少/更多、激活比更高（如 DeepSeek-V3 的 37B 激活）、或非 MoE 结构；通用性尚待验证。
- **缺少与同类系统的实测对比**：Fiddler、MoE-Lightning、Oneiros、CrossPool 等仅作定性区分，读者无法直接判断 VAMP 相对已有卸载/跨池方案的净增益。
- **两平台混杂变量**：H100 PCIe/TP2 与 H200 NVLink/TP4 在 GPU 型号、HBM 容量、TP 度、互连带宽上同时变化，作者承认无法隔离互连对卸载传输开销的影响。
- **闭环样本量有限**：n=3（部分 n=2）只能支撑"观察性"结论，作者明确未将其作为可复现性主张。
- **SLO 指标范围有限**：`Q(T,P)` 基于固定并发重放测得，不能用于估计系统最大可持续请求率，也不覆盖多租户或优先级混合场景。

## 8. 总体评价与启示

- **问题定位精准**：论文抓住的"权重池 vs KV 池静态硬边界"是 MoE 长时多轮服务中真实且被长期忽视的结构性瓶颈；"前缀缓存悬崖"这一阈值突变现象的刻画，比常规的"性能下降"叙事更有解释力与工程指导性。
- **方法设计自洽**：以"预估未来惩罚最小"统一三类动作（驱逐、卸载、抢占）的比较，把原本由固定优先级与 LRU 决定的调度，转化为显式的价值权衡；CUDA VMM 页重映射使"借 HBM"无需拷贝驻留 KV，工程上可行且开销可控。批处理感知卸载针对"batch 内路由并集≈全体专家"这一实测现象设计，避免了按需拉取的同步等待，是对 MoE 卸载常见误区的有效纠正。
- **代价坦率**：论文不掩饰 TTFT 换 TPOT 的权衡（+31.1% TPOT），并用 SLO 网格说明"不存在全局最优配置"，这种诚实的权衡呈现比单一指标的胜利更有说服力。
- **核心启示**：在 MoE + 长时多轮的负载下，**内存分区应当是运行时决策变量而非启动期常量**；且分区决策的依据应是"数据的未来复用价值"，而非"数据类型的静态优先级"。VAMP 的价值不仅在于 23.6× 的 TTFT 改善，更在于它示范了把 HBM 当作可重配置共享资源的系统范式——这一思路有望推广到 KV 与权重之外的其它内存竞争者（如激活缓冲、通信暂存、多模型共置场景）。
