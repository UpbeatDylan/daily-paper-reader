## 摘要
LLM 服务通过精确前缀匹配来复用 KV 缓存，因此当一个提示由一组可复用片段——检索到的段落、工具定义、少样本示例——组装而成时，这些片段的排序决定了可共享多少计算量。每个已部署系统都通过单一全局约定固定该顺序。我们证明，仅当请求至多包含两个片段时该做法才是最优的，而在一般情况下从渐近意义上是错误的。我们的主要结果是一条结构定理：最小前缀树成本等于 min_H sum_x w(x) t_x(H)，其中 H 为请求上的二叉层次结构，t_x(H) 是需要块 x 的请求集合的规范分解大小。因此，选择块顺序等价于在请求上选择一个层次结构。该恒等式给出了一个 O(3^m) 精确算法，将双片段情形识别为最小顶点覆盖，并表明在留一法族上，最优值是一棵二叉树的最小外部路径长度——即归并排序递归——因此全局顺序付出 Theta(n^2) 的代价，而真实成本为 Theta(n log n)。按公共交集进行凝聚聚类可实现节省的紧 1/2 近似。在三个 BEIR 语料库的 BM25 检索轨迹上，与生产 RAG 排序相比，所得布局将预填充减少 17–36%，且如理论预测，优势随检索深度增加而扩大。最后，按层次结构的 DFS 顺序服务请求，可使仅保存一个请求上下文的缓存精确达到无界缓存最优值，因此缓存容量与重排窗口可互为替代。

## Abstract
LLM serving reuses KV cache by exact prefix match, so when a prompt is assembled from a set of reusable pieces -- retrieved passages, tool definitions, few-shot exemplars -- the order chosen for those pieces determines how much computation can be shared. Every deployed system fixes that order by a single global convention. We prove this is optimal only when requests contain at most two pieces, and asymptotically wrong in general. Our main result is a structure theorem: the minimum prefix-trie cost equals min_H sum_x w(x) t_x(H) over binary hierarchies H on the requests, where t_x(H) is the canonical decomposition size of the set of requests needing chunk x. Choosing chunk orders is therefore equivalent to choosing one hierarchy over requests. The identity yields an O(3^m) exact algorithm, identifies the two-chunk case as minimum vertex cover, and shows that on the leave-one-out family the optimum is the minimum external path length of a binary tree -- the merge-sort recursion -- so a global order pays Theta(n^2) against a true cost of Theta(n log n). Agglomerative clustering by common intersection is a tight 1/2-approximation for the achievable saving. On BM25 retrieval traces over three BEIR corpora the resulting layout reduces prefill by 17-36% against production RAG ordering, and the margin widens with retrieval depth as the theory predicts. Serving requests in the hierarchy's DFS order finally lets a cache holding one request's context attain the unbounded-cache optimum exactly, so cache capacity and reorder window act as substitutes.

# 论文总结：《Prefix Sharing Is a Sorting Problem》

## 1. 核心问题与整体含义

- **背景**：主流 LLM 服务栈（vLLM、SGLang、TensorRT-LLM 及商业 API）都靠**精确前缀匹配**复用 KV cache——两个请求只在第一个不一致的 token 之前共享计算。
- **问题起源**：越来越多的真实流量中，prompt 并非用户手写的句子，而是系统拼装的可复用片段集合：RAG 检索段落、Agent 工具/函数定义、few-shot 示例、跨轮记忆/scratchpad、按租户组合的系统策略片段。
- **核心矛盾**：**片段是集合，prompt 是序列**。谁来定顺序？当前所有系统都用单一全局约定（检索排名、文档 id、流行度、插入时间），对所有请求一视同仁。而顺序对模型而言是自由的——模型看到同样的证据。
- **核心追问**：全局约定是最优的吗？答案：**仅在请求至多含两个片段时最优，一般情况下渐近错误**。
- **整体含义**：前缀共享的顺序选择本质上不是"排序问题"，而是**在请求集合上选择一棵二叉层次结构（聚类树）**的问题；这一定性把复杂度、精确算法、近似保证与调度统一到同一对象上。

## 2. 方法论

### 2.1 问题形式化（MPT）

- 给定 chunk 宇宙 $U$、权重 $w: U \to \mathbb{Z}_{>0}$（token 数）、请求 $R_1,\dots,R_m \subseteq U$。
- 为每个 $R_i$ 选一个排列 $\pi_i$，令 $T$ 为所得字符串的 trie，最小化
  $$\text{cost} = \sum_{v \in T,\, v \neq \text{root}} w(\text{chunk}(v))$$
- 该数值同时是 **prefill FLOP 账单**和（缓存足够大时）**KV 显存账单**。
- 两个变体：
  - $\text{OPT}_{\text{free}}$：每个请求独立排列（等价于"看到已铺设前缀再决定下一块"的自适应规则）；
  - $\text{OPT}_{\text{glob}}$：所有排列由 $U$ 上同一线性序诱导（即生产系统的做法）。

### 2.2 核心结果：结构定理（Theorem 1）

- 对 chunk $x$，记 $S_x=\{i: x\in R_i\}$；对请求集 $[m]$ 上的二叉层次 $H$，记 $t_x(H)$ 为 $S_x$ 在 $H$ 中的**规范分解大小**（$H$ 中完全含于 $S_x$ 的极大簇个数）。则：
  $$\text{OPT}_{\text{free}}(I)=\min_H \sum_{x\in U} w(x)\, t_x(H)$$
- 等价（利用二叉层次恰有 $m-1$ 个内部节点）的"节省形式"：
  $$\text{OPT}_{\text{free}}(I)=\sum_i w(R_i)-\max_H \sum_{v\ \text{internal}} w\!\left(\bigcap_{i\in\text{leaves}(v)} R_i\right)$$
- **证明思路**：
  - (≥) 任意布局的 trie 节点映射到请求子集，形成 laminar 族，可扩展为二叉层次；标号为 $x$ 的 trie 节点数 ≥ $t_x(H)$。
  - (≤) 给定 $H$ 自顶向下布局：在节点 $B$ 先发出 $I(B)\setminus I(\text{parent}(B))$，再递归两子节点；每个请求沿根到叶路径发出的集合不交且并集恰为其 $R_i$。
- **关键推论**：排列不再是独立自由度，**设计变量是请求的聚类**；兄弟子树不必以不同 chunk 开头；该恒等式与权重无关。

### 2.3 复杂度与全局序的边界

- **两片段情形（Proposition 2）**：$|R_i|=2$ 时 $\text{OPT}_{\text{free}}=\text{OPT}_{\text{glob}}=\tau(G)+m$，$G$ 为以请求为边的图，$\tau$ 为最小顶点覆盖数 → MPT 在 $k=2$ 即 NP-hard，且此时自适应性**毫无收益**。
- **Proposition 3**：最小可达的第一层代价是 $\{R_i\}$ 的最小权 hitting set，可由全局序达到——即"把最共享的 chunk 放最前"这条经验规则**只在顶层正确**。
- **Theorem 4（阈值是三）**：请求至多 2 个片段时 $\text{OPT}_{\text{glob}}=\text{OPT}_{\text{free}}$；3 个片段即失效，且最小反例**唯一**：$U=\{a,b,c,d\}$，请求为全部 4 个 3-子集，$\text{OPT}_{\text{free}}=8 < 9=\text{OPT}_{\text{glob}}$。即"全局 chunk 序的最小阻碍 = 4 顶点上的完全 3-均匀超图"。

### 2.4 无界分离（Theorem 5）

- **leave-one-out 族** $L_n$：$R_i=[n]\setminus\{i\}$（重主题重叠 RAG 流量的诚实漫画）：
  $$\text{OPT}_{\text{glob}}(L_n)=\tfrac{(n-1)(n+2)}{2}=\Theta(n^2),\qquad \text{OPT}_{\text{free}}(L_n)=n\lceil\log_2 n\rceil-2^{\lceil\log_2 n\rceil}+n=\Theta(n\log n)$$
  比值 $\Theta(n/\log n)\to\infty$。
- 推导要点：$S_x=[n]\setminus\{x\}$，在二叉树中单叶补集恰好分解为根到叶路径上悬挂的兄弟子树，故 $t_x(H)=\text{depth}(x)$，于是 $\text{OPT}_{\text{free}}$ = **二叉树最小外部路径长度** = 归并排序递归树（OEIS A001855）。
- **解读**：最优 KV 布局就是归并排序递归树；单一全局序是"缓存布局中的冒泡排序"——平方级 vs 正确的 $n\log n$。

### 2.5 算法与近似

- **凝聚公共前缀层次（本文方法）**：每个请求起始为单例簇，签名即 $R_i$；反复合并**公共交集权重最大**的两簇，签名取交集；再自顶向下遍历，在每个节点发出"在此处变为公共"的 chunk。$O(m^2\log m)$（bitset 交集），**无超参数**，正是节省形式的自然贪心。
- **Theorem 6**：令 $\text{SAV}(H)=\sum_{v\ \text{internal}} w(I(v))$，$H_g$ 为上述贪心层次，则对任意权重
  $$\text{SAV}(H_g)\ge \tfrac12 \max_H \text{SAV}(H)$$
