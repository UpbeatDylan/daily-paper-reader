## 摘要
混合LLM将全注意力层与线性注意力层交错排列，以降低长上下文推理成本，但这种结构使前缀缓存变得复杂。全注意力的KV缓存可按token寻址，而线性注意力层维护的循环状态无法回滚到任意前缀边界。现有系统通过物化循环状态检查点，将前缀复用限制在检查点对齐的位置。

我们提出 SuffixReplay，这是首个无需物化循环状态检查点、即可让混合LLM在缓存支持的每个页边界复用已缓存前缀的前缀缓存系统。我们的关键洞见是：只需让线性状态遗忘遥远过去。现代线性注意力机制利用循环衰减和门控来削弱旧输入的影响。因此，SuffixReplay 不是为每个前缀边界做检查点，而是仅重放该层输入隐藏状态中最近的后缀，并将其保留为锚点，从而近似匹配边界处的状态。在算法层面，SuffixReplay 将逐层和逐token的锚点稀疏性与有界重放预算相结合，以控制存储、计算和质量。在系统层面，它使用独立管理的锚点 sidecar 和流水线化重放路径，将锚点移动和状态重建与原生服务流水线重叠。我们在三个混合LLM上评估 SuffixReplay：OLMo-Hybrid-7B、Qwen3.5-4B 和 Qwen3.6-27B-FP8。在这些模型上，SuffixReplay 在 LongBench 和 RULER 上平均保留全预填充质量的 91.4–100%，同时仅使用 SGLang 默认 8192-token 检查点缓存的 0.36–0.51 倍摊销每token存储。集成到 SGLang 后，SuffixReplay 在分支工作负载上将中位 TTFT 降低 15–70%，当工作集超过 HBM 时保持 SGLang 的 2.3–4.3 倍吞吐量，并在高命中延续流量上与 SGLang 持平。

## Abstract
Hybrid LLMs interleave full-attention layers with linear-attention layers to reduce long-context inference cost, but this structure complicates prefix caching. Full-attention KV caches are token-addressable, whereas linear-attention layers maintain recurrent states that cannot be rolled back to arbitrary prefix boundaries. Existing systems materialize recurrent-state checkpoints, restricting prefix reuse to checkpoint-aligned positions.   We present SuffixReplay, the first prefix caching system that lets hybrid LLMs reuse cached prefixes at every cache-supported page boundary without materializing recurrent-state checkpoints. Our key insight is to just let linear states forget the distant past. Modern linear-attention mechanisms use recurrent decay and gating to attenuate the influence of old inputs. Therefore, instead of checkpointing every prefix boundary, SuffixReplay approximates the state at a matched boundary by replaying only a recent suffix of the layer's input hidden states, which we retain as anchors. At the algorithmic level, SuffixReplay combines layer-wise and token-wise anchor sparsity with a bounded replay budget to control storage, computation, and quality. At the system level, it uses an independently managed anchor sidecar and a pipelined replay path to overlap anchor movement and state reconstruction with the native serving pipeline. We evaluate SuffixReplay on three hybrid LLMs: OLMo-Hybrid-7B, Qwen3.5-4B, and Qwen3.6-27B-FP8. Across these models, SuffixReplay retains 91.4-100% of full-prefill quality on average across LongBench and RULER, while using only 0.36-0.51x the amortized per-token storage of SGLang's default 8192-token checkpoint cache. Integrated into SGLang, SuffixReplay reduces median TTFT by 15-70% on branching workloads, sustains 2.3-4.3x SGLang's throughput when the working set exceeds HBM, and matches SGLang on high-hit continuation traffic.

# 论文总结：Just Let Linear States Forget the Distant Past: Prefix Caching via Suffix Replay for Hybrid LLMs

## 1. 核心问题与研究动机

- **背景**：长上下文 LLM 服务面临两股互补的技术潮流——模型层面采用**混合架构**（全注意力 FA 层 + 线性注意力层交错），以削减二次复杂度的 FA 计算；系统层面采用**前缀缓存**，复用共享前缀以避免重复 prefill。
- **矛盾点**：前缀缓存的抽象是为 FA-only 模型设计的。FA 层的 KV 缓存是**按 token 可寻址**的，任意前缀边界都能直接截断复用；而线性注意力层把整个前缀压缩为一个**固定大小的循环状态**，通过原地更新推进，一旦推进到后位就无法代数回滚到任意更早的前缀位置（论文图 1a/1b）。
- **现有方案的局限**：Marconi、Sparse Prefix Caching、SGLang 等通过**物化循环状态检查点**来调和这一错配，使前缀复用被"离散化"——只有当命中端点恰好对齐已物化检查点时才可复用。加密检查点理论上可恢复 token 级粒度，但代价极高：Qwen3.5-4B 中一个线性状态检查点约 **49 MiB**，而单 token KV 仅约 **32 KiB**，相差约 **1500×**。
- **整体含义**：论文提出让混合模型获得与 FA-only 模型相同的**"连续前缀缓存"（continuous prefix caching）**粒度——在缓存支持的任意页边界（64-token 页）都能复用，且**完全不物化循环状态检查点**。

## 2. 方法论

### 2.1 核心洞见
论文标题即核心思想：**"只需让线性状态遗忘遥远过去"**。两层依据：

- 线性层的状态是前缀输入的确定性函数：
  \[
  S_j = f(h_1, \dots, h_j)
  \]
  因此虽然 \(S_n\) 无法代数回滚到 \(S_j\)，但可以通过**重放输入**重建它。
- 现代线性注意力（Mamba2 的 per-head decay、Gated DeltaNet 的 decay + rank-one erase）通过**循环衰减与擦除门**逐步削弱远期输入的影响，故可用**近期后缀**近似：
  \[
  S_j \approx S'_j = f(h_{j-k+1}, \dots, h_j)
  \]
  重放代价由后缀长度 \(k\) 决定，而非前缀长度 \(j\)。

### 2.2 三条设计约束（R1–R3）
- **R1 保质量**：重建状态应作为全状态的足够精确代理，目标平均 ≥90% 全 prefill 质量。
- **R2 限存储**：额外存储不得超过 SGLang 默认 8192-token 检查点间隔下的摊销开销，即 \(B_{\text{anchor}} \le B_{\text{ckpt}}/8192\)。
- **R3 保性能**：TTFT、吞吐、并发容量不得劣于原生前缀缓存路径。

### 2.3 算法设计（§4）
- **层稀疏锚点（layer-wise sparse anchors）**：将连续线性层分组（Group），仅在每个组的**入口层**存一份输入隐藏状态作为锚点；重放只在组内执行线性注意力计算、**跳过 FA 层**。三点收益：(a) 层向存储由 \(O(L)\) 降到 \(O(G)\)；(b) 重放代价只与重放长度有关，与匹配上下文长度无关；(c) 每组从自己的入口锚点重启，误差不跨组传播。模型有 \(G\) 个 FA 层则锚点数 \(A = G-1\)（OLMo-7B、Qwen3.5-4B 为 7，Qwen3.6-27B 为 15）。
- **token 稀疏锚点（token-wise sparse anchors）**：只在**页边界对齐的子集**位置保留锚点，密度 \(\rho = 1/16\)（64-token 页保留最后 4 行锚点）。对比了均匀采样与**密集采样**（锚点集中在页尾），校准实验显示密集采样在同等重放预算下质量更稳，故采用后者。
- **重放预算**：以"保留的锚点数"而非原始 token 计量重放长度，命中长度 \(n\) 时
  \[
  k = \min(0.05\,n,\ k_{\max})
  \]
  主实验取保守上限 \(k_{\max}=512\)（Qwen3.5-4B）与 256（Qwen3.6-27B-FP8）；质量扫描显示 \(k=128\) 是推荐的更低成本设置。
- **存储公式**（附录 A）：\(B_{\text{ours}} = A \cdot d \cdot 2\rho\) 字节/token；相比朴素全存方案（\(L_{\text{lin}}\cdot d\cdot 2\)）降低约 51–55×。
- **算法—系统契约**：对每个缓存页给出关联锚点；对每次命中给出所需近期锚点与重放长度桶。

### 2.4 系统设计（§5）
- **锚点 sidecar**：锚点块与其对应 KV 页挂在**同一 radix-tree 节点**上、共享准入与淘汰决策，但使用**独立的内存池与放置策略**（锚点可留主机 DRAM 而 KV 页在 HBM），打破了两者的物理耦合。
- **锚点写入**：把目标选择移出前向计算，主机预计算 destination table，实际写入放进**已捕获的 CUDA graph**（未采样位置写入 scratch 地址）；prefill 时压缩采样 token，decode 时按请求槽增量更新；完成后以页粒度异步传输与发布（Qwen3.5-4B 一个 64-token 页约 140 KB）。作者指出朴素实现会因**主机交互次数**而非传输字节导致 decode 吞吐下降（\(\rho=1/8\) 时 −3.3%，\(\rho=1/2\) 时 −12.1%）。
- **流水线化重放**：锚点拉取在专用 copy stream 上于 KV 回填前异步启动；重放在 replay stream 上按组顺序执行，forward stream 仅在到达消费该组状态的层时等待。重放图按"重放长度桶 × 组"预先捕获；批内多命中的重放后缀被**打包成一次变长执行**（用 device-side 边界与 sentinel 槽区分）。
- **fail-closed 设计**：非页对齐命中、锚点缺失/未发布、队列满、重放钩子不可用一律降级为 cache miss 走全 prefill；超出捕获桶的长度回退到 eager replay。
- **多轮快路径**：若上一轮活跃线性状态仍在，则直接续用、完全跳过重放；但该状态只是 best-effort，被淘汰也不影响正确性（重放路径始终是正确性路径）。
- **实现**：基于 SGLang v0.5.18，引擎侧改动约 **1.2K 行**、涉及 17 个既有文件 + 2 个新文件；**不修改任何注意力或循环状态 kernel**。Qwen3.5-4B 上捕获 48 个重放图、约 **1.1 GB** 显存，共享同一显存池，剩余显存低于 2.5 GB 时停止捕获。
