## 摘要
端侧大语言模型（LLM）服务是本地优先个人智能的基石，为用户提供数据主权、强隐私保障，并摆脱云 API 的延迟与成本。尽管 KV 缓存被广泛用于降低长上下文推理的延迟，但现有设计主要针对具有动态执行环境和充足内存带宽的云端 GPU 进行优化。这些架构假设在移动 NPU 上并不成立：在移动 NPU 上，计算图必须静态编译，且内存容量和 I/O 带宽都受到严重限制。在这项工作中，我们提出了一种面向移动端的计算-存储协同设计，用于前缀和非前缀 KV 复用。我们首先提出一种图内机制，将选择性 KV 重计算映射到静态 NPU 图上，从而协调算法的动态性与 NPU 的静态性。我们进一步开发了一种图间调度器，利用动态规划优化块合并并最小化填充。为解决移动带宽限制，我们引入一种分层 KV 管理器，其具有树-哈希-语义混合结构，并配有成本感知的预取和淘汰策略。我们还构建了一个二维流水线，将 KV 加载、重旋转和存储与 NPU 执行重叠，从而隐藏数据移动延迟。在代表性端侧工作负载和 LLM 上的实验表明，与不复用和仅前缀缓存相比，我们的设计将首 token 时间（TTFT）降低了 40-60%。

## Abstract
On-device large language model (LLM) serving is a cornerstone of local-first personal intelligence, offering users data sovereignty, strong privacy guarantees, and freedom from cloud API latency and cost. Although KV caching is widely used to reduce latency in long-context inference, existing designs were primarily optimized for cloud GPUs with dynamic execution environments and abundant memory bandwidth. These architectural assumptions do not hold on mobile NPUs, where computation graphs must be statically compiled and both memory capacity and I/O bandwidth are severely constrained. In this work, we present a compute-storage co-design for mobile-centric prefix and non-prefix KV reuse. We first propose an intra-graph mechanism that maps selective KV recomputation onto static NPU graphs, reconciling algorithmic dynamicity with NPU staticity. We further develop an inter-graph scheduler to optimize chunk merging and minimize padding with dynamic programming. To address mobile bandwidth limitations, we introduce a hierarchical KV manager featuring a tree-hash-semantic hybrid structure, along with cost-aware prefetching and eviction policies. We also build a two-dimensional pipeline that overlaps KV loading, rerotation, and storage with NPU execution, hiding data-movement latency. Experiments across representative on-device workloads and LLMs show that our design reduces time-to-first-token (TTFT) by $40-60\%$ compared with no reuse and prefix-only caching.

## 二、方法论

### 2.1 总体架构（图 2）
- 三层结构：**计算层**（图内静态化 + 图间调度）、**存储层**（分层 KV 管理 + 预取/淘汰）、**应用层**（文档 QA、对话历史、Agent 技能）。
- 关键设计原则：动态选择性重算 → 静态 NPU 图；分层 KV 管理 → 逼近算力单元；I/O 与 CPU/NPU 执行流水重叠 → 隐藏搬运延迟。

### 2.2 计算侧：图内静态化（§4.1）
- **chunk–pad–mask**：将非前缀 token 切分为固定长度块，不足则 padding；计算 KV 偏差前施加 valid mask，排除填充 token 进入 Top-K，并**强制选中最后一个 token** 以产出正确 logits（解决动态输入形状与输出 token 动态性）。
- **scatter–gather**：Top-K 选中的高偏差 token 重算 KV 后散射回被复用的 KV 缓存，替换对应条目（解决 token 选择与 KV 更新流程的动态性）。
- **图尺寸的延迟最优配置**：设 prefill 图容量 $L_P$、选择性重算图容量 $L_S$，处理长度 $n$ 的延迟为 $\lceil n/L \rceil \cdot \text{Latency}(L)$；以代表性负载的 token 长度频率 $freq(n)$ 求期望延迟并最小化。图尺寸限定为 32 的倍数（对齐 Qualcomm HMX tile）。最终取曲线拐点：$L_S=512$、$L_P=128$，此时非前缀选择性重算比普通 prefill 快 **2–3×**。
- **混合精度**：KV 偏差计算与 Top-K 比较全程使用 **FP16**（其余中间激活为 UINT16、KV 为 SpinQuant INT8、权重 INT4），并引入缩放因子 $1/\sqrt{D_{head}}$ 防止 FP16 溢出，避免直接量化到 INT8/UINT16 带来的精度损失。

### 2.3 计算侧：图间调度（§4.2）
- **问题**：前缀可复用、非前缀可复用、新 token 在提示中任意交错（动态性 ⑤），按类型逐一调用静态图会产生碎片化与大量填充浪费。
- **关键观察**：新 token 总是被选中计算，因此**可安全并入相邻的选择性重算图调用**。
- **动态规划**：定义 $T[i]$ 为处理到位置 $i$ 的最小延迟，转移为
  $T[i] = \min\{\,T[i-l_s(i)] + t_s,\; T[i-l_p(i)] + t_p\,\}$
  其中 $t_s, t_p$ 为两类图的单次调用延迟；$l_s(i)$ 为在容量约束与最小重算比 $r$ 约束下（新 token 最多吸收 $\lfloor qr \rfloor$ 个、消耗 $\lceil \Delta/r \rceil$ 容量）能被一次重算图吸收的最长后缀；$l_p(i)$ 为 prefill 图能打包的最长后缀；前缀复用区不需计算（$T=0$）。
- 该 DP 全局决定每个尾块由重算图还是 prefill 图执行，而非局部贪心。示例中（图 8）把新 token 12/15/20 并入重算调用，prefill 调用从 4 次降到 2 次，约降 25% 延迟。
- **通用性**：机制只依赖"提前编译的固定形状静态图 + 实测延迟/容量"，可迁移到 MediaTek APU、Apple ANE，只需重新标定 $L_P$、$L_S$ 与对齐粒度。

### 2.4 存储侧：分层 KV 管理（§5）
- **NPU KV Manager**：在 CPU–NPU 共享缓冲区维护固定大小的会话 KV buffer（约 $10^1$ MB 量级），NPU 经 DMA 直接载入 TCM 消费。
- **CPU KV Pool**：约 $10^2$ MB 量级，用轻量哈希表按底层数据库行 ID 索引；只存新生成或预取的 KV 块，而非完整前缀树；内存压力下触发淘汰。
- **Flash KV DB（树–哈希–语义混合结构）**：
  - 前缀树支持前缀复用与层级组织；
  - 每块附带 **64 位哈希码**支持相同非前缀块的快速查找；
  - **语义索引**（关键词稀疏嵌入 + 截断稠密嵌入，仅在 RAG 场景复用已有 embedding）定位可能含可复用子块的候选；
  - 用**线性时间 LCS**（后缀自动机 + 稀疏转移，期望 $O(|X|+|Y|)$）最终确认可复用子串；
  - 工程上采用 **SQLite 仅存元数据 + KV 张量外置为文件系统文件**，避免大 BLOB 造成的页内/页间碎片与秒级插入/加载延迟（附录 D）。
- **异步预取**：I/O 空闲期主动加载高预测复用概率的前缀块；预取只用空间与语义局部性，避免内存污染。
- **成本感知淘汰**：局部性评分 $R(c)=w_sR_s+w_tR_t+w_mR_m$（空间/时间/语义），淘汰按 $R(c)\cdot C(c)$ 排序。
  - CPU 池淘汰成本：前缀块为从 Flash 重载延迟 $T_{load}$，非前缀块近似为 0（可被重叠隐藏）；
  - Flash 淘汰成本：$C_{flash}=Latency_P(|c_i|)+C_{cascade}$，其中级联项 $\sum_{c_j\in Des(c_i)} f(c_j)\cdot Latency_S(|c_i|)$ 刻画"淘汰前缀链上的块导致后代失去前缀可复用性"的额外开销。

### 2.5 计算-存储流水线重叠（§6）
- **KV 加载隐藏**：非前缀复用需按原位置与新位置对 K 张量做 RoPE 重旋转，量化流程中还需 SpinQuant 反量化/重量化与 Hadamard 变换（内存密集，$O(n\log n)$），因此把 I/O 加载与重旋转都放到 CPU 异步执行。
- **Chunk–Shard 二维流水线**：NPU 按模型 shard 执行、提示按 chunk 处理，形成两维并行；NPU 执行 Chunk 0 的某 shard 时，CPU 同时准备后续 shard 与下一 chunk 的 KV。实测 shard 级并行把前缀块与首个非前缀块的未重叠加载延迟降低 **4×**（图 12）。
- **KV 存储隐藏**：新生成 KV 先留在 CPU 池标记为 dirty，后台线程在 I/O 空闲（如解码阶段）批量异步落盘，规避同步写 Flash 的可见延迟与写放大。
