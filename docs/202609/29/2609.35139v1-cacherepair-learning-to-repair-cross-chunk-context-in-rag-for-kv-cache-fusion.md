## 摘要
多文档检索增强生成（RAG）要求语言模型在处理多个检索到的文本块后回答问题。独立预计算每个块的 KV 缓存，并在检索到这些块时拼接缓存，可加速这一步骤。然而，组装后的缓存缺少跨块注意力信息，从而降低答案质量。选择性重计算方法通过在选定 token 上重新运行目标 LLM 来恢复缺失的跨块上下文，但会带来大量在线计算。我们提出 CacheRepair，一个轻量级网络，用于学习独立计算的 KV 缓存与将各块一起处理所生成的 KV 缓存之间的差异。该网络将压缩的 KV 特征与 token 嵌入相结合，并使用在每个块内双向、且从较早块流向较晚块的注意力。每个修复块接收压缩的缓存特征，并将预测的残差加到每个文档 token 的缓存中。每个修复网络针对特定的冻结目标 LLM，在通用检索语料上训练，并复用于下游数据集。我们的分析表明，修复可减少块边界附近以及整个块内部的 KV 误差。在三个目标 LLM 和四个下游数据集上的评估表明，在十二个模型-数据集组合中的十一个上，CacheRepair 处于实测的答案质量-延迟帕累托前沿。报告的首 token 时间（TTFT）包括在线缓存传输和修复。在所有十二个组合中，最大的修复器相比完整预填充在中位 TTFT 上实现 1.69–4.61 倍加速，并相比直接复用缓存将平均 F1 提高 2.1–26.1 个百分点。

## Abstract
Multi-document retrieval-augmented generation (RAG) requires a language model to process multiple retrieved text chunks before answering a question. Precomputing each chunk's KV cache independently and concatenating the caches when the chunks are retrieved can accelerate this step. However, the assembled cache lacks cross-chunk attention information, reducing answer quality. Selective recomputation methods recover the missing cross-chunk context by rerunning the target LLM on selected tokens, incurring substantial online computation. We introduce CacheRepair, a lightweight network that learns the difference between independently computed KV caches and those produced by processing the chunks together. The network combines compressed KV features with token embeddings and uses attention that is bidirectional within each chunk and flows from earlier to later chunks. Each repair block receives the compressed cache features, and the predicted residual is added to every document token's cache. Each repair network is trained for a specific frozen target LLM on a generic retrieval corpus and reused across downstream datasets. Our analysis shows that repair reduces KV errors both near chunk boundaries and throughout chunk interiors. Evaluation across three target LLMs and four downstream datasets places CacheRepair on the measured answer-quality-latency Pareto frontier in eleven of twelve model-dataset combinations. Reported time to first token (TTFT) includes online cache transfer and repair. Across all twelve combinations, the largest repairers achieve 1.69-4.61$\times$ speedups in median TTFT over full prefill and improve mean F1 by 2.1-26.1 percentage points over direct cache reuse.

# CacheRepair 论文结构化总结

## 1. 论文的核心问题与整体含义

**研究背景**
- 多文档检索增强生成（RAG）中，LLM 需要在生成答案前对多个检索到的文本块（chunk）执行 prefill，导致首 token 时间（TTFT）显著增加。
- 为降低重复计算，可将每个 chunk 的 KV 缓存独立预计算并存储，在检索时按请求顺序拼接复用，从而支持跨请求、跨组合、跨顺序的缓存重用。

**核心问题**
- 独立预计算的 chunk 缓存彼此之间缺少跨块注意力信息（即后块无法关注前块），拼接后形成所谓 **stale KV cache**，与联合 prefill 得到的 **joint KV cache** 存在差异，直接复用会导致答案质量明显下降。
- 现有的选择性重计算方法（CacheBlend、EPIC、InfoFlow）通过在部分 token 上重新运行目标 LLM 来恢复跨块上下文，但需要大量在线计算。

**核心研究问题**
- 能否用一个**轻量级外部网络**直接在 stale KV 中恢复跨块上下文，同时保持目标 LLM 冻结、缓存仍可离线复用？

**关键观察（动机）**
- 对 Qwen2.5-3B 的实证分析表明，stale KV 与 joint KV 的误差并非只集中在块边界，而是呈现两类结构：
  - **边界局部热点**：块起始附近误差显著升高；
  - **层持久性误差带**：某些层中误差横跨块内部位置。
- 这意味着修复需要覆盖**所有文档 token**，而不仅是边界或部分选中 token。

## 2. 方法论

**核心思想**
- 用外部轻量网络 Rθ 学习「joint KV − stale KV」的**残差**，直接对拼接后的 stale KV 做修正，逼近联合 prefill 的 KV 状态，而不改动冻结的目标 LLM。

**问题形式化**
- 请求 r 包含有序文档序列 D_r = [C_{π(1)}, …, C_{π(m)}] 后接 query。
- 目标：dKV_r = Rθ(KV_stale,r, D_r) ≈ KV_joint,r。
- 修复只依赖有序文档，不依赖 query 文本。

**推理流程**
1. **Chunk 缓存准备**：每个 chunk 独立 prefill，K 在存储时先去掉局部 RoPE，转为 canonical 坐标；V 保持原始坐标。
2. **StaleEncoder 与 token 融合**：
   - 将目标 LLM 所有层的 KV 压缩为宽度 d_b 的特征向量 s_t（每层、每 KV head、K/V 分量各有独立投影）。
   - 输入按固定 RMS 统计量 σ_stale 缩放。
   - 与冻结 token embedding 经投影 P_tok 后的向量做线性融合，得到修复主干输入 h⁰_t。
3. **Repair Blocks（块因果注意力）**：
   - 注意力掩码 A_ij = 1[c(j) ≤ c(i)]：**块内双向**（同一 chunk 内 token 可互相注意），**块间单向**（信息从较早块流向较晚块），与缺失上下文的方向一致。
   - 每个 block 接收原始缓存特征的学习投影 P_b(s)，即 **stale-feature reinjection**，保持缓存条件信息贯穿修复过程。
4. **KV 残差输出与全局 RoPE**：
   - LayerNorm + 线性 KV Residual Head 输出归一化残差 z_t。
   - 通过固定残差尺度 σ_∆ 恢复 KV 单位，加到完整 stale cache 上（输出 skip connection 保留原始 KV）。
   - 最后对 K 应用**全局 RoPE**，将 K 放到请求中的绝对位置。

**训练细节**
- **配对缓存监督**：同一文档序列分别用目标 LLM 做独立 prefill 与联合 prefill，两者在 canonical 坐标下的差值作为监督目标：
  - ∆KV*_t = KV_joint,t − KV_stale,t。
- **归一化**：σ_stale 和 σ_∆ 按层、KV head、K/V 分量、head 坐标分别计算 RMS。
- **损失函数**：归一化坐标下的均方误差（MSE），每个文档 token 和 KV 坐标等权。
- **优化**：AdamW，β=(0.9, 0.95)，weight decay 0.01，梯度裁剪，BF16 目标 LLM，100,000 更新计划，取第 6 个 epoch 的 checkpoint。

**关键设计点**
- 修复网络为每个目标 LLM 单独训练，但同一 checkpoint 在四个下游数据集间复用。
- 修复网络使用更少层数、更小隐藏维度，所有 token 都处理，但在线成本远低于全量重计算。

- 消融：6 种变体（A0–A5）+ A5-JR，统一训练预算下对比。
- 训练目标：MSE / QK/V / Huber 三种。
- KV Packet 校准预算扩展：512 / 2048 / 8192 示例。

**充分性评价**
- **覆盖面较广**：跨 3 个不同规模、不同家族的 LLM（Qwen2.5-3B/14B、Llama-3.1-8B），跨 4 个数据集，涵盖多跳 QA、RAG、阅读理解。
- **统计严谨**：使用请求级 bootstrap、配对抽样、同时置信区间，报告 p50/p90/p99，且明确指出哪些差异的区间包含零。
- **公平性设计**：
  - 所有方法使用相同的问题、输入、tokenization 和 chat template。
  - 训练/评测数据做了严格去重筛查（证据句、50-token 跨度、问题来源）。
  - KV Packet 使用相同通用语料训练，并做了校准预算扩展以排除预算不足导致的偏差。
  - 明确说明「答案 F1 不必然介于 Stale 与 Full Prefill 之间」，并额外做了独立批次验证。
- **诚实报告负面结果**：Qwen2.5-3B/MultiHop-RAG 上 KV Packet 在原始批次中优于 CacheRepair；Qwen2.5-3B/HotpotQA 上无修复器满足半延迟预算；最大修复器相比 Full Prefill 在多数设置上仍有 0.35–8.38 F1 的差距。
- **消融充分**：对注意力拓扑（block-causal / token-causal / bidirectional / block-diagonal）、残差输出路径、直接预测 vs 残差预测、训练目标都做了受控对比。

**潜在不足**
- 主评测为单请求、单 A800、warm pinned-host cache，与真实多租户、并发、冷缓存场景有差距。
- 训练和评测均为英文数据集，未涉及多语言、多模态或非 QA 任务。
- 修复器为每个目标 LLM 单独训练，未验证跨模型迁移。
- 部分消融只跑了 2 epoch / 25,000 更新，与 6 epoch 主 checkpoint 存在训练预算差异。
