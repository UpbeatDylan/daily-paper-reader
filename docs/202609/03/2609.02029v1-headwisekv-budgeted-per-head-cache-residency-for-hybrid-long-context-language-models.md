## 摘要
长上下文推理在解码过程中会保留不断增长的键值（KV）缓存，这消耗大量GPU内存并可能降低生成吞吐量。在混合语言模型中，这一瓶颈依然存在，因为其残差全局注意力层可能主导上下文相关的缓存需求。我们研究了如何在总KV驻留预算下分配这种状态。我们提出了HeadWiseKV，一个无需训练的框架，它在保持混合语言模型原有的局部、循环和线性路径的同时，压缩其残差全局KV缓存。它为每个物理KV头分配一个静态的多级历史窗口，使得服务前的缓存需求可预测。我们将此分配问题形式化为受限的操作率-失真问题，并提出SeqCalib作为HeadWiseKV中的核心策略生成算法。SeqCalib按执行顺序处理层，并基于部署时使用的较低层策略对每个决策进行条件化，从而考虑跨深度的交互。分组缓存运行时将所选策略实现为实际的每头KV驻留，而非完整缓存上的掩码。我们在四个混合长上下文模型上评估下游质量，并在Qwen3.6-27B上研究物理驻留和服务行为。在所评估的模型上，HeadWiseKV保持了接近完整KV的RULER和LoCoMo质量。在固定模型系统研究中，它在112K上下文长度下将采样峰值设备内存减少了8.59%，并将最大验证成功上下文从114K扩展到161K。

## Abstract
Long-context inference retains a growing key--value (KV) cache during decoding, which consumes substantial GPU memory and can reduce generation throughput. This bottleneck remains in hybrid language models because their residual global-attention layers can dominate context-dependent cache demand. We study how to allocate this state under an aggregate KV-residency budget. We introduce HeadWiseKV, a training-free framework that compresses the residual global KV caches of hybrid language models while preserving their native local, recurrent, and linear paths. It assigns each physical KV head a static, multilevel history window, making cache demand predictable before serving. We formulate this allocation as a restricted operational rate--distortion problem and propose SeqCalib as the core policy-generation algorithm in HeadWiseKV. SeqCalib processes layers in execution order and conditions each decision on the lower-layer policy used at deployment, thereby accounting for interactions across depth. A grouped-cache runtime materializes the selected policy as actual per-head KV residency rather than a mask over a full cache. We evaluate downstream quality across four hybrid long-context models and study physical residency and serving behavior on Qwen3.6-27B. HeadWiseKV retains near-Full-KV RULER and LoCoMo quality across the evaluated models. In the fixed-model systems study, it reduces sampled peak device memory by 8.59\% at a 112K context length and extends the largest verified successful context from 114K to 161K.

## 1. 核心问题与研究动机

- **KV 缓存瓶颈**：长上下文自回归推理过程中，每个全注意力层都要为每个已缓存 token 存储 key/value 向量，KV 缓存随上下文长度和并发数增长，容易耗尽 GPU 显存并降低生成吞吐。
- **混合模型并未消除瓶颈**：Gemma 2/3、Qwen3-Next/Qwen3.6 等混合架构通过全局注意力与局部滑窗注意力或循环（如 Gated-DeltaNet）块交替来降低缓存压力，但其中残留的全局注意力块仍会保留随 prompt 增长的历史，**混合化只是将缓存瓶颈转移到少数残差全局层**，而非消除。
- **现有方法的二维取舍**：
  - **策略决策时机**：prompt 相关动态方法（Ada-KV、HeadKV 等）能按当前请求挑选重要的孤立远距离证据，但需要请求期开销，且"先建满缓存再压缩"并不一定能降低 prefill 峰值内存；静态策略在 prefill 前固定容量，内存可预测但无法感知具体 prompt。
  - **缓存实现方式**：逻辑稀疏掩码可能只减少注意力计算而不减少物理驻留；真正的物理压缩（compaction/eviction）才能降低解码期驻留。
- **现有静态方法的不足**：StreamingLLM、DuoAttention、RazorAttention 等多为"检索头保留全历史、其余头压缩/流式"的**二值切分**，对混合模型中各残差全局头所需历史量不同的情况粒度过粗。
- **跨层校准难题**：缩短浅层缓存会改变深层表示；在"全满前缀"下标定的高层策略，部署后面对的实际输入可能不同。因此需要一个**在真实部署前缀条件下逐头微调分配、且能物理落地**的静态策略。

## 2. 方法论

### 2.1 总体框架（离线到在线流水线）

HeadWiseKV 由三部分构成：

1. **结构化驻留模型（Structured Residency Model）**：定义候选历史窗口与存储成本；
2. **SeqCalib**（核心离线算法）：按层序为每个可配置 KV 头选择历史窗口；
3. **分组缓存运行时（Grouped Cache Runtime）**：把策略矩阵物化为实际的物理逐头 KV 驻留。

全程无需重训练、无需修改模型架构。

### 2.2 结构化驻留模型（决策空间与代价）

- **决策单元**：采用 GQA 时多个 query 头共享一个物理 KV 头，因此决策单位是**物理 KV 头 (ℓ,h)**（而非 query 头），同一 GQA 组内所有 query 头共享分配结果。
- **策略赋值**：为每个可配置全局注意力头分配

  aℓh ∈ W = {w1,…,wK, full}

  其中 wk 表示一个连续后缀长度（如 8K、16K、32K），full 代表全量；完整策略是"逐层 × 逐物理 KV 头"的历史长度矩阵。
- **存储代价**：在上下文长度 C 下，驻留 token 数 rC(w)=min(w,C)，结合 KV 维度与有效精度换算为名义存储 nℓh,C，再对全部决策单元求和得到 NC(a)，并以全满策略归一化为率 RC(a)=NC(a)/NC(aF)。例如 RC=0.5 表示可配置全局头只需全满时一半的名义存储。
- **理想目标（受限操作率-失真问题）**：在归一化驻留不超过预算 β 的约束下，最小化与全满缓存模型输出的期望端到端失真（式 5）。但搜索空间 (K+1)^|U| 过大、需要端到端评估，直接求解不可行，故用 SeqCalib 替代全局搜索。

### 2.3 SeqCalib：顺序前缀条件化校准（核心算法）

- **执行顺序逐层处理**：SeqCalib 按前向执行顺序处理层，处理第 ℓ 层时冻结此前已选定的低层策略 a<ℓ（即 deployment 时真正生效的前缀），在该前缀条件下进行本层校准——体现"缩短浅层缓存会改变深层输入"的层间耦合。
- **候选评估方式**：对第 ℓ 层以全历史 trace 一次得到 Q/K/V 与注意力输出；然后在同一次 trace 上"重放"每个候选窗口 w，仅对候选后缀重归一化注意力权重，计算候选注意力输出 o(w) 与条件全历史输出 o(full) 的余弦相似度（含数值稳定处理），在标定数据上对样本、位置、GQA 组内 query 头求平均得到头级得分 bŜℓh(w | a<ℓ)。
- **选择规则（式 9）**：对每个头选取能满足相似度阈值 τ 的**最低名义存储代价**窗口；full 必然可行，因此每阶段可解。该过程保证的是"在已实现低层前缀条件下的逐层/逐头最低可行代价"，而非全局联合最优（文中明确为 stage-wise，非 joint-optimal）。
- **预算选择**：在一组有序阈值网格 τ1…τG 上独立运行 SeqCalib，得到若干 (策略、率、最低选头均值、阈值) 记录；给定预算 β 后，按字典序规则选择：先最大化最低选头均值（floor），再最小化率，最后取最小网格下标（确定性 tie-break）。
- 论文以受控的操作率-失真问题形式化该有限分配，并给出固定前缀最小性的形式化命题（Proposition 1）与共享窗口代价比较推论（Corollary 1）；附录还用 Lipschitz 扰动递推说明"低层截断改变高层状态"的递归依赖，从理论上说明按执行顺序校准的合理性。

### 2.4 运行时：从策略到物理驻留

- 服务器运行时**只加载一次**策略矩阵，不依据 prompt、请求历史或在线注意力分数重新计算。
- 每个可配置 KV 头只写入/读取其所属窗口对应的缓存分组；相同窗口的头可共享组配置，但 KV 内容仍互相独立；本地/循环/线性层保持原缓存路径不变。
- 关键点：这是**真实减少物理分配的按头驻留**，而非"全量缓存上的逻辑掩码"。校准与部署共享相同的层-头索引、窗口语义与注意力缩放，并做 trace 兼容性检查。

## 3. 实验设计

### 3.1 模型与配置

- 四个指令微调混合长上下文模型：**Qwen3.5-9B、Qwen3.6-27B、Qwen3.6-35B-A3B、Gemma4-31B**。

- 共享阈值 τ=0.995（不同模型因此产生不同驻留率）。

### 3.2 Benchmark 与任务

- **RULER**：长上下文检索（5 种 needle-in-a-haystack 任务，上下文 4K–128K，每配置 1200 例，0–100 分）。
- **LoCoMo**：对话长时记忆（10 段对话中类别 1–4 共 1540 问，基于证据的判分，裁判模型为 DeepSeek V4 Flash）。
- **τ²-Bench**：Airline 与 Retail 两个智能体任务域。
- **LongMemEval-S**（附录）：500 问长时交互记忆，独立审计标签后报告 Reviewed ACC。
- 质量指标只在同模型、同 benchmark、同驻留定义下比较。

### 3.3 对比基线

- **Full-KV**：未压缩对照（保留全部可配置全局历史）。
- **AdaKV**（动态、请求自适应，头级预算分配）。
- **HeadKV-R2**（动态、头级压缩）。
- **StreamingLLM**（静态 sink–recent 策略，4+90,364 缓存）。
