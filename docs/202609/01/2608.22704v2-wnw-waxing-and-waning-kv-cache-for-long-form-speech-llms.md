## 摘要
长音频输入使得KV缓存成为语音大语言模型的主要内存开销。仅预填充的KV压缩方法在逐出音频KV位置后将其永久丢弃，在解码过程中无法恢复。我们表明，这种方法在长音频上是不稳定的：预填充注意力集中在音频起始附近（注意力汇聚效应），而解码时注意力分布广泛，两者的排名重叠度很弱。我们提出WnW（蜡封与衰减KV缓存），通过离线校准将KV头分为锚定头、潮汐头和固定头三类。锚定头在GPU上保留所有音频KV，并提供解码时信号，指示每个标记读取自哪个音频区域；潮汐头保留CPU端补充，基于聚合的锚定头分数逐块召回；固定头仅保留GPU上的子集，其余永久丢弃。在LibriSpeech-Long上使用两个3B骨干模型（Voxtral-mini-3b和Qwen2.5-Omni-3B）进行测试，WnW在仅保留20%音频令牌于GPU的情况下，保持了接近全缓存精度的性能，而仅预填充的基线方法无法终止。结果在语言、任务和领域变化中具有泛化性，且在我们的测量中，CPU-GPU召回几乎不增加解码时开销。

## Abstract
Long-form audio inputs make the KV cache the dominant memory cost of speech LLMs. Prefill-only KV compression methods permanently discard audio KV positions once evicted, with no pathway to recover them during decoding. We show this is fragile on long-form audio: prefill attention concentrates near the audio start (an attention-sink effect), while decode-time attention distributes broadly, and the two rankings overlap weakly. We propose WnW (Waxing-and-Waning KV cache), which classifies KV-heads into anchor, tidal, and fixed roles via offline calibration. Anchor heads keep all audio KV on GPU and yield a decode-time signal of which audio region each token is read from; tidal heads keep a CPU-resident complement that is recalled chunk-by-chunk based on aggregated anchor-head scores; fixed heads keep only an on-GPU subset, with the rest permanently discarded. On LibriSpeech-Long with two 3B backbones (Voxtral-mini-3b and Qwen2.5-Omni-3B), WnW preserves near-Full-Cache accuracy while keeping only 20% of audio tokens on GPU, where prefill-only baselines fail to terminate. Results generalize across language, task, and domain shifts, and CPU-GPU recall adds little decode-time overhead in our measurements.

## 1. 核心问题与整体含义（研究动机与背景）

- **背景**：长音频输入使得 speech LLM 的 KV 缓存成为主要内存瓶颈。10 分钟音频在 12.5–25 tokens/秒的帧率下可产生 7,500–15,000 个音频 KV 位置，音频 KV 常占总缓存 70–80%。
- **现有方法的缺陷**：以 H2O、SnapKV、Ada-KV、AudioKV 为代表的 prefill-only 方法假设 prefill 注意力可以可靠预测解码时的注意力分布，在 prefill 阶段一次性确定保留的 KV 位置并永久丢弃其余位置，解码阶段没有恢复途径。
- **核心发现（问题根源）**：论文通过量化实验证明，在长音频场景中该前提不成立：
  - **注意力汇聚效应**：prefill 注意力将 47.9% 的质量集中在音频前 10% 位置，而解码累计注意力仅在该区间分配 9.8%，接近均匀分布；
  - **top-K 排名重叠弱**：prefill 与 decode-cumulative 注意力在 K=100 时的 Jaccard 重叠仅为 0.187(K=500 时为 0.240)，远不足以支撑 prefill 排名在解码期间的复用。
- **整体含义**：任何没有恢复路径的 KV 压缩方案在长语音场景下都存在结构性缺陷，在低预算时甚至无法正常终止生成（WER 超过 100%）。

## 2. 方法论：核心思想、关键技术细节

**核心思想**：WnW 将 KV 压缩决策从 prefill 阶段延迟到解码阶段，通过离线校准将 KV 头划分为三种功能角色，利用语音的时间对齐特性实现按需的音频块召回（waxing-and-waning，即“增消交替”），使保留集合能随解码过程动态演化。

**关键技术细节**：

1. **离线头部分类（Head Triage）**——通过两个互补信号对每个（层、KV 头）打分：
   - **语音分数（VS, Voice Score）**：衡量头的注意力是否锚定在音频内容上，即该头 top-attended 音频位置落入当前答案 token 对应词级时间区间的比例（基于 WhisperX 强制对齐），分数越高说明该头的注意力随生成内容在音频中推进；
   - **头敏感性（HS, Head Sensitivity）**：基于梯度的重要性指标——答案 token 交叉熵损失对每个头音频 key 向量的梯度 ℓ2 范数，衡量丢弃该头音频 KV 对损失的潜在影响；
   - 合并为 VS × HS 后，将 KV 头分为三类：
     - **锚定头（Anchor，5 个）**：语音锚定最强、损失敏感度最高，完整保留全部音频 KV，其解码时注意力作为“当前 token 正在读取哪个音频区域”的定位信号；
     - **潮汐头（Tidal）**：GPU 上保留按保留比例选取的子集，未选中的部分存放在 CPU 上，解码时根据锚定头聚合分数按块召回/释放；
     - **固定头（Fixed）**：仅在 prefill 时按每段 top-k 保留一个 GPU 子集，其余永久丢弃，无召回通道。
2. **Prefill 压缩**：按段（segment，与 2s stride 对应）执行 top-k 选择，保证时间覆盖均匀性；潮汐头的未选位置存入 CPU 备份，固定头则直接丢弃。
3. **解码时动态分块交换**：
   - 音频位置划分为 4s 窗口、2s 步长的重叠块（chunk），相邻块共享一个段；
   - 每个解码步，将所有锚定（层，Q 头）对的 softmax 注意力在音频位置上聚合：$A_\tau^{(s)} = \sum_{(l,h)\in anchor} \mathrm{softmax}(q^{(s)}_{l,h} K^\top_{l,h} / \sqrt{d})_\tau$，随后按块取均值得到块分数，选 top-k（k=3）块；
   - 对选中的块，潮汐头的 CPU 端补充被取回 GPU；若某补充块连续 δ=3 步未被选中则从 GPU 释放（CPU 副本保留）；
   - 保留比例：$\mathrm{retention}_i = \min(\tilde{s}_i \cdot \lambda, 1.0)$，其中 $\tilde{s}_i$ 为归一化重要性分数，λ 为控制保留幅度的超参数；两个超参数为 voice-head 数量 $n_{voice}$ 和 scale λ。

## 6. 主要结论与发现

- prefill 与 decode 注意力不匹配是长语音场景下 prefill-only 压缩的结构性缺陷：prefill 注意力受 sink 效应主导，而解码时注意力接近均匀分布。
- WnW 在保留率 r_GPU=0.2 时仍在两个 3B backbone 上保持近 Full Cache 的 WER（Voxtral 上差 ≤0.6，Qwen 上差 ~1.6），而 Ada-KV/AudioKV 在该预算下无法终止，ArkVale 显著落后。
- 头部分级有效：固定头可安全地静态压缩；潮汐头需要召回路径；锚定头的注意力是可靠的解码时间重要性信号。
- 泛化上：LibriSpeech 校准的 head 角色可迁移到法语、翻译和医疗领域，说明该划分不是校准集的过拟合。
- 效率上：CPU→GPU 召回传输随 tidal 头数量线性增长但绝对量小（≤1.04 MB/step），解码中位耗时波动 <5%，召回并非瓶颈。
- 与 AffPool 对比表明：prefill 时的 token 合并同样受“无恢复路径”限制，且合并的误差会逐层传播，在 20–40% 保留率下性能崩溃。

## 7. 优点：方法与实验设计的亮点

1. **问题诊断先行**：论文不是直接提出方法，而是先用实证数据（注意力分布图、Jaccard 重叠、逐头分析）揭示 prefill–decode 不匹配的结构性障碍，为方法设计提供了明确动机和可验证的依据。
2. **方法设计利用语音领域特有结构**：音频 token 时间有序且与转录文本词级对齐，因此锚定头注意力可以自然地跟踪生成前沿（generation frontier），这使 WnW 获得了文本 LLM 方法没有的结构性优势。
3. **两级互补的信号设计**：VS 衡量“注意力是否跟随内容移动”，HS 衡量“该头 KV 是否影响损失”，二者乘积既避免只选注意力相关但损失无关的头，也避免只选敏感但忽略音频的头，消融实验验证了两者缺一不可。
4. **三头分类设计的层次清晰**：锚定头——完整保留 + 作为 observer；潮汐头——召回通道 + CPU 静态备份；固定头——无召回。作用边界明确，无冗余设计。
5. **分块 + 段粒度的交换机制**：重叠块共享段的设计减少了频繁整块换入换出的颗粒度；δ=3 的释放滞后又防止了分数振荡导致的抖动；“CPU 副本持久存在”使得误逐出可恢复。
6. **实验设计比较严谨**：
   - 统一将基线限制为音频区域压缩，避免与文本/prompt 压缩混淆；
   - 报告逐方法实测 r_GPU 而非仅目标值；
   - 截断 WER 机制避免了非终止generation污染比较指标；
   - 校准集与测试集分离，并做了跨数据集校准鲁棒性验证（交换校准集后 head 角色 76/85 保留，WER 变化 ≤1.12）。
7. **超参数敏感性低**：块大小 8 倍范围、锚定头数量 20 倍范围内 WER 波动仅 ~0.3，说明默认配置不是狭窄调参的结果，方案稳定性好。

## 8. 不足与局限

1. **系统实现层面**：CPU–GPU 召回调度是 “naïvely scheduled”（论文原话），未使用 CUDA stream 等重叠手段优化，虽然测得开销小，但实际部署还有优化空间。
2. **高保留率下召回通道闲置**：当 GPU 预算充足时（r_GPU 较高），λ 达到饱和，潮汐头的召回通道处于休眠状态，可恢复性被搁置；论文将“解耦 n_voice 与 λ 使召回始终活跃”列为未来工作。
3. **仅限离线解码**：未覆盖流式（streaming）识别场景；虽然论文讨论了对流式 speech LLM 和同传的扩展思路，但未做实验验证。
4. **适用架构受限**：机制依赖 KV 缓存的存在，不适用于 cross-attention（如 Whisper）、transducer 或 state-space 架构；同时依赖“注意力沿时间推进”的前提，对非转录类音频任务（QA、对话、摘要）未做验证。
5. **校准标注依赖外部工具**：VS 的计算依赖 WhisperX 的词级时间对齐，校准需要额外标注管线；对齐置信度阈值（0.85）的选择影响校准集大小（降低到 0.44 会使校准 token 数 ×45，但 head 角色基本不变，WER 变化 ≤0.31——不过该分析仅给出相关性结论）。
6. **校准是 per-model 成本**：更换模型后需要重新计算 head 角色（如 24B 实验），虽然不需要按部署场景重算，但引入额外的一次性开销。
