## 摘要
混合大语言模型将全注意力层与线性注意力层交错排列，以降低长上下文推理的成本。这种结构使前缀缓存复杂化：全注意力键值缓存可基于 token 寻址，而线性注意力层维护的循环状态无法回滚到任意前缀边界。现有混合前缀缓存方法通过存储循环状态检查点来解决这种不匹配。因此，token 级匹配只能在存储检查点对齐的位置直接使用，将前缀复用限制在一组离散边界上。我们提出 Tail-Replay，一种前缀缓存机制，能够在混合大语言模型中实现无约束的 token 级前缀复用。关键洞察在于，诸如 Gated DeltaNet 之类的线性注意力机制可视为对输入前缀的一种结构化有损压缩：门控循环更新会逐步衰减较早输入的影响。因此，通过仅重放该匹配前缀的一个较短的最新后缀，可以很好地近似其循环状态。Tail-Replay 利用这一特性，缓存精确的全注意力键值缓存，同时省略循环状态检查点。在缓存命中时，它通过重放匹配前缀的一个较短的最新后缀来重建线性注意力状态。因此，复用边界由共享 token 决定，而非循环状态检查点。我们使用 LongBench 和 RULER 基准，在三个基于 Gated DeltaNet 的混合模型上评估 Tail-Replay。仅使用 5%–10% 的重放预算，它在 LongBench 和 RULER 上保留了全预填充质量的 92.8%–99.9%。在服务效率方面，我们评估了多种匹配前缀长度（8K、16K 和 32K）下的首 token 时间加速比。加速比随前缀长度增长，在 32K 时相对全预填充达到 $9.1$–$14.3\times$。

## Abstract
Hybrid large language models interleave full-attention layers with linear-attention layers to reduce the cost of long-context inference. This structure complicates prefix caching: full-attention key-value caches are token-addressable, whereas linear-attention layers maintain recurrent states that cannot be rolled back to arbitrary prefix boundaries. Existing hybrid prefix caching methods address this mismatch by storing recurrent-state checkpoints. As a result, token-level matches are directly usable only at positions aligned with stored checkpoints, constraining prefix reuse to a discrete set of boundaries. We present Tail-Replay, a prefix caching mechanism that enables unconstrained token-level prefix reuse in hybrid large language models. The key insight is that linear-attention mechanisms such as Gated DeltaNet can be viewed as a structured, lossy compression of the input prefix: gated recurrent updates progressively attenuate the contributions of earlier inputs. Consequently, the recurrent state of a matched prefix can be well approximated by replaying only a short, recent suffix of that prefix. Tail-Replay exploits this property by caching the exact full-attention key-value cache while omitting recurrent-state checkpoints. On a cache hit, it reconstructs the linear-attention states by replaying a short, recent suffix of the matched prefix. As a result, the reuse boundary is determined by the shared tokens rather than by recurrent-state checkpoints. We evaluate Tail-Replay on three Gated DeltaNet-based hybrid models using the LongBench and RULER benchmarks. With only a 5--10\% replay budget, it retains 92.8--99.9\% of full-prefill quality on LongBench and RULER. For serving efficiency, we evaluate time-to-first-token speedups across multiple matched-prefix lengths---8K, 16K, and 32K. The speedup grows with prefix length, reaching $9.1$--$14.3\times$ over full prefill at 32K.

- **核心矛盾：线性注意力的“诅咒”**：在纯 FA 模型中，可复用状态是 token 可寻址的 KV 缓存，可在任意 token 边界复用；但线性注意力层通过就地递归更新将前缀压缩为循环状态，状态一旦推进就无法回滚到任意早期前缀边界。因此，即使两个请求共享大量前缀 token，线性注意力状态也无法直接复用——论文称之为“prefix caching 中线性注意力的诅咒”。
- **现有工作的不足**：已有的混合前缀缓存方案（如 Marconi、Sparse Prefix Caching）通过显式管理循环状态检查点（checkpoint）来缓解该问题，但并未消除根本限制——前缀复用仍被约束在检查点对齐的离散边界上，而非由共享 token 前缀的任意边界决定。
- **Tail-Replay 的整体定位**：论文提出一种无需循环状态检查点、支持无约束 token 级前缀复用的混合大模型前缀缓存机制，从根源上摆脱线性注意力状态不可回滚的限制。

## 2. 论文提出的方法论

### 2.1 核心思想

- **关键洞察**：现代线性注意力机制（如 Gated DeltaNet）本质上是对输入前缀的一种**结构化有损压缩**：门控循环更新会逐步衰减较早输入的影响（门控值 α_i ∈ (0,1] 控制遗忘速度）。因此，匹配前缀的循环状态可以通过**仅重放该前缀的一小段最近后缀**来高精度近似——早期 token 对最终状态的贡献已经衰减到可以忽略，尾部 token 才是状态的主体。
- **总体策略**：只缓存精确的 FA KV（token 可寻址）和 FA 输出隐藏状态，省略线性注意力循环状态检查点。缓存命中时，用缓存 FA KV 直接复用全注意力部分，用短后缀回放重建线性注意力状态。这样，前缀复用边界由匹配的共享 token 长度决定，天然支持任意 token 边界。

### 2.2 关键技术与流程

- **缓存内容**：对每个前置输入 P = (t₁, t₂, …, tₙ)，缓存 FA 层的 token 级状态 {(K_FA^i, V_FA^i, h_i)}_{i=1}^{n}，其中 (K_FA^i, V_FA^i) 是 FA 层的键/值向量，h_i 是该 token 的 FA 层输出隐藏状态。
- **分组独立回放（Independent Tail-Replay）**：将混合模型按架构划分为若干个组，每组由一个 FA 层及其后续连续的线性注意力层组成。缓存每个 FA 层的输出隐藏状态，保证组内第一个线性注意力层的输入与原始预填充时精确一致，从而将回放误差限制在组内、不跨组传播。
- **回放过程**：给定覆盖前 m 个 token 的缓存命中，取最近 k = ⌈rm⌉ 个缓存 FA 输出隐藏，从零状态 Ŝ_{m−k} = 0 开始，对该尾部逐 token 应用 GDN 更新：  
  Ŝ_i = T_i Ŝ_{i−1} + β_i v_i^LA (k_i^LA)ᵀ，i = m−k+1, …, m  
  其中 T_i = α_i(I − β_i k_i k_iᵀ)，k_i^LA、v_i^LA 由回放过程从 FA 输出隐藏经线性注意力组计算得到。最终状态 Ŝ_m 即为匹配前缀边界处线性注意力状态的近似。每个组独立执行该过程。
- **回放后继续服务**：所有组的线性状态重建完成后，用重建的循环状态 + 检索到的 FA KV 继续处理未匹配的后续 token。

### 2.3 两种效率优化

- **尾部 FFN 跳过（Tail-FFN Skip）**：回放组的最后一个线性注意力块之后的 FFN 输出在状态重建中并不需要——下一组从下一个 FA 层的缓存输出隐藏开始。因此回放时跳过该 FFN，只计算用于更新循环状态的线性注意力块，减少计算开销。
- **传输/回放重叠（Transfer/Replay Overlap）**：Tail-Replay 不依赖缓存 FA KV，因此 FA KV 从主机到设备（H2D）的传输可与回放在独立复制流上并行执行，仅在 query 前向前同步，使回放隐藏大部分数据搬运成本。

## 3. 实验设计

- **评估模型**：三个基于 Gated DeltaNet（GDN）的混合大模型——OLMo-Hybrid-7B、Qwen3.5-4B、Qwen3.6-27B。
- **质量评估基准**：
  - **LongBench**：长上下文多任务基准，包含 narrativeqa、hotpotqa、qasper、musique、qmsum 等任务，上下文长度覆盖 16K、31K/32K、64K。指标为各任务 token-F1 或 ROUGE-L 分数。

- **对比方法**：
  - **Full prefill**（全预填充）：不做任何缓存复用，作为质量上界。
  - **Zero-only**：复用匹配的 FA KV，但将线性注意力循环状态置零、不进行回放，用于隔离状态重建的收益。
  - **Tail-Replay with r=5% / r=10%**：论文提出的方法，两种回放预算。
- **效率评估**：以 narrativeqa 作为共享前缀场景，名义上下文长度 8K、16K、32K，测量首 token 时间（TTFT，从缓存传输或回放开始到生成第一个 token），每个条件重复 20 次取均值。对比配置包括：
  - FULL（全预填充基线）
  - H2D-SER（FA KV 串行主存到设备传输 + 回放）
  - H2D-OVL+skip（传输与回放重叠 + FFN 跳过优化）

## 6. 论文的主要结论与发现

- **质量保持**：在 LongBench 上，r=5% 时 Tail-Replay 保留全预填充质量的 92.8%–98.9%，r=10% 时为 93.9%–98.1%；在 RULER 上，r=5% 保留 93.1%–99.9%，r=10% 保留 96.7%–99.9%。总体上，短尾部回放即可高保真近似完整线性状态。
- **Zero-only 对比**：Zero-only 基线的质量显著低于 Tail-Replay，在 RULER 上差距尤为明显（如 Qwen3.6-27B 的 RULER Zero-only 仅约 0.061–0.405 vs 全量 1.0），说明线性注意力状态的准确重建是实质性的质量收益来源，而非简单复用 FA KV 即可。
- **服务效率**：TTFT 加速比随匹配前缀长度增长——32K 前缀下，5% 回放 + 重叠传输实现对全预填充的 9.1×–14.3× 加速（OLMo-Hybrid-7B 9.82×、Qwen3.5-4B 9.12×、Qwen3.6-27B 14.32×）。相对串行 H2D 传输，OVL+skip 优化在 32K 时进一步降低 TTFT 18%–42%。
- **回放预算影响**：从 5% 提高到 10%，在短上下文（8K/16K）下对 TTFT 影响不大，但在 32K 下会明显增加 TTFT（如 Qwen3.6-27B 从 251.8ms 升至 371.3ms），此时回放计算成为主导成本，提示实践中按前缀长度动态选择回放预算。
- **核心结论**：利用线性注意力门控衰减特性，用 5%–10% 的尾部回放即可在质量与效率之间取得良好折中，实现混合大模型中无检查点约束的 token 级前缀复用。

## 7. 优点

- **洞察新颖且基础**：将线性注意力机制本质总结为“结构化有损压缩 + 渐进遗忘”，由此推导出尾部回放策略，而不是依赖更多检查点或更复杂的状态管理——思路简洁而有力。
- **彻底绕开检查点约束**：由于不缓存循环状态检查点，缓存命中后的复用边界直接由共享 token 前缀决定，天然支持任意 token 粒度匹配，从根上解决了混合模型前缀缓存的核心矛盾。
- **分组独立回放缓解误差传播**：缓存 FA 输出隐藏状态，使每组线性层的回放输入精确匹配原预填充输入，避免组间误差逐层累积；设计上能扩展到任意混合架构（只要确定 FA 层与线性层的分组即可）。
- **工程优化实用**：尾部 FFN 跳过和传输/回放重叠是直接针对回放开销的务实优化，实验数据表明 OVL+skip 在长前缀下显著降低 TTFT（18%–42%）。
- **评估质量与效率并重**：质量侧覆盖真实长上下文任务和合成压力测试，效率侧配套完整 TTFT 分析，并纳入 Zero-only 消融来归因收益来源。
- **实验具有可复现基础**：使用了公开模型和基准（LongBench、RULER），并给出完整逐单元格数据（附录 A），便于后续研究复现与扩展。

## 8. 不足与局限

- **方法仅验证于 Gated DeltaNet**：实验只覆盖 GDN 一种线性注意力/状态空间机制，未覆盖

未覆盖 **Mamba、RWKV、RetNet、基于核方法的线性注意力** 等其他主流状态空间或线性注意力变体。这些机制的循环更新规则与门控衰减特性各不相同（有的甚至不含显式门控遗忘），Tail-Replay“尾部回放近似完整状态”的前提未必成立，因此其方法在更广义线性注意力模型上的普适性尚未得到验证。
- **缺少理论误差保证**：论文对回放近似精度的论证主要依赖经验数据，没有给出回放误差随预算比例 r、前缀长度 m 变化的解析上界或收敛性分析。对于对状态精度敏感的下游任务（如长链推理、多轮记忆召回），缺少可预测的可靠性指标，生产部署时难以事先评估风险。
- **质量评估场景覆盖有限**：LongBench 选取的任务单元不多（6 个任务单元），未覆盖代码生成、工具调用、多轮对话、智能体协调等当前混合 LLM 典型服务负载；RULER 虽是压力测试，但为合成数据，与真实请求分布的偏差较大。更关键的是，现有评估只验证了“单次请求命中共享前缀”后的质量，没有评估多轮对话中**同一请求多次参考前缀缓存**时的连续质量变化。
- **效率指标单一**：仅以 TTFT 作为效率度量，未报告端到端吞吐率（requests/s）、GPU 利用率、显存占用、缓存容量管理开销等对系统设计至关重要的指标；场景也仅覆盖单一切割的共享前缀完全命中，未涉及多级共享前缀、部分命中、混合不同前缀长度等真实流量模式。
- **缺少与既有方案的端到端对比**：未在相同硬件与负载下与 Marconi、Sparse Prefix Caching 等已有的混合模型缓存方案进行对照，无法定量说明 Tail-Replay 相较这些专门方案的 TTFT、内存开销与命中率收益，使得其相对优势主要体现为“相对自身全预填充/无回放”的加速，而非“相对业界基线”的领先。
- **实验条件披露不充分**：未说明 GPU 数量、并行化配置（张量/流水并行度）、批处理大小、缓存容量限制等，影响实验的可复现性与对不同规模部署形态的迁移判断。
- **边界条件分析不足**：没有讨论当前缀命中很短（如 k 很小）、门控衰减较慢、或命中前缀处于状态机中段时的退化表现；也没有分析与请求生成部分很长时重建误差对生成质量的长期累积影响。

## 9. 总结

Tail-Replay 提出了一种兼具简洁性与实用性的混合大模型前缀缓存范式：将线性注意力门控更新视为对前缀的“结构化有损压缩”，从而把“循环状态不可回滚”的传统限制转化为“回放短尾即可近似恢复”的机会，实现了不受检查点约束的任意 token 级前缀复用。在 OLMo-Hybrid-7B、Qwen3.5-4B、Qwen3.6-27B 三个模型上，5%–10% 的尾部回放预算即可高保真逼近全预填充质量，并在 32K 共享前缀下实现 9.1×–14.3× 的首 token 时间加速，加上传输/回放重叠与 FFN 跳过优化，具有明确的服务部署价值。与此同时，其普适性（其他线性注意力变体）、理论保证（误差界）、系统完整性（吞吐、内存、真实负载）以及与既有方案的直接横向对比仍有待进一步工作填补。总体而言，这是一篇洞察扎实、实验规范、工程落地意识强的系统论文，对混合 LLM 推理服务的设计有重要参考价值。
