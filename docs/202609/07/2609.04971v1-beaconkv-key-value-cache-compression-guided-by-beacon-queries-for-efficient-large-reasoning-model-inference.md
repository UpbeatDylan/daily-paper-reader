## 摘要
大型推理模型（LRMs）通过扩展的思维链（CoT）生成实现了卓越的问题求解能力，但由此产生的关键-值（KV）缓存随序列长度线性增长，并造成严重的内存瓶颈，在长推理轨迹中常常超过GPU容量。现有的KV缓存压缩方法依赖近期查询来估计未来令牌的重要性，隐含地假设它们可作为未来注意力模式的可靠代理。我们证明，这一假设在长时推理中失效：某些解码步骤会生成思考复核令牌（TRT），这些令牌会重新关注遥远的先前上下文，例如推理轨迹早期制定的任务求解方案。通过系统分析，我们发现与TRT对应的查询在嵌入空间中聚集成少量相似性组。基于这一洞见，我们提出BeaconKV，一种无需训练的KV缓存压缩方法，它维护信标查询——每个全局查询簇的紧凑代表——以预测哪些KV对将被重新访问，而无需存储完整查询历史。在四个开源LRM和多样化的推理基准测试中，BeaconKV总体上优于现有压缩方法，实现了高达5.8倍的内存减少，同时几乎保持完整缓存的准确性并将吞吐量提高4.3倍以上。

## Abstract
Large Reasoning Models (LRMs) achieve superior problem-solving through extended Chain-of-Thought (CoT) generation, but the resulting key-value (KV) cache grows linearly with sequence length and creates severe memory bottlenecks, often exceeding GPU capacity for long reasoning traces. Existing KV cache compression methods rely on recent queries to estimate future token importance, implicitly assuming these serve as reliable proxies for future attention patterns. We demonstrate that this assumption fails in long-horizon reasoning: certain decoding steps generate Thought Revisiting Tokens (TRT) that re-attend to distant previous context, such as task-solving plans formulated early in the trace. Through systematic analysis, we discover that queries corresponding to the TRT cluster into a small number of similarity groups in the embedding space. Based on this insight, we propose BeaconKV, a training-free KV cache compression method that maintains beacon queries, compact representatives for each global query cluster, to anticipate which KV pairs will be revisited without storing the entire query history. Across four open-source LRMs and diverse reasoning benchmarks, BeaconKV generally outperforms existing compression methods, achieving up to $5.8\times$ memory reduction while nearly preserving full cache accuracy and improving throughput by over $4.3\times$.

- **论文的核心发现**：在长时推理中，某些解码 token 会“思想回溯”——即重新注意很早之前形成的解题计划和问题约束。作者称这类 token 为 **Thought Revisiting Tokens (TRT)**。它们对应的全局 query 是稀疏、偶发且难以通过近期 query 预测的，因此现有方法会提前驱逐未来仍会被重访的关键 KV 对。
- **关键进一步观察**：这些 TRT 对应的全局 query 并非散乱无章，而是在嵌入空间中聚成少量相似簇；因此可以用少量“信标 query”（beacon queries）代表这些簇，从而**免训练地**预测未来可能被重访的 KV。
- **整体意义**：论文提出 BeaconKV，一种无需训练的 KV 缓存压缩方法，在保持接近无压缩精度的同时大幅降低峰值内存、提升吞吐，为 LRM 的长链推理部署提供低成本压缩方案。

## 2. 论文提出的方法论

### 2.1 核心思想

- 将注意力 query 分为两类：**local queries**（主要注意邻近 key）与 **global queries**（对应 TRT，注意远距离 key）。
- 维护两类观测 query：
  - **近期 query**：保持局部上下文连贯性；
  - **beacon queries**：通过在线采样保留的、能代表历史全局 query 簇的少量 query。
- 在需要驱逐 KV 时，用这两类 query 对所有候选 KV 计算注意力重要性分数，保留下一次可能被重访的 KV，而不是仅依赖近期 query。

### 2.2 关键技术细节

- **Continual Farthest Point Sampling（Continual FPS）**：
  - 对每个 attention head 维护有界 query 缓冲区；
  - 缓冲区达到上限 \(B^Q_{\max}\) 时，用 FPS 按余弦相似度贪心选择“几何上最不重复”的 query，压缩到下限 \(B^Q_{\min}\)；
  - 如此可在不存储全部 query 历史的前提下，持续追踪推理轨迹中出现的全局 query 簇。
- **RoPE 对齐**：
  - beacon queries 在计算重要性时被旋转到当前解码位置 \(t\)，模拟“如果信标所代表的 TRT 此刻发生”的注意力；
  - recent queries 保留原始位置编码，维持局部注意力信号。
- **Max 聚合的 KV 重要性评分**：
  - 对于 Grouped Query Attention (GQA) 模型，组内所有 head 和所有观测 query 的注意力权重使用 **max-pooling**，而非 mean；
  - 因为 TRT 信号稀疏且幅度高，mean 聚合会稀释关键信号，而 max 能保证任一 beacon query 识别出的重要 KV 被保留。
- **驱逐/保留策略**：
  - 始终保留前缀 token 和最近若干 token；
  - 剩余 KV 预算按注意力分数选取 Top-K；
  - 驱逐完成后，将 beacon 与 recent 查询合并并再次 FPS 压缩，更新下一步的 beacon 集合。

### 2.3 算法流程（文字概述）

1. Prefill 阶段：缓存全部 KV，并用 FPS 从初始 query 序列初始化 beacon 集合。
2. 持续解码：新生成的 pre-RoPE query 进入缓冲区，满后触发 FPS 压缩。
3. 接近 KV 上限时：固定当前 beacon queries 并开始收集 recent queries。
4. 到达 KV 上限时：将 beacon queries 旋转至当前步、与 recent queries 合并，计算每个 KV 位置的最大注意力分数。
5. 保留强制窗口 + Top-K 高分 KV，驱逐其余；然后合并/压缩 observation queries，进入下一轮。

## 6. 论文的主要结论与发现

- **TRT 的普遍性**：长链推理中，全局重访注意力并非个别 head 的孤立行为，而是分布于不同层和 head，是一种系统性的注意力模式。
- **现有方法失效原因**：仅依赖 recent query 无法预判稀疏且偶发的 TRT，容易在压缩时过早丢弃仍会被重访的早期 KV。
- **BeaconKV 有效性强**：在四个 LRM 和多个推理基准上普遍优于 RPC、SnapKV 和 R-KV；在低预算区间优势尤其明显，最高相对现有方法提升 **31.7 个百分点**。
- **高压缩 + 高效率可兼得**：在 Qwen3-4B 上，2K KV 预算下峰值内存从 77.0GB 降至 13.3GB（**5.8×**），吞吐从 82.3 提至 356.4 tokens/s（**4.3×以上**），同时精度几乎无损。
- **Max 聚合与 balanced query 配比更优**：16 recent + 16 beacon（nrecent=16，nbeacon=16）的配置在精度与延迟之间取得最佳平衡；Max 聚合在低预算下显著优于 Mean。
- **动态抽样优于固定初段 query**：仅保留初始 query + recent query 的 Initial+Recent 远不如 BeaconKV，说明 Continual FPS 动态捕捉新出现的全局 query 簇更关键。
