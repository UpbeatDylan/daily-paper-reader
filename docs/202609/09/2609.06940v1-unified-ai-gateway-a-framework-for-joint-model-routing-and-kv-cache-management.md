## 摘要
大型语言模型（LLM）推理日益跨越规模、能力、价格和提供商各异的模型。这种转变给开发者带来两类成本：一是从众多模型中选择并在其间切换的集成成本；二是当KV缓存不可用或与所选模型不兼容时，重建KV缓存的推理成本。我们将统一AI网关定义并分析为一种边缘部署的AI流量中枢的系统设置。它协调端设备、边缘资源和云模型服务之间的模型路由、KV缓存管理以及计算放置。在请求时，网关在任务质量、延迟、成本和资源约束下联合选择目标模型、执行站点和KV缓存操作。与此同时，后台缓存管理操作为后续请求优化KV缓存的放置、复制、检索和生命周期决策。我们综合了关于KV缓存重用、压缩、跨模型映射、分布式存储和传输的现有证据，并讨论了将这些能力整合到一个系统中仍面临的挑战。在八种典型工作负载配置中，我们的工作负载级分析模拟报告的TTFT加速为1.25倍至13.28倍，输入成本收益为1.20倍至6.16倍。

## Abstract
Large language model (LLM) inference increasingly spans models that differ in size, capability, price, and provider. This shift creates two costs for developers. One is the integration cost of choosing among and switching between many models. The other is the inference cost of rebuilding a KV cache when it is unavailable or incompatible with the selected model. We define and analyze the Unified AI Gateway as a system setting for an edge-deployed AI traffic hub. It coordinates model routing, KV cache management, and compute placement across end devices, edge resources, and cloud model services. At request time, the gateway jointly selects a target model, an execution site, and a KV cache action under task-quality, latency, cost, and resource constraints. In parallel, background cache-management actions optimize KV cache placement, replication, retrieval, and lifecycle decisions for subsequent requests. We synthesize existing evidence on KV cache reuse, compression, cross-model mapping, distributed storage, and transfer, and discuss the remaining challenges of integrating these capabilities into one system. Across eight typical workload profiles, our workload-level analytical simulation reports TTFT speedups of 1.25$\times$--13.28$\times$ and input-cost benefits of 1.20$\times$--6.16$\times$.

## 1. 论文的核心问题与整体含义（研究动机和背景）

*   **核心问题**：随着 LLM 生态扩张，开发者越来越多地在不同规模、能力、价格和供应商的模型之间进行选择与切换。这种多模型部署带来双重成本：
    1.  **集成成本**：需要面对众多模型的选择与切换，传统 AI 网关虽然提供了统一的 API 和路由（如负载均衡、故障切换），但**没有将 KV 缓存与模型/供应商选择进行协调**。
    2.  **推理成本**：当路由切换到目标模型时，源模型的 KV 缓存可能**不可用或不兼容**，导致目标模型必须重新执行完整的上下文预填充（prefill）。这种重复计算可能抵消切换模型带来的能力或价格优势。
*   **现有方案的不足**：当前支持分散在网关服务、推理引擎（如 vLLM、SGLang）和缓存系统（如 LMCache、Mooncake）中，它们**没有在端、边、云等多设备与服务中与供应商和模型选择联合协调**。路由决策因此可能丢弃有用状态，增加首个令牌时间（TTFT）和输入成本，并造成“缓存引发的模型锁定”。
*   **核心意义**：本文提出 **统一AI网关（Unified AI Gateway）** ，将其定义为一种**边缘部署的系统架构**，在端（终端）- 边（边缘）- 云（云端）连续体上，联合协调模型路由、KV 缓存管理和计算放置，从而将 KV 缓存视为可在不同模型、站点间复用、映射、传输的一等网关管理资源，以此从根本上解决多模型推理中的集成与推理成本问题。

## 2. 论文提出的方法论

### 2.1 核心思想
全局控制平面（Global Control Plane）在**请求级（在线）** 和**请求流级（后台）** 两个时间尺度上协同决策。它将模型路由、缓存处理（复用、映射、压缩、传输、重建）和计算放置（端/边/云）视为一个耦合的整体，而非常规网关中的独立模块。

### 2.2 关键技术路径
对于每个候选模型和站点，控制平面比较五条缓存准备路径：
1.  **精确缓存命中**（direct reuse）：源与目标模型的 KV 缓存格式兼容，直接复用。
2.  **跨模型映射**（cross-model mapping）：将源模型 KV 缓存经转换函数 $\hat{K}_j(c_t) = f_{i \to j}(K_i(c_t))$ 映射到目标模型空间。
3.  **边缘端预填充**（edge prefill）：在边缘节点执行 prefill 生成新缓存。
4.  **远程缓存传输**（remote transfer）：从远端存储传输可用缓存。
5.  **目标端重预填充**（target-side re-prefill）：放弃缓存，在目标模型被执行站点重新做全量 prefill。

### 2.3 核心模型与公式逻辑
**请求级联合决策**：在每个请求 $t$，选择元组 $(\text{模型，执行站点，缓存动作})$ 以最小化加权的归一化延迟 $\tilde{L}$ 与成本 $\tilde{C}$，并满足延迟 $L_{tjea} \le \bar{L}_t$ 和质量 $Q_{tjea} \ge \underline{Q}_t$ 约束（式 2）。缓存交付延迟模型为：
$$T_{transfer} \approx \frac{S_{tjea}^{compressed}}{B} + T_{RTT} + T_{queue} + T_{copy} + T_{restore}$$
其中 $S_{compressed}$ 为压缩后传输的 KV 缓存大小，$B$ 为可用带宽，其余项分别对应往返时延、排队、拷贝与恢复开销（式 1）。
**跨模型映射触发条件**（式 3）：当映射与传输总时延小于目标端重 prefill 时延，且映射误差 $\varepsilon_{i→j}$ 低于容许质量损失 $\delta$ 时，可执行跨模型映射而非重 prefill。

**后台缓存管理**：跨请求流持续优化缓存池，决定缓存副本的放置 $(P_t(K))$、复制、迁移与基于频率、局部性、容量、新鲜度、授权的淘汰策略。这些后台动作为后续请求塑造可行的动作集合 $A_t$ 与成本基础。

**工作负载级延迟与成本估算**（式 4-8）：论文用简化的线性加二次 prefill 延迟模型（$T_{prefill}(L)=a_{prefill}L + b_{attn}L^2 + τ_{prefill}$）估算各缓存准备路径的耗时，并引入有效缓存命中率 $h$、模型切换率 $r_{switch}$ 来计算统一网关与基线网关的 TTFT 和输入令牌成本比值。

## 6. 论文的主要结论与发现

1.  **显著收益**：在 25%/50%/75% 三个切换率下，8 类负载模拟的 TTFT 加速比分别为 1.25×–5.39×、1.49×–9.48× 和 1.74×–13.28×；输入成本比分别为 1.20×–2.72×、1.41×–4.44× 和 1.61×–6.16×。
2.  **最佳适用场景**：高缓存命中率、长上下文、短输出且存在跨轮状态复用的**智能体类负载**（如长时程编码智能体）收益最大：在 75% 切换率下有 12.87× 的 TTFT 加速和 5.18× 的输入成本收益。
3.  **模型切换频率是杠杆**：在论文映射计算可重叠的理想假设下，有效缓存处理可以降低模型切换的成本，解锁更灵活且频繁的路由调整。
4.  **核心论断**：要实现统一网关，需将 KV 缓存放置到请求路径上，与路由和计算放置联合控制，任何单独的组件优化（如单纯强调复用、压缩或分布式缓存）都无法自动解决网关级模型切换导致的重复计算问题。

## 7. 优点

*   **问题定义清晰**：首次系统化地将 KV 缓存管理提升到网关级资源进行联合控制的角度，超越了现有网关只做静态路由、只把缓存看作引擎内部细节的范围。
*   **跨层折中分析框架**：引入统一优化目标（耦合质量、延迟、成本、资源），以拉通不同组件（路由、复用、压缩、映射、存储、PD 解耦）的工作流。
*   **覆盖范围全面的证据梳理**：综述了大量相关文献（从精确前缀缓存、非前缀复用、语义复用直到跨模型映射、分布式存储），提供了很好的系统进展背景。
*   **清晰的条件式见解**：通过对不同切换概率和带宽的敏感性分析，指出统一网关的价值依赖于有效复用/映射的可行性与传输开销的竞争关系。

## 8. 不足与局限

*   **实验未能排除模拟的乐观假设**：论文将映射计算视为可完全遮盖在传输过程中且命中即是安全命中，没有引入匹配/映射的可信度折扣，也未与“直接重 prefill”做细粒度对比。真实系统中映射的内存开销与共享链路导致的尾部延迟可能显著抵消其优势。
*   **决策模型理想化**：正式模型假设 $A_t$ 为给定缓存放置 $P_t$ 下的已知集合，却未对后台管理动作（复制、逐出）给出及时优化策略或实现低层机制，把实时决策所需的哪些动作具体可行、具体开销的推断留给了未来。
*   **缺少应用层生态考虑**：讨论强调标准化 KV 缓存描述、数据模型、转换/传输 API 的必要性，但未给出与现有闭源商业大模型 API（不开源 KV 缓存）在混合生态中的适用边界——只有在完全自托管且架构上可互通的情况下本文所述的映射才是真正可行的。
*   **弱化了资源公平与隐私隔离问题**：在性能模拟中高度依赖边缘侧高并发访问、授权请求和后台管理开销的摊销假设，这些假设并不总能满足真实边缘场景的资源约束，端侧或租户级隔离的缓存有效率会受到显著制约。
*   **量化的成本模型局限**：价格模型按“缓存读取折扣”简单线性化，未模拟供应商对预填充、跨区数据传输、出口带宽的差异计费，也没有考虑多区域复制的地域数据驻留合规带来的成本上浮。
