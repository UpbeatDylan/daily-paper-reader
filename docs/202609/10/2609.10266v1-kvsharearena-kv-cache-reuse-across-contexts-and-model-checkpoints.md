## 摘要
LLM 服务系统已经在复用 KV 缓存，但仅限于被复用文本位于提示词最开头的情况。两类日益增长的工作负载打破了这一条件：检索增强生成服务器会为每个查询组装不同的检索片段集合，而多智能体协调器会读取其他智能体撰写的报告。当缓存被复用到新提示词中时，其携带的位置信息是错误的，并且从未关注过其他来源。缓存也可能由同一模型家族的不同检查点写入，这会改变所存储的值。针对这类缓存的修复方法已在三个彼此独立的研究社区中出现，各自按自己的标准衡量；而现有基准仅测试精确前缀复用，此时没有任何损失。KVShareArena 在检索片段和智能体报告上，对跨提示词上下文和模型检查点的 KV 缓存复用进行基准测试。它按每种方法在无缓存与完全重计算之间所弥补差距的比例来评分，并在持有缓存的情况下计入计算、内存和单请求延迟，同时单独报告构建缓存的一次性成本。我们发现，无需重计算的位置校正足以应对，直到一个问题需要同时使用多个来源。在这种情况下，只有那些付出代价——通过重新编码部分缓存或进行训练——的方法才能弥补一半到三分之二的差距；未修复的缓存可能比无缓存更差。在单个提示词上无害的缓存压缩方法，在新写入的智能体报告上明显落后于位置校正。这些规律在三个模型组上均成立。当缓存由不同检查点写入时，免训练方法几乎不受影响，而在某一检查点的缓存上训练的适配器会损失质量。测试框架、冻结查询集和成本核算以 pip 包形式发布，附带自动提交流程和公开排行榜。

## Abstract
LLM serving systems already reuse KV caches, but only when the reused text sits at the very start of the prompt. Two growing workloads break this condition: a retrieval-augmented generation server assembles a different set of retrieved chunks for every query, and a multi-agent coordinator reads reports written by other agents. Reused inside a new prompt, a cache carries the wrong positions and never attended to the other sources. The cache may also have been written by a different checkpoint of the same model family, which changes the stored values. Repair methods for such caches have appeared in three separate communities, each measured on its own terms, and existing benchmarks test only exact-prefix reuse, where nothing is lost. KVShareArena benchmarks KV-cache reuse across prompt contexts and model checkpoints on retrieved chunks and agent reports. It scores every method by the fraction of the gap it recovers between no cache and full recomputation, and charges compute, memory, and per-request latency with the cache in hand, reporting the one-time cost of building a cache separately. We find that correcting positions, which needs no recomputation, is enough until a question needs several sources at once. There, only methods that pay, by re-encoding part of the cache or by training, recover half to two thirds of the gap; unrepaired caches can be worse than no cache. Cache-compression methods that are harmless on a single prompt fall significantly behind position correction on freshly written agent reports. These patterns hold across three model boards. When a different checkpoint wrote the cache, training-free methods are barely affected, while an adapter trained on one checkpoint's caches loses quality. Harness, frozen querysets, and cost accounting ship as a pip package with an automated submission workflow and a public leaderboard.

# KVShareArena 论文中文总结

## 1. 核心问题与整体含义

- **研究背景**：LLM 服务系统已普遍复用 KV 缓存，但现有前缀缓存要求被复用文本必须位于提示词最开头，且所有前置 token 完全一致。这是无损复用的前提，也使其适用范围很窄。
- **现实冲突**：两类快速增长负载打破该条件：
  - RAG 为每个查询动态选择、排序、组装不同检索片段；
  - 多智能体系统由协调器读取其他智能体刚生成的报告。
- **两类错位问题**：
  - **位置错位**：缓存中的 token 在出生上下文中的位置，与在新提示词中的组装位置不一致；
  - **相互盲视**：各来源块独立编码，彼此之间从未建立跨来源注意力连接。
  - **跨检查点复用**：缓存可能由同一模型家族的不同 checkpoint 写入，张量形状一致但 KV 值已改变。
- **研究动机**：修复此类缓存的方法已在 RAG 服务、多智能体、潜在通信三个社区分别出现，但各自任务、上限和成本口径不同，缺少统一第三方比较；现有 KV 缓存 benchmark 只测精确前缀复用，无法暴露错位复用损失。
- **整体含义**：论文提出 **KVShareArena**，一个跨提示词上下文和模型检查点的 KV 缓存复用 benchmark，统一评估质量与计算、内存、延迟成本，并发布 pip 包、冻结查询集、自动提交流程和公开排行榜。

## 2. 方法论：核心思想与关键技术细节

- **核心思想**：把 KV 复用问题形式化为两因素设计：
  - 使用上下文是否匹配出生上下文；
  - 生产者权重是否匹配接收者权重。
- **四个实验单元**：
  - 精确前缀控制：同上下文、同权重；
  - 仅检查点交接：同上下文、不同权重；
  - 跨上下文复用：不同上下文、同权重；
  - 跨上下文 + 检查点变化：不同上下文、不同权重。
- **两类工作负载轨道**：
  - **Retrieved Evidence**：RAG 主榜，独立缓存原始检索片段，按查询选择和组装；
  - **Agent Reports**：多智能体迁移轨道，专家智能体在未看到问题的情况下读取各自分片并生成报告，匹配部署中缓存可提前预计算的情形。
- **质量指标 PGR**：
  - 每个榜单固定两个锚点：  
    - floor：消费者完全不使用共享材料时的分数；  
    - ceiling：对同一 payload 全量重计算时的分数。
  - 性能差距恢复比例：  
    `PGR = (S_method - S_floor) / (S_ceiling - S_floor)`
  - PGR 为 0 表示等于 floor，为 1 表示等于 ceiling，可超过 1，也可为负；负值意味着复用缓存还不如无缓存。
- **成本三前沿**：
  - 计算：`PrefillWorkSaved = 1 - R/D`，其中 R 为答案时重计算的 dense payload layer-tokens，D 为 dense payload layer-tokens；
  - 内存：`KVBytesSaved = 1 - B_method / B_dense`，按实际张量测量，包含 scale、索引和拷贝；
  - 运行时：`TTFTSaved = 1 - T_method / T_dense`，仅在共享后端上测量，且是“缓存已在手”的每请求延迟。
- **缓存构建成本**：构建缓存的一次性成本单独报告，不摊入每请求延迟；是否摊销取决于工作负载读取次数和存储层级。
- **汇总分数**：  
  `Sβ,w = (1 + β) A C / (β A + C)`，其中 A 是裁剪到 [0,1] 的 PGR，C 是三个节省量的加权平均；默认 β=0.1，偏向质量，计算和内存等权。
- **准入与单变量纪律**：数据集/机制需通过预注册准入条件：
  - C1：ceiling - floor ≥ 0.25；
  - C2：自由位置对齐后的残差占比 ≥ 0.25 且置信区间不含零；
  - C3：残差在配对检验下显著。
- **方法分类**：选择性重计算、注意力校准、位置对齐、锚点增量复用、媒介替换、微调修复、训练软 token 适配器、解码 KV 交接修复、复用下压缩。
