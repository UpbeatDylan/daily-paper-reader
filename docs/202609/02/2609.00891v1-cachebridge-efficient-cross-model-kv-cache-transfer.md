## 摘要
在多模型系统中，不同LLM之间共享上下文要求接收模型重放共享前缀，因为KV缓存是模型特定的。近期的闭式跨模型KV迁移（下文称为全头映射）通过拟合源缓存到目标缓存的免训练仿射映射避免了这种重放。然而，其全头设计将每个目标KV头映射到选定层中的每个源KV头，这使得迁移质量对架构差异敏感，并导致映射器存储和应用开销随层支持增加而增长。为此，我们提出CacheBridge，它在保留闭式仿射接口用于在线部署的同时，协同设计了架构索引映射器支持、注意力对齐校准和有界映射器构建。CacheBridge将每个目标头限制到一个匹配的源头，通过因果注意力敏感性加权重建误差，并使用融合GPU核函数计算加权充分统计量而无需物化完整观测张量。在三个迁移方向上，CacheBridge恢复了Ministral 3中Full-Head Mapping丢失大量精度的两个迁移方向，同时保持了Qwen3上99.83%的平均目标保留率。在Qwen3 14B→32B上，它将映射器存储减少8倍，应用加速最高达3.0倍，以十分之一的校准数据即可匹配全头映射，并将500序列构建时间从92.63秒减少到8.63秒（10.7倍）。

## Abstract
Sharing context between LLMs in a multi-model system requires the receiving model to prefill the shared prefix because KV caches are model-specific. Recent closed-form cross-model KV transfer, hereafter Full-Head Mapping, avoids this replay by fitting a training-free affine mapper from source to target caches. However, its full-head design maps each target KV head from every source KV head in the selected layers, making transfer quality sensitive to architectural differences and causing mapper storage and application cost to grow with layer support. To this end, we introduce CacheBridge, which co-designs architecture-indexed mapper support, attention-aligned calibration, and bounded mapper construction while retaining a closed-form affine interface for online deployment. CacheBridge restricts each target head to a matched source head, weights reconstruction errors by causal attention sensitivity, and uses a fused GPU kernel to construct weighted sufficient statistics without materializing full observation tensors. Across three transfer directions, CacheBridge recovers the two Ministral 3 transfer directions where Full-Head Mapping loses substantial accuracy while preserving 99.83\% mean target retention on Qwen3. On Qwen3 $14\mathrm{B}\to32\mathrm{B}$, it reduces mapper storage by $8\times$, accelerates application by up to $3.0\times$, matches \fullhead with one tenth of the calibration data, and reduces 500-sequence construction from 92.63 to 8.63 seconds ($10.7\times$).

## 1. 论文核心问题与整体含义

**研究动机与背景**：在多模型LLM系统中，一次交互往往由多个模型接力完成。模型间的控制权切换时，接收模型无法直接复用发送模型的KV缓存——因为KV缓存是模型特定的表示，与模型内部结构紧密耦合。传统方案要求接收方重新执行prefill以重建共享前缀上下文，这在长上下文中成为突出的延迟瓶颈。

近期工作Full-Head Mapping首次提出训练自由、闭式可解的跨模型KV缓存迁移：通过一次离线拟合，学习一个仿射映射器，把发送方（源模型）的KV缓存直接映射为接收方（目标模型）可用的KV缓存，使在线交接无需目标侧重新prefill，也无需任务特定的适配训练。

**核心问题**：Full-Head Mapping采用“全头映射”设计——每个目标头从选定层中接收来自所有源头的特征——带来三个相互耦合的缺陷：

1. **模型敏感性强**：该机制对不同架构的适应能力差异巨大。同一套500序列校准协议下，它在Qwen3 14B→32B上能保持近原生性能（79.2% vs 80.2%），但在Ministral 3 3B→14B与8B→14B两个方向上精度崩塌（分别仅52.2%与44.4%），说明等效的KV接口规格下存在架构依赖的头对应关系未被利用。
2. **KV拟合误差不等于续写质量**：坐标级重建R²度量的是逐维缓存恢复程度，而续写质量取决于接收方注意力输出误差。等范数的KV残差在不同查询下可能产生截然不同的输出漂移，加权方式不当将让回归能力错配实际损失度量。
3. **成本随层支持增长**：映射器应用延迟随选定源层数k近线性增长。在Ministral 3 3B→14B上，k=16时逼近目标重新prefill的耗时，k≥20后反而更慢——全头映射的统计灵活性直接转化为在线系统的部署负担。

**论文主张**：提出CacheBridge——将“映射器支持结构、校准目标、构造路径”三方面协同设计，在保留闭环仿射部署接口的同时解决上述问题。核心思想可概括为：用架构索引的头匹配替代无差别的全头混杂，用注意力敏感度重加权替代坐标均匀回归，用有界的融合构造替代碎片的通用物化。

## 2. 方法论：CacheBridge

### 2.1 总体框架

系统沿袭“离线拟合一次 + 在线仿射映射”双阶段管线；离线阶段利用对齐的源/目标KV轨迹，选出源层（固定top-k），为每个目标层ℓ的每个目标KV头h拟合一个映射器（闭式岭回归）；在线阶段对源缓存做对齐收集、层选取，再应用仿射映射生成目标解码缓存。

三个组件分别嵌入管道不同环节：
- **Head-Local**设定映射支持（每个目标头只与单一架构对齐的源头块相连）
- **Attn-Repair**在选定支持内调整校准数据的权重（对齐注意力敏感性）
- **Fused-Fit**提供新的GPU核函数，使充分统计量构造绕过完整观测张量物化

在线阶段仅应用紧凑的仿射映射，离线引入的校准逻辑不改变在线接口。

### 2.2 Head-Local：头级别结构局部性

**全头特征（原方法）**：

$$x^{full}_{\ell,h,t} = \mathrm{concat}_{j \in S_\ell,\ g \in [H_s]} Z^{S}_{j,t,g},\quad p_f = k H_s d_s$$

即目标头h收集每个选定源层中全部Hs个KV头的内容特征。

**Head-Local特征（本方法）**：

$$x^{local}_{\ell,h,t} = \mathrm{concat}_{j \in S_\ell} Z^{S}_{j,t,a(h)},\quad p_\ell = k d_s$$

其中a(h)为确定性架构索引映射（非学习得到）；源与目标KV组对齐时取a(h)=h。

**参数规模对比**：

$$C_{full} / C_{local} = H_s$$

非偏置系数直接减少Hs倍（本文实验为8×），因为无论选定层数k、目标头数Ht如何变化，该因子恒定。8×降低映射器体积并削减在线仿射运算的主导项。

### 2.3 Attn-Repair：注意力对齐校准

动机：第ℓ层KV误差对最终输出的传播误差为δh_out⁽¹⁾ = Σᵢ PᵢBᵢεᵢ，真实度量是εᵀJᵀJε（J = 接收方雅各比矩阵），而非坐标级R²时的‖ε‖²。逐token定位到边界后，用因果注意力的一阶敏感度构建单层近似重加权。

对属于KV头h的查询头集合G(h)，给定边界c，逐位置的敏感度定义如下：

- **V分量**：$r^V_i = \sum_{u \in G(h)} a^2_{ui}$
- **K分量**：$r^K_i = \sum_{u \in G(h)} a^2_{ui}\cdot\frac{\|v_i - o_u\|_2^2 \cdot \|q_u\|_2^2}{d}$

其中a_ui是注意力权重，o_u为注意力输出，d为键维度。V-Jacobian的Frobenius范数中有与值宽度相关的常数因子，在按边界归一化时抵消，因此无需显式估计。

**权重收缩（控制有效样本量）**：注意力权重可能高度集中，直接施加将摧毁结构回归的样本量基础。论文引入了向均匀权重收缩的单参数族：

$$w_i(\alpha) = 1 + \alpha(r_i - 1),\quad \alpha \in [0,1]$$

其Kish有效样本量满足：

$$n_{eff}(w) = \frac{n}{1+\alpha^2 CV^2(r)}$$

设τℓ = min(n, 2pℓ)（2pℓ为随特征宽度扩展的启发式目标），取α\*为满足neff ≥ τℓ的最大值：

$$\alpha^* = \min \left(1,\ \sqrt{\frac{n/\tau_\ell - 1}{CV^2(r)}}\right)$$

该机制在原始校准边界（32个对数间隔位置）有效实现“按注意力敏感度分配拟合努力”，且不改变映射器的系数结构或在线应用代码。

### 2.4 Fused-Fit：有界映射器构造

给定Head-Local的头匹配后，不同目标层选择不同的源层子集——top-k层选择导致支持面在不同目标层间碎片化。通用做法需要反复对非连续块执行“收集→居中→加权→物化”，内存带宽远高于小型回归计算。

**解法**：新设计了一个两遍扫描的融合GPU核函数：
- 第一遍：固定归约树求加权均值
- 第二遍：有界分块流式构建单头面板；核函数兼具“gather选定头块 + 居中 + 加权 + 写入连续每头面板”功能；随之以头批量（head-batched）矩阵乘累积两个充分统计量

$$A_h = \sum_i w_{i,h}(x_{i,h}-\mu^h_x)(x_{i,h}-\mu^h_x)^\top$$

$$B_h = \sum_i w_{i,h}(x_{i,h}-\mu^h_x)(y_{i,h}-\mu^h_y)^\top$$

最终按照标准算子求解：

$$\hat{W}_h = (A_h + \lambda I)^{-1}B_h,\quad \hat{b}_h = \mu^h_y - \mu^h_x \hat{W}_h$$

块大小b下临时内存仅O(Ht·b(2pℓ + dt))，外加必要的充分统计量空间。求解器原有对象不变——映射器支持、权重、正则化强度、数值精度与序列化Schema均保持一致，Fused-Fit不改变数学解而只是改变构造路径。

## 6. 主要结论与发现

1. **故障方向恢复，质量提升**：在两个Ministral 3故障方向（3B→14B与8B→14B），CacheBridge将HellaSwag从52.2%和44.4%分别恢复至72.6%和76.0%，恢复20.4与31.6个精度点；四个任务的平均目标保留率从65.89%和59.43%提升至88.23%和97.57%。

2. **保持并改善正常工作方向**：在Qwen3 14B→32B上，4项任务相对Full-Head Mapping单点变化为(−1.80, +0.20, +0.20, +1.76)个百分点，平均目标保留率为99.83%（Full-Head为99.72%）。

3. **架构对齐的映射支持是决定性因素**：在相同计算预算下，Block-PCA控制使主要保留率降低13.97点，全部7个非对齐循环移位平均降低15.50点；恒等对齐头（shift 0）始终优于非对齐分配——这说明8×压缩带来的收益不是单纯来自参数体量下降，而来自与架构索引先行信息一致的支持结构。

4. **注意力加权提升续写但不等同于KV拟合提升**：在Qwen3上应用Attn-Repair，K/V R²仅变化了0.006/0.001，但main retention提升1.25点、NLL@4K从2.446降至2.350——有力说明“以注意力敏感度作为校准杠杆”能打破坐标重建指标与续写质量间的通道。

5. **数据效率大幅提升**：CacheBridge仅用50条校准序列的平均目标保留率即可匹配Full-Head Mapping用500条（500条校准全量）的水平（99.89% vs 99.44%），即十分之一校准数据实现同等迁移质量。

6. **系统开销显著下降**：映射器体积从4.296GB降至0.538GB（8×）；应用延迟在128/512/1,024 token前缀下分别1.6×/2.4×/3.0×加速；500序列映射器构建中位数从92.63秒降到8.63秒（10.7×）。

## 7. 方法优点

1. **去训练且保持闭式仿射部署接口**：Head-Local与Attn-Repair均不引入额外学习模块，在线推理时仍只是若干仿射变换；与其他“学习翻译器”类工作（Cache-to-Cache、Dery等、Latent Cache Flow、Mixture-of-Translators）相比，不增加开环推理环节和部署复杂度。

2. **映射器支持结构与架构先验直连**：使用GQA的查询→KV头归属关系和KV头数一致性作为硬约束，本质上是把模型结构知识嵌入统计估计器，避免了“数据驱动但无架构意识”的全头混杂带来的弱识别问题。

3. **针对度极高的消融设计**：Block-PCA控制与循环头分配的对照实验不仅控制容量，还控制“输入特征内容”与“对应关系”——这种精细归因在系统论文中较为难得。

4. **注意力校准与有效样本量之间的折衷处理**：对高度集中的注意力权重做有下限（neff ≥ min(n, 2pℓ)）的收缩，理论完备且实现轻量，一次性应用于目标层、头、K/V，无需任务标签。

5. **有界全融合核**：Fused-Fit两遍扫描以可预测的内存上界完成统计量构造，既满足不规则支持又规避了通用materialize的带宽瓶颈，快速且保留求解器的数学等同性。

6. **物理系统量度和学术质量指标并肩呈现**：存储、延迟、构造

6. **物理系统量度和学术质量指标并肩呈现**：存储体积、应用延迟、构造耗时等工程指标与精度保留率、NLL、R²等学术指标在同一套实验框架下同步报告，使得“架构设计改进 → 参数体量下降 → 延迟/内存收益”这条因果链完整闭合，而不是把系统优化与模型质量分成两张皮。

7. **保持公平对比的高度纪律性**：所有对照方法共用相同的校准序列、层选择方式、岭正则化强度、居中处理和评分样例，仅变化源头fan-in结构；λ=0.01直接沿用参考实现而不做针对性调整。这使观测到的差异可以干净地归因于论文提出的三个组件，而非超参偶然性或实现偏心。

8. **概念表述清晰且有层次**：“支持结构”、“校准目标”、“构造路径”三者分离的问题分解方式，使读者能独立评估每个组件的必要性与贡献，也便于后续工作在任意单一维度上继续改进。

## 8. 方法不足与局限

1. **头对齐依赖强架构先验**：Head-Local的前提是源与目标模型存在可用的查询→KV头归属关系且KV头数一致（实验中均为8头GQA→GQA，取a(h)=h）。若源与目标KV头数不等、GQA分组结构不同、或来自完全不同的架构家族（如Llama→Qwen），该恒等分配便不再适用；论文的循环移位实验虽然说明“错配有害”，却未给出更一般异构场景下的自动对齐策略。

2. **对源层选择机制本身缺乏深度创新**：层选择仍沿用Full-Head Mapping的单层OLS探头+top-k挑选，CacheBridge只改变了选定层之后的特征聚合方式。若上游层选择本身不稳定或选出的源层在分布外场景不再最优，Head-Local的窄支持会进一步放大层选错误的代价。

3. **校准边界与在线场景存在分布落差**：校准序列固定为FineWeb-Edu且总在相同边界附近采样权重，而实际推理请求的提示分布可能偏离该范围（更长、更结构化、更多对话历史）。Attn-Repair的敏感度权重是在校准边界上计算的，未验证目标域漂移下的鲁棒性。

4. **有效性结论依赖三类有限模型对**：三个迁移方向均在同一模型家族内部且共享相同词表规模相近的预训练分布。家族间迁移（如Ministral→Qwen）、有无embedding共享、tokenizer差异等更严峻场景未被覆盖，Head-Local依赖的深度对齐是否在这些场景依然成立仍是开放问题。

5. **注意力加权正则强度τℓ = min(n, 2pℓ)的启发式性质**：虽然论文给出了可解释的有效样本量下限推导，但2pℓ这个目标本身是经验设定，没有系统扫描不同倍数或更精细的自适应策略；对α\*的边界裁剪也可能使实际权重收缩程度比理论最优更保守。

6. **在线延迟测量不包含完整链路**：映射器延迟虽单测，但并未报告端到端TTFT（含权重加载、层选择查表、缓存重排、目标模型首token解码等）的完整数字；在真实推理服务中，缓存搬迁与kernel launch开销可能部分吞噬映射器加速所赢得的1.6×~3.0×。

7. **安全性/负面能力未讨论**：跨模型KV迁移改变了目标模型实际看到的上下文表征，这种非原生输入在越狱鲁棒性、事实一致性、上下文忠实性上的影响完全没有评估；KV域注入攻击是否因映射器而放大是值得关注的空白。

8. **代码与可复现性细节有限**：论文未提供开源实现、随机种子管理、校准数据的精确采样流程、以及目标侧NLL评估的16条长流的具体来源。Fused-Fit核函数的数值稳定性边界（float32累积误差、与参考float64解的差）也未报告。

## 9. 与相关工作/替代方案的比较定位

- **与Full-Head Mapping（直接基线）**：CacheBridge不是推翻其“闭式仿射跨模型映射”的基本主张，而是在同一个匹配问题内部重新设计了特征支持、加权与构造路径。相比基线的普遍退化（尤其架构宽度跳变场景），CacheBridge以更低参数预算实现更高精度与更低延迟，是同一框架下的显著帕累托改进。

- **与端到端映射训练方法（Cache-to-Cache, Dery等, Latent Cache Flow）**：这类方法把映射器当作可学习翻译器，以海量配对文本训练；优点是灵活、可适配大跨度差异，缺点是训练成本高、在线需额外运行翻译网络、难以保证闭式收敛。CacheBridge选择回归路线，换取了固定小矩阵乘法延迟和零附加训练。

- **与PC A/KV压缩迁移路线**：PCA等降维方法可视为“特征压缩以互相靠拢”的通用手段；论文的Block-PCA控制显示同等维度下无架构先验的压缩显著更差，说明这类纯数据驱动方法在这类任务上的天花板低于结构知识引导的Head-Local。

- **与多头注意力剪枝/稀疏化类比**：从“用所有头”到“用对齐的对应头”近似于结构化稀疏——支持模式不再是数据驱动而是由架构锚定的，因此天然具备跨模型的可迁移性；论文可视作结构化先验在缓存映射这一新场景下的成功应用。

- **与双向注意力蒸馏/表示对齐文献的关系**：Head-Local头对齐指标a(h)=h可理解为极简的“逐头表示锚定”；若推广到一般头匹配，可借鉴注意力头对齐的哈希或最优传输技术，但论文未沿此方向展开，留下清晰的后续空间。

## 10. 总体评价与结论

CacheBridge是一篇系统性较强的跨模型KV缓存迁移改进工作。它在方法层面干净利落地切出“支持结构—校准目标—构造路径”三个可独立演进的设计维度，分别以Head-Local、Attn-Repair、Fused-Fit回答，并在精度、数据效率、存储体积与延迟四类指标上取得一致收益。尤其值得肯定的是其消融控制设计：用Block-PCA排除“容量假说”、用循环移位排除“纯随机对应也能工作”、用K/V R²几乎不变而NLL改善的隔离结果证明注意力重新加权确实作用于续写质量而非坐标重建——这些对照直接支撑了论文的三个核心论断，而非堆砌更多精度数字。

与此同时，其适用性边界也清晰可见：恒等头对齐依赖GQA结构相似且KV头数一致的模型对，跨家族迁移与KV头数不等场景尚缺乏处理方案；层选择沿用旧法；校准域与在线域之间的漂移未被充分测试；系统收益的端到端测量仍待补全。若将这些边界视为限制而不视为否定，则论文在“通过架构索引信息提升统计估计效率”这一更广义问题上提供了坚实且可复用的正面证据。

从学术贡献看，CacheBridge的价值不限于具体方法：它示范了如何把一个工程系统问题分解为有对应可验证指标的三个子问题，也再次验证了一个更普适的原则——当回归器输入来自深度网络中间表征时，特征支持结构中的架构对齐先验往往比增加特征宽度或拟合容量更决定最终下游质量。对后续研究者的直接启发是：与其让映射器“看到所有头”然后从数据中自己发现对应关系，不如把已知的架构索引关系直接编码进支持结构，然后把节省的预算用于注意力敏感度赋权与更高效的构造实现。

综合而言，本文方法创新清晰、实验完成度高、系统收益可量化，属于该子领域中质量上乘的实证研究；主要短板在架构泛化性与端到端部署验证。建议读者将HellaSwag上的大幅恢复视为结构性证据而非泛化承诺，同时关注其消融设计的方法论示范意义。
