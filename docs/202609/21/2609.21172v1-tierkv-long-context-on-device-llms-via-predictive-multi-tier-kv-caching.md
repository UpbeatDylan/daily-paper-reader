## 摘要
大语言模型（LLM）正迁移到移动设备，以处理日益多样化的文本、图像、视频和音频工作负载。这些应用通常需要长上下文，使得键值（KV）缓存成为主要内存瓶颈，因为它随序列长度线性增长，并在每个解码步骤中被访问。先前工作通过低秩压缩、令牌驱逐或闪存卸载来减少 KV 缓存占用，但由此产生的重建开销、不可逆的令牌丢失或 I/O 停顿可能会抵消节省内存带来的收益。我们提出 TierKV，一个基于预测式多层级缓存优化（PMCO）的移动端 LLM 推理框架。在解码开始之前，PMCO 根据预填充隐藏状态预测未来的缓存需求，并在设备内存与精度预算下，将令牌联合分配到精确、低秩和闪存卸载层级。该方案保留了对完整上下文的访问，消除了反应式驱逐的循环依赖，并支持一种闭式求解器在运行时选择层级边界和逐层秩。在三款移动 SoC 上的八个文本、视觉和音频模型中，TierKV 将预填充吞吐量较现有移动 LLM 框架最高提升 17.6 倍，将驻留 RAM 的 KV 缓存减少 12.5–34%，从而在相同内存预算下支持显著更长的上下文，同时仅带来轻微精度下降。

## Abstract
Large language models (LLMs) are moving onto mobile devices for increasingly diverse workloads over text, images, video, and audio. These applications often require long contexts, making the Key-Value (KV) cache a dominant memory bottleneck because it grows linearly with sequence length and is accessed at every decoding step. Prior work reduces KV-cache footprint through low-rank compression, token eviction, or flash offloading, but the resulting reconstruction overhead, irreversible token loss, or I/O stalls can offset the benefit of saving memory. We present TierKV, a mobile LLM inference framework built on Predictive Multi-Tier Cache Optimization (PMCO). Before decoding starts, PMCO predicts future cache demand from prefill hidden states and jointly assigns tokens to exact, low-rank, and flash-offloaded tiers under the device memory and accuracy budgets. This formulation retains access to the full context, removes the circular dependency of reactive eviction, and admits a closed-form solver that selects tier boundaries and per-layer ranks at runtime. Across eight text, vision, and audio models on three mobile SoCs, TierKV improves prefill throughput by up to 17.6x over existing mobile LLM frameworks, reduces RAM-resident KV cache by 12.5-34%, thereby enabling substantially longer contexts under the same memory budget, while incurring only minor accuracy degradation.

## 1. 核心问题与研究动机

- **背景**：LLM 正从云端向移动端迁移，端侧应用（本地 RAG、思维链推理、多模态理解）普遍需要长上下文，即使简短的用户查询也会因检索文档、历史交互或视觉 token 而膨胀为数千 token。
- **核心瓶颈**：KV 缓存随序列长度线性增长，且在每一步解码中都被读取，使长上下文解码迅速变为内存受限。移动 SoC 内存带宽低，且 DRAM 需与 OS、系统服务共享。
- **现实约束**：以 OnePlus 12（12 GB RAM）为例，系统强制预留约 4.7 GB，仅剩约 6.8 GB 作为稳定应用预算；Llama-3.2-3B 在 32K 上下文下仅 KV 缓存就需约 1.8 GB，超出预算会触发 Low Memory Killer 直接杀进程。
- **现有方案的三类缺陷**：
  - 低秩压缩：多依赖静态秩或需在注意力中重建全秩张量，在 OnePlus 12 上平均增加 30% 计算开销。
  - Token 驱逐：不可逆的信息丢失，长程依赖任务上质量下降。
  - 闪存卸载：受内存带宽与闪存延迟限制。
  - 潜注意力转换（如 MHA2MLA）：引入随上下文长度扩展的逐 token GEMV，在移动 GPU 上使吞吐在 100 token 时下降 46%、900 token 时下降 75%。
- **整体含义**：论文主张将移动端 KV 缓存管理重新表述为**解码前的预测式资源分配问题**，而非解码后期的被动压缩决策，目标是同时实现内存缩减、精度保持与零额外计算瓶颈。

## 2. 方法论：Predictive Multi-Tier Cache Optimization (PMCO)

### 2.1 核心思想

- 在解码开始前，利用 prefill 阶段已算出的隐藏状态预测未来缓存需求，并联合决定每个 token 的 KV 对放在哪一层级。
- 采用**三级缓存抽象**，沿序列维度由两个边界 $n$、$m$ 划分：
  - **Tier-0（精确）**：$t \in (0, n]$，保持未压缩，保护对压缩敏感的位置（尤其是早期 attention-sink token）。
  - **Tier-1（压缩）**：$t \in (n, m]$，以 SVD 低秩形式存储，逐层秩为 $R_l$。
  - **Tier-2（卸载）**：$t \in (m, L]$，驻留闪存，以有界内存支撑超长上下文。
- **关键特性**：完整上下文跨三层保留而非永久丢弃；Tier-2 保持全秩（闪存驻留本身不占 RAM，压缩反而增加重建延迟与精度权衡）。

### 2.2 设计依据（表 4 的压缩敏感性分析）

- 全 token 压缩不安全：GSM8k 在 25% 秩时准确率从 0.7809 崩至 0.0258，12.5% 秩时仅 0.008；保留少量精确窗口即可恢复大部分判别能力。
- 全部卸载过昂贵：移动平台 host-to-device 传输仅 1.66 GB/s，卸载 Llama-3.2-3B 的 9.6K token 每步解码增加约 189 ms。
- 最优层级边界依赖请求：MMLU 在精确比 0.8 时容忍 12.5% 秩（0.6804 vs 0.6807），GSM8k 同样设置下仅 0.011，因此需按请求自适应。

### 2.3 问题形式化

- **延迟模型**（式 2）：
  $$T_{total} = T_{attn}(n) + T_{svd}(m-n, R) + T_{io}(L-m)$$
- **内存模型**（式 3）：
  $$M_{total} = M_w + M_{buf} + M_{T0}(n) + M_{T1}(n, m, R)$$
  其中 Tier-2 token 驻留磁盘，不出现在 $M_{total}$ 中。
- **优化目标**（式 4）：
  $$\min_{n,m,R} T_{total}(n,m,R) \quad \text{s.t. } M_{total} \le M_{limit},\ 0<n<m\le L,\ \mathcal{F}(n,R)\ge \text{AccThreshold}$$
- **解空间**：逐层秩剖面离线校准，在线决策空间为 $O(L^2 \cdot |\mathcal{R}|)$；校准在 2 块 NVIDIA A6000 上每模型 <20 分钟，每层仅产生 256 字节元数据。

### 2.4 预测式缓存配置

- **长度预测（training-free）**：
  - 复用 prefill 隐藏状态 $h_t$，以 Shannon 熵 $\mathcal{E}_t$ 生成重要性权重 $\alpha_t$，得到提示指纹 $z_{prompt} = \sum_t \alpha_t h_t$。
  - 在设备端历史数据库 $\mathcal{M}$ 上做 k-NN 余弦相似度检索，对检索到的历史输出长度取平均得到 $\hat{L}_{gen}$。
  - 无需辅助模型参数或离线训练，可随设备端提示分布自适应。
- **鲁棒性**：过预测仅造成预算内未用容量（每请求最多 13.67 MB），欠预测仅增加 Tier-2 I/O，不影响精度，也不会触发 OOM。
- **线性化成本模型**：对 KQV GEMV、FFN GEMM、SVD 重建 GEMM（约占 90% 计算）离线微基准，建立 $T_{est}$（式 7）与 $M_{est}$（式 8），并把 I/O bubble 视为可用计算窗口。
- **闭式求解器**：对每个候选 $R$，求延迟与内存归一化后的平衡轨迹
  $$\frac{\alpha \cdot T_{est}}{T_{max}} = \frac{\beta \cdot M_{est}}{M_{limit}}$$
  在 $(n,m)$ 平面上化为线性方程，与可行多边形求交得到 $(n^*, m^*)$；遍历小离散集 $\mathcal{R}$ 返回最低延迟可行解，在线选择耗时 <0.1 s/请求。
- **Algorithm 1 流程**：预测 $L$ → 加载长度相关成本/精度模型 → 求解连续问题 → 可行性循环（内存超限则将 $m$ 逐步前移，必要时同步调整 $n$）。

### 2.5 运行时设计

- **融合分离路径注意力（Fused Split-Path Attention）**：
  - 在单个 online-softmax 循环中同时遍历精确块与压缩块；精确块走标准 FlashAttention 路径。
  - 压缩块仅对当前块重建 key：$K_{recon} = Z_{SK}^\top \cdot W_{uk}$，重建结果不离开 SRAM，不写回全秩缓存。
  - **潜空间 Value 累积**：$O_{latent} = \sum_j P_j \cdot Z_{SK}^{(j)\top}$，最后一次性投影 $O_{proj} = O_{latent} \cdot W_{uv}$，V 路径复杂度从 $O(L \cdot z \cdot d)$ 降至 $O(L \cdot z + z \cdot d)$；在 Llama-3.2-1B、50% 秩下减少 45% FLOP。
- **执行流水线**：
  - 观察到 I/O bubble 以可预测的逐层节奏出现，将 bubble 序列视为周期性计算资源而非一次性暂存窗口。
  - **非对称 K/V 调度**：$K_{recon}$ 是延迟关键路径（softmax 等待它），被派发进 bubble；潜 V 累积写入逐层缓冲，单次投影推迟到层边界。
  - $K_2(R)$ 即为该重叠调度下测得的逐 token 重建成本，因此 PMCO 选出的配置天然适配每层 bubble。
  - 端到端较非重叠基线降低 10–30% 延迟。
- **自动调优 kernel**：搜索空间包括工作组分块（16–128）、SIMD 向量宽度（1–8）、循环展开（1–8）、跨步访问与本地缓存开关；每模型仅需 1–4 次预热运行。
