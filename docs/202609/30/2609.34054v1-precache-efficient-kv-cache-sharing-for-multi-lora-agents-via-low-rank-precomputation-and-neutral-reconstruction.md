## 摘要
多LoRA智能体系统通过共享一个公共骨干模型来实现高效的角色专业化。然而，每个智能体都会重复处理不断增长的共享轨迹并构建各自的KV缓存，从而在长时程任务中引入显著的内存与计算冗余。现有的KV缓存共享方法减少了这种重复预填充，但它们要么需要额外训练或架构约束，要么仍保留大量模型计算。此外，直接复用缓存会使当前智能体依赖前一个智能体适配器生成的缓存状态，从而削弱其自身LoRA所编码的角色特定行为。我们提出PReCache，一种免训练的KV缓存共享框架，包含两种设计，即PreLRShared和ReBaseShared，它们共享使用预训练权重计算的基础缓存，并预计算紧凑的智能体特定低秩（LR）缓存。为消除重复预填充，PreLRShared在首次处理共享上下文时为每个智能体预计算其LR缓存，使当前智能体无需重新处理先前智能体已处理的上下文即可使用自身的LR缓存。为提高共享准确性，ReBaseShared从无适配器的隐藏状态重建共享基础缓存，减少由前一个智能体的适配表示所导致的剩余误差。为最小化其重建开销，我们提出两种推理方案，分别面向单流推理和并发服务，分别在每个智能体轮次结束后或与其执行同时进行相同重建。在多个模型和智能体基准上，PreLRShared相比无KV缓存共享的推理，实现了最高3.1倍的TTFT加速和2.3倍的每请求吞吐量提升。在评估的缓存共享方法中，ReBaseShared总体上最能保持准确性，相较无缓存共享的推理，平均仅下降1.1个百分点。

## Abstract
Multi-LoRA agent systems enable efficient role specialization by sharing a common backbone model. However, each agent repeatedly processes the growing shared trajectory and constructs its own KV cache, introducing substantial memory and computation redundancy in long-horizon tasks. Existing KV cache sharing methods reduce this repeated prefill, but they either require additional training or architectural constraints or retain substantial model computation. Moreover, direct cache reuse causes the current agent to rely on cache states generated by the previous agent's adapter, weakening the role-specific behavior encoded by its own LoRA. We present PReCache, a training-free KV cache sharing framework with two designs, namely PreLRShared and ReBaseShared, that share the base cache computed using the pretrained weights and precompute a compact agent-specific low-rank (LR) cache. To remove repeated prefill, PreLRShared precomputes each agent's LR cache when the shared context is first processed, allowing the current agent to use its own LR cache without reprocessing context processed by previous agents. To improve sharing accuracy, ReBaseShared reconstructs the shared base cache from adapter-free hidden states, reducing the remaining error caused by the previous agent's adapted representation. To minimize its reconstruction cost, we propose two inference schemes tailored to single-stream inference and concurrent serving, performing the same reconstruction after each agent's turn or alongside its execution, respectively. Across multiple models and agent benchmarks, PreLRShared achieves up to a 3.1x TTFT speedup and a 2.3x improvement in per-request throughput over inference without KV cache sharing. ReBaseShared best preserves accuracy overall among the evaluated cache-sharing methods, with an average drop of only 1.1 points relative to inference without cache sharing.

# PReCache 论文总结

## 1. 核心问题与整体含义（研究动机与背景）

- **背景**：多 LoRA 智能体系统通过共享一个预训练骨干模型、为每个角色挂载轻量 LoRA 适配器，实现角色专业化，显著降低模型内存占用，尤其适合资源受限场景。
- **核心痛点**：
  - 多智能体协作会不断累积共享轨迹（用户请求、检索信息、工具观测、前序智能体输出），轨迹随轮次增长而变得极长且 prefill 密集。
  - 每个智能体都要**独立重复处理**已被前序智能体处理过的上下文，并构建**各自的 KV 缓存**，造成严重的内存与计算冗余。
  - 直接复用缓存（FullShared）会引入精度下降：由于不同适配器权重不同，即使处理同一上下文，KV 缓存也不同；当前智能体会依赖前一个智能体适配器生成的缓存状态，**削弱其自身 LoRA 所编码的角色特定行为**。
- **已有方法的不足**：
  - 跨模型/智能体共享方法（学习映射、校准变换、专用架构）需要额外训练或架构约束，难以直接用于现有多 LoRA 智能体。
  - 免训练的偏差校正方法针对前缀/位置差异，在智能体间前缀匹配时校正量不变，对 LoRA 适配器差异**退化为 FullShared**。
  - 选择性重计算（DroidSpeak、CacheBlend、RelayCaching）在异构 LoRA 下精度恢复不足，提高重计算比例又会损失计算与内存收益。
  - LRAgent 的 BaseShared 虽能保持精度、降低缓存内存，但仍需当前智能体对累积上下文做全长度骨干处理来构建 LR 缓存，**大部分重复 prefill 未被消除**；BaseLRShared 虽消除重复处理，但要求所有适配器共享同一 LoRA 下投影，不兼容现有适配器。
- **研究目标**：在**免训练、不限制现有 LoRA 适配器**的前提下，同时降低 KV 缓存内存占用与重复 prefill 计算，且不显著损失精度。

## 2. 方法论

### 2.1 核心思想
- 将适配后的投影输出分解为**基础贡献**与**适配器贡献**：
  - 对冻结投影 $W_0$ 与 LoRA 权重 $A_i, B_i$（$r \ll d_{in}, d_{out}$），有
    $Y_i = X_{i,adpt}(W_0 + A_iB_i) = \underbrace{X_{i,adpt}W_0}_{基础贡献} + \underbrace{(X_{i,adpt}A_i)B_i}_{适配器贡献}$
- 因此 KV 缓存可拆为：**共享基础缓存**（用预训练权重计算）+ **紧凑的智能体特定低秩（LR）缓存**（秩为 r）。
- PReCache 包含两个设计：**PreLRShared**（消除重复 prefill）与 **ReBaseShared**（在保留 LR 预计算的同时提升基础缓存共享精度），并配套两种推理调度（LP / DB）。

### 2.2 PreLRShared：LR 缓存预计算
- 当某个上下文片段**首次被处理**时（例如智能体 i 处理 $L_P$），就把**所有 N 个智能体**的下投影 $A_k$ 应用到该批隐藏状态 $X_{i,adpt}$ 上，一次性构造 $X_{i,adpt}A_k$（$k=1,\dots,N$）。
- 智能体 i 轮次结束后，共享基础缓存与全部 LR 缓存均覆盖 $L_P$。
- 后续智能体 j 直接复用共享基础缓存 + 自己的 LR 缓存，**只需处理新增上下文 $L_C$**，无需重算累积轨迹；同时对新上下文继续为所有智能体扩展 LR 缓存。
- 效果：把原本对 $L_P$ 的**全维度骨干处理**替换为**轻量的秩 r 下投影**。

### 2.3 ReBaseShared：中性基础缓存重建
- 问题：共享基础缓存 $X_{i,adpt}W_0$ 仍带前一个智能体适配器的影响（适配效应逐层传播）。
- 做法：用**关闭适配器**的隐藏状态 $X_{neut}$ 构造**中性基础缓存** $X_{neut}W_0$。
- 理论分析（附录 A.1）：设 $\Delta_i = C_i - C_{neut}$、$\Delta_j = C_j - C_{neut}$，定义范数比 $\rho = \|\Delta_i\|_2/\|\Delta_j\|_2$ 与余弦相似度 $\cos\theta$，则两方案相对误差之比为
  $$\Gamma_{err} = \frac{E_{prev}}{E_{neut}} = \sqrt{1 + \rho^2 - 2\rho\cos\theta}$$
  当且仅当 $\rho \geq 2\cos\theta$（即 $\Gamma_{err}\geq 1$）时，中性基础缓存相对误差更低。附录 A.2 在 LLaMA-3.1-8B 与 Ministral-8B 的三种智能体转换（plan→action、action→reflect、reflect→plan）上逐层测量，$\Gamma_{err}$ 在所有层均大于 1，验证了该条件成立。
- ReBaseShared 保留 LR 预计算，并用**同一批无适配器隐藏状态**为其他智能体构造 LR 缓存。

### 2.4 两种推理调度（LP / DB）
- **LP（Lazy Prefill）**：仅单流边缘推理使用。当前智能体轮次内只跑适配路径；解码结束后，用无适配器骨干对新增上下文 $L_C$ 做一次**连续 prefill**，扩展中性基础缓存。避免维护无适配器解码路径，且重建可**与工具调用重叠**。
- **DB（Double Batching）**：并发服务使用。在 prefill 与解码阶段**同时**调度适配路径与无适配器路径（double-batching），两路径处理相同 token 与位置但维护独立 KV 视图；适配路径只关注当前智能体 KV 缓存并产生 logits，无适配器路径只关注中性基础缓存并扩展它。
- 两者产生**逻辑等价**的缓存状态，仅重建时机不同：LP 适合单流边缘推理，DB 适合并发服务端（减少排队延迟）。

## 6. 主要结论与发现

- **精度**：ReBaseShared 在评估方法中总体最接近 NonShared，平均仅下降 **1.1 个百分点**，与 BaseShared 相当；PreLRShared 平均退化在 **1.0–3.3 个百分点**之间，且仍与选择性重计算基线相当或更优。
- **效率（单流）**：PreLRShared 相比 NonShared 最高 **3.1× TTFT 加速**、**2.3× 每请求吞吐提升**；ReBaseShared LP 最高 **3.0× TTFT 加速**、**1.6× 吞吐提升**，并在长轨迹上优于所有选择性重计算基线。BaseShared 因仍需智能体特定骨干处理，接近 NonShared/DroidSpeak。
- **效率（并发）**：高负载下 PreLRShared 与 ReBaseShared DB 保持优势；非饱和负载下每请求吞吐分别比 NonShared 高 **1.6×** 与 **1.3×**；高请求率下差距扩大，反映服务容量差异。
- **调度选择**：LP 在单流推理中 TTFT 更低、吞吐更高（重建在下一智能体 TTFT 之外）；DB 在并发服务中随请求率升高优于 LP（避免单独重建 prefill 阻塞队列）。
- **内存**：PreLRShared 与 ReBaseShared 保持 BaseShared 的内存效率，接近 FullShared；66.4k token 时峰值内存**在 FullShared 的 2% 以内**，比选择性重计算基线**少 17–23%**。
- **可扩展性**：智能体数 N 从 4 增至 8 时，PreLRShared/ReBaseShared LP 的 TTFT 仅增 3%/7%（基线增 32–53%），吞吐降约 6%（基线降 20–30%），内存仅增 1–2%；其开销主要取决于**新增上下文总量**而非智能体轮次间隔。
- **中性重建有效性**：逐层测量显示 $\Gamma_{err}$ 在所有层均 >1，中性基础缓存比前序智能体基础缓存更接近当前智能体的基础缓存。
