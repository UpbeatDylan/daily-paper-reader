## 摘要
扩散大语言模型（dLLM）最近作为一种有前景的自回归 LLM 替代方案出现，能够支持非自回归文本生成。然而，其实际部署仍受限于低效推理，主要原因是缺乏有效的键值（KV）缓存和可扩展的并行解码机制。现有加速方法通常孤立地研究 KV 缓存与并行解码，忽视了当缓存复用与并行 token 验证联合应用时出现的 I/O 瓶颈。在本工作中，我们提出 Flash-dLLM，一个免训练推理加速框架，用于快速且内存高效的 dLLM。Flash-dLLM 首先将 GPU 内存 I/O 识别为启用 KV 缓存的 dLLM 推理中的主要瓶颈，并通过 I/O 感知的融合 KV 缓存内核来减少冗余内存移动，从而解决该问题。基于这种优化的缓存机制，Flash-dLLM 进一步提出一种高效的、由 KV 缓存驱动的草稿-验证解码策略，其中 dLLM 本身同时充当草稿器和验证器，无需辅助模型。这种统一设计能够加快解码，同时保持生成质量，并提升对更长序列和更大批大小的可扩展性。在数学推理和代码生成基准上的大量实验表明，Flash-dLLM 在推理速度和内存效率方面均持续优于现有最先进的 dLLM 加速方法。特别是，在 GSM8K 和 HumanEval 上，它分别比先前最强基线 Elastic-Cache 实现了 5.1× 和 11.0× 的加速。

## Abstract
Diffusion Large Language Models (dLLMs) have recently emerged as a promising alternative to autoregressive LLMs by enabling non-autoregressive text generation. However, their practical deployment remains limited by inefficient inference, largely due to the absence of effective Key-Value (KV) caching and scalable parallel decoding mechanisms. Existing acceleration methods typically study KV caching and parallel decoding in isolation, overlooking the I/O bottlenecks that arise when cache reuse and parallel token verification are jointly applied. In this work, we introduce $\textbf{Flash-dLLM}$, a training-free inference acceleration framework for fast and memory-efficient dLLMs. Flash-dLLM first identifies GPU memory I/O as a dominant bottleneck in KV-cache-enabled dLLM inference and addresses it with an I/O-aware fused KV-cache kernel that reduces redundant memory movement. Building on this optimized cache mechanism, Flash-dLLM further proposes an efficient KV-cache-driven draft-and-verify decoding strategy, where the dLLM itself serves as both drafter and verifier without requiring an auxiliary model. This unified design enables faster decoding while preserving generation quality and improving scalability to longer sequences and larger batch size. Extensive experiments on mathematical reasoning and code-generation benchmarks demonstrate that Flash-dLLM consistently outperforms existing state-of-the-art dLLM acceleration methods in both inference speed and memory efficiency. In particular, it achieves $5.1\times$ and $11.0\times$ speedups over prior strongest baseline Elastic-Cache on GSM8K and HumanEval, respectively.

- **整体含义**：论文提出 **Flash-dLLM**，一个免训练推理加速框架，将 IO 感知 KV 缓存与缓存驱动的并行草稿-验证解码统一设计，把扩散语言生成的内在并行性转化为实际墙钟加速，并改善显存效率与长序列/大 batch 可扩展性。

## 2. 方法论

### 2.1 核心思想
联合优化两个层面：(1) 以 IO 感知融合内核减少冗余 KV 缓存显存搬运；(2) 利用 token 稀疏性与置信度动态，让 dLLM 自身兼任草稿器与验证器，实现高效并行解码。

### 2.2 关键技术细节

**（1）Flash-Cache：IO 感知 KV 缓存**

- **融合 KV 缓存内核**：传统实现在每层为查询集 Qt 分别启动 QKV 投影、RoPE、缓存写入、注意力四个 CUDA 内核，每层 HBM 流量约为 `4 × O(Qd_model) + O(Nd)`，非注意力操作算术强度低，导致缓存更新路径受内存限制。受 Flash Attention 启发，融合内核在 SRAM 中完成投影与 RoPE，并直接将 K/V 写入 KV 缓存，消除中间键值物化，降低 HBM 流量与显存占用，实测取得 **1.37× 加速**（RTX 3090）。
- **调度式 Flash 注意力（Scheduled Flash Attention）**：针对扩散 LLM 中序列长度动态多变（缓存阶段 vs. 更新阶段、Elastic-Cache 自适应、并行解码进度不一）的问题，将每个 batch 划分为多个序列块，用**块表（block table）**对齐查询块与对应 KV 块，避免 padding 与同步开销，支持灵活增删块。
- **选择性缓存更新（Selective Cache Update）**：仅维护并更新固定数量（tracking budget βt）的**最受关注 token**。每步对已解码 token 计算注意力得分：
  `a_t^i = Σ_l (1/H) Σ_h (1/|M_t^{βm}|) Σ_{j∈M_t^{βm}} S_{j,i}^{t,l,h}`
  追踪集 `T^{t+1} = top-k({a_t^i}, βt − |Dt|) ∪ Dt`，下一步查询集 `Q^{t+1} = M^{t+1}_{βm} ∪ T^{t+1}`，将每步计算量限定为 `βt + βm`。

**（2）Flash-Verify：KV 缓存驱动的草稿-验证并行解码**

- **动机**：置信度感知解码只接受置信度 `ci ≥ ε` 的 token，丢弃大量正确预测，造成吞吐上限。
- **两阶段流程**：
  - **草稿阶段**：对查询集 `Qt = Tt ∪ Mt_{βm}` 跑一次前向，将掩码位置按置信度分为**确信集 Dt**（≥ ε，直接接受）与**搜索集 St**（< ε，待验证）。
  - **验证阶段**：构造含三组元素的验证查询——调整后的追踪集 Tv、用草稿预测 `x̂i` 填充的搜索位置（**草稿视图**）、用 `[MASK]` 填充的同一位置（**掩码视图**）。两视图共享位置嵌入，但被**因果注意力掩码**隔离（追踪上下文不能看草稿视图；同位置两视图互不可见），从而在单次额外前向中获得独立预测。
  - **接受规则**：`accept(i) = I[x̂i = x̃i] · I[c̃i ≥ γ]`，沿解码顺序从左到右接受，遇到首个不匹配即停止。
- **成本**：验证复用同一融合内核与预分配 KV 缓存，仅查询 token 与注意力掩码改变，额外成本正比于 `2βm` 而非全序列。
- **理论保证（附录 C）**：在 Assumption 1 下，证明单 token 偏差 `TV(πi, pi) = 1 − c̃i ≤ 1 − γ`；块级偏差 `TV(πA, pA) = 1 − Π c̃ik ≤ 1 − γm ≤ m(1 − γ)`。γ 门控掩码视图置信度，保证对模型自身链式法则联合分布的有界偏差。

## 6. 主要结论与发现

- **吞吐提升**：Flash-Cache 在 greedy 下提速 8.0×–58.5×；置信度感知下 17.0×–102.2×；结合 Flash-Verify 达 148.0–210.6 tokens/s，整体提速 22.3×–148.2×。
- **相对最强基线**：较 Elastic-Cache 在 GSM8K 与 HumanEval 上分别实现 **5.1× 与 11.0× 加速**（摘要）；表 2 显示 Flash-Cache + Flash-Verify 达 210.6 tokens/s（81.0×），准确率 83.02%，优于所有基线。
- **准确率**：在 GSM8K-512 上同时取得最高准确率（83.02%）与最高吞吐（210.6 tokens/s）；数学任务上组合方法距最佳准确率在 1.78 个百分点内；256-token 代码生成差距略大（HumanEval 3.66、MBPP 3.60 个百分点）。
- **长序列增益更大**：从 256 到 512 token，GSM8K 提速由 29.1× 增至 81.0×，MBPP 由 61.7× 增至 148.2×。
- **可扩展性**：Flash-dLLM 近线性扩展至 batch size 32，而 Fast-dLLM 在 batch 24 时 OOM；batch 16 时显存约 26 GB vs. Fast-dLLM 50 GB，**降低约 48%**。
- **Flash-Verify vs. 置信度解码**：在共享准确率区间（约 82.6%–82.9%）下吞吐达 190–210 vs. 140–160 tokens/s；每迭代解码 token 数更多（7.2 vs. 5.6），准确率高 3.5%。
- **超参权衡**：增大 βt 或 γ 提升准确率但降低吞吐；γ 提供更细粒度的并行度控制。

## 7. 优点

- **问题识别精准**：明确指出并量化 KV 缓存与并行解码**联合**时的 I/O 瓶颈，而非孤立优化，视角新颖。
- **统一设计**：Flash-Cache 与 Flash-Verify 共享同一融合内核与预分配 KV 缓存，协同增效。
- **免训练且无需辅助模型**：dLLM 自身兼任草稿器与验证器，通过双视图因果掩码实现自验证，无需外部 AR 验证器或额外训练，部署成本低。
- **理论支撑**：附录 C 给出 Flash-Verify 的**有界偏差保证**（单 token 与块级 TV 距离界），说明 γ 门控的合理性，区别于纯经验方法。
- **工程优化扎实**：融合 Triton 内核、块表调度式注意力、预分配平坦缓存布局，兼顾显存与吞吐。
- **实验较全面**：多任务、多生成长度、多超参扫描、5 种子统计、批大小扩展与显存分析，且基线在统一环境重跑。
- **可扩展性突出**：近线性扩展至 batch 32 且显存显著降低，实用性强。

## 8. 不足与局限

- **模型覆盖有限**：仅在 LLaDA-1.5（及文中提及的另一代表性掩码扩散 LLM）上评测，未验证连续空间扩散语言模型，而后者缓存更新模式可能不同。
