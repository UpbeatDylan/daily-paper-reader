## 摘要
前缀缓存对于高效地服务大语言模型（LLM）至关重要，尤其是对于会以不断增长的对话和工具使用历史反复调用模型的智能体式工作负载。通过复用先前已处理前缀的键值（KV）状态，前缀缓存避免了冗余的预填充计算。然而，其有效性取决于能否保留足够大的 KV 缓存状态集合。为保存所有历史 KV 状态而配置足够的缓存代价过高，且往往没有必要；而容量不足则可能显著降低缓存命中率。因此，确定 KV 缓存工作集——即达到目标命中率所需的最小缓存容量——对于高效的缓存配置和系统设计至关重要。我们提出 KVSET，一种在线分析器，用于估计 LLM 服务工作负载的 KV 缓存工作集。KVSET 使用 Mattson 栈算法高效估计大范围缓存容量下的缓存命中率。对于每个 KV 缓存页，KVSET 计算其 LRU 栈距离，并将其与每个候选容量对应的页数进行比较。该比较无需独立模拟每种容量配置，即可确定该页在各容量下是否命中。因此，KVSET 大幅降低了传统逐容量模拟的计算与内存开销，使在线工作集分析变得切实可行。KVSET 还根据达到目标命中率所需前缀页中的最大 LRU 深度来确定最小缓存容量。我们使用从生产环境 LLM 工作负载中收集的轨迹验证了 KVSET，并表明其估计值与真实缓存部署的测量结果密切吻合。该开源实现同时支持在线请求处理和离线轨迹回放。

## Abstract
Prefix caching is critical for efficient large language model (LLM) serving, particularly for agentic workloads that repeatedly invoke the model with a growing conversation and tool-use history. By reusing the key-value (KV) states of previously processed prefixes, prefix caching avoids redundant prefill computation. Its effectiveness, however, depends on retaining a sufficiently large set of KV cache states. Provisioning enough cache to preserve all historical KV states is prohibitively expensive and often unnecessary, whereas insufficient capacity can substantially degrade the cache hit rate. Determining the KV cache working set, defined as the minimum cache capacity required to achieve a target hit rate, is therefore essential for efficient cache provisioning and system design. We present KVSET, an online analyzer that estimates the KV cache working set of LLM serving workloads. KVSET uses the Mattson stack algorithm to efficiently estimate cache hit rates across a wide range of cache capacities. For each KV cache page, KVSET computes its LRU stack distance and compares it with the page number of each candidate capacity. This comparison determines whether the page would be a hit at each capacity without independently simulating every capacity configuration. KVSET therefore substantially reduces the computational and memory overhead of conventional capacity-by-capacity simulation and makes online working-set analysis practical. KVSET further determines the minimum cache capacity based on the maximum LRU depth among the prefix pages required to achieve the target hit rate. We validate KVSET using traces collected from production LLM workloads and show that its estimates closely match measurements from real cache deployments. The open-source implementation supports both online request processing and offline trace replay.

- **研究动机**：LLM 智能体工作负载（编码助手、深度研究、客服等）常以多轮、工具调用方式反复调用模型，每轮通常复用大部分历史输入输出。前缀缓存通过复用已计算的 KV 状态避免重复 prefill，从而提升吞吐、降低成本。
- **核心矛盾**：前缀缓存的有效性取决于能否保留足够大的 KV 状态集合。保留全部历史 KV 状态代价过高，且往往没有必要；容量不足又会显著降低缓存命中率。
- **关键概念**：论文提出分析 **KV 缓存工作集**，即达到目标命中率所需的最小缓存容量。其目标不是缓存全部历史，而是以明确的目标命中率/覆盖率来指导容量规划。
- **整体含义**：现有方法如 `kvcache-simulator` 需要针对多个候选容量分别重放轨迹，开销大，难以在线集成。KVSET 旨在用单次轨迹分析同时估计多个容量下的命中率，并确定最小容量，使在线容量规划变得可行。

## 2. 方法论

- **核心思想**：面向页粒度 LRU 前缀缓存，利用 LRU 的栈性质与 Mattson 栈算法。对每个 KV 页计算其 **LRU 栈距离**，即可判断该页在任意缓存容量下是否会命中，而无需为每个容量单独模拟一个缓存池。
- **关键技术细节**：
  - 将 token 前缀复用转化为 **KV 页引用流**，按页粒度管理缓存。
  - 对每个页记录最近一次访问位置，并用 **Fenwick 树** 维护访问位置信息。
  - 每次访问时，Fenwick 树统计“比被访问页更近被访问过的不同页数”，该数量即该页的 LRU 栈距离。
  - 若某页的栈距离小于候选容量 `C`，则在该容量下命中；否则未命中。由此可一次性得到多个容量下的命中/未命中结果。
- **算法流程概述**：
  1. 接收在线请求或离线轨迹，将请求中的前缀复用解析为 KV 页访问序列。
  2. 对每个页访问，计算其 LRU 栈距离。
  3. 将栈距离与各候选容量比较，聚合所有访问，得到容量—命中率曲线。
  4. 根据达到目标命中率所需前缀页中的 **最大 LRU 深度**，确定该请求/工作负载所需的最小缓存容量。
- **吞吐关系**：论文指出 prefill 吞吐随 KV 命中率非线性上升。按文中上下文，关系可理解为 `T = T0 / (1 - r)`，其中 `T0` 为零命中时吞吐，`r` 为命中率；高命中率区间收益显著。
- **实现支持**：开源实现同时支持 **在线请求处理** 和 **离线轨迹回放**，便于生产系统在线分析与容量规划。

## 6. 主要结论与发现

- KVSET 能较准确地估计不同缓存容量下的命中率，预测值与真实缓存部署测量密切吻合。
- 容量—命中率曲线呈非线性：
  - 低容量区间，命中率随容量增长快速上升。
  - 超过某一点后，边际收益显著递减。
- 容量规划应基于明确的 **覆盖目标**，而不是保留全部历史 KV 状态。
- 在生产 coding-agent 轨迹中：
  - **99.9% 覆盖率**所需容量随请求流持续增长，未见收敛。
  - **99% 覆盖率**约需 **5 TiB** KV 存储。
  - **95% 覆盖率**约需 **1 TiB** KV 存储。
- 对分层缓存的实际建议：若 CPU 内存和磁盘分别目标 95% 与 99% 请求覆盖，可考虑约 **1 TiB CPU 内存 + 5 TiB 磁盘**。
- KVSET 支持在线请求处理和离线轨迹回放，可作为分层缓存容量规划的基础工具。

## 7. 优点

- **方法高效**：利用 Mattson 栈算法与 Fenwick 树，单次轨迹重放即可得到多个容量下的命中率，避免逐容量模拟。
- **在线可行**：计算和内存开销低，适合集成到在线 LLM 服务系统，进行实时容量分析。
- **页粒度精确分析**：面向实际 KV 页缓存，而非仅做粗粒度 token 或请求级估计。
- **生产验证**：使用真实生产 coding-agent 轨迹，并与 Mooncake + SGLang 的真实部署测量对比。
- **实践指导明确**：提出以覆盖率目标驱动容量规划，并给出 95%、99%、99.9% 覆盖下的容量差异与分层缓存建议。
- **开源贡献**：提供开源实现，支持在线与离线模式，据称是首个支持在线 KV 缓存容量分析的开源工具。

## 8. 不足与局限

- **淘汰策略限制**：KVSET 仅适用于 **LRU 淘汰**，未扩展到 LFU、FIFO、ARC 或其他实际可能采用的策略。
